PART B — WHY THE PRESCRIBED COMMAND CANNOT PRODUCE A SYMBOL COUNT
================================================================================

Four independent defects. Any one of them alone invalidates the count.

B1. IT MATCHES STEMS, NOT NAMES. The pass never writes a full symbol name as a
    literal. It builds names by CONCATENATING a stem with an ABI-width string
    (and optionally an axis suffix) at emit time — see Part C for every site.
    `"cqrt_rz_"` is one grep result but denotes 27 distinct symbols.

B2. IT IS BLIND TO SYMBOLS THE PASS NEVER EMITS. `cqrt_h` and `cqrt_h_controlled`
    are DECLARED and DEFINED in the frozen ABI but appear NOWHERE in ir-pass/ —
    so the grep cannot see them at all, at any expansion. `cqrt_alloc_handle` is
    likewise never emitted by the pass (it is a runtime-internal helper). The
    grep censuses what the pass EMITS; the shim must satisfy what the ABI
    DECLARES. Those are different sets.

B3. IT SEARCHES THE WRONG LAYER. The authoritative `cqrt_*` surface is the
    hand-written header runtime/cq_runtime.h, not ir-pass/src. CQ_lang says so
    itself, in tools/core_abi_link_check.py:5-9 — that tool exists precisely
    because enumerating `cqrt_*` from the emitter layer is the wrong move.

B4. IT SAYS NOTHING ABOUT `cq_template_*`, which is ~94% of the link surface
    (2880 of 3053 total symbols). The `cqrt_*` core is the small half.

WHAT TO USE INSTEAD. Two commands, one per family. Both are ground truth because
both read the DECLARATION layer:

    # cqrt_* core ABI  -> 173.  Comment-stripped; tolerant of the return type
    # and of column alignment (see the WARNING below).
    python3 - <<'EOF'

    t=re.sub(r"/\*.*?\*/"," ",t,flags=re.S); t=re.sub(r"//[^\n]*"," ",t)
    print(len(set(re.findall(r"\b(cqrt_[A-Za-z0-9_]+)\s*\([^;{]*\)\s*;",t))))

      printf '%s ' "$f"

    done

>>> WARNING — THE EXTRACTOR TRAP, HIT LIVE WHILE WRITING THIS FILE <<<
    cq_runtime.h is hand-written and COLUMN-ALIGNED. Declarations look like:

        void cqrt_x      (int32_t q);
        void cqrt_h      (int32_t q);

    The obvious regex `cqrt_[a-z0-9_]+\(` requires `(` to touch the name and so
    SILENTLY MISSES every aligned declaration. During this census that regex
    returned 124 and looked entirely plausible — it had dropped 49 symbols,
    including `cqrt_h` itself, the very symbol Step 0.7 is about. The correct
    count is 173. Always allow `\s*` before `(`, and always strip comments first.

    CQ_lang independently documents the SAME failure mode from its own history
    (tools/core_abi_link_check.py:32-38): its first draft pinned an alternation
    of return types and silently missed `bool cqrt_measure_i1` and
    `_Float16 cqrt_measure_f16` — "it UNDER-COVERED while reporting success".
    That file's standing instruction is: never "fix" a mismatch by narrowing the
    comparison. An under-covering extractor is the exact analogue, at the census
    layer, of this repo's clean-trace dirty-ancilla hazard: a green-looking
    result that is quietly wrong. Cross-check in BOTH directions.

E1. STEP 0.7 (`cqrt_h`) — RESOLVED. All three horns of the stated trilemma are
    wrong; the truth is a fourth option.

    EVIDENCE:
      runtime/cq_runtime.h:226    void cqrt_h      (int32_t q);
      runtime/cq_runtime.h:238    void cqrt_h_controlled   (int32_t ctrl, int32_t q);
      runtime/cq_runtime.c:454    void cqrt_h(int32_t q) { printf("cqrt_h(h%d)\n", q); }
      runtime/cq_runtime.c:482    void cqrt_h_controlled(...)
      runtime/cq_runtime.h:217    "`cqrt_h` is still declared + defined but
                                   unemitted (reserved for Phase 8 / 11)"
      tools/free_pairing_check.py:646
                                  "Self-adjoint; the pass does not emit it.
                                   Classified for safety."
      ir-pass/include/ControlledSymbols.h:53,62,72,77
                                  declares xFn, cswapFn, cnotFn, toffoliFn —
                                  there is NO hFn. The emitter has no way to
                                  name cqrt_h.
      grep -rn 'cqrt_h' ir-pass/  -> no matches at all.

    RESOLUTION: `cqrt_h` is DECLARED + DEFINED in the frozen ABI but is NEVER
    EMITTED by the IR pass. Therefore:
      * PRD §1 listing cqrt_h in the core runtime family is CORRECT — it is a
        real ABI symbol and libcqops must DEFINE it or a link against the ABI
        header set is incomplete.
      * PRD §8's sink vtable having NO `h` entry is ALSO CORRECT, and is not a
        missing entry. A gate that is never emitted needs no sink dispatch.
      * §12's Grover building H from rotations is consistent and is in fact
        FORCED: since the pass never emits cqrt_h, H can only arrive via
        cqrt_ry/cqrt_rz. This also keeps Rule 4 intact (no H on the classical
        path).
    So: do NOT add an `h` entry to the sink vtable, and do NOT treat cqrt_h as
    an over-declaration to be dropped. Implement cqrt_h/cqrt_h_controlled as
    defined-but-unreachable bodies (a loud abort naming the symbol is the
    right shape — it is dead ABI, and if it ever fires, an assumption broke).
    M04 can freeze the vtable shape in Step 5 without an `h` entry.

E2. `cqrt_free` IS LIVE — and CQ_lang's own header comment about it is STALE.

    runtime/cq_runtime.h:40-41 claims: "cqrt_free(handle): width-irrelevant

    THAT COMMENT IS WRONG AT THIS REVISION. cqrt_free is emitted from at least

      ir-pass/src/BennettWrap.cpp:106          ir-pass/src/IOSinkLowering.cpp:709

      ir-pass/src/SelectMergeEmit.cpp:270,278  ir-pass/src/BreakReversePlay.cpp:473,488,600
    and it appears in many committed lit fixtures (control_swap_select_*.ll,
    lowering_uncompute_branch_botharms.ll, ...).

    WHY THIS MATTERS HERE: libcqops Rule 6 ("free only a provably-zero rail";
    a dirty free is a HARD ERROR) is built entirely on cqrt_free being a live,
    frequently-emitted symbol. It is. Rule 6 is well-founded. Had the census
    trusted the header prose instead of the emitter, Rule 6 would have looked

    This also raises the stakes on Step 0.5 blocker 2 (`_unc` vs `cqrt_free`

E3. `cqrt_alloc_handle` IS RUNTIME-INTERNAL, NOT A LOWERING TARGET.
    runtime/cq_runtime.h:43-45: "the internal helper cqrt_alloc_handle, which is

    NEW DECISION THE PRD DOES NOT YET RECORD — does v1 own i80?

    i80 symbols are pure classical permutations well inside v1's kernel set —

    in the PRD rather than let the shim's cross product decide it silently.
    Whichever way it goes, the shim grid is 1595 or 1455 — never 1474.
