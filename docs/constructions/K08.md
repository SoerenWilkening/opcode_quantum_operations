## 1. Julia source excerpt

Verbatim, `third_party/bennett/src/adder.jl` lines 64-146:

```julia
function lower_add_cuccaro!(gates::Vector{ReversibleGate}, wa::WireAllocator,
                            a::Vector{Int}, b::Vector{Int}, W::Int)
    W <= 1 && return lower_add!(gates, wa, a, b, W)  # fallback for 1-bit

    # Allocate single ancilla X (initial carry c_0 = 0)
    X = allocate!(wa, 1)
    # 6W - 5 gates after the Bennett-gsxe §3.5 optimisation (was 6W - 4).
    sizehint!(gates, length(gates) + 6 * W)

    # MAJ gate: CNOT(c,b); CNOT(c,a); Toffoli(a,b,c)
    # Transforms (c_i, b_i, a_i) → (c_i ⊕ a_i, b_i ⊕ a_i, c_{i+1})
    # where c_{i+1} = MAJ(a_i, b_i, c_i) written into position of a_i.
    #
    # Bennett-gsxe / U_: §3.5 trick — the Toffoli that would write c_W
    # into a[W-1] (or a[1] when W=2) and its matching Phase-3 uncompute
    # are both omitted; one new Toffoli in Phase 2 XORs the same MAJ
    # product directly into b[W]. The wires a[W-1] (resp. a[1]) thus
    # retain a_{W-1} (resp. a_1) across the boundary instead of briefly
    # holding c_W.

    if W == 2
        # Phase 1 first MAJ — Toffoli dropped (it would write c_2 into a[1])
        push!(gates, CNOTGate(a[1], b[1]))
        push!(gates, CNOTGate(a[1], X[1]))
        # Phase 2 — inject Toffoli with controls (X[1], b[1])
        push!(gates, CNOTGate(a[W], b[W]))
        push!(gates, CNOTGate(a[W-1], b[W]))
        push!(gates, ToffoliGate(X[1], b[1], b[W]))
        # Phase 3 last UMA — matching Toffoli dropped
        push!(gates, CNOTGate(a[1], X[1]))
        push!(gates, CNOTGate(X[1], b[1]))
        return b
    end

    # W ≥ 3 path.

    # Phase 1: MAJ ripple up (compute carries into a[] wires)
    # First MAJ: inputs (X[1], b[1], a[1])
    push!(gates, CNOTGate(a[1], b[1]))
    push!(gates, CNOTGate(a[1], X[1]))
    push!(gates, ToffoliGate(X[1], b[1], a[1]))

    # Middle MAJs i = 2..W-2 (full)
    for i in 2:(W-2)
        push!(gates, CNOTGate(a[i], b[i]))
        push!(gates, CNOTGate(a[i], a[i-1]))
        push!(gates, ToffoliGate(a[i-1], b[i], a[i]))
    end

    # Phase 1 last middle MAJ at i = W-1 — Toffoli omitted (§3.5).
    # Post-state: a[W-2] = c_{W-1} ⊕ a_{W-1}; b[W-1] = b_{W-1} ⊕ a_{W-1};
    # a[W-1] still holds a_{W-1} (NOT c_W).
    push!(gates, CNOTGate(a[W-1], b[W-1]))
    push!(gates, CNOTGate(a[W-1], a[W-2]))

    # Phase 2: compute s_W into b[W] using the moved Toffoli.
    # s_W = b_W ⊕ a_W ⊕ c_W. The two CNOTs contribute b_W ⊕ a_W ⊕ a_{W-1};
    # the Toffoli adds (a[W-2]·b[W-1]) = MAJ(a_{W-1}, b_{W-1}, c_{W-1}) ⊕ a_{W-1}
    # which combines with the spurious a_{W-1} term to leave c_W.
    push!(gates, CNOTGate(a[W], b[W]))
    push!(gates, CNOTGate(a[W-1], b[W]))
    push!(gates, ToffoliGate(a[W-2], b[W-1], b[W]))

    # Phase 3 first UMA at i = W-1 — Toffoli omitted (§3.5 match).
    # CNOT(a[W-1], a[W-2]) restores a[W-2] = c_{W-1}; the next CNOT
    # computes s_{W-1} into b[W-1].
    push!(gates, CNOTGate(a[W-1], a[W-2]))
    push!(gates, CNOTGate(a[W-2], b[W-1]))

    # Phase 3 middle UMAs i = W-2..2 (full)
    for i in (W-2):-1:2
        push!(gates, ToffoliGate(a[i-1], b[i], a[i]))
        push!(gates, CNOTGate(a[i], a[i-1]))
        push!(gates, CNOTGate(a[i-1], b[i]))
    end

    # Last UMA: (X[1], b[1], a[1]) — full
    push!(gates, ToffoliGate(X[1], b[1], a[1]))
    push!(gates, CNOTGate(a[1], X[1]))
    push!(gates, CNOTGate(X[1], b[1]))

    return b  # result is in b's wires
end
```

## 2. Gate sequence as indexed pseudo-code

libcqops naming: `acc[0..W-1]` is Bennett's `b` (the accumulator, overwritten with
the sum); `b[0..W-1]` is Bennett's `a` (the addend, restored at the end); `x` is
the single ancilla `X[1]`. Bennett is 1-indexed; the pseudo-code below is 0-indexed.

K8 is **not** a `cq_sandwich` kernel — there is no copy-out and no reverse half. It
is still written as an indexed step function so that a *caller's* sandwich (K11)
can replay it, and so the driver's palindrome check applies uniformly.

### W ≥ 3

```
n_compute = 3 + 3*(W-3) + 2 + 3 + 2 + 3*(W-3) + 3       # = 6W - 5 gates
step index s counts GATES, not phases; phases listed in emission order.

PHASE 1 — MAJ ripple up
  s=0 : CX (ctrl b[0],   tgt acc[0])
  s=1 : CX (ctrl b[0],   tgt x)
  s=2 : CCX(ctrl x, acc[0], tgt b[0])          <-- TARGET IS b[] (the addend)

  for i = 1 .. W-3:                            # Bennett i = 2..W-2
      CX (ctrl b[i],     tgt acc[i])
      CX (ctrl b[i],     tgt b[i-1])           <-- TARGET IS b[]
      CCX(ctrl b[i-1], acc[i], tgt b[i])       <-- TARGET IS b[]

  # last middle MAJ at Bennett i = W-1 : Toffoli dropped (§3.5)
  CX (ctrl b[W-2], tgt acc[W-2])
  CX (ctrl b[W-2], tgt b[W-3])                 <-- TARGET IS b[]

PHASE 2 — high sum bit, with the relocated Toffoli
  CX (ctrl b[W-1],   tgt acc[W-1])
  CX (ctrl b[W-2],   tgt acc[W-1])
  CCX(ctrl b[W-3], acc[W-2], tgt acc[W-1])

PHASE 3 — UMA ripple down
  # first UMA at Bennett i = W-1 : Toffoli dropped (§3.5 match)
  CX (ctrl b[W-2], tgt b[W-3])                 <-- TARGET IS b[]
  CX (ctrl b[W-3], tgt acc[W-2])

  for i = W-3 down to 1:                       # Bennett i = W-2..2
      CCX(ctrl b[i-1], acc[i], tgt b[i])       <-- TARGET IS b[]
      CX (ctrl b[i],   tgt b[i-1])             <-- TARGET IS b[]
      CX (ctrl b[i-1], tgt acc[i])

  # last UMA
  CCX(ctrl x, acc[0], tgt b[0])                <-- TARGET IS b[]
  CX (ctrl b[0], tgt x)
  CX (ctrl x,    tgt acc[0])

POSTSTATE: acc = (acc + b) mod 2^W ; b restored to its input value ; x = |0>
NO copy-out steps. NO reverse half.
```

### I6 status — **CRITICAL**

> **I6 = inside a `cq_sandwich` compute half, every gate TARGET is a bit of the
> scratch region.**

**Answer: NO, not unconditionally. `i6_ok = false`.**

For every `W ≥ 3`, K8 emits gates whose **target is a bit of the addend register
`b`** — the wires marked `<-- TARGET IS b[]` above. Bennett uses the `a[]` wires as
the carry-chain storage (`adder.jl:100` "compute carries into a[] wires") and
restores them during Phase 3. The **end state** of `b` is unchanged
(`test_gboa_dirty_bit_hygiene.jl:74` pins `a preserved`), but I6 is a **per-gate**
predicate, not an end-state predicate.

Consequences that MUST be honoured in M15 and M18:

1. **K8 may only be called with BOTH `acc` and `b` inside the active scratch
   extent.** Inside K11's (`mul`) sandwich compute half that is satisfiable — the
   accumulator and each partial-product register are both scratch. Anywhere else
   the Debug scratch-extent assertion (Rule 8) will fire, and it will be right to.
2. **K8 cannot use the standard kernel signature.** Rule 8's type-level I6 guard is
   `const cq_bit *` for controls / `cq_bit *` for targets. K8's addend is a target,
   so **`b` is non-const**. That deletes the by-construction half of the I6 defence
   for this one kernel.

   > **THE PROTOTYPE THIS PARAGRAPH USED TO PRINT —
   > `void cq_addacc(cq_ctx*, cq_bit *acc, cq_bit *b, int W)` — IS NOT WHAT SHIPPED,
   > and it is unusable in two independent ways** (K11.md §2b's interface note said
   > so and this document did not follow it). It has no ancilla parameter, so K8
   > would have to allocate `x` itself, which breaks I6(b) for the one wire K11.md's
   > R8 trace indicts; and it has no step index, so a sandwiched caller could only
   > invoke it as a single step, which is not an involution (re-running gives
   > `acc + 2b`). **Landed at Step 15, `src/kernels/addacc.h`:**
   >
   > ```c
   > typedef struct { cq_bit *acc, *b, *x; int W; } cq_addacc_block;
   >
   > int  cq_addacc_steps(int W);                                 /* 6W - 5 */
   > void cq_addacc_step (cq_ctx*, const cq_addacc_block*, int u);
   > void cq_kernel_addacc(cq_ctx*, const cq_addacc_block*);  /* all steps */
   > void cq_addacc_check(const cq_addacc_block*);
   > ```
   >
   > `cq_addacc_step` is the entry point a sandwiched caller uses, and the only
   > one; `cq_kernel_addacc` is for a caller with no sandwich around it.

   > **AND THE DEBUG SCRATCH-EXTENT ASSERTION DOES *NOT* "CARRY THE WHOLE BURDEN" —
   > that sentence named a safeguard that does not exist for the call shape K8
   > actually has.** `check_target` (`src/emit.c:39-48`) fires only when a sandwich
   > is armed (`ctx->scratch_lo` non-NULL, set by `sw_arm` in `src/sandwich.c` for
   > the two compute halves only), and the whole check lives inside
   > `#if CQOPS_DEBUG_INVARIANTS`, so it is absent from Release entirely. K8 has no
   > sandwich of its own, so on a bare call there is **no diagnostic in either
   > configuration**. M15 therefore supplies its own entry guard, `cq_addacc_check`,
   > a hard error in **both** configurations — see consequence 3.
3. **Materialisation hazard.** Because `b[]` bits are gate targets, a *classical*
   `b[i]` gets materialised by the fold table. If `b` is genuine scratch (born
   `BIT_ZERO`) that emits no `X` and the counts below hold. If `b` is a register
   with classical bits at non-zero values, materialisation emits an `X`, the count
   drifts off `6W−5`, **and** a reverse replay would re-emit that `X` at the wrong
   point. This is precisely the R1 failure mode. Both operands scratch, or fail loud.

## 4. Ancilla count

**Formula: exactly `1` ancilla qubit, for every `W ≥ 2`, independent of W.**

`adder.jl:69` — `X = allocate!(wa, 1)` — is the only allocation in the function.
`X` plays the role of the initial carry `c_0 = 0`; it is set to `a_1` by the first
MAJ's `CNOT(a[1], X[1])` and cleared by the last UMA's `CNOT(a[1], X[1])` — at
`W ≥ 3` that pair is `adder.jl:103` and `adder.jl:142`, and **on the `W == 2`
branch it is `adder.jl:87` and `adder.jl:93`**, since that branch returns at `:95`
and never reaches either of the first two lines. (§4's own corollary below gets
the branch split right; this paragraph did not.) Either way `X` returns to `|0⟩`
before the function returns. Pinned by `test/test_gboa_dirty_bit_hygiene.jl:77-83`,
which asserts every wire outside `a ∪ b` is `false` after simulation, for
`W ∈ {2,3,4,8}` over seven `(a,b)` pairs including both overflow cases.

**libcqops does not allocate it.** `x` is a **caller-supplied** bit — a member of
`cq_addacc_block` — for the reason K11.md §2b gives: an allocation in the middle
of a compute half is a scratch bit step 0 did not pre-materialise, which breaks
I6(b) for exactly the wire K11.md's R8 trace indicts. See §2's I6 consequence 2
for the shipped signature.

The addend register `b` also serves as transient carry storage (§2) but is **not**
an ancilla — it is an operand, and it is restored, not freed.

At `W ≤ 1` Bennett's fallback allocates `2W = 2` wires (`adder.jl:4-5`) and does
**not** clean them; they rely on Bennett's global wrap. libcqops does not take that
path (§5, D1).

### Why K8 is the accumulator only, and must NEVER be substituted for K6/K7

Four independent reasons, in decreasing order of severity:

1. **The shape is wrong.** The libcqops kernel contract is
   `dst ^= f(a, b)` with `a`, `b` unchanged. K8's semantics are `b ← a + b` — a
   different, destructive shape. PRD §4,
   "the reason v1 uses ripple-carry rather than Cuccaro" (PRD-v1.md:509 @ 961905f),
   already records this decision;
   the source confirms it (`adder.jl:62`: "b overwritten with a+b mod 2^W").
2. **Its uncompute is the reverse circuit, not a re-run.** CQ_lang's `_unc(out, a, b)`
   means "recompute `f` from the still-live sources and XOR it into `out`", which
   works for K6 because `f ⊕ f = 0`. Re-running K8 does **not** undo it: the second
   run gives `acc ← a + (a + acc) = 2a + acc`. Undoing K8 requires emitting its gates
   in reverse order (legal — every gate is self-inverse, `gates.jl:4`) — but libcqops
   has no place to emit a reverse pass at the CQ_lang boundary, and CQ_lang never
   asks for one. Substituting K8 for K6 is therefore a **silent miscompile**, not a
   test failure: the forward value is right, and only the `_unc` is wrong.
3. **It destroys a live SSA operand, and upstream has NO guard against that.**
   Read the pinned tree carefully — the liveness gate that used to protect Cuccaro
   is **gone**. `op2_dead` is still computed at `src/lowering/arith.jl:204-205` and
   still passed at `:207`, but `_pick_add_strategy` (`src/lowering/arith.jl:20-26`)
   never reads it; its own docstring says the parameter is "retained in the
   signature for backward compatibility" (`arith.jl:17-18`). An explicit
   `add=:cuccaro` returns at `arith.jl:22` and reaches `lower_add_cuccaro!` at
   `arith.jl:209` **whether or not op2 is live**. The only remaining protection is
   that `:auto` never picks it (`arith.jl:25`: `return :ripple`), plus one
   hand-placed override in the loop unroller (`src/lowering/cfg.jl:243-246`, which
   says in as many words that it "defends against an explicit caller-passed
   `add=:cuccaro`" corrupting loop-carried accumulators). `test/test_cuccaro_safety.jl`
   is **not** evidence to the contrary: every case in it compiles with the default
   `add=:auto`, which post-U27 resolves to `:ripple`, so the file no longer
   exercises Cuccaro at all.
   libcqops runs no liveness analysis either — CQ_lang owns liveness and frees the
   named result rail itself (`NORTH_STAR` §3). So there is no deadness proof to
   inherit and none to construct; K8's precondition must be enforced by M15's own
   loud assert.
4. **It is more expensive both ways.** Sandwiched, `13W−10` vs ripple's `11W−4`;
   Toffoli-depth `2(2W−3)` vs ripple's roughly-halved chain
   (`docs/plots/depth.jl:37-38`: ripple `[14,30,62,126]` vs cuccaro
   `[26,58,122,250]` — ~2× worse at every width). Bennett removed Cuccaro from its
   own default dispatcher for exactly this reason
   (`src/lowering/arith.jl:8-19`, Bennett-spa8 / U27).

K8's one real advantage is the **ancilla count**: `1`, versus `W` for ripple
(`docs/src/howto/arithmetic_strategy.md:48-49`). That is worth having precisely
where the accumulator is a long-lived scratch register inside a bigger sandwich —
i.e. K11 — and nowhere else. And even that is contingent on decision D2 above.
