# K05 — casts (`sext` / `zext` / `trunc`, int↔int)

**Bennett source:** `third_party/bennett/src/lowering/arith.jl` lines 534-566 (pinned commit 980805de8531…)
**libcqops module:** M13 `kernels/cast.c` (IMPLEMENTATION_PLAN.md:201, 90 LOC budget, no split seam)
**Clean or sandwich:** **clean** — there is no compute half to sandwich.

`lower_cast!` allocates exactly one wire vector, `r = allocate!(wa, T)` (arith.jl:540), and
that vector **is the result**, not scratch. Every gate emitted in all three branches targets
`r[i]`; the source `src` appears only as a CNOT *control* and is never a target. So the
construction allocates zero scratch and therefore leaves zero scratch dirty. There is nothing
for `cq_sandwich` to reverse.

This matches PRD-v1.md §5 ("Naturally clean already (no sandwich needed): `and`, `or`, `xor`,
constant `shl/lshr/ashr`, `sext/zext/trunc`") and the PRD §6 K5 row (`✔`, `≤ T CNOT`). Both
claims hold against the source — see §3.

> **Do not wrap K5 in `cq_sandwich`.** It would still be *correct* (compute `scratch ^= a`,
> copy out `dst ^= scratch`, uncompute `scratch ^= a`), but it costs **3×** the CX and burns
> `F` ancillae to achieve exactly what one CX per bit already achieves. The `✔` in the
> catalogue is load-bearing.

## 1. Julia source excerpt

`third_party/bennett/src/lowering/arith.jl`, lines 534-566, verbatim:

```julia
# ---- casts (sext, zext, trunc) ----

function lower_cast!(gates, wa, vw, inst::IRCast)
    src = resolve!(gates, wa, vw, inst.operand, inst.from_width)
    F = inst.from_width
    T = inst.to_width
    r = allocate!(wa, T)

    if inst.op == :zext
        for i in 1:F; push!(gates, CNOTGate(src[i], r[i])); end
    elseif inst.op == :sext
        for i in 1:F; push!(gates, CNOTGate(src[i], r[i])); end
        for i in F+1:T; push!(gates, CNOTGate(src[F], r[i])); end
    elseif inst.op == :trunc
        # Bennett-gboa / U139 wire-state contract:
        #   - r[1:T] ← src[1:T] (CNOT-copy of the low T bits).
        #   - src[T+1..F] are NOT touched: they remain at their SSA-input
        #     values for the rest of the gate sequence. This is intentional
        #     — `src` is a pure SSA read, not consumed. Bennett's outer
        #     reverse pass uncomputes whatever produced src in the first
        #     place; the high bits never need explicit zeroing here.
        #   - r is freshly allocated (zero-initialised), so the result wires
        #     don't have a "dirty" issue.
        # If a future liveness pass wants to free src mid-circuit, it must
        # first uncompute src's full F-bit producer — NOT just bits 1..T.
        # Pinned by `test/test_gboa_dirty_bit_hygiene.jl`.
        for i in 1:T; push!(gates, CNOTGate(src[i], r[i])); end
    else
        throw(ArgumentError("lower_cast!: unknown cast op :$(inst.op) (supported: $_IR_CAST_OPS)"))
    end

    vw[inst.dest] = r
end
```

## 2. Gate sequence as indexed pseudo-code

libcqops kernel shape (Rule 7). K5 is unary, so the `b` operand is unused:

```c
void cq_kernel_zext (cq_ctx*, cq_bit *dst, const cq_bit *a, int F, int T);
void cq_kernel_sext (cq_ctx*, cq_bit *dst, const cq_bit *a, int F, int T);
void cq_kernel_trunc(cq_ctx*, cq_bit *dst, const cq_bit *a, int F, int T);
/* semantics: dst ^= cast(a);  a unchanged;  zero ancillae */
```

### zext, F → T (F ≤ T)

```
n_compute = F                       /* NOT T — see the note below */

step(s), s in [0, F):
    cq_emit_cx(ctx, &a[s], &dst[s]);

/* dst[F .. T-1]: NO STEP AT ALL. Not "emit nothing" — there is no loop
   iteration. Those bits were born CQ_BIT_ZERO when dst was allocated and
   they stay CQ_BIT_ZERO: zero gates AND zero qubits, permanently. */
```

### sext, F → T (F ≤ T)

```
n_compute = T

step(s), s in [0, F):
    cq_emit_cx(ctx, &a[s], &dst[s]);          /* copy the value bits   */

step(s), s in [F, T):
    cq_emit_cx(ctx, &a[F-1], &dst[s]);        /* broadcast the sign bit */
```

Note the degenerate `F == 1` case (`sext i1 → iN`: **5 of the 15** sext pairs have an `i1`
source — `i1 → {i8,i16,i32,i64,i128}`, opcode_table.yaml:238-241,251): `a[F-1] == a[0]`, so
*every* step controls off the same single bit. The
result is `0x00…0` or `0xFF…F`, which is what C's `(int8_t)(signed)_Bool` means.

### trunc, F → T (T < F)

```
n_compute = T

step(s), s in [0, T):
    cq_emit_cx(ctx, &a[s], &dst[s]);

/* a[T .. F-1] are NEVER READ and NEVER WRITTEN. See §5 item 6 —
   they stay owned by `a`'s handle. K5 must NOT free them. */
```

### Copy-out steps

**None.** There is no scratch region and therefore no copy-out phase and no reverse phase.
The CX *is* the `^=`. `n_copyout = 0`, `n_reverse = 0`.

### I6 statement

> **I6** — inside a `cq_sandwich` compute half, every gate **target** is a bit of the scratch
> region.

K5 does not run under `cq_sandwich`, so I6 is **vacuously satisfied** (there is no compute
half). The property that actually matters here, and which K5 does satisfy, is the *reason*
I6 exists:

- **Every gate target is a `dst` bit.** All four `push!` sites in arith.jl:543/545/546/560
  target `r[i]`, never `src[i]`.
- **Every source bit appears only as a control.** Controls are never materialised (Rule 8),
  so `a` is bit-for-bit unchanged, kind-for-kind, on exit — which is exactly the kernel
  contract's "leaving `a` and `b` unchanged".
- This is enforced *by construction* by the emitter signature: `a` is `const cq_bit *`, and
  `cq_emit_cx` takes its control as `const cq_bit *`. A K5 that tried to target a source bit
  would not compile.

**No I6 violation. Not a critical finding.** K5 is the one kernel in the catalogue where the
invariant is structurally impossible to break.

## 3. Gate-count formula

### 3a. Derivation — counting the loops in the Julia source

Only four `push!(gates, …)` calls exist in lines 536-566, and all four push a `CNOTGate`
(verified by listing every `Gate(` occurrence in that line range: 543, 545, 546, 560). There
is **no `NOTGate` and no `ToffoliGate` anywhere in `lower_cast!`.**

| Branch | Loop(s) | Iterations |
|---|---|---|
| `:zext` (543) | `for i in 1:F` | `F` |
| `:sext` (545) | `for i in 1:F` | `F` |
| `:sext` (546) | `for i in F+1:T` | `T − F` (zero-trip when `T == F`) |
| `:trunc` (560) | `for i in 1:T` | `T` |

So: zext = `F`; sext = `F + (T − F)` = **`T`**; trunc = **`T`**.

Not counted, and deliberately so: `resolve!` at line 537 can emit up to `F` `NOTGate`s when
the operand is a `ConstOperand` (operand.jl:37-41). That is Bennett materialising a *literal*
into wires before the cast runs; it is not the cast's cost, and libcqops never pays it at all
(§5 item 2).

### 3b. Worst case — all source bits are `CQ_BIT_Q`, `dst` fresh all-`BIT_ZERO`

This is the number the L4 golden pins. **Compute half and sandwiched total are identical**
because the kernel is clean.

| | zext F→T | sext F→T | trunc F→T |
|---|---|---|---|
| NOT (`X`) — compute | 0 | 0 | 0 |
| CNOT (`CX`) — compute | `F` | `T` | `T` |
| Toffoli (`CCX`) — compute | 0 | 0 | 0 |
| **total — compute** | **`F`** | **`T`** | **`T`** |
| NOT — **sandwiched** | 0 | 0 | 0 |
| CNOT — **sandwiched** | `F` | `T` | `T` |
| Toffoli — **sandwiched** | 0 | 0 | 0 |
| **total — sandwiched** | **`F`** | **`T`** | **`T`** |

**PRD §6's `≤ T CNOT` claim holds**, and is tight for two of the three ops: zext is `F ≤ T`
(slack whenever `F < T`), sext is exactly `T`, trunc is exactly `T`.

### 3c. Realised counts — the fold table actually applied

libcqops does not pay for classical bits. Let `Q(S) ≜ #{ i ∈ S : a[i].kind == CQ_BIT_Q }`.
Forward direction (`dst` fresh, every bit `CQ_BIT_ZERO`), per PRD §3:

- `a[i] = CQ_BIT_ZERO` → `CX` with a ZERO control → **nothing**. 0 gates, 0 qubits.
- `a[i] = CQ_BIT_ONE` → `emit_x(dst[i])`; `dst[i]` is a constant → flip in place → **0 gates,
  0 qubits**; `dst[i]` becomes `CQ_BIT_ONE`.
- `a[i] = CQ_BIT_Q(q)` → target is a constant → **materialise** `dst[i]` (constant was 0, so
  **no `X`**), then `sink.cx` → **1 CX, 1 qubit**.

| | zext F→T | sext F→T | trunc F→T |
|---|---|---|---|
| `X` | 0 | 0 | 0 |
| `CX` | `Q([0,F))` | `Q([0,F)) + (T−F)·[a[F−1] is Q]` | `Q([0,T))` |
| `CCX` | 0 | 0 | 0 |
| qubits allocated | `Q([0,F))` | same as `CX` | same as `CX` |

Two L5 (classical short-circuit) cases fall straight out and should be pinned:

- **A fully-classical cast is 0 gates and 0 qubits** at every `(F, T)` and all three ops.
- **`zext i8 → i128` on a classical `i8` is literally free** — 0 gates, 0 qubits, and the
  resulting i128 register owns zero qubits (**I4**). This is the concrete mechanism behind
  PRD §1's "i128 costs nothing beyond width-genericity".

### 3d. `_unc` direction — where the `X` gates come from (Rule 14)

`_unc(out, a)` re-runs the same kernel with `dst = out`. `out` is **not** all-`BIT_ZERO`, so
the fold table takes a different row and **the forward/`_unc` counts differ**:

If `a[i]` was a classical constant at forward time (so `out[i]` is a classical constant) but
`a[i]` has since been promoted to `CQ_BIT_Q` by an in-place `cqrt_ry`/`cqrt_rz` on the source
(D6: we never demote), then `CX(Q, constant)` → **materialise `out[i]`, emitting `X` because
the constant was 1**, then `sink.cx`. Worst case:

| | zext F→T | sext F→T | trunc F→T |
|---|---|---|---|
| `X` — `_unc` worst case | `≤ F` | `≤ T` | `≤ T` |
| `CX` — `_unc` worst case | `≤ F` | `≤ T` | `≤ T` |
| qubits — `_unc` worst case | `≤ F` | `≤ T` | `≤ T` |

The forward emitted **zero** `X` and, in the classical case, **zero** qubits. So K5 — the
simplest kernel in the catalogue — is a clean, cheap, exhaustively-testable witness for
PRD §10 / Rule 14: **`unc == forward` is not an invariant, and asserting it is risk R6.**
The L4 test file for M13 should quote the PRD §10 note verbatim.

Single-variable form, `W → 2W` widening and `2W → W` narrowing:

|---|---|---|---|
| 1 | 1 | 2 | 1 |
| 8 | 8 | 16 | 8 |
| 16 | 16 | 32 | 16 |
| 32 | 32 | 64 | 32 |

## 4. Ancilla count

**Zero. `ancillae(F, T) = 0`, unconditionally** — for all three ops, all `(F, T)`, all
bit-kind masks, both the forward and the `_unc` direction.

There is nothing to return to `|0⟩` because nothing is taken from the pool as scratch.
Bennett's single `allocate!(wa, T)` (arith.jl:540) allocates the *result* `r`, which is
`vw[inst.dest]` (line 565) — the SSA value, not scratch; in libcqops that vector is `dst`,
supplied by the caller. Qubits *are* taken from the pool during the kernel, but only via
`cq_materialise` on `dst` bits (Rule 5), and those belong to `dst`, whose lifetime CQ_lang
owns. K5 itself allocates and frees nothing.

(The one shared control ancilla that `cq_ctrl_push` may lazily acquire belongs to the emitter
mode — Rule 9 — not to K5. No kernel is aware the controlled axis exists.)

## 5. Deltas from upstream

1. **`dst =` vs `dst ^=`.** Bennett allocates the result inside `lower_cast!` and *defines*
   it (`vw[inst.dest] = r`, line 565). libcqops takes `dst` from the caller and XORs into it.
   On a fresh all-`BIT_ZERO` `dst` the two coincide (`0 ^ x = x`), which is why the gate
   sequence ports verbatim. They diverge on `_unc` — §3d — and that divergence is the point
   of the contract, not a defect.

2. **Constant operands never materialise.** Bennett's `resolve!` turns a `ConstOperand` into
   real wires plus one `NOTGate` per set bit (operand.jl:30-42). libcqops folds the constant
   through the CX at emission and allocates nothing (PRD §3). So the realised libcqops count
   is always `≤` Bennett's for the same cast, often 0.

3. **Do not port `_fold_constants`.** Bennett recovers the same savings *after* emission, via
   a gate-level pass (`src/lowering/driver.jl:407+`, default-on since Bennett-epwy / U28) that
   tracks known wire values and rewrites `CNOT(known-0, …)` → nothing, `CNOT(known-1, t)` →
   `NOT(t)`, etc. That is an optimiser. libcqops gets the identical result *structurally*, at
   emission, from the fold table — and v1 forbids gate-level optimisation outright. Same
   outcome, different timing, and ours cannot drift out of sync with the shadow.

4. **zext's high bits: wires vs constants.** Bennett leaves `r[F+1..T]` as physically
   allocated, untouched zero **wires** — real qubits in the count. libcqops leaves them as
   `CQ_BIT_ZERO` **constants**: zero qubits (I4). This is the single largest representational
   win in K5 and it is what makes wide zext free.

5. **No width guard upstream; libcqops must add one.** Neither `lower_cast!` nor the `IRCast`
   constructor (ir_types.jl:206-215) asserts `F ≤ T` for zext/sext or `T ≤ F` for trunc. A
   `:zext` with `T < F` walks `r[i]` past its end — in Julia that is a `BoundsError`; in C it
   is a **buffer overrun**. M13 must assert the width relation explicitly and fail loud.
   (Bennett's fp-cast fallbacks even encode `T == F` as `:trunc`, instructions.jl:7662/7685,
   which lowers to an `F`-CNOT identity copy. CQ_lang's cast grid contains no same-width pair
   — verified in §5 item 8 — so libcqops need not support that shape, but should reject it
   loudly rather than silently copy.)

6. **trunc's dropped bits — no leak, and the reason is ownership, not luck.** Bennett
   (arith.jl:548-559) says outright that `src[T+1..F]` are left at their SSA values and that
   the *global* reverse pass cleans up whatever produced them. libcqops has no global reverse
   pass, and does not need one here, because **the dropped bits are not ancillae — they are
   bits of `a`**, the caller's source register. The kernel contract requires `a` be left
   unchanged; K5 simply never reads or writes them; the qubits behind them stay owned by
   `a`'s handle. CQ_lang decides when `a` dies, by emitting `cqrt_free(a)` (which asserts
   provable-zero, Rule 6) or by `_unc`-ing `a` from *its* own sources first. That is above our
   box. Two hard prohibitions follow:

   - **K5 must not free `a`'s high bits.** They hold the discarded high half of the value and
     are not provably `|0⟩`. Freeing them is precisely the silent-state-collapse signature
     Rule 6 exists to catch.
   - **K5 must not "optimise" trunc into an alias/move** that reparents `a`'s low `T` qubits
     into `dst`. That violates I2 (no qubit index in two live registers) and makes the next
     `cqrt_free` on either handle a double-free of a rail that is not provably zero. **Copies
     are physical, never aliases** (Rule 5 / I2). The temptation is real here — trunc *looks*
     like a pure slice — which is why it is written down.

7. **Free-list order.** Bennett's `WireAllocator` free list is sorted **descending** and
   `pop!` returns the **minimum** index (wire_allocator.jl:3, 19-21) — lowest-index-first.
   libcqops D4 is **LIFO**. Same gate counts; different qubit indices in a trace. Irrelevant
   to L4 (counts), relevant to L6 (trace goldens) — which is exactly why kernel goldens pin
   counts and not traces.

8. **⚠ The width grid in the live CQ_lang table is wider than this task's brief and than the
   PRD.** Read from `/Users/sorenwilkening/Desktop/CQ_lang/tools/opcode_table.yaml`
   (lines 232-324), the `int_width` cast pairs are:

   | opcode | pairs | grid |
   |---|---|---|
   | `sext` | **15** | `{i1,i8,i16,i32,i64} → {i8,i16,i32,i64,i128}`, strictly widening. **No i80.** |
   | `zext` | **20** | the same 15, **plus `{i1,i8,i16,i32,i64} → i80`** |
   | `trunc` | **20** | `{i128,i64,i32,i16,i8} → {i1,i8,i16,i32,i64}`, strictly narrowing, **plus `i80 → {i1,i8,i16,i32,i64}`** |

   Three things follow, none of which I am authorised to settle here:

   - **`i80` is in the cast grid and is not in the PRD.** The table's own comments say i80 is
     a `zext` **destination only** and a `trunc` **source only** (never a `sext` operand,
     never a `zext` source, never a `trunc` destination) — it exists to serve the
     `promoteFp80Union` RMW field-insert/extract idiom (bd 3c6m.51 Inc 2). K5's construction
     is width-generic and handles `T = 80` / `F = 80` with no change whatsoever, so this costs
     M13 nothing. But it does mean the K5 symbol grid is **55 pairs, not the 30 the table's
     own stale header comment claims** ("Integer width casts (3 kinds x 10 pairs each = 30
     pairs)", line 231), and it likely bears on the unresolved **Step 0.5 blocker #1**
     (symbol count 1455 vs 1474). **Do not resolve that blocker from this doc** — recount from
     the whole table.
   - **The table's header comments are stale relative to its own data.** Line 231 says 30
     int-width pairs; the lists below it contain 55. Line 21 says "9 kinds, 90 pairs" for all
     casts. Trust the `pairs:` lists, not the prose.
   - **This repo has no pinned copy of `opcode_table.yaml` yet** (Step 0 has not run; there is
     no `third_party/` copy of it). I read CQ_lang's live working tree, which may be ahead of
     whatever revision PRD-v1.md was written against. That is the most likely explanation for
     the i80 discrepancy — but it is an explanation, not a verification.

9. **The cast grid carries `variants: [fwd, inv, unc]` — no `controlled`.** Every cast pair
   declares three variants (opcode_table.yaml:236, 260, 295), versus the ten-variant
   `fwd_qq/fwd_hl/inv_*/controlled_*/unc_*` grid the binary ops carry (line 184). The table's
   naming header (lines 35-52) confirms "Controlled axis is BINARY-ops-only". PRD §10 says
   CQ_lang's spine no longer emits `_inv` for data templates, so `cq_template_<op>_<from_to>_inv`
   is a **link-surface symbol** the shim must emit but the spine should never call; per the
   compare precedent it would be "allocate a fresh rail and run the forward". `gen_shim.py`
   (M27) needs to emit it either way. Flagging it because K5 is a *unary cast*, and the
   `_hl`/`_lh` shape tokens that dominate the binary grid do not apply here at all — the
   uncompute spelling is the bare `cq_template_<op>_<from_to>_unc(out, src)` (line 54).

10. **Possible shadow-poison interaction with `_unc` — INFERRED, NOT VERIFIED, please file.**
    §3d's `_unc` scenario requires the source to have been rotated in-place between forward and
    uncompute. PRD §3's shadow rule poisons a bit to *unknown* on any `Ry`/`Rz` outside the
    classical angle set, and poison is sticky. If CQ_lang restores the source's state with an
    inverse rotation, our shadow stays *unknown* even though the state is determinate — the
    sanctioned direction of conservatism — but then `_unc` leaves `out[i]` as a qubit whose
    shadow is not known-zero, and the following `cqrt_free(out)` **hard-errors on a rail that
    is actually clean**. I did not verify this: it depends on shadow semantics that are not
    implemented yet and on CQ_lang restore behaviour I did not read. It is not K5-specific —
    it would hit every kernel. Noting it here because K5 is the smallest place to reproduce it.
