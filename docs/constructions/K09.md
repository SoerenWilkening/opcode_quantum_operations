**Clean or sandwich:** **sandwich** — all three primitives are dirty by design.

- `lower_eq!` leaves `diff[1..W]` holding `a ⊕ b` and `or[1..W-1]` holding the running OR-prefix. Neither is uncomputed inside the function.
- `lower_ult!` leaves `nb[1..W]` = `¬b`, `carry[1..W+1]` = the full ripple carry chain, and `axnb[1..W]` = `a ⊕ ¬b`. None is uncomputed.
- `lower_slt!` additionally leaves `af`, `bf` (the sign-flipped copies of `a`, `b`) dirty.

Bennett tolerates this because its single global forward–copy–reverse wrap (`bennett_transform.jl`) cleans everything at the top level. libcqops has no global wrap, so Bennett-in-the-small applies (PRD §5): compute the raw flag into scratch, XOR it into `dst`, replay the compute half in reverse, release scratch.

**Result shape — read this before writing the kernel.** `icmp` produces a **one-bit** flag, not a W-bit register (`ir_types.jl:79`: *"width of operands (result is always i1)"*). So in the kernel contract

```c
void cq_kernel_cmp(cq_ctx*, cq_bit *dst, const cq_bit *a, const cq_bit *b, int W);
```

`a` and `b` are `W` bits wide but **`dst` is exactly one `cq_bit`**. Consequently the copy-out is **1 CNOT (+ at most 1 X)**, *not* the "W CNOTs" that PRD §5's generic sandwich sketch writes at `PRD-v1.md:382`. K9 is the only kernel in the catalogue where `|dst| ≠ W`. See §5 delta 10. **I6(b) does not touch this**: `dst` is not part of the scratch region and is not pre-materialised (§4).

# ---- comparison (icmp) ----

function lower_icmp!(gates, wa, vw, inst::IRICmp)
    a = resolve!(gates, wa, vw, inst.op1, inst.width)
    b = resolve!(gates, wa, vw, inst.op2, inst.width)
    W = inst.width; p = inst.predicate

    result = if p == :eq;  lower_eq!(gates, wa, a, b, W)
    elseif p == :ne;       lower_not1!(gates, wa, lower_eq!(gates, wa, a, b, W))
    elseif p == :ult;      lower_ult!(gates, wa, a, b, W)
    elseif p == :ugt;      lower_ult!(gates, wa, b, a, W)
    elseif p == :ule;      lower_not1!(gates, wa, lower_ult!(gates, wa, b, a, W))
    elseif p == :uge;      lower_not1!(gates, wa, lower_ult!(gates, wa, a, b, W))
    elseif p == :slt;      lower_slt!(gates, wa, a, b, W)
    elseif p == :sgt;      lower_slt!(gates, wa, b, a, W)
    elseif p == :sle;      lower_not1!(gates, wa, lower_slt!(gates, wa, b, a, W))
    elseif p == :sge;      lower_not1!(gates, wa, lower_slt!(gates, wa, a, b, W))
    else throw(ArgumentError("lower_icmp!: unknown predicate :$p (supported: $_IR_ICMP_PREDS)"))
    end
    vw[inst.dest] = result
end

function lower_eq!(g, wa, a, b, W)
    diff = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(a[i], diff[i]))
        push!(g, CNOTGate(b[i], diff[i]))
    end
    if W == 1
        r = allocate!(wa, 1)
        push!(g, CNOTGate(diff[1], r[1])); push!(g, NOTGate(r[1]))
        return r
    end
    or = allocate!(wa, W - 1)
    push!(g, CNOTGate(diff[1], or[1]))
    push!(g, CNOTGate(diff[2], or[1]))
    push!(g, ToffoliGate(diff[1], diff[2], or[1]))
    for k in 2:(W - 1)
        push!(g, CNOTGate(or[k - 1], or[k]))
        push!(g, CNOTGate(diff[k + 1], or[k]))
        push!(g, ToffoliGate(or[k - 1], diff[k + 1], or[k]))
    end
    r = allocate!(wa, 1)
    push!(g, CNOTGate(or[W - 1], r[1])); push!(g, NOTGate(r[1]))
    return r
end

function lower_ult!(g, wa, a, b, W)
    nb = allocate!(wa, W)
    for i in 1:W; push!(g, CNOTGate(b[i], nb[i])); push!(g, NOTGate(nb[i])); end
    carry = allocate!(wa, W + 1)
    push!(g, NOTGate(carry[1]))
    axnb = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(a[i], axnb[i])); push!(g, CNOTGate(nb[i], axnb[i]))
        push!(g, ToffoliGate(a[i], nb[i], carry[i + 1]))
        push!(g, ToffoliGate(axnb[i], carry[i], carry[i + 1]))
    end
    r = allocate!(wa, 1)
    push!(g, CNOTGate(carry[W + 1], r[1])); push!(g, NOTGate(r[1]))
    return r
end

function lower_slt!(g, wa, a, b, W)
    af = allocate!(wa, W); bf = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(a[i], af[i])); push!(g, CNOTGate(b[i], bf[i]))
    end
    push!(g, NOTGate(af[W])); push!(g, NOTGate(bf[W]))
    return lower_ult!(g, wa, af, bf, W)
end

function lower_not1!(g, wa, w::Vector{Int})
    r = allocate!(wa, 1)
    push!(g, CNOTGate(w[1], r[1])); push!(g, NOTGate(r[1]))
    return r
end

### 1.2 What each primitive actually computes (hand-traced)

- **`lower_eq!`** — `diff[i] = a[i] ⊕ b[i]`. The `(CNOT, CNOT, Toffoli)` triple is the standard reversible OR: `t ^= x; t ^= y; t ^= x&y` gives `x ∨ y` on a zero target. So `or[k]` is the running OR-prefix and `or[W-1] = OR_i(a[i] ⊕ b[i]) = (a != b)`. `r = ¬or[W-1] = (a == b)`. The `W == 1` branch exists purely because `or = allocate!(wa, W-1)` is empty at `W = 1` and `or[1]` would be an out-of-bounds read; there the raw flag is `diff[1]`, which is also `(a != b)`. **The raw scratch flag is `a != b` at every width.**
- **`lower_ult!`** — computes `a + ¬b + 1 = a − b` and reads the carry-out. `nb = ¬b`; `carry[1] = 1` is the `+1`; the two Toffolis are the majority function `c_out = (a & nb) ⊕ ((a ⊕ nb) & c_in)`. `carry[W+1]` is the carry-out of `a − b`, which is **1 iff `a ≥u b`**. `r = ¬carry[W+1] = (a <u b)`. **The raw scratch flag is `a ≥u b`.**
- **`lower_slt!`** — copies `a→af`, `b→bf`, flips the MSB of each (bias by `2^(W-1)`), then runs `ult` on the biased values. `a <s b ⟺ (a ⊕ 2^(W-1)) <u (b ⊕ 2^(W-1))`. **The raw scratch flag is `a ≥s b`.**

## 2. Gate sequence as indexed pseudo-code

All indices below are **0-based** (C convention); Bennett's are 1-based. `scr_*` names are scratch regions acquired from M08.

**Each step is exactly one *structural* gate.** Under **I6(b)** (`IMPLEMENTATION_PLAN.md` §0.2) every scratch bit is `CQ_BIT_Q` before step 0 runs, and every target in a compute half is scratch (I6(a)) — so a target is **never** materialised mid-half and no step ever costs 2 gates. A step can still cost **0**, but only when one of its *controls* is a classical **operand** bit (`a[i]` / `b[i]`), never because of scratch state; see §3.3.1. So "one gate per step" is a statement about the step function, and under I6(b) it is *also* the emitted count whenever every operand bit is on a qubit. This is deliberate and load-bearing: the plan's driver replays `for s in (n_compute, 0]` (`IMPLEMENTATION_PLAN.md:42`), which is a correct inverse **only** if reversing step order also reverses gate order. One gate per step makes that automatic. If a step emitted two gates, the driver would have to reverse within the step too, and `lower_ult!`'s loop body is *not* order-insensitive (`CX(a,axnb)` and `CX(nb,axnb)` write `axnb[i]`, which the following Toffoli reads as a control).

### 2.1 `eq` compute half — `n_compute = 5W − 3`

Scratch: `scr_diff[0..W-1]`, `scr_or[0..W-2]` (empty at `W = 1`). Total `2W − 1` bits.

```
/* Phase A — diff, steps s in [0, 2W) :  i = s/2 */
  s even :  CX(a[i],  scr_diff[i])
  s odd  :  CX(b[i],  scr_diff[i])

/* Phase B — OR-reduce, steps s in [2W, 5W-3).  Absent when W == 1.
   u = s - 2W ;  k = u/3 ;  j = u%3            (k in [0, W-1))          */
  k == 0:
    j == 0 :  CX (scr_diff[0], scr_or[0])
    j == 1 :  CX (scr_diff[1], scr_or[0])
    j == 2 :  CCX(scr_diff[0], scr_diff[1], scr_or[0])
  k >= 1:
    j == 0 :  CX (scr_or[k-1],   scr_or[k])
    j == 1 :  CX (scr_diff[k+1], scr_or[k])
    j == 2 :  CCX(scr_or[k-1],   scr_diff[k+1], scr_or[k])

/* raw flag (holds a != b) */
  raw_ne = (W == 1) ? scr_diff[0] : scr_or[W-2]
```

`n_compute = 2W + 3(W−1) = 5W − 3`, and at `W = 1` Phase B is empty giving `2 = 5·1 − 3`. **The formula is uniform across the `W == 1` special case** — the branch is needed for the index, not for the count.

Copy-out (`n_copyout`):

```
  eq :  step 0: CX(raw_ne, dst[0]);  step 1: X(dst[0])     -> n_copyout = 2
  ne :  step 0: CX(raw_ne, dst[0])                          -> n_copyout = 1
```

### 2.2 `ult` compute half — `n_compute = 6W + 1`

Called with `(a,b)` for `ult`/`uge` and with `(b,a)` for `ugt`/`ule` — the swap is at the call site, not in the step function.

Scratch: `scr_nb[0..W-1]`, `scr_carry[0..W]` (index 0 = `c_in`), `scr_axnb[0..W-1]`. Total `3W + 1` bits.

```
/* Phase A — nb = ~b, steps s in [0, 2W) :  i = s/2 */
  s even :  CX(b[i], scr_nb[i])
  s odd  :  X (scr_nb[i])

/* Phase B — carry seed, step s == 2W */
            X (scr_carry[0])                    /* c_in = 1, the '+1' of two's complement.
                                                   *** Under I6(b) scr_carry[0] is ALREADY
                                                   a qubit here, so this X IS EMITTED. It
                                                   used to fold to 0 gates and leave a
                                                   classical ONE, which then degraded the
                                                   j==3 Toffoli at i=0 into a CX. Neither
                                                   happens any more — see §3.3. This one
                                                   step is the whole re-issue. ***        */

/* Phase C — ripple, steps s in [2W+1, 6W+1).
   u = s - (2W+1) ; i = u/4 ; j = u%4                                    */
  j == 0 :  CX (a[i],        scr_axnb[i])
  j == 1 :  CX (scr_nb[i],   scr_axnb[i])
  j == 2 :  CCX(a[i], scr_nb[i],           scr_carry[i+1])
  j == 3 :  CCX(scr_axnb[i], scr_carry[i], scr_carry[i+1])

/* raw flag (holds a >=u b for the operand order passed in) */
  raw_uge = scr_carry[W]
```

`n_compute = 2W + 1 + 4W = 6W + 1`.

Copy-out:

```
  ult (a,b) :  CX(raw_uge, dst[0]); X(dst[0])   -> 2     /* ult = ~(a >=u b)  */
  ugt (b,a) :  CX(raw_uge, dst[0]); X(dst[0])   -> 2     /* ugt = ult(b,a)    */
  uge (a,b) :  CX(raw_uge, dst[0])              -> 1     /* raw flag IS uge   */
  ule (b,a) :  CX(raw_uge, dst[0])              -> 1     /* ule = b >=u a     */
```

### 2.3 `slt` compute half — `n_compute = 8W + 3`

Called with `(a,b)` for `slt`/`sge` and `(b,a)` for `sgt`/`sle`.

Scratch: `scr_af[0..W-1]`, `scr_bf[0..W-1]`, plus the whole `ult` scratch. Total `5W + 1` bits.

```
/* Phase A — biased copies, steps s in [0, 2W) :  i = s/2 */
  s even :  CX(a[i], scr_af[i])
  s odd  :  CX(b[i], scr_bf[i])

/* Phase B — sign-bit flip, steps 2W and 2W+1 */
  s == 2W    :  X(scr_af[W-1])
  s == 2W+1  :  X(scr_bf[W-1])

/* Phase C — steps s in [2W+2, 8W+3):
   the §2.2 ult step function verbatim, with (a,b) := (scr_af, scr_bf),
   step index s - (2W+2), 6W+1 steps.                                    */

/* raw flag (holds a >=s b) */
  raw_sge = scr_carry[W]
```

`n_compute = 2W + 2 + (6W + 1) = 8W + 3`.

Copy-out:

```
  slt (a,b) :  CX(raw_sge, dst[0]); X(dst[0])   -> 2
  sgt (b,a) :  CX(raw_sge, dst[0]); X(dst[0])   -> 2
  sge (a,b) :  CX(raw_sge, dst[0])              -> 1
  sle (b,a) :  CX(raw_sge, dst[0])              -> 1
```

### 2.4 I6(a) and I6(b) — both sides checked

I6 was split into two parts on **2026-08-14** (`IMPLEMENTATION_PLAN.md` §0.2), because the target-side condition alone was not sufficient. K9 satisfies both.

**I6(a) — target side. Is every compute-half gate target inside scratch? YES for all three primitives.**

| Primitive | Every target | Every control | Verdict |
|---|---|---|---|
| `eq` | `scr_diff[i]`, `scr_or[k]` | `a[i]`, `b[i]`, `scr_diff[*]`, `scr_or[k-1]` | ✔ sources appear only as controls |
| `ult` | `scr_nb[i]`, `scr_carry[0]`, `scr_axnb[i]`, `scr_carry[i+1]` | `b[i]`, `a[i]`, `scr_nb[i]`, `scr_carry[i]`, `scr_axnb[i]` | ✔ |
| `slt` | `scr_af[i]`, `scr_bf[i]`, `scr_af[W-1]`, `scr_bf[W-1]`, then all of `ult`'s | `a[i]`, `b[i]`, then `scr_af`/`scr_bf` | ✔ |

**I6(b) — control side. Is every scratch bit `CQ_BIT_Q` for the whole compute half? YES — guaranteed by the driver, not by anything K9 does.** `cq_sandwich` pre-materialises the entire scratch region before step 0. Two K9 `ult` steps read scratch state and therefore *did* fold before the decision:

```
step 2W        X  (scr_carry[0])                              scr_carry[0] : ZERO -> classical ONE, 0 gates
step 2W+1+3    CCX(scr_axnb[0], scr_carry[0], scr_carry[1])   c2 = ONE     -> degrades to CX
```

Under I6(b) neither fires — that is the whole of §3.3, and it is why the counts moved.

> **materialised by a later step**, so the reverse replay emits a gate the forward never
> did. K9 does not have that shape. `scr_carry[0]` is read as a **`ONE`** control — which
> emits a gate (the degraded `CX`), not zero — and it is **never targeted again** after step
> `2W`, so it is never materialised late. Its kind is fixed by step `2W` in *both* halves,
> so the two halves mirror exactly even without pre-materialisation.
>
> More generally: **every** K9 scratch bit is fully written before it is first read as a
> control, and no K9 scratch bit is written after its first control-read. Verified
> exhaustively — the fold table applied by hand to the §2 step sequences over **all**
> `3^(2W)` operand bit-kind masks for `eq`, `ult` and `slt` at `W ∈ {1,2,3,4,5}`
> (`3 × (9 + 81 + 729 + 6561 + 59049) = 199,287` masks): the forward stream equals the
> reverse-of-the-reverse stream in **every** case, so
> the sandwich cancelled and scratch returned to `|0⟩` under the old regime too.
> **UNVERIFIED-BY-EXECUTION** in the sense that no Bennett and no libcqops code was run —
> this is my own transcription of `arith.jl:424-472` and of `PRD-v1.md:284-296`.
>
> **What this changes:** nothing numeric. The `+2` delta and every figure in §3 stand. What

> genuinely need I6(b) are the ones whose scratch is read as a control before it is written;
> the plan's R8 witnesses (`W=3`, `a=b={Q,ZERO,ZERO}`; `{ZERO,Q}`-only at `W=5`) come from
> such a kernel, not from K9. I6(b) is still right for K9 — it is a driver-level guarantee
> rather than a per-kernel hand-argument (§0.1's whole point) — but K9 is a *beneficiary*,
> not the motivating case.

Two further notes.

1. In `slt`, Phase C's *controls* are `scr_af` / `scr_bf` — scratch bits, not the caller's `a` / `b`. That is fine for I6(a), which constrains **targets** only; and under I6(b) those controls are `CQ_BIT_Q`, so Phase C emits its full gate sequence at every operand bit-kind mask (§3.3.1). The true sources `a` and `b` are touched exactly once each, in Phase A, and only as controls, so the "leave `a` and `b` unchanged" half of the kernel contract holds trivially.
2. `dst[0]` is targeted only in copy-out, which sits **outside** the reversed region (`IMPLEMENTATION_PLAN.md:36-43`). No compute-half step ever names `dst`, and `dst` is **not** part of the pre-materialised scratch region.

## 3. Gate-count formula in W

> **Re-issued 2026-08-14 under I6(b).** The decision of 2026-08-14 (`IMPLEMENTATION_PLAN.md` §0.2) splits I6 into a target side (a) and a control side (b), and makes `cq_sandwich` **pre-materialise the entire scratch region at step 0**. Consequence for K9: **no fold on a scratch bit can ever fire**, so every figure that was previously lowered by such a fold has moved. If you are diffing against a copy of this doc dated before 2026-08-14:
>
> | Figure | OLD (pre-I6(b), fold-aware) | **NEW (I6(b), normative)** |
> |---|---|---|
> | `ult` / `ugt` sandwiched total | `12W + 2` — **98** at W=8 | **`12W + 4`** — **100** at W=8 |
> | `ule` / `uge` sandwiched total | `12W + 1` — 97 at W=8 | **`12W + 3`** — 99 at W=8 |
> | `slt` / `sgt` sandwiched total | `16W + 6` — **134** at W=8 | **`16W + 8`** — **136** at W=8 |
> | `sle` / `sge` sandwiched total | `16W + 5` — 133 at W=8 | **`16W + 7`** — 135 at W=8 |
> | `ult` compute-half qubits | `3W` | **`3W + 1`** |
> | `slt` compute-half qubits | `5W` | **`5W + 1`** |
> | `eq` / `ne` sandwiched total | `10W − 4` / `10W − 5` | **unchanged** — `eq` folds nothing |
> | `eq` / `ne` compute-half qubits | `2W − 1` | **unchanged** |
>
> **Single root cause:** step `2W` of `ult` is `X(scr_carry[0])`. On a `BIT_ZERO` scratch bit that used to fold to zero gates and leave a classical `ONE`, which then degraded the following `CCX` to a `CX`. Under I6(b) `scr_carry[0]` is already `CQ_BIT_Q`, so the `X` is emitted and the `CCX` stays a `CCX`. **Per `ult` invocation: +1 X, +1 CCX, −1 CX — net +1 gate.** A sandwich runs `ult` twice, hence +2 on the total; `slt` contains exactly one `ult`, so it inherits the same +2. The seven derived predicates inherit through their base primitive.
>
> The 1-bit result shape is **unchanged** — `icmp` is still `i1` (`ir_types.jl:79`).

Two layers of number are reported, plus one **withdrawn** layer kept only for diffing.

- **(A) Bennett-verbatim** — literally counting `push!` calls in the Julia function, including the `r` result wire. This is the cross-checkable ground truth against `arith.jl`; it is *not* what libcqops emits. **Unaffected by I6(b)** — Bennett has no classical operand kind at all (§5 delta 12).
- **(B) libcqops structural step count** — `n_compute`, the number of steps in the step function. **Under I6(b) this is also the *emitted* count whenever every operand bit is on a qubit**, because the only bits whose kind could have folded a step away inside the compute half are scratch bits, and those are all `CQ_BIT_Q` before step 0. **This is the L4 golden**, and it is the number the driver needs — one number, not two.
- **(C) — WITHDRAWN 2026-08-14.** The old "fold-aware emitted count" layer, which differed from (B) for `ult` and `slt`. Retained in §3.3 as a **quarantined counterfactual only**. **Do not pin it.**

### 3.2 (B) libcqops compute half — structural step count **and** emitted count

The compute half is Bennett's function **minus** the trailing result-wire materialisation (`r = allocate!; CNOT(x, r[1]); NOT(r[1])`), because in libcqops that pair becomes the copy-out into `dst`.

Derivation, per primitive, subtracting `(1 X, 1 CX)` from the layer-(A) totals of §3.1:

- `eq` : `X = 1 − 1 = 0` · `CX = (4W − 1) − 1 = 4W − 2` · `CCX = W − 1` → `n_compute = 0 + (4W−2) + (W−1) = 5W − 3`
- `ult`: `X = (W + 2) − 1 = W + 1` · `CX = (3W + 1) − 1 = 3W` · `CCX = 2W` → `n_compute = (W+1) + 3W + 2W = 6W + 1`
- `slt`: `X = (W + 4) − 1 = W + 3` · `CX = (5W + 1) − 1 = 5W` · `CCX = 2W` → `n_compute = (W+3) + 5W + 2W = 8W + 3`

| Primitive | X | CX | CCX | `n_compute` | scratch bits | **scratch qubits** |
|---|---|---|---|---|---|---|
| `eq` | `0` | `4W − 2` | `W − 1` | `5W − 3` | `2W − 1` | `2W − 1` |
| `ult` | `W + 1` | `3W` | `2W` | `6W + 1` | `3W + 1` | `3W + 1` |
| `slt` | `W + 3` | `5W` | `2W` | `8W + 3` | `5W + 1` | `5W + 1` |

**Structural count == emitted count** here, provided every operand bit is on a qubit. Scratch bits and scratch qubits are now the *same number* for all three primitives — I6(b) materialises them all (§4).

**Sandwiched total** `= 2 × (compute half) + copy-out`, with copy-out `= 1 CX` for the **five** predicates whose raw scratch flag already *is* the answer (`ne`, `ule`, `uge`, `sle`, `sge`), and `1 CX + 1 X` for the **five** that need inverting (`eq`, `ult`, `ugt`, `slt`, `sgt`) — see the per-predicate copy-out lists in §2.1–§2.3, which enumerate all ten. Copy-out sits outside the reversed region, so it is counted once, not twice.

Arithmetic, spelled out for the two families that moved:

```
ult / ugt :  2 x (X=W+1, CX=3W, CCX=2W)  =  (2W+2, 6W, 4W)
             + copy-out (1 X, 1 CX)      =  (2W+3, 6W+1, 4W)
             total = (2W+3) + (6W+1) + 4W = 12W + 4

slt / sgt :  2 x (X=W+3, CX=5W, CCX=2W)  =  (2W+6, 10W, 4W)
             + copy-out (1 X, 1 CX)      =  (2W+7, 10W+1, 4W)
             total = (2W+7) + (10W+1) + 4W = 16W + 8
```

| Predicate | X | CX | CCX | **total** | vs. OLD |
|---|---|---|---|---|---|
| `eq` | `1` | `8W − 3` | `2W − 2` | `10W − 4` | unchanged |
| `ne` | `0` | `8W − 3` | `2W − 2` | `10W − 5` | unchanged |
| `ult`, `ugt` | `2W + 3` | `6W + 1` | `4W` | **`12W + 4`** | was `12W + 2` |
| `ule`, `uge` | `2W + 2` | `6W + 1` | `4W` | **`12W + 3`** | was `12W + 1` |
| `slt`, `sgt` | `2W + 7` | `10W + 1` | `4W` | **`16W + 8`** | was `16W + 6` |
| `sle`, `sge` | `2W + 6` | `10W + 1` | `4W` | **`16W + 7`** | was `16W + 5` |

`ugt` / `sgt` cost the same as `ult` / `slt` (operand swap is free — it is an argument-order change, zero gates). `ule` / `uge` / `sle` / `sge` each cost exactly **one X less** than their non-negated sibling, because the trailing `NOT` cancels against the raw flag's own inversion.

**The Toffoli column is the one that matters most and it is the one that moved**: the ult and slt families are now `4W` sandwiched Toffolis, not `4W − 2`. That is exactly what L4 exists to protect.

### 3.3 (C) WITHDRAWN — the fold table no longer reaches scratch

PRD §3's fold table (`PRD-v1.md:284-296`) is normative, and **before** the I6(b) decision it fired twice inside `ult`:

1. Step `2W` is `X(scr_carry[0])`. A freshly acquired scratch bit was `CQ_BIT_ZERO`, i.e. classical, so fold row 1 — *"`X(t)`, `t` constant → flip the constant in place → **0 gates**"* (`PRD-v1.md:286`) — turned it into a classical `CQ_BIT_ONE` and emitted nothing.
2. At `i = 0`, step `j == 3` is `CCX(scr_axnb[0], scr_carry[0], scr_carry[1])`. With `scr_carry[0] = ONE`, the `c2 = ONE` row (`PRD-v1.md:294`) degraded that Toffoli to `CX(scr_axnb[0], scr_carry[1])`.

**Neither fires any more.** `cq_sandwich` materialises `scr_carry[0]` — along with every other scratch bit — at step 0, so at step `2W` it is `CQ_BIT_Q` and row 2 of the table applies (*"`X(t)`, `t` qubit → `sink.x(t.q)`"*, `PRD-v1.md:287`): **1 X emitted**. At `i = 0, j == 3` both controls are `Q`, so the last `CCX` row applies (`PRD-v1.md:296`): **1 CCX emitted**. The semantics are identical either way — with `c_in = 1`, `MAJ(a, nb, 1) = a ∨ nb`, and the fold merely computed that with cheaper gates.

**Pre-materialisation itself emits nothing.** Scratch is born `BIT_ZERO`, and `cq_materialise` emits an `X` only if the constant was `1` (`IMPLEMENTATION_PLAN.md` §0.2; `PRD-v1.md:380` — *"all scratch bits -> CQ_BIT_Q. 0 gates, W_scratch qubits"*). **Step 0 costs qubits, never gates.** Do not add `X`s for it.

**Quarantined counterfactual — DO NOT PIN.** For diff purposes only, the withdrawn layer (C) figures were:

| Primitive | X | CX | CCX | total | qubits | status |
|---|---|---|---|---|---|---|
| `eq` | `0` | `4W − 2` | `W − 1` | `5W − 3` | `2W − 1` | identical to (B) — `eq` folded nothing |
| `ult` | `W` | `3W + 1` | `2W − 1` | `6W` | `3W` | **counterfactual — withdrawn** |
| `slt` | `W + 2` | `5W + 1` | `2W − 1` | `8W + 2` | `5W` | **counterfactual — withdrawn** |

### 3.3.1 The one thing that still depends on operand bit-kinds

I6(b) removes *scratch* from the fold's reach. It does not — and is not meant to — materialise the caller's operands: `a` and `b` arrive as `const cq_bit *` and keep whatever kind they had (Rule 5, I5, delta 8). So a **classical operand bit still folds its own step away**. Every step whose controls are all scratch is now unfoldable:

| Step | Controls | If a control operand bit is `ZERO` | If it is `ONE` |
|---|---|---|---|
| `eq` A: `CX(a[i], scr_diff[i])`, `CX(b[i], scr_diff[i])` | operand | 0 gates | 1 X |
| `eq` B (all of it) | **scratch — always `Q`** | *cannot fold* | *cannot fold* |
| `ult` A: `CX(b[i], scr_nb[i])` | operand | 0 gates | 1 X |
| `ult` A: `X(scr_nb[i])` | *(target only)* | *cannot fold* | *cannot fold* |
| `ult` B: `X(scr_carry[0])` | *(target only)* | *cannot fold* | *cannot fold* |
| `ult` C `j==0`: `CX(a[i], scr_axnb[i])` | operand | 0 gates | 1 X |
| `ult` C `j==1`, `j==3` | **scratch — always `Q`** | *cannot fold* | *cannot fold* |
| `ult` C `j==2`: `CCX(a[i], scr_nb[i], scr_carry[i+1])` | operand + scratch | 0 gates | 1 CX |
| `slt` A: `CX(a[i], scr_af[i])`, `CX(b[i], scr_bf[i])` | operand | 0 gates | 1 X |
| `slt` B, `slt` C (**all** of it) | **scratch — always `Q`** | *cannot fold* | *cannot fold* |

Three consequences, stated plainly.

1. **It is sound.** A source's kind cannot change inside a compute half (I6(a) — controls are never materialised, enforced by `const`-qualification), so the forward and reverse halves fold *identically* and the sandwich still cancels exactly. This is a count reduction, not a miscompile — unlike the generic scratch-side hazard R8, which I6(b) closes (and which, per §2.4's ⚠, K9 turns out never to have had).
2. **`slt`'s entire Phase C is now bit-kind independent**, because its controls are `scr_af` / `scr_bf`, which are scratch. So the slt family's Toffoli count is `4W` sandwiched at *every* operand mask. `ult`'s is not: a classical `a[i]` kills the `j == 2` Toffoli at that index.
3. **Pin the L4 golden at the all-quantum operand mask.** That is the row §3.4 tabulates, and under I6(b) it is a function of `W` alone. Partially-classical masks fold to **at most** that count and belong to **L5**, not L4 — see the ⚠ below for why "at most", not "strictly fewer". The plan's consequence 1 (*"a kernel's gate count is a function of W alone"*, `IMPLEMENTATION_PLAN.md` §0.2) is exact once **scratch** is out of the picture; this residual operand-driven folding is the only remaining caveat for K9, and it is **flagged for the plan, not settled here**.

## 4. Ancilla count

**Under I6(b), every scratch bit is a qubit.** `cq_sandwich` pre-materialises the whole scratch region at step 0, so the two columns that used to differ for `ult` and `slt` are now the same number. The rise is `+1` qubit for both, and it is `scr_carry[0]`.

| Primitive | Scratch `cq_bit`s | **Qubits taken from the pool** | OLD (pre-I6(b)) | Where they come from |
|---|---|---|---|---|
| `eq` | `2W − 1` | `2W − 1` | `2W − 1` (unchanged) | `scr_diff[W]` + `scr_or[W−1]` (`arith.jl:425, 435`); at `W=1` just `scr_diff[1]` |
| `ult` | `3W + 1` | **`3W + 1`** | `3W` | `scr_nb[W]` + `scr_carry[W+1]` + `scr_axnb[W]` (`arith.jl:450, 452, 454`) |
| `slt` | `5W + 1` | **`5W + 1`** | `5W` | `ult`'s `3W+1` plus `scr_af[W]` + `scr_bf[W]` (`arith.jl:466`) |

Per predicate: `eq`/`ne` → `2W − 1`; `ult`/`ugt`/`ule`/`uge` → `3W + 1`; `slt`/`sgt`/`sle`/`sge` → `5W + 1`. The operand swap in `ugt`/`ule`/`sgt`/`sle` costs nothing here either.

| Family | W=1 | W=8 | W=16 | W=32 | W=64 |
|---|---|---|---|---|---|
| `eq`, `ne` — `2W − 1` | 1 | 15 | 31 | 63 | 127 |
| `ult`, `ugt`, `ule`, `uge` — `3W + 1` | 4 | **25** | 49 | 97 | 193 |
| `slt`, `sgt`, `sle`, `sge` — `5W + 1` | 6 | **41** | 81 | 161 | 321 |

`scr_carry[0]` **used to be** the one scratch bit that never became a qubit: a folded `X` seeded it to a classical `CQ_BIT_ONE` and it stayed classical for the whole kernel. Under I6(b) it is materialised at step 0 like every other scratch bit, so the qubit cost now equals the scratch-bit cost exactly. This is consequence 3 of the decision — pre-materialisation buys structural reversal at the price of qubits, and it costs **no gates** (§3.3).

**Plus `dst`.** `dst[0]` is *not* scratch and is *not* pre-materialised. On a forward call it arrives all-`BIT_ZERO` and takes its single qubit when the copy-out `CX` fires (`cq_materialise` on a `ZERO` constant: 1 qubit, 0 gates). So:

- **Peak pool draw during the kernel** = scratch qubits (table above) `+ 1` for `dst`, on top of whatever `a` and `b` already hold, which is the caller's.
- **After return** = `1` qubit, `dst`'s — scratch is released back to the LIFO pool (D4). That is exactly what **L2** asserts: the live-qubit set equals precisely `dst`'s qubits.
- **Fully-classical operands** = **0** scratch qubits and **0** for `dst`. The kernel short-circuits before `cq_sandwich`, so pre-materialisation never runs and the result is a constant bit (§3.3.1, `PRD-v1.md:378-379`). **L5** holds unchanged.

**All scratch returns to |0⟩.** The reverse half of the sandwich replays the identical gate sequence in reverse step order — sound because **both** halves of I6 hold (§2.4), and I6(b) is what makes "identical" true rather than merely likely — and `X`, `CX`, `CCX` are each self-inverse (`gates.jl:3` states this for Bennett's own types; the same is true of the libcqops emitter). Note that libcqops needs **zero** ancillae beyond scratch for the derived predicates: Bennett's `lower_not1!` allocates a wire per negation and its `r` result wire is a further one, both of which libcqops eliminates by folding into copy-out (§5 delta 1).

## 5. Deltas from upstream

> **Two entries changed on 2026-08-14 under I6(b): the new delta 12 (pre-materialised scratch — read it first, it is the cause) and delta 3 (the golden trap, which has *inverted sign*). Delta 4 is now closed. Delta 11's counterfactual numbers moved with the rest.**

1. **No `r` result wire, no `lower_not1!` wire.** Bennett materialises the flag onto a fresh wire (`arith.jl:445, 461, 476`). libcqops turns that `CNOT + NOT` into the sandwich copy-out onto `dst`. Saves 1 ancilla on the three primitives and a second on each of the six negated predicates, plus the associated gates.

2. **The trailing double negation is folded, not emitted.** Bennett computes e.g. `uge = ¬ult(a,b) = ¬¬(carry-out)`. libcqops copies the raw carry-out straight into `dst` with a single CX and emits no X at all. This is not re-deriving a construction (Rule 1) — it is the mechanical consequence of the `dst ^= f` contract collapsing two involutions on one bit — but it **does** change the golden versus a literal transcription, so it needs to be a recorded decision, not an implementation detail. Affected: `ne`, `ule`, `uge`, `sle`, `sge` lose one X each relative to naive transcription; `eq`, `ult`, `ugt`, `slt`, `sgt` keep exactly one.

3. **⚠ THE GOLDEN TRAP — SIGN INVERTED 2026-08-14. Under I6(b) the fold does NOT fire, and the trap is now the opposite of what it was.** *Old trap:* `X(scr_carry[0])` on a `BIT_ZERO` scratch bit emitted 0 gates, and the resulting classical `ONE` control degraded `CCX(scr_axnb[0], scr_carry[0], scr_carry[1])` to a `CX` — so anyone porting the Julia gate-for-gate would **over**-count by 1 X and 1 Toffoli per `ult`. *New trap:* `scr_carry[0]` is pre-materialised, both gates are emitted in full, and anyone working from a **pre-2026-08-14 copy of this document** (or from any note that says "the fold removes an X and a Toffoli") will **under**-count by exactly that amount — `2` X and `2` Toffoli per sandwiched compare, since the sandwich runs `ult` twice. 12. **⭐ NEW 2026-08-14 — we pre-materialise the scratch region; Bennett does not, and upstream the question cannot even arise.** `cq_sandwich` turns every scratch bit into a `CQ_BIT_Q` qubit at step 0, before the first compute step runs (**I6(b)**, `IMPLEMENTATION_PLAN.md` §0.2). This is a **libcqops-only** step with no counterpart in `arith.jl`.

    **Why Bennett has nothing to port here.** Bennett has **no classical operand kind at all**: `const WireIndex = Int` (`gates.jl:1`) — every operand of every gate is a wire index, and `NOTGate` / `CNOTGate` / `ToffoliGate` (`gates.jl:6-22`) each store nothing but wire indices. There is no `ZERO` / `ONE` / `Q` distinction anywhere in the gate layer, and `WireAllocator` (`wire_allocator.jl:8-28`) hands out indices, not values.     **Why it is needed — and what K9 does *not* show. ⚠ CORRECTED 2026-08-14.** The generic hazard is risk **R8** (`IMPLEMENTATION_PLAN.md:435`): a scratch bit read as a `BIT_ZERO` control (0 gates forward) and **materialised by a later step**, so the reverse replay emits a gate the forward never did — scratch left dirty while **L1 stays green**. That is the silent-miscompile class this repo exists to prevent (CLAUDE.md §Prime Directive). **K9 is not an instance of it.** `ult` step `2W` (`X(scr_carry[0])`) does fold against scratch state, but it folds to a classical **`ONE`**, which is read as a control that still *emits* a gate (the degraded `CX`), and `scr_carry[0]` is never targeted again — so it is never materialised late and the halves mirror exactly without I6(b). Verified exhaustively over all `3^(2W)` masks at `W ≤ 5` (§2.4). For K9 the purchase is **count stability**, not correctness: the gate count stops depending on the scratch materialisation schedule, which is what makes a single L4 golden per `(predicate, W)` sound (risk **R5**). The correctness argument for I6(b) has to be made on a kernel that actually reads scratch before writing it — not on this one.

    **What it costs and what it buys.** Costs: `+1` qubit for `ult`, `+1` for `slt`, `0` for `eq` (§4) — and **zero gates**, because scratch is born `BIT_ZERO` and `cq_materialise` emits an `X` only for a `ONE` (§3.3). Buys: reversal is structural, and the gate count no longer depends on the scratch materialisation schedule, which is what makes a single L4 golden per `(predicate, W)` sound (risk **R5**). Bounded by delta 8 and consequence 2 of the decision: **operands are not pre-materialised, and the all-classical case never enters the sandwich**, so L5's zero-gate zero-qubit guarantee is untouched.
