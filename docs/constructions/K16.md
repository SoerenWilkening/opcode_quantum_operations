**Clean or sandwich:** **sandwich**, and the reason is one order of magnitude larger
than K15's. Four `cq_mul_block`s sit in K16's compute half, and a `cq_mul_block` is
*itself* Bennett-in-the-small's compute half — `pp[j]` is never recycled because
Cuccaro restores its addend, and `x[j]` is a caller-owned ancilla per accumulate
(`K11.md` §7.2). Add every comparator's carry chain, every mux's `d` vector, every
eq block's OR-prefix, and the 106-bit assembly's five adders, and **nothing in this
kernel returns to `|0⟩` on its own.** Upstream gets away with it through one *global*
forward–copy–reverse wrap; libcqops has no global wrap, so K16 gets the local one
(PRD §5; Rule 2). Cost is 2× the compute half at the **same** ancilla peak (PRD-v2
§3.3, *"Rule 2 doubles the gates and does not move the peak"*).

> **Do not `cqrt_free` anything inside K16's compute half.** `pp_ll`'s top 12 bits,
> the whole of the dead `:94-102` region (§1.3), `wr_104` on the `msb_at_105` path,
> `wr_105` on the other — all are provably dead *mathematically* and not one of them
> is provably `|0⟩` to the two-bit shadow. The sandwich reverse is the only thing
> that returns K16's scratch to `|0⟩`. K12.md and K15.md carry the identical warning

### 1.1 `soft_fmul` — `fmul.jl:1-215`, verbatim

```julia
"""
    soft_fmul(a::UInt64, b::UInt64) -> UInt64

IEEE 754 double-precision multiplication on raw bit patterns.
Uses only integer operations. Bit-exact with hardware `*`.

Fully branchless: all paths computed unconditionally, results selected
via `ifelse`. Required for correct reversible circuit compilation.

The dominant cost is the 53×53 mantissa multiply, implemented as a
widening multiply via four 27×26-bit partial products (schoolbook
decomposition into half-words that fit in UInt64 without overflow).
"""
function soft_fmul(a::UInt64, b::UInt64)::UInt64
    SIGN_MASK = UInt64(0x8000000000000000)   # bit 63
    BIAS      = Int64(1023)

    # ── Unpack ──
    sa = a >> 63
    ea = (a >> 52) & UInt64(0x7FF)
    fa = a & FRAC_MASK

    sb = b >> 63
    eb = (b >> 52) & UInt64(0x7FF)
    fb = b & FRAC_MASK

    # ── Result sign: XOR ──
    result_sign = sa ⊻ sb

    # ── Special-case predicates ──
    a_nan = (ea == UInt64(0x7FF)) & (fa != UInt64(0))
    b_nan = (eb == UInt64(0x7FF)) & (fb != UInt64(0))
    a_inf = (ea == UInt64(0x7FF)) & (fa == UInt64(0))
    b_inf = (eb == UInt64(0x7FF)) & (fb == UInt64(0))
    a_zero = (ea == UInt64(0)) & (fa == UInt64(0))
    b_zero = (eb == UInt64(0)) & (fb == UInt64(0))

    # ── Special-case results ──
    # Inf * 0 = NaN; Inf * finite = Inf; Inf * Inf = Inf
    inf_result = (result_sign << 63) | INF_BITS
    zero_result = result_sign << 63              # signed zero

    # ── Implicit leading 1 for normal, raw fraction for subnormal ──
    ma = ifelse(ea != UInt64(0), fa | IMPLICIT, fa)
    mb = ifelse(eb != UInt64(0), fb | IMPLICIT, fb)

    # Effective exponents (subnormal: stored 0 → effective 1)
    ea_eff = ifelse(ea != UInt64(0), Int64(ea), Int64(1))
    eb_eff = ifelse(eb != UInt64(0), Int64(eb), Int64(1))

    # Bennett-xy4j / U06: pre-normalise subnormal operands so the leading 1
    # sits at bit 52 before the 53×53 multiply. Without this, a subnormal
    # operand's leading 1 lies below bit 52 and the bit-104/105 extractor
    # below reads the wrong MSB position, losing up to ~48 mantissa bits.
    # Mirrors fdiv.jl:42-43 and fma.jl:67-69. No-op on already-normal inputs
    # (m is ≥ 2^52 and exponent adjustment is zero).
    (ma, ea_eff) = _sf_normalize_to_bit52(ma, ea_eff)
    (mb, eb_eff) = _sf_normalize_to_bit52(mb, eb_eff)

    # ── Unbiased exponent sum ──
    # result_exp = ea + eb - bias
    # But we work in biased form: result_exp_biased = ea + eb - bias
    result_exp = ea_eff + eb_eff - BIAS

    # ── 53×53 → 106-bit mantissa multiply ──
    # Decompose into half-words to avoid overflow.
    # ma, mb are at most 53 bits (bit 52 = implicit 1).
    # Split each into high 27 bits and low 26 bits:
    #   ma = a_hi * 2^26 + a_lo
    #   mb = b_hi * 2^26 + b_lo
    # Product = a_hi*b_hi*2^52 + (a_hi*b_lo + a_lo*b_hi)*2^26 + a_lo*b_lo
    # Each partial product fits in 53 bits, cross terms in 54 bits.
    a_lo = ma & UInt64(0x03FFFFFF)            # low 26 bits
    a_hi = ma >> 26                           # high 27 bits
    b_lo = mb & UInt64(0x03FFFFFF)            # low 26 bits
    b_hi = mb >> 26                           # high 27 bits

    pp_ll = a_lo * b_lo                       # max 52 bits
    pp_lh = a_lo * b_hi                       # max 53 bits
    pp_hl = a_hi * b_lo                       # max 53 bits
    pp_hh = a_hi * b_hi                       # max 54 bits

    # Assemble 106-bit product as (prod_hi : prod_lo), each UInt64.
    # prod_lo holds bits [0:63], prod_hi holds bits [64:105].
    #
    # Start with pp_ll in prod_lo.
    # Add cross terms shifted left by 26.
    # Add pp_hh shifted left by 52.

    # Cross term sum (may be up to 54 bits)
    cross = pp_lh + pp_hl                     # max 54 bits, no overflow

    # prod_lo = pp_ll + (cross << 26)
    cross_lo = cross << 26                    # bits [26:79] → low 64 bits
    prod_lo = pp_ll + cross_lo
    # Carry from prod_lo addition
    carry_lo = ifelse(prod_lo < pp_ll, UInt64(1), UInt64(0))

    # prod_hi = (cross >> 38) + pp_hh + carry_lo + (pp_hh_lo_part)
    # cross >> 38 gives the high bits of (cross << 26) that didn't fit in prod_lo
    cross_hi = cross >> 38
    pp_hh_shifted = pp_hh << 52               # low bits of pp_hh*2^52 in prod_lo
    # Actually, we need to add pp_hh*2^52 to the 128-bit product.
    # pp_hh * 2^52: low 12 bits go into prod_lo[52:63], rest into prod_hi.
    # But prod_lo already has pp_ll + cross_lo. Let's redo properly.

    # Restart assembly more carefully:
    # 106-bit product P = pp_ll + (cross << 26) + (pp_hh << 52)
    #
    # Split into prod_hi (bits 64-105) and prod_lo (bits 0-63):
    #
    # Layer 1: pp_ll (52 bits) → all in prod_lo
    # Layer 2: cross << 26 → bits [26, 79]
    #   prod_lo gets bits [26,63] = cross[0:37] << 26
    #   prod_hi gets bits [64,79] = cross[38:53]
    # Layer 3: pp_hh << 52 → bits [52, 105]
    #   prod_lo gets bits [52,63] = pp_hh[0:11] << 52
    #   prod_hi gets bits [64,105] = pp_hh[12:53]

    # Let's just do it with add-with-carry.
    # acc_lo = pp_ll
    # acc_lo += cross << 26; carry1 if overflow
    # acc_lo += pp_hh << 52; carry2 if overflow
    # acc_hi = (cross >> 38) + (pp_hh >> 12) + carry1 + carry2

    acc_lo = pp_ll
    term2 = cross << 26
    sum1 = acc_lo + term2
    c1 = ifelse(sum1 < acc_lo, UInt64(1), UInt64(0))

    term3 = pp_hh << 52
    sum2 = sum1 + term3
    c2 = ifelse(sum2 < sum1, UInt64(1), UInt64(0))

    prod_lo_final = sum2
    prod_hi_final = (cross >> 38) + (pp_hh >> 12) + c1 + c2

    # ── Extract the relevant 55 bits for working format ──
    # The 106-bit product has the leading 1 at bit 105 (if both inputs had
    # implicit 1 at bit 52: 52+52+1=105, but we count from 0).
    # Actually: ma has leading 1 at bit 52, mb at bit 52.
    # Product leading 1 is at bit 104 or 105 (105 if carry).
    #
    # We need 53 mantissa bits + 3 GRS bits = 56 bits from the top of the product.
    # The product is in bits [0,105]. The top 56 bits are [50,105] or [49,105].
    #
    # Working format: bit 55 = leading 1, bits [54:3] = fraction, bits [2:0] = GRS.
    # So we want to extract starting from the leading 1, take 56 bits.
    #
    # If the product's MSB is at bit 105 (in prod_hi bit 41):
    #   wr = product[105:50] (56 bits), sticky = OR of product[49:0]
    # If MSB is at bit 104:
    #   wr = product[104:49] (56 bits), sticky = OR of product[48:0]

    # Check if bit 105 (= prod_hi bit 41) is set
    msb_at_105 = (prod_hi_final >> 41) & UInt64(1)

    # Case 1: MSB at 105 → extract bits [105:50], sticky from [49:0]
    # That's (prod_hi << 23) | (prod_lo >> 41) for the 56-bit working value... no.
    # bits [105:50] = 56 bits. prod_hi has bits [64:105] = 42 bits.
    # So bits [105:64] = prod_hi[0:41], bits [63:50] = prod_lo[63:50]
    # wr_105 = (prod_hi << 14) | (prod_lo >> 50)... let me think more carefully.
    #
    # product bit N:
    #   if N >= 64: prod_hi[N-64]
    #   else: prod_lo[N]
    #
    # We want bits [105:50] right-justified in a UInt64.
    # = (prod_hi << (64 - 50)) ... no.
    # Bits 105 down to 50. That's prod_hi[41:0] (42 bits) concatenated with
    # prod_lo[63:50] (14 bits) = 56 bits total.
    # = (prod_hi_final << 14) | (prod_lo_final >> 50)
    # But prod_hi_final might have bits above 41 — mask first.
    wr_105 = ((prod_hi_final & ((UInt64(1) << 42) - UInt64(1))) << 14) | (prod_lo_final >> 50)
    sticky_105 = ifelse((prod_lo_final & ((UInt64(1) << 50) - UInt64(1))) != UInt64(0),
                        UInt64(1), UInt64(0))
    wr_105 = wr_105 | sticky_105

    # Case 2: MSB at 104 → extract bits [104:49], sticky from [48:0]
    wr_104 = ((prod_hi_final & ((UInt64(1) << 42) - UInt64(1))) << 15) | (prod_lo_final >> 49)
    sticky_104 = ifelse((prod_lo_final & ((UInt64(1) << 49) - UInt64(1))) != UInt64(0),
                        UInt64(1), UInt64(0))
    wr_104 = wr_104 | sticky_104

    # Select and adjust exponent
    wr = ifelse(msb_at_105 != UInt64(0), wr_105, wr_104)
    # MSB at 105 means an extra factor of 2 → exponent +1
    result_exp = ifelse(msb_at_105 != UInt64(0), result_exp + Int64(1), result_exp)

    # Mask to 56 bits (bit 55 = leading 1, bits 54:0 = fraction + GRS)
    wr = wr & ((UInt64(1) << 56) - UInt64(1))

    # ── Normalize subnormal inputs ──
    # If either input was subnormal, normalize (leading 1 should be at bit 55).
    (wr, result_exp) = _sf_normalize_clz(wr, result_exp)

    # ── Handle subnormal result (exponent underflow) ──
    (wr, result_exp, flushed_result, subnormal, flush_to_zero) =
        _sf_handle_subnormal(wr, result_exp, result_sign)

    # ── Round to nearest even + pack ──
    (normal_result, overflow_result, exp_overflow, exp_overflow_after_round) =
        _sf_round_and_pack(wr, result_exp, result_sign)

    # ── Final select chain ──
    result = normal_result
    result = ifelse(exp_overflow | exp_overflow_after_round, overflow_result, result)
    result = ifelse(subnormal & flush_to_zero, flushed_result, result)
    result = ifelse(a_zero | b_zero, zero_result, result)
    result = ifelse((a_inf | b_inf) & (a_zero | b_zero), INDEF, result)  # Inf * 0 (Bennett-r84x)
    result = ifelse((a_inf | b_inf) & !(a_zero | b_zero), inf_result, result)
    result = ifelse(a_nan | b_nan, _sf_propagate_nan2(a, b, a_nan, b_nan), result)

    return result
end
```

@inline function _sf_normalize_to_bit52(m::UInt64, e::Int64)
    # Bennett-tpg0: defensive guard for m == 0. Substitute IMPLICIT
    # (1<<52, leading 1 already at the target bit) so the CLZ is a
    # no-op; restore zero outputs at the end.
    m_zero = m == UInt64(0)
    e_orig = e
    m = ifelse(m_zero, IMPLICIT, m)

    need32 = (m & (UInt64(0xFFFFFFFF) << 21)) == UInt64(0)
    m = ifelse(need32, m << 32, m)
    e = ifelse(need32, e - Int64(32), e)

    need16 = (m & (UInt64(0xFFFF) << 37)) == UInt64(0)
    m = ifelse(need16, m << 16, m)
    e = ifelse(need16, e - Int64(16), e)

    need8 = (m & (UInt64(0xFF) << 45)) == UInt64(0)
    m = ifelse(need8, m << 8, m)
    e = ifelse(need8, e - Int64(8), e)

    need4 = (m & (UInt64(0xF) << 49)) == UInt64(0)
    m = ifelse(need4, m << 4, m)
    e = ifelse(need4, e - Int64(4), e)

    need2 = (m & (UInt64(0x3) << 51)) == UInt64(0)
    m = ifelse(need2, m << 2, m)
    e = ifelse(need2, e - Int64(2), e)

    need1 = (m & (UInt64(1) << 52)) == UInt64(0)
    m = ifelse(need1, m << 1, m)
    e = ifelse(need1, e - Int64(1), e)

    # Restore zero: byte-identical for m != 0 (m_zero is false, ifelse
    # picks the CLZ result); for m == 0 returns (0, e_orig).
    m_final = ifelse(m_zero, UInt64(0), m)
    e_final = ifelse(m_zero, e_orig, e)
    return (m_final, e_final)
end

@inline function _sf_handle_subnormal(wr::UInt64, result_exp::Int64, result_sign::UInt64)
    subnormal = result_exp <= Int64(0)
    shift_sub = Int64(1) - result_exp
    flush_to_zero = shift_sub >= Int64(56)
    shift_clamped = clamp(shift_sub, Int64(0), Int64(63))
    shift_u = UInt64(ifelse(flush_to_zero, Int64(0), shift_clamped))
    lost_mask_sub = (UInt64(1) << shift_u) - UInt64(1)
    lost_sub = ifelse((wr & lost_mask_sub) != UInt64(0), UInt64(1), UInt64(0))
    wr_sub_result = (wr >> shift_u) | lost_sub
    flushed_result = result_sign << 63

    wr = ifelse(subnormal,
         ifelse(flush_to_zero, wr, wr_sub_result),
         wr)
    result_exp = ifelse(subnormal, Int64(0), result_exp)

    return (wr, result_exp, flushed_result, subnormal, flush_to_zero)
end
```

@inline function _sf_round_and_pack(wr::UInt64, result_exp::Int64, result_sign::UInt64)
    # Overflow check
    exp_overflow = result_exp >= Int64(0x7FF)
    overflow_result = (result_sign << 63) | INF_BITS

    # Round to nearest even
    guard      = (wr >> 2) & UInt64(1)
    round_bit  = (wr >> 1) & UInt64(1)
    sticky_bit = wr & UInt64(1)
    frac       = (wr >> 3) & FRAC_MASK

    grs = (guard << 2) | (round_bit << 1) | sticky_bit
    round_up = (grs > UInt64(4)) | ((grs == UInt64(4)) & ((frac & UInt64(1)) != UInt64(0)))

    frac_rounded = frac + UInt64(1)
    mant_overflow = frac_rounded == IMPLICIT
    frac_final = ifelse(round_up,
                 ifelse(mant_overflow, UInt64(0), frac_rounded),
                 frac)
    exp_after_round = ifelse(round_up & mant_overflow,
                             result_exp + Int64(1),
                             result_exp)
    exp_overflow_after_round = exp_after_round >= Int64(0x7FF)

    # Pack normal result
    exp_pack = UInt64(clamp(exp_after_round, Int64(0), Int64(0x7FE)))
    normal_result = (result_sign << 63) | (exp_pack << 52) | frac_final

    return (normal_result, overflow_result, exp_overflow, exp_overflow_after_round)
end
```

## 2. Gate sequence as an indexed block table

### 2.0 Grain, spans, and the three representation rules

**Grain is LITERAL, per PRD-v2 §7.2** — *"One block per operator occurrence as the
source spells it; every intermediate a 64-bit span (the Julia type's width); no
common-subexpression sharing; no narrowing towards the field width."* Three readings
are fixed here, all three carried over verbatim from K15.md §2.0 so that the two
documents cannot drift:

- **"the Julia type's width" is the DECLARED type, so a `Bool` is ONE bit and a
  `UInt64`/`Int64` is SIXTY-FOUR** (PRD-v2 §7.2's 2026-09-18 clarification, D-K18-1).
  `a_nan`, `b_nan`, `a_inf`, `b_inf`, `a_zero`, `b_zero` are `Bool` and get one-bit
  spans. `sa`, `ea`, `result_sign`, `msb_at_105`, `c1`, `c2`, `sticky_105` are 64-bit
  spans even though each holds at most one bit of information, because each is declared
  `UInt64`. That is what makes every `ifelse(Bool, UInt64, UInt64)` land on
  `cq_mux_block` **unchanged** — `cond` one bit, arms `W` bits, which is M17's declared
  shape (`mux.h`, *"one bit; only `cond[0]` is read"*).
- **`Int64` and `UInt64` are the same 64 `cq_bit`s.** `Int64(ea)` at `fmul.jl:48` is a
  reinterpret: **wiring**, zero gates, zero qubits. What it changes is which comparator
  the *next* row uses. **In `soft_fmul` that question never arises** — §3.1 records
  zero `slt`-family rows, because every comparison on the `Int64` `result_exp` happens
  inside `_sf_handle_subnormal` and `_sf_round_and_pack`, which are M32's. That is a
  real difference from K15 and §5.7 turns on it.
- **No CSE means no CSE.** §5.1 lists the **nine** repeated subexpressions this
  produces in `soft_fmul` — two more than `soft_fadd` has, and three of the nine are in
  the final select chain rather than in the predicate block.

**Three representation rules decide, for each operator occurrence, whether it is a
block, a view, or nothing** — K15.md §2.0's three, unchanged, with the one place K16
stresses each differently:

1. **A block** — anything that computes a new value. Every `+ - * & | ⊻ ~ == != <` and
   every `ifelse`. It targets a fresh scratch span and its gates are the owning
   module's step function. **In K16 this includes `*`, four times, and each one is a
   whole `cq_mul_block` — 4,224 scratch bits and 26,336 slots apiece** (`K11.md` §7.3,
   measured).
2. **A view — zero gates, zero qubits** — a **constant-amount** shift and a reinterpret.
   K12.md §2.1's precedent is exact: build a local `cq_bit` array holding the source
   span's entries at the shifted positions and `CQ_BIT_ZERO` at the vacated ones, and
   hand that to the consuming block. Three riders, all load-bearing and all K15's:
   - **It must be rebuilt from the step index on every call**, never carried in mutable
     state — the driver replays indices in reverse.
   - **It is sound because a scratch span's `cq_bit` entries never change kind
     mid-half.** I6(b) pre-materialises the whole region at step 0, and I6 forbids
     materialising a source inside a compute half.
   - **The vacated lanes are literal `CQ_BIT_ZERO`**, departing from K12's `r0_hi` for
     K15's stated reason: K16's compute half is straight-line, so there is no iteration
     for a fold to make non-uniform. **§3.2 is where this stops being a bookkeeping
     detail** — it is the only thing that puts a classical lane inside a
     `cq_mul_block`'s operand.
3. **A constant is a SOURCE, never scratch** — PRD-v2 §7.3, verbatim: *"We pass them as
   `const cq_bit` arrays of `CQ_BIT_ZERO`/`CQ_BIT_ONE` and the §3 fold table elides
   every gate they control."* `FRAC_MASK`, `IMPLICIT`, `INF_BITS`, `QUIET_BIT`, `INDEF`,
   `0x7FF`, `0`, `1`, `1023`, `0x03FFFFFF`, and the four **constant-folded** masks
   `(1<<42)−1`, `(1<<50)−1`, `(1<<49)−1`, `(1<<56)−1` are file-static `cq_bit[64]`
   tables. They cost **zero qubits**.

> **THE FOUR `(UInt64(1) << k) - UInt64(1)` MASKS ARE CONSTANTS, NOT A SHIFT ROW AND A
> SUB ROW.** `fmul.jl:174`, `:175`, `:180`, `:181`, `:191` each spell a compile-time
> constant as an expression. Julia folds them; so do we, exactly as K15 folds
> `_sf_normalize_clz`'s six `(0xFFFFFFFF << 24)`-shaped masks and as `~SIGN_MASK` is
> folded there. Transcribing them as live `shl` + `sub` blocks would add five barrel
> rows to a kernel §5.4 audits as having **zero** variable shifts, and would make the
> D8 audit wrong by construction.

> **RULE 2 AND RULE 3 DISAGREE ABOUT `ma & 0x03FFFFFF`, AND HERE THE DISAGREEMENT IS
> WORTH FOUR `cq_mul_block` OPERAND MASKS RATHER THAN 960 SLOTS.** K15.md §2.0 states
> the contest: a mask by a *constant* is bit-for-bit a relabel, so rule 2 would make it
> a view; PRD-v2 §7.3's own worked example costs it as a block (*"`a & ~SIGN_MASK` costs
> zero gates and zero qubits on classical lanes and one CX per quantum lane"*). **This
> document follows §7.3, as K15 does.** The consequence is specific to K16 and is
> §3.2's whole subject: as a **block**, `a_lo`'s output is a pre-materialised scratch
> span whose every lane is `CQ_BIT_Q`, so the four products run at a **64-lane** operand
> mask; as a **view**, `a_lo`'s lanes 26–63 would be literal `CQ_BIT_ZERO` and the
> products would run at the 26/27-lane mask `K11.md` §7.5 measured. **It is a PRD
> amendment, not a kernel choice, and `9ve.22` must not settle it in code.**

**Constants make the fold table fire deterministically, and that is the structural
novelty against K11 and K12.** A slot whose only control is a constant `CQ_BIT_ZERO`
emits **nothing**; one whose control is `CQ_BIT_ONE` emits a **demoted** gate
(`CCX → CX`, `CX → X`). This is not mask-dependence — a constant is constant at every
operand mask — but it does mean **slots ≠ gates**, permanently, and §2.6 and §3 both
turn on it.

### 2.2 The block table — 122 rows in SOURCE ORDER

**Reading instructions.** One row per **operator occurrence** in §1's Julia. `V` = view
(rule 2: zero slots, zero gates, zero qubits). `C_x(w)` is the cost of block `x` at
width `w`, **asked of its module and never written down** — §3.0. `Kn` denotes a
`const cq_bit[64]` constant source (rule 3). Every `ifelse` row names its `cond` first.
Where a compare's *raw* flag has the wrong sense the row carries `+1`, one `X` on the
block's own flag bit, which is scratch and therefore I6(a)-legal and self-inverse.

**`==` is `C_eq(W) + 1` and `!=` is `C_eq(W)`.** The eq/ne block's raw flag holds
`a != b` (`cmp.h`, *"`orr[W-2]` IS `a != b`"*), so `!=` reads it directly and `==`
flips it in place. The `ult`-family raw flag holds `a >=u b` (K09 §2.2), so `<` costs
the `+1`; **all three of K16's compares are `<`, so all three carry it.**

### 2.4 I6(a) and I6(b)

**I6(a) — every compute-half gate target a kernel names is scratch. YES, by
construction and not by inspection.** Every row of §2.2 is either a view (emits
nothing) or a block whose targets are the block's own vectors, laid inside K16's one
scratch region. The two rails `a` and `b` appear in rows A1–A8, W18 and W19 and **only
ever as `const cq_bit *` controls**, which `cq_emit_*`'s signature makes structural
(Rule 8's first enforcement mechanism). The four `cq_mul_block`s inherit the same
guarantee from their own type — `mul.h`, *"`a` and `b` are CONTROLS ONLY, never
targets … neither can be materialised BY CONSTRUCTION"* — and that is what makes P2 and
P3 legal at all, since `a_hi` and `b_hi` are **views over `ma'`/`mb'`**, spans earlier
rows wrote. The five hand-off rows inherit the obligation and must be checked in
`9ve.19`, not here.

**I6(b) — every scratch bit is `CQ_BIT_Q` for the whole compute half. YES, and it is
the driver's doing.** `cq_sandwich` pre-materialises the whole region before step 0
(plan §0.2), at zero gates, because scratch is born `CQ_BIT_ZERO`. Three consequences
specific to K16:

- **No fold ever fires on a scratch bit**, so every gate whose controls are all scratch
  emits. That is what makes §3's slot arithmetic a function of `W` alone.
- **The folds that DO fire are exactly the constant-source ones** (§2.0 rule 3) and the
  view-vacated lanes. They are the same at every operand mask, forward and backward, so
  the palindrome is unaffected — **a constant-elided slot is still a slot.**
- **It is why §3.2's product masks are what they are.** `a_lo` is a pre-materialised
  scratch span, so its provably-zero lanes 26–63 are `CQ_BIT_Q` and fold nothing.

**The I6(a) extent must cover the views' *underlying* spans, and a view is not a
separate allocation.** `a_hi` is `ma'[26..63]` followed by 26 literal `CQ_BIT_ZERO`:
reading it as a control reads `ma'`, which is inside the extent. Nothing targets a view.
The reflex *"assert the operand arrays are disjoint objects"* is the trap K12.md §2.1a
records and would reject all twenty-three view rows, P3 and P4 among them — **guards
compare ranges, never base pointers.**

### 2.5 The step dispatch — a static prefix sum, NOT a division

K12's decode is `t = s / K(W)`, `j = s % K(W)`, because its compute half is `W`
identical iterations. **K16's compute half is straight-line: there is no iteration, so
there is no modulus.** The dispatch is

```
/* built once, at kernel entry, from the 122-row table of §2.2 */
static int off[123];        /* off[0] = 0; off[n+1] = off[n] + slots(row n) */

step(s):
    n = upper_bound(off, s) - 1      /* which row owns slot s */
    u = s - off[n]                   /* the row's own index    */
    dispatch on row n's block type:
        and/or/xor  -> emit directly, bit u / (gates per bit)
        eq | ne     -> cq_eq_step    (block_n, u)
        ult         -> cq_ult_step   (block_n, u)   [ + the trailing X for `<` ]
        add         -> cq_add_step   (block_n, u)   [ 9ve.30 — DOES NOT EXIST ]
        sub         -> cq_sub_step   (block_n, u)
        mux         -> cq_mux_step   (block_n, u)
        mul         -> cq_mul_step   (block_n, u)   [ M18 ]
        norm52      -> cq_norm52_step(block_n, u)   [ UNASSIGNED — §5.5 ]
        clz         -> cq_clz_step   (block_n, u)   [ M32 ]
        subnorm     -> cq_subnorm_step(block_n, u)  [ M32 ]
        round       -> cq_round_step (block_n, u)   [ M32 ]
```

**`off[]` must be a pure function of `W` and of nothing else** — the driver replays
indices in reverse and a table rebuilt from mutable state would desynchronise the
halves. Building it once at entry from `cq_mul_steps(64)`, `cq_eq_steps(64)`,
`cq_ult_steps(64)`, … (the *measurements*, never the literals) is what makes §3.0's
composition identity hold by construction rather than by coincidence.

**Four rows own 85% of the index space, and the binary search must not be "optimised"
because of it.** `4 · cq_mul_steps(64)` is 105,344 of roughly 123,425 slots, so a
cached cursor looks attractive — and a cursor is mutable state across steps, which the
previous paragraph forbids. The search is about seven comparisons over 123 entries per
step; that is noise beside the gate stream.

### 2.6 The slot-scan derivation

**What a K12-shaped kernel gets wrong is the slot arithmetic, not the gates**
(CLAUDE.md's callout, restated as PRD-v2 §7.1), and K16 is K12's shape with 122
boundaries instead of four. The instrument is K12's
`the_phase_boundaries_match_an_independent_slot_scan`: re-derive the **op KIND** of
every compute-half slot from the blocks' own structure and compare against the recorded
stream at the all-quantum operand mask. It records only which of `X` / `CX` / `CCX`
each slot emits — what a boundary error moves and what a gate-list error does not — so
it is not a second transcription of anything.

**TWO THINGS CHANGE FROM K12'S SCAN, AND BOTH ARE FORCED.**

**(1) THE KIND IS FOUR-VALUED.** K12's scan asserts `cq_mock_count(&m) == 2n + W` and
then walks `slot s ↔ stream index s`. That identity is **false for K16**, because §2.0
rule 3's constants and rule 2's vacated view lanes make some slots emit nothing and
demote others. The scan must predict `{NONE, X, CX, CCX}` per slot and walk the stream
with a separate cursor that advances only on non-`NONE`. A scan that keeps K12's 1:1
assumption goes red on row A3 and stays red; the reflex fix — deleting the constant
rows from the prediction — is what turns the instrument off. This is K18's D-K18-6 and
K15's §2.6 rider, and K16 is the third kernel to need it.

**(2) THE FOUR `mul` ROWS ARE PREDICTED AT THEIR BOUNDARIES AND DELEGATED IN THEIR
INTERIORS, AND THAT IS NOT LAZINESS.** Re-deriving `cq_mul_step`'s 26,336-slot schedule
inside K16's scan would be a **second transcription of K11** — the exact thing
CLAUDE.md says the scan must not be (*"it is not a second transcription of anything"*)
— and K11 already owns that assertion, in
`the_blocks_stream_is_the_kernels_forward_half_gate_for_gate`, which *"measures both in
one run and reads no golden"* (`K11.md` §7.3). So K16's scan asserts, per product `p`:

- the block's **extent** is `[off[P_p], off[P_p] + cq_mul_steps(64))`, with
  `cq_mul_steps` **called**, never written down;
- the kind at the block's **first** slot and its **last** slot;
- that the four extents are **disjoint and contiguous** in the order P1 … P4.

Everything an off-by-one at a `mul` boundary can do shows up in those three; everything
inside is K11's. **State this in the test file**, because a reader who finds the
interior unpredicted will otherwise "fix" it.

**The per-block op-kind sub-schedules**, each read out of its module's own K-doc and
none of them re-derived here:

```
/* K02 §2 — and: one CCX per bit. With a CONSTANT operand mask m: */
sched_and (W, m, v) = m[v] ? CX : NONE                  /* v in [0, W)   */
sched_and (W, ·, v) = CCX                               /* two quantum operands */

/* K03 §2 — or: three gates per bit, CX, CX, CCX. With a constant operand m: */
sched_or  (W, m, v) : i = v/3, j = v%3
    j==0 -> CX
    j==1 -> m[i] ? X   : NONE
    j==2 -> m[i] ? CX  : NONE

/* K01 §2 — xor: two CX per bit. With a constant operand m (this is `!x`): */
sched_xor (W, m, v) : i = v/2, j = v%2
    j==0 -> CX
    j==1 -> m[i] ? X : NONE

/* K09 §2.1 / §7 — eq/ne compute half, 5W-3 slots */
sched_eq  (W, v) = v < 2W ? CX : ((v-2W)%3 == 2 ? CCX : CX)

/* K09 §2.2 — ult compute half, 6W+1 slots (divrem's `sched_ult` verbatim) */
sched_ult (W, v) : v <  2W -> (v%2==0 ? CX : X)
                   v == 2W -> X
                   else    -> ((v-(2W+1))%4 < 2 ? CX : CCX)

/* K06 §2 — add compute half, 5W-2 slots */
sched_add (W, v) : v < 5(W-1) -> [CX,CX,CCX,CCX,CX][v%5]
                   else       -> CX

/* K07 / add.h — sub compute half, 7W-1 slots (divrem's `sched_sub` verbatim) */
sched_sub (W, v) : v <  2W -> (v%2==0 ? CX : X)
                   v == 2W -> X
                   else    -> u = v-(2W+1);
                              u >= 5(W-1) ? CX : ((u%5==2||u%5==3) ? CCX : CX)

/* K10 §2.1 — mux, 4 slots per bit */
sched_mux (v) = (v%4 == 3) ? CCX : CX

/* K11 §7 — mul: TWO-LEVEL, and the INTERIOR IS NOT RE-DERIVED HERE.
 * Block j is (W - j) phase-P Toffolis then cq_addacc_steps(W) accumulate
 * steps, so start(j) = j(7W-5) - j(j-1)/2 and the half is cq_mul_steps(W).
 * The accumulate's own kinds are K08's; ask M15, do not restate. */
```

**The top-level decode the scan re-derives** is the prefix sum over §2.2's table — **as
this document writes it**, with each row's length obtained by calling
`cq_mul_steps(64)`, `cq_eq_steps(64)`, `cq_ult_steps(64)`, `cq_sub_steps(64)`,
`cq_mux_steps(64)`, … and **never** by reading M34's own `off[]`. That is the
independence: the doc's table against the code's table.

**Three boundaries are worth a named case**, because an off-by-one there produces a
plausible gate rather than a crash: the **R15 ↔ S1 seam** (the last adder of the
assembly against the first masked extraction — the seam itself, so a slip there is also
a file-split slip); the **four P boundaries**, for the reason in the box above; and the
**S10 ↔ S11 boundary**, where the two extractions are near-identical 8-row groups and an
off-by-one can be absorbed by the second — K15 records the same hazard for its six
J-stage groups, and K16's version is two groups instead of six but with the same
absorbing structure.

   `ea != 0`, `ma` has bit 52 set and cannot be zero), and `fmul.jl:209` overrides with
   `zero_result` for exactly that input. **So the tpg0 guard is dead in `fmul`'s select
   chain and live in `fpconv`'s, where `_sf_normalize_to_bit52(UInt64(fa), Int64(1))` is
   called on a raw fraction.** Anchor 25 exists to say so; do not "simplify" the guard
   away on the strength of `fmul` alone.

### 5.6 The Cuccaro substitution applies FOUR times in one kernel

`mul.h`'s headline delta: *"multiplier.jl:29 calls the OUT-OF-PLACE ripple `lower_add!`,
and we substitute the IN-PLACE Cuccaro accumulator K8 (M15) into that slot."* Scratch
`W² + 2W` against ripple's `3W² + W` — **4,224 against 12,352 at `W = 64`** — plus `2W`
fewer Toffolis per product. Source-verified that upstream's `soft_fmul` takes the ripple
path: `_pick_mul_strategy(:auto, W)` returns `:shift_add` for every `W` under the
default `target=:gate_count` (`arith.jl:50-57`), and `:depth` is the only arm that
returns `:qcla_tree`.

**K16 is the first kernel in the catalogue where that delta is multiplied.** It is also
where its recorded price is paid four times over: *"K11's L4 golden is SELF-PINNED and
there is no published figure to reconcile it against"* (`mul.h`). §3.3's ancilla
reconciliation is not available for the same reason, and §4 says so rather than
producing a number.

**The Rule 7 objection to Cuccaro does not reach here either, and the argument is
`mul.h`'s one level up.** K8 is barred from K6/K7 because its uncompute is the reverse
circuit rather than a re-run. Inside a `cq_mul_block` the accumulator is internal —
created, used and destroyed inside one `cq_sandwich` compute half, never exposed to
`_unc`. K16 inherits that: CQ_lang's uncompute re-enters `cq_kernel_fmul` from the top
and gets `f ⊕ f = 0`.

### 5.y The classical short-circuit — a C transcription, and its cost is not optional here

Risk R9's short-circuit applies: all-classical operands never enter the sandwich and
`dst` is written as constants. **PRD-v2 §7.4 forbids computing those constants with the
host `double` operator**, on a measurement, and **four** of its five IEEE-unspecified
cells are reachable from `fmul` — one more than from `fadd`:

| cell | reached from | this box (x86_64) | the circuit |
|---|---|---|---|
| **`0 · Inf`** | `fmul.jl:210`'s `INDEF` arm | `fff8000000000000` | `INDEF` |
| `qNaN₁ × qNaN₂` | `fmul.jl:212` / `_sf_propagate_nan2` | the FIRST operand's payload | first operand |
| `qNaN × sNaN`, both orders | same | **the first operand, quietened** | quietened first operand |
| `sNaN × sNaN` | same | the first, quietened | same |

They agree **on this box** and would not on arm64. **So `cq_fmul_classical(uint64_t,
uint64_t)` is a C transcription of §1.1's Julia over `uint64_t`** — the same source,
evaluated on constants. Four riders:

- **This is the ONE place M34's L5 lives, and `K11.md` §7.4 says so.** *"There is no R9
  short-circuit in the block … that is where M34's own fold belongs: at `soft_fmul`'s
  entry, over the whole routine, not per block."* Without it, an all-classical `fmul`
  draws **25,088** qubits from the pool for an operation with no quantum input — the
  largest L5 violation available anywhere in the catalogue, ~46× K12 i8's whole peak.
- **L1's oracle stays INDEPENDENT**: the host `double` operator with the cells above
  **pinned by table as literals**, so the reference does not reuse the transcription.
- **`tests/support/`'s host probe** (PRD-v2 §7.4, bead `9ve.4`, `tests/support/fphost.c`)
  must be in place before anchors 16–19, or a host with FTZ/DAZ set fails them in the
  *oracle* rather than in the port. `fmul` is the kernel where that matters most:
  anchor 18 multiplies two subnormals, which DAZ flushes to zero on the way in.
- **`-ffp-contract=off`'s reason does not reach here**: the transcription is integer only
  and touches no `double`. The library's only contact with a C `double` in the fp surface
  is the `memcpy` at `cqrt_alloc_f64` / `cqrt_measure_f64` (PRD-v2 §3.1).

**Under a QUANTUM control L5's "zero gates, zero qubits" becomes false and that is the
correct answer.** The short-circuit still writes `dst` through `cq_emit_x`, whose
constant row cannot fire inside a promoted region, so each lane becomes a wire driven by
a real `CX`. K16 has 64 `dst` lanes, so at `CQ_KD_CTRL_Q0` with an all-classical mask the
claim to assert is that `live` grew by exactly the number of `dst` lanes that became
wires.

### 6.6 What this document is for

It WAS the specification `9ve.22` implemented against, and the composition check and the
slot scan were written from it before M34 existed — which is what §6.3 item 5 and item 1
are the payoff for: both were settled on paper and neither had to be re-derived under a
red test. It is now the specification PLUS the measurement, and §3.M, §4.M and §6.3 are
the parts that are true today. Everything else is the draft as written, kept so the two
can be compared. Read `bd ready` and the filesystem for status.
