### 1.1 `soft_fadd` — `fadd.jl:1-136`, verbatim

```julia
"""
    soft_fadd(a::UInt64, b::UInt64) -> UInt64

IEEE 754 double-precision addition on raw bit patterns.
Uses only integer operations. Bit-exact with hardware `+`.

Fully branchless: every path is computed unconditionally and results are
selected via `ifelse`. This ensures LLVM emits `select` instructions
(not `br`+`phi`), which is required for correct reversible circuit
compilation — branching causes false-path sensitization bugs in the
phi resolution algorithm.

Working format: mantissa shifted left by 3 for guard/round/sticky bits.
  bit 55 = implicit 1, bits 54-3 = 52-bit fraction, bits 2/1/0 = G/R/S.
"""
function soft_fadd(a::UInt64, b::UInt64)::UInt64
    SIGN_MASK = UInt64(0x8000000000000000)   # bit 63

    # ── Unpack ──
    sa = a >> 63
    ea = (a >> 52) & UInt64(0x7FF)
    fa = a & FRAC_MASK

    sb = b >> 63
    eb = (b >> 52) & UInt64(0x7FF)
    fb = b & FRAC_MASK

    # ── Special-case predicates (computed unconditionally) ──
    a_nan = (ea == UInt64(0x7FF)) & (fa != UInt64(0))
    b_nan = (eb == UInt64(0x7FF)) & (fb != UInt64(0))
    a_inf = (ea == UInt64(0x7FF)) & (fa == UInt64(0))
    b_inf = (eb == UInt64(0x7FF)) & (fb == UInt64(0))
    a_zero = (ea == UInt64(0)) & (fa == UInt64(0))
    b_zero = (eb == UInt64(0)) & (fb == UInt64(0))

    # ── Special-case results ──
    # NaN: any NaN input → propagate quietened operand (Bennett-r84x / U08).
    # Inf+Inf same sign → Inf; Inf-Inf → x86 indefinite (INDEF).
    inf_inf_result = ifelse(sa == sb, a, INDEF)
    # Inf + finite → Inf
    inf_finite_a = a   # a is Inf
    inf_finite_b = b   # b is Inf
    # Zero + Zero: same sign → keep sign, diff sign → +0
    zero_zero_result = ifelse(sa == sb, a, UInt64(0))

    # ── Order by magnitude: ensure |a| >= |b| ──
    a_mag = a & ~SIGN_MASK
    b_mag = b & ~SIGN_MASK
    swap = a_mag < b_mag

    sa_ord = ifelse(swap, sb, sa)
    sb_ord = ifelse(swap, sa, sb)
    ea_ord = ifelse(swap, eb, ea)
    eb_ord = ifelse(swap, ea, eb)
    fa_ord = ifelse(swap, fb, fa)
    fb_ord = ifelse(swap, fa, fb)

    # ── Implicit leading 1 for normal numbers ──
    ma = ifelse(ea_ord != UInt64(0), fa_ord | IMPLICIT, fa_ord)
    mb = ifelse(eb_ord != UInt64(0), fb_ord | IMPLICIT, fb_ord)

    # Effective exponents (subnormal: stored 0 → effective 1)
    ea_eff = ifelse(ea_ord != UInt64(0), ea_ord, UInt64(1))
    eb_eff = ifelse(eb_ord != UInt64(0), eb_ord, UInt64(1))
    d = ea_eff - eb_eff                        # >= 0 since |a| >= |b|

    # ── Working format: shift left by 3 for G/R/S room ──
    wa = ma << 3
    wb = mb << 3

    # ── Align: shift wb right by d, tracking sticky ──
    # Case 1: d >= 56 — everything shifts out, just sticky
    wb_large = ifelse(wb != UInt64(0), UInt64(1), UInt64(0))
    # Case 2: 0 < d < 56 — shift with sticky tracking
    # Clamp d to valid shift range for computing the mask (avoid UB at d=0 or d>=64)
    d_clamped = ifelse(d == UInt64(0), UInt64(1), ifelse(d >= UInt64(64), UInt64(63), d))
    lost_mask = (UInt64(1) << d_clamped) - UInt64(1)
    sticky = ifelse((wb & lost_mask) != UInt64(0), UInt64(1), UInt64(0))
    wb_mid = (wb >> d) | sticky
    # Case 3: d == 0 — no shift
    wb_aligned = ifelse(d >= UInt64(56), wb_large,
                 ifelse(d > UInt64(0),   wb_mid,
                                         wb))

    # ── Add AND subtract mantissas (both computed unconditionally) ──
    wr_add = wa + wb_aligned
    wr_sub = wa - wb_aligned

    same_sign = sa_ord == sb_ord
    wr_raw = ifelse(same_sign, wr_add, wr_sub)

    # Exact cancellation: subtraction yields zero → result is +0.0
    exact_cancel = (!same_sign) & (wr_sub == UInt64(0))

    result_sign = sa_ord

    # Use wr_raw for normalization (if exact_cancel, we'll override at the end)
    # Substitute 1 for zero to avoid undefined normalization behavior
    wr = ifelse(exact_cancel, UInt64(1), wr_raw)
    result_exp = Int64(ea_eff)

    # ── Normalize: overflow (bit 56 set from addition carry) ──
    overflow = (wr >> 56) != UInt64(0)
    lost_ov = wr & UInt64(1)
    wr_ov = (wr >> 1) | lost_ov                # preserve sticky in bit 0
    exp_ov = result_exp + Int64(1)
    wr = ifelse(overflow, wr_ov, wr)
    result_exp = ifelse(overflow, exp_ov, result_exp)

    # ── Normalize: underflow (leading 1 below bit 55) ──
    (wr, result_exp) = _sf_normalize_clz(wr, result_exp)

    # ── Handle subnormal result (exponent underflow) ──
    (wr, result_exp, flushed_result, subnormal, flush_to_zero) =
        _sf_handle_subnormal(wr, result_exp, result_sign)

    # ── Round to nearest even + pack ──
    (normal_result, overflow_result, exp_overflow, exp_overflow_after_round) =
        _sf_round_and_pack(wr, result_exp, result_sign)

    # ── Final select chain: priority order ──
    # NaN > Inf > Zero > Subnormal flush > Exp overflow > Normal
    result = normal_result
    result = ifelse(exp_overflow | exp_overflow_after_round, overflow_result, result)
    result = ifelse(subnormal & flush_to_zero, flushed_result, result)
    result = ifelse(exact_cancel, UInt64(0), result)
    result = ifelse(a_zero & b_zero, zero_zero_result, result)
    result = ifelse(b_zero & (!a_zero), a, result)
    result = ifelse(a_zero & (!b_zero), b, result)
    result = ifelse(a_inf & b_inf, inf_inf_result, result)
    result = ifelse(b_inf & (!a_inf), inf_finite_b, result)
    result = ifelse(a_inf & (!b_inf), inf_finite_a, result)
    result = ifelse(a_nan | b_nan, _sf_propagate_nan2(a, b, a_nan, b_nan), result)

    return result
end
```

### 1.2 `soft_fsub` — `fsub.jl:1-26`, verbatim — and `soft_fneg` — `fneg.jl:1-6`

```julia
"""
    soft_fsub(a::UInt64, b::UInt64) -> UInt64

IEEE 754 double-precision subtraction on raw bit patterns.

Implemented as `a + (-b)` via `soft_fadd` and `soft_fneg`, with a
guard for NaN operands: IEEE 754-2019 §6.2.3 requires NaN sign and
payload to propagate through arithmetic ops, but unconditionally
applying `soft_fneg` to a NaN operand would flip its sign bit before
`soft_fadd`'s NaN-input passthrough sees it.  The fix routes NaN-`b`
through `soft_fadd` unchanged so the propagated result preserves
the operand's original sign.

Bennett-r84x's NaN canonicalisation audit explicitly skipped fsub on
the assumption that fadd∘fneg would inherit correct NaN handling;
test_m63k_softfloat_strict_bits.jl Layer 2 caught the resulting
sign-flip on `normal − NaN`.
"""
function soft_fsub(a::UInt64, b::UInt64)::UInt64
    # NaN test: biased exponent all-ones AND fraction non-zero.
    ea_b = (b & EXP_MASK) >> 52
    fa_b =  b & FRAC_MASK
    b_is_nan = (ea_b == UInt64(0x7FF)) & (fa_b != UInt64(0))
    b_eff    = ifelse(b_is_nan, b, soft_fneg(b))
    return soft_fadd(a, b_eff)
end
```

    wr = ifelse(need32, wr << 32, wr)
    result_exp = ifelse(need32, result_exp - Int64(32), result_exp)

    need16 = (wr & (UInt64(0xFFFF) << 40)) == UInt64(0)
    wr = ifelse(need16, wr << 16, wr)

    wr = ifelse(need4, wr << 4, wr)

@inline function _sf_handle_subnormal(wr::UInt64, result_exp::Int64, result_sign::UInt64)
    subnormal = result_exp <= Int64(0)
    shift_sub = Int64(1) - result_exp
    flush_to_zero = shift_sub >= Int64(56)
    shift_clamped = clamp(shift_sub, Int64(0), Int64(63))
    shift_u = UInt64(ifelse(flush_to_zero, Int64(0), shift_clamped))
    lost_mask_sub = (UInt64(1) << shift_u) - UInt64(1)
    lost_sub = ifelse((wr & lost_mask_sub) != UInt64(0), UInt64(1), UInt64(0))
    wr_sub_result = (wr >> shift_u) | lost_sub
    flushed_result = result_sign << 63

    wr = ifelse(subnormal,
         ifelse(flush_to_zero, wr, wr_sub_result),
         wr)
    result_exp = ifelse(subnormal, Int64(0), result_exp)

    return (wr, result_exp, flushed_result, subnormal, flush_to_zero)
end

```julia
@inline function _sf_round_and_pack(wr::UInt64, result_exp::Int64, result_sign::UInt64)
    # Overflow check
    exp_overflow = result_exp >= Int64(0x7FF)
    overflow_result = (result_sign << 63) | INF_BITS

    # Round to nearest even
    guard      = (wr >> 2) & UInt64(1)
    round_bit  = (wr >> 1) & UInt64(1)
    sticky_bit = wr & UInt64(1)
    frac       = (wr >> 3) & FRAC_MASK

    grs = (guard << 2) | (round_bit << 1) | sticky_bit
    round_up = (grs > UInt64(4)) | ((grs == UInt64(4)) & ((frac & UInt64(1)) != UInt64(0)))

    frac_rounded = frac + UInt64(1)
    mant_overflow = frac_rounded == IMPLICIT
    frac_final = ifelse(round_up,
                 ifelse(mant_overflow, UInt64(0), frac_rounded),
                 frac)
    exp_after_round = ifelse(round_up & mant_overflow,
                             result_exp + Int64(1),
                             result_exp)
    exp_overflow_after_round = exp_after_round >= Int64(0x7FF)

    # Pack normal result
    exp_pack = UInt64(clamp(exp_after_round, Int64(0), Int64(0x7FE)))
    normal_result = (result_sign << 63) | (exp_pack << 52) | frac_final

    return (normal_result, overflow_result, exp_overflow, exp_overflow_after_round)
end
```

### 1.4 What `fsub` does that `fadd(a, fneg(b))` would not — the `Bennett-m63k` fix, FOUND AND QUOTED

**PRD-v2 §5's M33 row says *"Do not spell `fsub` as `fadd(a, fneg(b))` — upstream
fixed a NaN-RHS sign bug in exactly that composition (`Bennett-m63k`)"*. The
snapshot carries that fix and says so in its own words.** It is `fsub.jl:6-17`,
quoted verbatim in §1.2 above, and the operative sentences are:

> *"unconditionally applying `soft_fneg` to a NaN operand would flip its sign bit
> before `soft_fadd`'s NaN-input passthrough sees it. The fix routes NaN-`b`
> through `soft_fadd` unchanged so the propagated result preserves the operand's
> original sign."* — `fsub.jl:8-12`

and the provenance, which names both beads and the test that caught it:

> *"Bennett-r84x's NaN canonicalisation audit explicitly skipped fsub on the
> assumption that fadd∘fneg would inherit correct NaN handling;
> test_m63k_softfloat_strict_bits.jl Layer 2 caught the resulting sign-flip on
> `normal − NaN`."* — `fsub.jl:14-17`

**The precise delta, stated as a circuit obligation rather than as prose.**
`soft_fsub` is **not** `soft_fadd(a, soft_fneg(b))`. It is

```
soft_fsub(a, b) = soft_fadd(a, ifelse(b_is_nan, b, soft_fneg(b)))
```

with `b_is_nan` recomputed from `b` (`fsub.jl:21-23`) — so `b_eff` is `b` **unchanged**
when `b` is a NaN, and `b ⊻ SIGN_MASK` otherwise. The bug the guard prevents is
visible in `soft_fadd`'s own final select chain: `fadd.jl:133` hands
`_sf_propagate_nan2(a, b, a_nan, b_nan)` its **`b` argument**, and
`_sf_propagate_nan2` returns `b | QUIET_BIT` (`softfloat_common.jl:24`) —
*"Preserves sign and payload"* (`softfloat_common.jl:20`). Without the guard the
`b` reaching that line is already sign-flipped, so `normal − NaN` returns the NaN
with the wrong sign bit. IEEE 754-2019 §6.2.3 requires the payload **and the sign**
to propagate.

**Three consequences for M33, all of them structural:**

1. **`fsub` is a WRAPPER over `fadd`'s compute half, not a second kernel and not a
   sign flip at the call site.** §2.2's table gains a seven-row prologue (§3.2) and
   nothing else changes. Anything that flips `b`'s sign before the prologue — a
   `_controlled` variant, a caller-side `fneg`, an M38 `soft_fneg` call spliced in —
   reintroduces exactly `Bennett-m63k`.
2. **The guard recomputes the NaN test from `b` and does NOT share `fadd`'s `eb`/`fb`.**
   `fsub.jl:21` spells it `(b & EXP_MASK) >> 52` where `fadd.jl:25` spells the same
   value `(b >> 52) & 0x7FF`. Under PRD-v2 §7.2's literal grain those are **two
   different operator sequences** and both are transcribed. Sharing them is CSE.
3. **`soft_fneg` on a 64-bit span is a block, not wiring.** `a ⊻ SIGN_MASK`
   (`fneg.jl:6`) changes a value rather than a label, so it needs a fresh span:
   64 slots (K01's two-gates-per-bit XOR against a constant operand), of which
   63 lanes emit one `CX` and lane 63 emits `CX` then `X`. See §2.0 rule 1.

**Nothing in `fsub.jl` is unreachable for us, and the guard is not an
optimisation.** It costs the five rows of §3.2 and it is the difference between a
bit-exact `fsub` and one that is wrong on exactly the inputs PRD-v2 §7.12's anchor
list forces into every L1 draw.

### 2.0 Grain, spans, and the three representation rules

**Grain is LITERAL, per PRD-v2 §7.2** — *"One block per operator occurrence as the
source spells it; every intermediate a 64-bit span (the Julia type's width); no
common-subexpression sharing; no narrowing towards the field width."* Three readings
of that sentence are fixed here because §2.2 is unreadable without them:

- **"the Julia type's width" is the DECLARED type, so a `Bool` is ONE bit and a
  `UInt64`/`Int64` is SIXTY-FOUR.** `a_nan`, `swap`, `same_sign`, `overflow`,
  `subnormal`, `need32`… are `Bool` and get one-bit spans; `sa`, `ea`, `d`, `wr`,
  `result_exp` are 64-bit spans even though `sa` can only ever be 0 or 1 and `ea`
  is eleven bits. That is exactly PRD-v2 §7.2's *"no narrowing towards the field
  width"*, and it is what makes every `ifelse(Bool, UInt64, UInt64)` land on
  `cq_mux_block` **unchanged** — `cond` one bit, arms `W` bits, which is M17's
  declared shape (`mux.h`, *"one bit; only `cond[0]` is read"*).
- **`Int64` and `UInt64` are the same 64 `cq_bit`s.** `Int64(ea_eff)` (`fadd.jl:100`)
  and `UInt64(...)` (`softfloat_common.jl:179`) are reinterprets: **wiring**, zero
  gates, zero qubits. What changes is which comparator the *next* row uses — signed
  rows go to M16's `slt` block, unsigned rows to its `ult` block. Getting that wrong
  is K9's `uge`-meaning-`ule` trap in a new costume and **only L1 sees it**.
- **No CSE means no CSE, including across the two `ifelse` arms of one line.**
  §5.1 lists the seven repeated subexpressions this produces; PRD-v2 §7.2 names one
  of them.

**Three representation rules decide, for each operator occurrence, whether it is a
block, a view, or nothing.** They are the whole of the difference between a 42k-slot
compute half and a 100k one, and each is a decision with a named authority:

1. **A block** — anything that computes a new value. Every `+ - & | ⊻ ~ == != < <= >
   >=` and every `ifelse`, and the variable-amount shifts. It targets a fresh scratch
   span and its gates are the owning module's step function.
2. **A view — zero gates, zero qubits** — a **constant-amount** shift and a
   reinterpret. K12.md §2.1's precedent is exact: *"The left shift is therefore a
   relabelling of `cq_bit` array entries and costs zero gates and zero qubits (Rule 3
   — a `cq_bit` is a value, not a wire)."* The step function assembles a 64-entry
   local `cq_bit` array holding the source span's entries at the shifted positions and
   `CQ_BIT_ZERO` at the vacated ones, and hands that to the consuming block. Three
   riders, all load-bearing:
   - **It must be rebuilt from the step index on every call** and never carried in
     mutable state — the driver replays indices in reverse (K12.md §2.1, *"must be
     recomputed from `t`, never carried in mutable state"*).
   - **It is sound because a scratch span's `cq_bit` entries never change kind
     mid-half.** I6(b) pre-materialises the whole region at step 0, and I6 forbids
     materialising a source inside a compute half, so a copied `cq_bit` value cannot
     go stale.
   - **The vacated lanes are literal `CQ_BIT_ZERO`, not scratch qubits, and that is
     the one place this departs from K12's `r0_hi`.** K12 made its zero-fill a real
     scratch register because *"as literals they would fold, iteration `t = 0` would
     stop costing what every other iteration costs, and the slot decode would need a
     `t = 0` branch"* (K12.md §2.1) — a **loop-uniformity** argument. K15's compute
     half is straight-line: there is no iteration for a fold to make non-uniform, and
     the fold is a function of the constant alone, so it is identical at every
     operand mask. The cost is that **slot index is not stream index** (§2.6).
3. **A constant is a SOURCE, never scratch** — PRD-v2 §7.3, verbatim: *"We pass them
   as `const cq_bit` arrays of `CQ_BIT_ZERO`/`CQ_BIT_ONE` and the §3 fold table elides
   every gate they control."* `SIGN_MASK`, `~SIGN_MASK`, `FRAC_MASK`, `IMPLICIT`,
   `INDEF`, `QUIET_BIT`, `0x7FF`, `0`, `1`, `56`, `63`, `64`, `0x7FE`, `INF_BITS` and
   the six CLZ masks are file-static `cq_bit[64]` tables. They cost **zero qubits**.

> **RULE 2 AND RULE 3 DISAGREE ABOUT `a & FRAC_MASK`, AND THIS DOCUMENT FOLLOWS
> RULE 3 BECAUSE PRD-v2 §7.3 IS THE AUTHORITY — BUT THE DISAGREEMENT IS REAL AND
> 9ve.21 SHOULD NOT DISCOVER IT IN CODE.** A mask by a *constant* is, bit for bit, a
> relabel: lane `i` of `a & FRAC_MASK` is `a[i]` where the mask bit is 1 and
> `CQ_BIT_ZERO` where it is 0 — the same kind of thing a constant shift is, and a view
> would cost nothing. PRD-v2 §7.3's own worked example costs it as a block instead:
> *"`a & ~SIGN_MASK` costs zero gates and zero qubits on classical lanes and **one CX
> per quantum lane**."* §2.2 follows the PRD. The delta is not small — 15 AND rows at
> 64 bits, 960 slots and 960 scratch qubits — and it is a **PRD amendment**, not a
> kernel choice, so it belongs in §7.3 or nowhere.

**Constants make the fold table fire deterministically, and that is the structural
novelty against K12.** Every v1 kernel's compute half has `n_compute` slots that each
emit exactly one gate at the all-quantum operand mask, because under I6(b) every
scratch bit is `CQ_BIT_Q` and the only classical things in sight are *operand* bits.
K15 has constants everywhere, so a slot whose only control is a constant `CQ_BIT_ZERO`
emits **nothing**, and one whose control is `CQ_BIT_ONE` emits a **demoted** gate
(`CCX → CX`, `CX → X`). This is not mask-dependence — a constant is constant at every
operand mask — but it does mean **slots ≠ gates**, permanently, and §2.6 and §3 both
turn on it.

`const cq_bit[64]` constant source (rule 3). Every `ifelse` row names its `cond` first.
Where a compare's *raw* flag has the wrong sense the row carries `+1`, one `X` on the
block's own flag bit, which is scratch and therefore I6(a)-legal and self-inverse.

**`==` is `C_eq(W) + 1` and `!=` is `C_eq(W)`.** The eq/ne block's raw flag holds
`a != b` (K09 §2.1, *"raw flag (holds a != b)"*), so `!=` reads it directly and `==`
flips it in place. The same asymmetry runs the other way for the comparators: the
`ult`-family raw flag holds `a >=u b` (K09 §2.2) and the `slt`-family raw flag holds
`a >=s b` (K09 §2.3), so `>=` and `<=` are free and `<` and `>` cost the `+1`.

> ### ═══ RULE 12 SPLIT SEAM — **ALIGN ↔ ADD-AND-NORMALISE** ═══
>
> **The seam is between `fadd.jl:83` and `fadd.jl:86`: rows A1–G17 above, rows H1–M26
> below.** PRD-v2 §5 records it in advance — *"The exponent-difference shift is the
> half that is `O(W)` in its own right and is the half `fma` reuses"* — and the
> structural facts that make it the right cut, rather than the convenient one, are:
> (i) **everything crossing the seam is named**: `wa`, `wb_aligned`, `sa_ord`,
> `sb_ord`, `ea_eff`, plus the six class flags `a_nan … b_zero` and the two
> special-case results, which the final select chain reads and nothing in between
> touches; (ii) the ALIGN half is the only half containing a **barrel**, so D8 lives
> entirely on one side of the cut (§5.3); and (iii) it is the half **M39 `fma`
> reuses** (PRD-v2 §5's M39 row), so exporting it is owed to a module that does not
> exist yet and the export shape has to survive that. **`fsub`'s prologue (§3.2)
> attaches ABOVE this seam**, at row A0, not below it.
>
> Suggested file split when M33 crosses 300 lines: `src/kernels/fadd_align.c`
> (A–G, plus the block-offset table for those rows) and `src/kernels/fadd.c`
> (H–M, the step dispatch and the Rule 7 entry points). The **prefix-sum table stays
> in one place**, because two tables is two chances to get §2.5 wrong.

### 2.4 I6(a) and I6(b)

**I6(a) — every compute-half gate target a kernel names is scratch. YES, by
construction and not by inspection.** Every row of §2.2 is either a view (emits
nothing) or a block whose targets are the block's own vectors, laid inside K15's one
scratch region. `a` and `b` — the two rails — appear in rows A1–A8, C3, C4, D1, D2,
M10, M13, M18, M21, M23, M24 and **only ever as `const cq_bit *` controls**, which
`cq_emit_*`'s signature makes structural (Rule 8's first enforcement mechanism). The
constant tables are `const` for the same reason and could not be targets if someone
wanted them to be. The one row that is not M33's own gates — L1, M32's — inherits the
obligation and must be checked in `9ve.19`, not here.

**I6(b) — every scratch bit is `CQ_BIT_Q` for the whole compute half. YES, and it is
the driver's doing.** `cq_sandwich` pre-materialises the whole region before step 0
(plan §0.2), at zero gates, because scratch is born `CQ_BIT_ZERO`. Two consequences
specific to K15:

- **No fold ever fires on a scratch bit**, so every gate whose controls are all
  scratch emits. That is what makes §3's slot arithmetic a function of `W` alone.
- **The folds that DO fire are exactly the constant-source ones** (§2.0 rule 3), and
  they are the same at every operand mask. `wb_large`'s mux (G2) reads two constant
  arms, `fa`'s mask (A4) reads `KFRAC` — those elide, always, identically, forward and
  backward. **A constant-elided slot is still a slot**: the driver visits it in both
  directions and it emits nothing in both, so the palindrome is unaffected.

**The I6(a) extent must cover the views' *underlying* spans, and a view is not a
separate allocation.** `wa` is `[K0,K0,K0] ++ ma[0..60]`: reading it as a control
reads `ma`, which is inside the extent. Nothing targets a view. The reflex "assert the
operand arrays are disjoint objects" is the trap K12.md §2.1a records and would reject
all twenty view rows — **guards compare ranges, never base pointers**.

### 2.5 The step dispatch — a static prefix sum, NOT a division

K12's decode is `t = s / K(W)`, `j = s % K(W)`, because its compute half is `W`
identical iterations. **K15's compute half is straight-line: there is no iteration, so
there is no modulus.** The dispatch is

```
/* built once, at kernel entry, from the 172-row table of §2.2 */
static int off[173];        /* off[0] = 0; off[n+1] = off[n] + slots(row n) */

step(s):
    n = upper_bound(off, s) - 1      /* which row owns slot s */
    u = s - off[n]                   /* the row's own index    */
    dispatch on row n's block type:
        and/or/xor  -> emit directly, bit u / (gates per bit)
        eq | ne     -> cq_eq_step   (block_n, u)
        ult family  -> cq_ult_step  (block_n, u)      [ + the trailing X for `<`/`>` ]
        slt family  -> cq_slt_step  (block_n, u)      [ + the trailing X for `<`/`>` ]
        add         -> cq_add_step  (block_n, u)
        sub         -> cq_sub_step  (block_n, u)
        mux         -> cq_mux_step  (block_n, u)
        barrel      -> cq_barrel_step(block_n, u)
        round       -> cq_round_step(block_n, u)      [ M32 ]
```

**`off[]` must be a pure function of `W` and of nothing else** — the driver replays
indices in reverse and a table rebuilt from mutable state would desynchronise the
halves. Building it once at entry from `cq_ult_steps(64)`, `cq_sub_steps(64)`, … (the
*measurements*, never the literals) is what makes §3.0's composition identity hold by
construction rather than by coincidence.

**`upper_bound` is a binary search over 173 entries per step, run ~42,000 times per
compute half and twice per call.** That is ~700k comparisons per `fadd`, which is
noise beside the gate stream but is worth knowing before someone "optimises" it into a
cached cursor — a cursor is mutable state across steps and is the exact hazard the
previous paragraph forbids.

### 2.6 The slot-scan derivation

**What a K12-shaped kernel gets wrong is the slot arithmetic, not the gates**
(CLAUDE.md's callout), and K15 is K12's shape with 172 boundaries instead of four. The
instrument is K12's `the_phase_boundaries_match_an_independent_slot_scan`: re-derive
the **op KIND** of every compute-half slot from the blocks' own structure, and compare
against the recorded stream at the all-quantum operand mask. It records only which of
`X` / `CX` / `CCX` each slot emits — what a boundary error moves and what a gate-list
error does not — so it is not a second transcription of anything.

**ONE THING CHANGES FROM K12'S SCAN AND IT IS NOT OPTIONAL: THE KIND IS
FOUR-VALUED.** K12's scan asserts `cq_mock_count(&m) == 2n + W` and then walks
`slot s ↔ stream index s`. That identity is **false for K15**, because §2.0 rule 3's
constants make some slots emit nothing and demote others. The scan must predict
`{NONE, X, CX, CCX}` per slot and walk the stream with a separate cursor that advances
only on non-`NONE`. A scan that keeps K12's 1:1 assumption will go red on row A3 and
stay red, and the reflex fix — deleting the constant rows from the prediction — is what
turns the instrument off.

**The per-block op-kind sub-schedules**, each read out of its module's own K-doc and
none of them re-derived here:

```
/* K02 §2 — and: one CCX per bit. With a CONSTANT operand mask m: */
sched_and (W, m, v) = m[v] ? CX : NONE                  /* v in [0, W)   */
sched_and (W, ·, v) = CCX                               /* two quantum operands */

/* K03 §2 — or: three gates per bit, CX, CX, CCX. With a constant operand m: */
sched_or  (W, m, v) : i = v/3, j = v%3
    j==0 -> CX
    j==1 -> m[i] ? X   : NONE
    j==2 -> m[i] ? CX  : NONE

/* K01 §2 — xor: two CX per bit. With a constant operand m (this is `!x`): */
sched_xor (W, m, v) : i = v/2, j = v%2
    j==0 -> CX
    j==1 -> m[i] ? X : NONE

/* K09 §2.1 — eq/ne compute half, 5W-3 slots */
sched_eq  (W, v) = v < 2W ? CX : ((v-2W)%3 == 2 ? CCX : CX)

/* K09 §2.2 — ult compute half, 6W+1 slots (this is divrem's `sched_ult` verbatim) */
sched_ult (W, v) : v <  2W -> (v%2==0 ? CX : X)
                   v == 2W -> X
                   else    -> ((v-(2W+1))%4 < 2 ? CX : CCX)

/* K09 §2.3 — slt compute half, 8W+3 slots */
sched_slt (W, v) : v <  2W       -> CX                   /* af then bf, both CX */
                   v in {2W,2W+1}-> X
                   else          -> sched_ult(W, v-(2W+2))

/* K06 §2 — add compute half, 5W-2 slots */
sched_add (W, v) : v < 5(W-1) -> [CX,CX,CCX,CCX,CX][v%5]
                   else       -> CX

/* K07 / add.h — sub compute half, 7W-1 slots (divrem's `sched_sub` verbatim) */
sched_sub (W, v) : v <  2W -> (v%2==0 ? CX : X)
                   v == 2W -> X
                   else    -> u = v-(2W+1);
                              u >= 5(W-1) ? CX : ((u%5==2||u%5==3) ? CCX : CX)

/* K10 §2.1 — mux, 4 slots per bit */
sched_mux (v) = (v%4 == 3) ? CCX : CX

/* K10 §2.2 — barrel shl/lshr, W + sum_k[(W - 2^k) + 4W] slots, L = ceil(log2 W) */
sched_barrel(W, L, v) : v < W -> CX                       /* INIT */
                        else, per stage k: (W - 2^k) CX   /* SHIFT */
                                           then 4W slots sched_mux /* MUX */
```

**The top-level decode the scan re-derives** is the prefix sum over §2.2's table —
**as this document writes it**, with each row's length obtained by calling
`cq_ult_steps(64)`, `cq_sub_steps(64)`, `cq_mux_steps(64)`, … and **never** by reading
M33's own `off[]`. That is the independence: the doc's table against the code's table,
which is the same relation §3.4's composition check has, and it is what makes the scan
worth writing. A scan that reads `off[]` proves the array is self-consistent and
nothing else.

**Three boundaries are the ones worth a named case**, because an off-by-one there
produces a plausible gate rather than a crash: the G17 ↔ H1 seam (the last mux of ALIGN
against the first CX of the adder — both `CX`, so only the *operands* differ and only
L1 sees it); the six J-stage boundaries (six identical groups in a row, the one place
K15 has a repeating structure and therefore the one place an off-by-one can be absorbed
by the next group); and the L1 hand-off, where M33's slot space ends and M32's begins.

| `qNaN + sNaN`, both orders | same | the qNaN, no signalling priority | quietened operand, upstream's priority |

They agree **on this box** and would not on arm64, so a host-operator short-circuit
gives a program whose classical mode and quantum mode return different bits on the same
input, on some hosts only. **So `cq_fadd_classical(uint64_t, uint64_t)` is a C
transcription of §1.1's Julia over `uint64_t`** — the same source, evaluated on
constants — and `cq_fsub_classical` is §1.2's. Four riders:

- **`-ffp-contract=off`'s reason does not reach here**: the transcription is integer
  only and touches no `double`. The library's only contact with a C `double` in the fp
  surface is the `memcpy` at `cqrt_alloc_f64` / `cqrt_measure_f64` (PRD-v2 §3.1).
- **L1's oracle stays INDEPENDENT**: it is the host `double` operator with the three
  cells above **pinned by table as literals**, so the reference does not reuse the
  transcription. An oracle sharing code with the implementation is blind to what that
  code gets wrong.
- **`tests/support/`'s host probe** (PRD-v2 §7.4) — round-to-nearest, FTZ/DAZ off —
  must be in place before the subnormal anchors 15, 28 and 29, or a host with FTZ set
  fails them in the *oracle* rather than in the port.
- **Cost: ~60 lines**, one per named intermediate group, and L1 checks it against the
  circuit on every mixed-mask case.

### 6.5 Ranked risks

1. **THE SLOT ARITHMETIC — 172 boundaries where K12 has four.** The instrument is
   §2.6's slot scan and it is the single most important thing `9ve.21` writes, before
   the kernel. Two specific hazards inside it: the scan's op kind must be
   **four-valued** (a constant-folded slot emits nothing, so slot index is not stream
   index — the assumption K12's scan is built on and the reflex a reader will carry
   over), and the six J-stage groups are the one repeating structure in K15, so an
   off-by-one there can be absorbed by the next group and produce a plausible gate
   rather than a crash.
2. **THE BARREL'S D8 BEHAVIOUR AT `d ≥ 64`.** §5.3 audits it as DISCARDED, and the
   discard is itself a transcribed select (rows G14, G17). If that select is mis-wired
   the divergence goes live, and the audit's own conclusion is what stops anyone
   looking. The only detectors are anchors 18 and 19 — and note that the snapshot
   contradicts itself about what Julia even does for `d ≥ 64` (§5.3's box), so
   "check it against the source" is not available as a fallback.
3. **THE G/R/S HAND-OFF TO M32.** `fadd.jl:13-14`'s working format — implicit 1 at bit
   55, fraction 54–3, G/R/S at 2/1/0 — is a contract between M33 and M32 that **no C
   type expresses**. A one-bit disagreement is right on every input that does not round
   and wrong on the ties, so L1's 32 random samples reach it essentially never and only
   anchors 24–26 and 29 see it. It also crosses a bead boundary (`9ve.19` ↔ `9ve.21`),
   which is where contracts go to be assumed.
4. **THE FOUR MISSING STEP EXPORTS (§5.7).** Two of them — the out-of-place `add` and
   the signed compare — are not named in PRD-v2 §7.10, so an implementer reading only
   the PRD will discover them mid-kernel and be tempted by the two substitutions that
   are silently wrong: K8's accumulator for K6 (a correct forward and a wrong `_unc` —
   a miscompile, not a test failure), and the unsigned comparator for the signed one
   (wrong for every negative `result_exp`, invisible to everything but L1).
5. **THE TWO ORPHANED SHARED HELPERS (§5.4).** Unassigned, they get transcribed four
   times. Deciding them changes K15's row count by a factor of three, so it has to be
   decided **before** `9ve.21` starts, in PRD-v2 §5.
6. **`clamp` IS NOT A PORT (§1.5, §5.6).** Small, unambiguous, and the one line of
   K15 that Rule 1 does not cover. It needs a decision, not an implementer's judgement.
7. **THE §7.3 vs K12 DISAGREEMENT ABOUT CONSTANT MASKS (§2.0's box).** Worth 960 slots
   and 960 qubits, resolvable only in PRD-v2 §7.3, and easy to settle silently in code
   in either direction.
8. **R11's pool ceiling.** 21.3k qubits is ~40× K12 at i8 and D2/D20's ceiling is
   hard. The behaviour is already decided (PRD-v2 §4's R11, D25) and the live
   prohibition is that **neither the shim nor M33 may grow its own "that will not fit"
   check**. Listed last because it is a known disposition, not an open question.
