# K25 — IEEE binary64 round-to-integral: `trunc`, `floor`, `ceil`, `rint`/`nearbyint`, `round` (`f64`)

**Module** M38b — `src/kernels/fround*.{h,c,inc}`, the second half of PRD-v2 §5's
M38 `fmisc` row (the sign ops and `fmin`/`fmax` are M38a, K24).
**Bead** `opcode_quantum_operations-9ve.27.2` (parent `9ve.27`). **Upstream**
Bennett.jl at the pinned commit in `third_party/bennett/COMMIT`, file
`third_party/bennett/src/softfloat/fround.jl`.

K25 ports five Julia bodies as five UNARY Rule 7 kernels at `W = 64`. It ships no
`cqrt_*`/`cq_template_*` wiring: that is a later ABI bead, which must take the
name mapping from §1.2 below and not guess it.

**Four things in this document are load-bearing.** (1) **The name mapping is not
identity** (§1.2) — C `round` is `soft_round_away`, and `rint`/`nearbyint` are
`soft_round`. (2) **`soft_floor` and `soft_ceil` call `soft_fadd`**, which is
M33's; this module reaches it through `cq_fadd_block`, an export added to M33
by this bead as `cq_fsub_block`'s exact twin (§5.1). (3) **Every `Int64` compare is `slt`**, and at the three `clamp`
sites that is not a style choice but the difference between a correct barrel
amount and a wrapped one (§2.0 D-K25-3). (4) **Slots and gates come apart**, as
in every fp module since M31: every composition identity is over SLOTS.

## 1. Julia source excerpt

Five functions, one file, all at the pinned commit.

```julia

    exp = Int64((a >> 52) & UInt64(0x7ff))                      # :18
    is_special = exp == Int64(0x7ff)                            # :26
    is_nan_input = is_special & ((a & FRAC_MASK) != UInt64(0))  # :27
    special_result = ifelse(is_nan_input, a | QUIET_BIT, a)     # :28
    is_small = exp < Int64(1023)                                # :30
    is_integer = exp >= Int64(1075)                             # :32
    frac_bits = Int64(1075) - exp                               # :35
    frac_bits_clamped = clamp(frac_bits, Int64(0), Int64(52))   # :37
    mask = ~((UInt64(1) << frac_bits_clamped) - UInt64(1))      # :39

             ifelse(is_integer, a, normal_result)))
```

`soft_round` and `soft_round_away` are quoted in full in the pinned file; the
rows of §2.3 cite every line. `soft_round_away`'s own docstring (`:222-229`)
states the two places it differs from `soft_round`: the exactly-half arm is
folded into one `exp == 1022` predicate (`:254`), and `round_up` is
`round_bit == 1` alone (`:274`).

### 1.1 The constants

`softfloat_common.jl:8-14`: `FRAC_MASK`, `IMPLICIT`, `QUIET_BIT` (and
`SIGN_MASK`-shaped literals written inline). `FRAC_MASK`, `0x7ff`, the sign mask,
`0x7FFF…` and `& 1` are **view masks** (PRD-v2 §7.3 as amended) — wiring, no
row cost. The thirteen operand codes that ARE sources are listed in
`src/kernels/fround.h` (`CQ_FI_*`); two of them are **constant-folded
expressions over literals**: `reinterpret(UInt64, 1.0)` (`:92`, `:159`, `:255`)
and `one_bits | UInt64(0x8000000000000000)` (`:69-70`) — K15 §2.0 rule 3 and
K20's `~SIGN_MASK`: an operator whose every operand is a literal is a constant,
not a row.

### 1.2 The LLVM-name → `soft_*` mapping (PRD-v2 §7.7), for the ABI bead

| C / LLVM | `soft_*` | kernel | rounding |
|---|---|---|---|
| `trunc` | `soft_trunc` | `cq_kernel_ftrunc` | toward zero |
| `floor` | `soft_floor` | `cq_kernel_ffloor` | toward −∞ |
| `ceil` | `soft_ceil` | `cq_kernel_fceil` | toward +∞ |
| `rint`, `nearbyint` | **`soft_round`** | `cq_kernel_fround_even` | nearest, ties to EVEN |
| `round` | **`soft_round_away`** | `cq_kernel_fround_away` | nearest, ties AWAY |

There is no `soft_rint`. Julia's `round` is ties-to-even and C's is ties-away,
so pairing C `round` with `soft_round` is the K9 trap in fp dress: right on every
input that is not an exact `N.5`. `the_name_mapping_separates_on_every_tie`
pins both kernels on 0.5, −0.5, 1.5, 2.5, −2.5 and 3.5 as literals, and the
circuit anchors of both kernels include the ties (§6.2). `lrint`/`llrint` stay
aborts (PRD-v2 §7.9).

## 2. Gate sequence as an indexed row table

### 2.0 Decisions the transcription rests on

- **D-K25-1 — literal grain (§7.2).** One row per operator occurrence, 64-lane
  spans for every `UInt64`/`Int64`, one-bit spans for every `Bool`, no CSE:
  `soft_round`'s `abs_a & FRAC_MASK` is written four times (`:148`, `:155`,
  `:158`, `:171`) and is four views; `exp == 1022` is computed twice (`:155`,
  `:158`) and is two `eq` rows.
- **D-K25-2 — the raw-wire convention (K09 §5 delta 2).** `cq_eq_flag` is `a != b`
  and `cq_slt_block`'s `carry[W]` is `a >=s b`; so `!=` and `>=` read the raw
  wire and every `==` and `<` (and the clamp's `>`) owes one `lower_not1!`.
  `(round_bit == 1)` and `(lsb_after_trunc == 1)` are `eq` + `not1` each — the
  grain reads the operator, not what a 0/1 value means.
- **D-K25-3 — every `Int64` compare is `slt` (§7.6's two signednesses).**
  `exp < 1023`, `exp < 1022` and `exp >= 1075` are on a value provably in
  `[0, 2047]`, where `ult` gives the same bit — a RECORDED EQUIVALENT MUTANT that
  L4 sees and L1 does not (`cq_slt_steps(64) = 515 > cq_ult_steps(64) = 385`).
  The clamp's four compares are on `1075 - exp`, NEGATIVE for every `exp > 1075`;
  there `ult` reads −972 as `2^64 − 972`, the clamp picks the upper bound, and
  every NaN/Inf/huge input reaches the barrel with the wrong amount. Only the
  selected branch hides that (the `is_integer`/`is_special` arms discard
  `normal_result`), so L1 cannot see it either; the census (four `slt` per
  program) and the composition identity can.
- **D-K25-4 — `clamp` is D-K23-5's reading, verbatim.** `Base.clamp`'s body is not
  in the snapshot; M32 ships `ifelse(x < lo, lo, ifelse(x > hi, hi, x))` as the
  six rows `slt(x, lo)`, `not1`, `slt(hi, x)`, `not1`, `mux(hi)`, `mux(lo)`.
  K25 copies the order at all three sites (`:37`, `:168`, `:262`) and
  `cq_fround_eval`'s `clamp_i64` has the same shape. All readings agree in value
  wherever `lo <= hi`; the order is what the slot scan pins.
- **D-K25-5 — `~x` is `lower_xor!` against an all-ones constant** (M37's
  reading: LLVM spells `~x` as `xor %x, -1`; there is no full-width
  `lower_not!`). Each lane's second CNOT demotes to an X.
- **D-K25-6 — the nested `ifelse` chains evaluate innermost first**, which is
  Julia's argument order; `soft_round`'s `is_below_half | is_exactly_half`
  (`:197`) is an argument of the second `ifelse` and so precedes the inner two
  muxes.
- **D-K25-7 — `soft_trunc` is INLINED, `soft_fadd` is HANDED OFF.** floor and
  ceil inline trunc's 27-row body at a named base (`cq_fround_trunc_base`: 2 and
  3) — one flat program, one prefix map, M37's `fptosi`-into-`fptoui` shape —
  and reach `soft_fadd` as ONE `CQ_FIOP_FADD` row (§5.1).
- **D-K25-8 — `W` other than 64 is a hard error in both configurations**, M40's
  posture: every `soft_*` here is `(UInt64)`.

owed.

### 2.4 Scratch layout — flat, one memoised prefix map per program

One contiguous region per kernel call; each row owns `cq_fi_row_region` bits at
the prefix offset. The maps are pure functions of the five compile-time tables
and the siblings' published costs (the K21/M39 argument: not a cursor). The
row lookup is the LAST row whose first slot is `<= u` (a run of zero-slot views
shares a boundary); the dispatch also refuses a zero-slot row. `k->off` is
applied in `cq_fi_base` and nowhere else — every span AND the `off` handed to
the two inner region-owning blocks (the barrel, M33's fadd).

### 2.5 The copy-out

64 CNOTs from the last row (a `mux`'s own span) into `dst`, with the I6 extent
disarmed by the driver. `cq_fround_result` refuses a last row that is not a mux.

### 2.6 I6(a) and I6(b)

Every target is a bit of the region; the rail, the views, the constants and every
block output come back `const`. The region is pre-materialised by `cq_sandwich`,
so every row's output is quantum at every operand mask.

## 3. Gate count

### 3.1 The composition identity — over SLOTS

`cq_fround_steps(p) = Σ rows (count × slots asked of the owning module)` and the
same for bits, asserted twice in `the_programs_are_the_sum_of_their_blocks` (from
the census, and row by row through the test's own cost function), plus the
exact decomposition `floor = trunc + fadd + 2·eq + and1 + mux` and `ceil = floor
+ not1`.

## 5. Deltas and decisions not written elsewhere

### 5.1 `soft_fadd` is M33's exported `cq_fadd_block`, added by this bead

M33 exported `cq_fsub_block` (K19's fptoui) and no `cq_fadd_block`; floor and
ceil are the first callers of `soft_fadd` outside M33. The first landing of this
bead reached M33's ADD program through the internal `src/kernels/fadd_int.h`
(`cq_fa_step`, M33's UNMAPPED path). By the coordinator's ruling the brief was
widened to M33 for ONE additive change: `cq_fadd_block` / `cq_fadd_region` /
`cq_fadd_steps` / `cq_fadd_step` / `cq_fadd_result` in `src/kernels/fadd.h`,
implemented in `fadd_emit.c` through the SAME two mapped helpers as
`cq_fsub_block` (`blk_step`, `blk_result`: memoised map, fit check, one binary
search), so the two blocks cannot drift apart in guards. No fadd golden moved.
`fround_fadd.c` now includes only `fadd.h`. Measured once each, Release, one
47,815-slot compute half: `cq_fa_step` ~0.26 s, `cq_fadd_step` ~0.06-0.07 s.

The slot scan's delegated run (tests) still drives M33's UNMAPPED `cq_fa_step`
through `fadd_int.h` on purpose: the kernel reaches the mapped path, so the
comparison is between two decode paths of M33's one program.

### 5.2 floor's `-1.0` and ceil's `+1.0` are constants, not rows

`:69-70` and `:92` bind literals; `neg_one_bits = one_bits | 0x8000…` has no
non-literal operand and is constant-folded (§1.1). An `or` row over two
constants would cost 192 slots and 64 bits and fold every gate.

### 5.3 The `slt`-for-`ult` equivalent mutants are recorded, not "fixed"

See D-K25-3: three of each program's four `slt`s are value-equivalent to `ult`;
the fourth pair (the clamp) is not. Both kinds are left as `slt` because the
source's type is `Int64`.

## 6. Confidence

### 6.1 L1's oracle and anchors

The oracle is the host libm (`trunc`/`floor`/`ceil`/`rint`/`nearbyint`/`round`),
which is exact on every non-NaN input; NaN rows are answered from the literal
upstream rule (quietened, sign and payload kept). `rint` and `nearbyint` are
both asked and must agree; the host probe (bd 9ve.4) is asserted in-process
first. The complete classical table is the generic 15 unary singles plus 25
fround singles (every tie, both `2^52` boundaries, `2^52 − 0.5` with its carry,
`0.49999999999999994`, `1.9999999999999998`, ±sNaN, ±0.3, …), checked against
the classical body, plus a seeded 20,000-pattern classical differential over all
five bodies. The circuit replays eight anchors per kernel (§7.12), chosen to
separate each kernel from its neighbour:

| kernel | anchors |
|---|---|
| trunc | sNaN, −Inf, −0.5, 2.5, −2.5, −0.3, 2^52+1, max subnormal |
| floor | −sNaN, −Inf, −0.5, 2.5, −2.5, −0.3, −1.5, −min subnormal |
| ceil | sNaN, +Inf, 0.5, 2.5, −2.5, 0.3, 1.5, max subnormal |
| even | −sNaN, 0.5, −0.5, 2.5, −2.5, 3.5, 0.49999999999999994, 1.9999999999999998 |
| away | sNaN, 0.5, −0.5, 2.5, −2.5, 1.5, 0.49999999999999994, 2^52 − 0.5 |

### 6.2 Structural instruments (read no golden)

Census; well-formedness (strictly earlier references, known codes, one-bit
operands of one-bit ops); the trunc-body inlining identity (rows
`[base, base+27)` are trunc's rows shifted by `base`; `fadd(truncated, ±1.0)`;
`ifelse(need, fadd, truncated)` with the fadd arm TRUE); the composition
identity; the four-valued slot scan with its own cursor, delegating the barrel
and M33's fadd to standalone runs through M12's and M33's OWN step functions;
the span-disjointness scan; the palindrome at the two half-rail masks; two
programs in one region (each program at off 0 with its neighbour above it); and
an executed reachability proof for the three table-reading guards.

### 6.3 Risks, ranked

1. **M33's block contract (§5.1).** fround is `cq_fadd_block`'s only library
   consumer; M33's own `two_fadd_blocks_in_one_region_do_not_collide`,
   composition identity and six block death cases pin it independently.
2. **Select-chain arm order** (bd a-select-chain-defect-is-seen-by-l1-alone):
   swapped arms keep every count; only L1 anchors see them, which is why each
   kernel's eight anchors cover every arm of its own chain.
3. **The clamp's signedness** (D-K25-3): value-invisible on the selected branch.

### 6.4 Searched for and NOT found

No `soft_rint`, no `soft_nearbyint` in `fround.jl` or `softfloat.jl`'s exports;
no `UInt128`; no variable shift outside the nine.
