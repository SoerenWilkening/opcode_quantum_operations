# K07 — sub (two's complement over the K06 ripple-carry adder)

**Bennett source:** `third_party/bennett/src/adder.jl` lines 148–172 (`lower_sub!`), pinned commit 980805de85314b3da7ac25cf6454b56566f8e609
**libcqops module:** M14 `kernels/add.c` (IMPLEMENTATION_PLAN.md §3 Layer 3, split seam `add.c ↔ sub.c`; Step 12)
**Clean or sandwich:** **sandwich**.
**Status:** §3–§6 **re-issued 2026-08-14** under **I6(b)** (pre-materialised scratch — see
IMPLEMENTATION_PLAN.md §0.2). L4 golden moved `15W − 4` → **`15W − 2`** (116 → **118** at
W = 8); scratch qubits `3W − 1` → **`3W`**. See the box at the head of §3.

The compute half writes three scratch regions and leaves two of them dirty: the
complement `nb[0..W-1] = ¬b`, the sum region `t[0..W-1]`, and the carry chain
`c[0..W-1]` with `c[0]` pre-set to 1 (the `+1` of two's complement). Only `t` is wanted;
`nb` and `c[1..W-1]` are dirty by construction. Bennett cleans them with its single
global forward–copy–reverse wrap; libcqops applies the same wrap locally
(Bennett-in-the-small, PRD §5): compute → copy-out `t` into `dst` (W CNOTs) → replay the
compute backwards → free scratch. As with K06, the sum region is *scratch* and not `dst`,
because the kernel contract is `dst ^= f(a,b)` and `dst` is non-zero on the `_unc` path
while step j=3 reads the sum-region bit as a **control**.

**No strategy dispatch exists for sub.** `src/lowering/arith.jl:215` is
`elseif inst.op == :sub; lower_sub!(gates, wa, a, b, W)` — unconditional. There is no
Cuccaro-sub and no QCLA-sub in the tree (`grep -rn "lower_sub"` over `src/` returns only
the definition and that one call site). K07 is a pure port of K06's carry chain with a
complemented second operand and carry-in 1.

## 1. Julia source excerpt

`third_party/bennett/src/adder.jl` lines 148–172, verbatim:

```julia
"""Subtraction via two's complement: result = a - b  (mod 2^W)."""
function lower_sub!(gates::Vector{ReversibleGate}, wa::WireAllocator,
                    a::Vector{Int}, b::Vector{Int}, W::Int)
    not_b = allocate!(wa, W)
    # Bennett-5kio / U109: 2W gates for ~b; carry_in = 1 NOTGate; then
    # adder body 5W - 2 gates ⇒ ~7W total.
    sizehint!(gates, length(gates) + 7 * W + 1)
    for i in 1:W
        push!(gates, CNOTGate(b[i], not_b[i]))
        push!(gates, NOTGate(not_b[i]))
    end
    result = allocate!(wa, W)
    carry  = allocate!(wa, W)
    push!(gates, NOTGate(carry[1]))        # carry_in = 1
    for i in 1:W
        push!(gates, CNOTGate(a[i], result[i]))
        push!(gates, CNOTGate(not_b[i], result[i]))
        if i < W
            push!(gates, ToffoliGate(a[i], not_b[i], carry[i + 1]))
            push!(gates, ToffoliGate(result[i], carry[i], carry[i + 1]))
        end
        push!(gates, CNOTGate(carry[i], result[i]))
    end
    return result
end
```

`a − b = a + ¬b + 1 (mod 2^W)`. Lines 155–158 build `¬b` into fresh scratch — a copy
(`CNOT`) then a flip (`NOT`) per bit; the copy is unavoidable because `b` is a source and
must not be mutated (I6, and Rule 7's "leaving `a` and `b` unchanged"). Line 161 injects
the `+1` by setting the carry-in to 1. Lines 162–170 are `lower_add!`'s body verbatim
with `not_b` substituted for `b` — same recurrence, same ordering constraint (the MAJ
Toffoli at j=3 consumes `result[i]` while it still holds `a_i ⊕ ¬b_i`, before the j=4
CNOT turns it into the sum bit).

## 2. Gate sequence as indexed pseudo-code

One gate per step. See K06 §5 Delta D1 — **this granularity is mandatory, not a stylistic
choice**; a per-bit-index step is not an involution and the reverse half would leave the
carry chain dirty.

```
env: { cq_bit *dst; const cq_bit *a, *b; cq_bit *nb, *t, *c; int W; }
     scratch region = nb[0..W-1] ++ t[0..W-1] ++ c[0..W-1]        (3W bits)

     STEP 0 -- driver, not a compute step.  cq_sandwich PRE-MATERIALISES all 3W
     scratch bits before compute(0) runs (I6(b), plan §0.2).  They are born
     BIT_ZERO and cq_materialise emits an X only for a constant 1, so step 0
     costs 3W QUBITS and ZERO GATES.  From here to the end of the reverse half
     every scratch bit is CQ_BIT_Q, so no fold can fire on a scratch operand
     and step s emits an identical gate sequence on both passes.

     nb[0..W-1] scratch complement  (|0> on a qubit)
     t [0..W-1] scratch sum region  (|0> on a qubit)
     c [0..W-1] scratch carry chain (|0> on a qubit; c[0] is the carry-in, set
                                     to 1 by phase 2 -- now a REAL X on a qubit,
                                     no longer a free constant flip)

n_compute = 2W + 1 + 5*(W-1) + 3       /* = 7W - 1 structural gate slots */
n_copyout = W

compute(s):
    /* --- phase 1: nb = ~b  (2W slots) --- */
    if s < 2W:
        i = s / 2 ;  j = s % 2
        j==0 :  CX(b[i] -> nb[i])
        j==1 :  X (        nb[i])

    /* --- phase 2: carry-in := 1  (1 slot) --- */
    elif s == 2W:
        X (c[0])

    /* --- phase 3: ripple-carry a + nb  (5(W-1) + 3 slots) --- */
    else:
        u = s - (2W + 1)
        if u < 5*(W-1):
            i = u / 5 ;  j = u % 5
            j==0 :  CX (a[i]         -> t[i]   )
            j==1 :  CX (nb[i]        -> t[i]   )
            j==2 :  CCX(a[i], nb[i]  -> c[i+1] )
            j==3 :  CCX(t[i], c[i]   -> c[i+1] )
            j==4 :  CX (c[i]         -> t[i]   )
        else:
            i = W-1 ;  j = u - 5*(W-1)     /* top bit: no carry-out produced */
            j==0 :  CX (a[W-1]  -> t[W-1])
            j==1 :  CX (nb[W-1] -> t[W-1])
            j==2 :  CX (c[W-1]  -> t[W-1])

copyout(k):
        CX (t[k] -> dst[k])                /* k in [0, W) — this is the "^=" */

cq_sandwich(ctx, compute, n_compute, copyout, n_copyout, env);
/* driver: compute 0..n-1 ; copyout 0..W-1 ; compute n-1..0 */
```

W=1 degenerates correctly: phase 1 is 2 slots, phase 2 is 1, phase 3 is only the `j==0,1,2`
tail; `n_compute = 6 = 7·1 − 1` ✔.

### I6(a) — is every compute-half gate target inside scratch?

**Yes.** Targets are `nb[i]`, `c[0]`, `t[i]`, `c[i+1]` — all scratch. `a` and `b` appear
**only as controls** (`b` exactly once each, at phase-1 j==0). `dst` is touched only in
`copyout`, outside the reversed region. The `const cq_bit *` control / `cq_bit *` target
split enforces this at compile time. No I6(a) violation.

### I6(b) — is every scratch bit `CQ_BIT_Q` for the whole compute half?

**Yes, by construction** — `cq_sandwich` pre-materialises all 3W scratch bits at step 0
(plan §0.2, decision of 2026-08-14).

This is the part K07 actually needed, and the earlier edition of this document got it
wrong. It observed that two scratch bits are read as **controls** — `t[i]` (step j==3) and
`c[0]` (steps j==3 and j==4) — and then argued case by case whether each was
pass-symmetric. `t[i]` was **not**: with `a_i` and `b_i` both classical and the carry
quantum, the forward pass saw `t[i]` as `BIT_ZERO` and folded the j==3 `CCX` to nothing,
while the reverse pass saw it as `CQ_BIT_Q` and emitted a real `CCX`. The halves stop
mirroring, scratch is left dirty, and L1 stays green throughout. That is risk **R8**.

I6(b) deletes the case analysis rather than resolving it: every scratch control is
`CQ_BIT_Q` on both passes, so there is nothing to fold and nothing to reason about. The
old per-bit arguments are retained in §5 as **historical** (D2, D2b), because D2b's `c[0]`
is exactly the bit whose pre-materialisation costs the `+2 CCX` in §3.

## 3. Gate-count formula in W

> **Re-issued 2026-08-14 under I6(b)** — `cq_sandwich` pre-materialises the entire scratch
> region at step 0 (IMPLEMENTATION_PLAN.md §0.2, decision of 2026-08-14; plan §1 GAP 1).
>
> | | OLD (pre-2026-08-14) — **withdrawn** | NEW (this issue) |
> |---|---|---|
> | compute half, total | `7W − 2` (W ≥ 2) | `7W − 1` (all W ≥ 1) |
> | sandwiched CCX | `4W − 6` → 26 at W = 8 | `4W − 4` → **28** at W = 8 |
> | sandwiched total, **the L4 golden** | `15W − 4` → 116 at W = 8 | `15W − 2` → **118** at W = 8 |
>
> The whole `+2` is `+2 CCX`. The old figure credited a fold on `c[0]`, the two's-complement
> carry-in: it was a classical `BIT_ONE`, so the i=0 `CCX(t[0], c[0] → c[1])` demoted to a
> `CX` and the phase-2 `X(c[0])` was a free constant flip. Under I6(b) `c[0]` is a
> pre-materialised **qubit** and folds nothing. A reader diffing against an older copy will
> see `15W − 4` / `116`; that figure is **withdrawn**, and it agrees with the plan's own
> GAP 1 ledger ("K07 116→118"). Everything below is re-derived from
> `third_party/bennett/src/adder.jl` at pinned commit `980805de`, not carried over.

### 3.1 Structural count — re-derived from source

Counting the loops in `src/adder.jl:155-170` (the §1 excerpt; line numbers re-checked
against the file, not recalled):

* **`:155-158`**, loop `i = 1..W`: one `CNOTGate` (`:156`) + one `NOTGate` (`:157`) per
  iteration → **W CNOT + W NOT**.
* **`:161`**: **1 NOT** — `push!(gates, NOTGate(carry[1]))`, the `+1` of two's complement.
* **`:162-170`**, loop `i = 1..W`: 3 unconditional `CNOTGate`s (`:163`, `:164`, `:169`) +
  2 `ToffoliGate`s guarded by `i < W` (`:166`, `:167`) → **3W CNOT + 2(W−1) Toffoli**.

| | arithmetic | count |
|---|---|---|
| NOT       | `W + 1`                 | **W + 1** |
| CNOT      | `W + 3W`                | **4W** |
| Toffoli   | `2(W − 1)`              | **2W − 2** |
| **total** | `(W+1) + 4W + (2W−2)`   | **7W − 1** |

This reproduces the source's own comment at `:152-153` ("2W gates for ~b; carry_in = 1
NOTGate; then adder body 5W - 2 gates ⇒ ~7W total"): `2W + 1 + (5W − 2) = 7W − 1` ✔.

### 3.2 Emitted count — under I6(b) it *equals* the structural count

The old edition ran two regimes, **(S) structural** and **(E) emitted after the PRD §3
fold table**. **Under I6(b) they coincide for quantum operands, and (E) is withdrawn.**
Walking the §2 step list with every scratch bit already `CQ_BIT_Q` (step 0) and `a`, `b`
all `CQ_BIT_Q`:

| step | gate | controls | target | fold? | emitted |
|---|---|---|---|---|---|
| ph.1 j=0 | `CX(b[i] → nb[i])`          | `b[i]` Q     | `nb[i]` Q    | no | 1 CX |
| ph.1 j=1 | `X(nb[i])`                  | —            | `nb[i]` Q    | no | 1 X |
| ph.2     | `X(c[0])`                   | —            | `c[0]` **Q** | **no — old (E) said 0 gates** | 1 X |
| ph.3 j=0 | `CX(a[i] → t[i])`           | `a[i]` Q     | `t[i]` Q     | no | 1 CX |
| ph.3 j=1 | `CX(nb[i] → t[i])`          | `nb[i]` Q    | `t[i]` Q     | no | 1 CX |
| ph.3 j=2 | `CCX(a[i], nb[i] → c[i+1])` | Q, Q         | `c[i+1]` Q   | no | 1 CCX |
| ph.3 j=3 | `CCX(t[i], c[i] → c[i+1])`  | Q, **Q**     | `c[i+1]` Q   | **no — old (E) said CCX→CX at i=0** | 1 CCX |
| ph.3 j=4 | `CX(c[i] → t[i])`           | **Q**        | `t[i]` Q     | **no — old (E) said CX→X at i=0** | 1 CX |

Every structural slot emits exactly one gate, so the compute half is
**W+1 X, 4W CX, 2W−2 CCX, total 7W−1** — Bennett's own number, unmodified.

Pre-materialisation itself emits **nothing**: scratch is born `BIT_ZERO`, and
`cq_materialise` emits an `X` only when the constant was 1. Step 0 costs **3W qubits and
0 gates** (§4). Do not add X gates for it.

### 3.3 Sandwiched total

`cq_sandwich` runs compute forwards, then `copyout`, then compute backwards. `copyout` is
`CX(t[k] → dst[k])` for `k ∈ [0,W)`: `t[k]` is a scratch qubit and `dst[k]` is a fresh
`BIT_ZERO` result bit, so each one materialises `dst[k]` and emits a real CX — **W CX**
(PRD §3: a CX from a tainted bit into an untainted bit allocates a qubit).

* X    : `2(W + 1)`       = **2W + 2**
* CX   : `2(4W) + W`      = **9W**
* CCX  : `2(2W − 2)`      = **4W − 4**
* total: `2(7W − 1) + W`  = **15W − 2**

| | compute half | sandwiched (**the L4 golden**) |
|---|---|---|
| NOT (X)       | W + 1  | 2W + 2 |
| CNOT (CX)     | 4W     | 9W |
| Toffoli (CCX) | 2W − 2 | 4W − 4 |
| **total**     | 7W − 1 | **15W − 2** |

**These closed forms are exact at every `W ≥ 1` — the `W ≥ 2` dagger is gone.** That is a
second, smaller win from I6(b): the old edition needed a hand-written W=1 special case
(compute 5, sandwiched 11) precisely because the `c[0]` folds it credited were the only
ones still alive at W=1. With `c[0]` a qubit, W=1 falls straight out of the formula —
`2W−2 = 0` Toffolis, which is the correct "no carry stage" answer, rather than the old
forms' nonsensical `−1` / `−2`. (The old CNOT row degenerated at W=1 too, less visibly:
`4W = 4` against a true old count of 3. Only the *totals* were accidentally right, because
that `+1 CX` cancelled the `−1 CCX` — see §3.4.)

### 3.4 Withdrawn (E) figures — counterfactual, DO NOT PIN

Recorded only so a reader holding an older copy can see exactly what moved. These are what
the counts **would** have been had scratch bits been allowed to stay classical — i.e.
under the design that risk R8 rules out. **Counterfactual — do not pin.**

| | compute half (E, withdrawn) | sandwiched (E, withdrawn) |
|---|---|---|
| NOT (X)       | W + 1    | 2W + 2 |
| CNOT (CX)     | 4W †     | 9W † |
| Toffoli (CCX) | 2W − 3 † | 4W − 6 † |
| **total**     | 7W − 2   | 15W − 4 |

† W ≥ 2 — and the daggers belong on the **CNOT *and* Toffoli** rows, not on the total.
The true old W = 1 breakdown is `2 X / 3 CX / 0 CCX` compute and `4 X / 7 CX / 0 CCX`
sandwiched (the hand-written special case, totals 5 and 11). Against that, the (E) forms
give `4 CX / −1 CCX` and `9 CX / −2 CCX` — **two** wrong rows each, not one. The
**totals** `7·1−2 = 5` and `15·1−4 = 11` come out right only because the `+1 CX` and
`−1 CCX` errors cancel, which is precisely why a total-only check would not have caught
the degeneracy. The new forms need no dagger on any row (§3.3, §3.5 row W = 1).

### 3.6 Cross-check against the re-issued K06 — the identity survives

K06 (`lower_add!`, `src/adder.jl:1-18`) re-issued under I6(b) is `0 X / 3W CX / 2W−2 CCX`
in the compute half, `5W − 2` total, sandwiched `2(5W−2) + W = **11W − 4**`.

| | K06 | K07 | delta |
|---|---|---|---|
| X (compute)   | 0      | W + 1  | + (W + 1) |
| CX (compute)  | 3W     | 4W     | + W |
| CCX (compute) | 2W − 2 | 2W − 2 | **0** |
| **compute total**   | 5W − 2  | 7W − 1  | **+ (2W + 1)** |
| **sandwiched total**| 11W − 4 | 15W − 2 | **+ (4W + 2)** |

**The structural identity `K07 = K06 + 2W + 1` (compute half) holds exactly** —
`(5W − 2) + 2W + 1 = 7W − 1` ✔ — with the `2W` being phase 1 (W CX + W X for `¬b`) and the
`1` being phase 2's carry-in `X`. Sandwiched, the delta is exactly twice that,
`2(2W+1) = 4W + 2`, because `copyout` is W CX in both kernels and does not scale:
`(11W − 4) + 4W + 2 = 15W − 2` ✔. At W = 8: `84 + 34 = 118` ✔.

Two things to note, both consequences of the re-issue:

* **The old *folded* identity `K07 = K06 + 2W + 2` is dead.** Under I6(b) there is only one
  relation, the structural one. If a future reader finds `+2W+2` in an older copy, it
  belonged to the withdrawn (E) column.
* **K07's Toffoli count still equals K06's, but now for one reason instead of two.** The
  old edition explained the coincidence as "both fold exactly one Toffoli out of the i=0
  stage — K06 because `c[0] = ZERO` kills it, K07 because `c[0] = ONE` demotes it to a
  CNOT." That explanation is withdrawn along with the numbers. The real reason is trivial:
  `:162-170` is `lower_add!`'s body verbatim with `not_b` substituted for `b`, so the
  recurrence and its Toffoli guard `i < W` are literally the same code. `2W − 2` in both.

**L4 should assert the identity, not just the bare number**, so a K06 change cannot
silently desynchronise K07.

### 3.7 The gate count is W-alone *for quantum operands* — one honest caveat

Plan §0.2's consequence 1 says the count "is a function of `W` alone". That is exactly true
of the **scratch** side, which is the side that mattered: no fold on `nb`, `t` or `c` can
fire, so the forward and reverse halves are identical and a single golden per `(kernel, W)`
is sound. It is *not* a claim that a classical **source** operand stops folding — `a` and
`b` appear as controls, and a classical control still folds (that is the whole point of the
fold table). See §5 D9 for the corrected `x − 1` numbers.

So: pin `15W − 2` as the golden for the generic all-`CQ_BIT_Q` mask, and compute any
constant-operand golden from the fold table. The difference from before is that the golden
no longer moves when a *scratch* bit's kind moves, because scratch kinds no longer move.

### 3.8 Upstream baseline — there is none for sub

**Bennett publishes no `x−1` / `x−y` gate-count baseline.** `test_gate_count_regression.jl`
pins `x+1` (four widths), `x*x + 3x + 1`, `x + 3`, and `x*x` — no subtraction.
`BENCHMARKS.md`'s "Gate Counts" table (lines 7–34) has no subtraction row.
`benchmark/regression_baselines.jsonl` has none (13 rows, `grep -c sub` = 0). So Step 12's
mandated upstream validation ("pin `x+1` at `i8` against Bennett's published baseline")
applies to **K06 only**; K07 has to be validated structurally — against the §3.1
derivation and against K06 plus a known delta (§3.6).

Note that this cuts both ways after the re-issue. There is no upstream number that could
have caught the withdrawn `15W − 4`, and none that confirms `15W − 2`. K07's only defences
are the §3.1 loop count (which does reproduce the source's own `~7W` comment) and the §3.6
identity against K06. Both are re-derived here; neither has been executed.

**On the 58 vs 100 question** (`README.md:114` and `CLAUDE.md` Principle 6 give

## 4. Ancilla count

**Re-issued 2026-08-14 under I6(b): `3W − 1` → `3W`.**

**Scratch bits: `3W`** — `nb[0..W-1]` (W) + `t[0..W-1]` (W) + `c[0..W-1]` (W).

**Qubits materialised: `3W`, unconditionally, at step 0.** `cq_sandwich` pre-materialises
the whole scratch region before `compute(0)` runs, so the qubit count no longer depends on
the operand bit-kind mask at all:

* `nb[0..W-1]` — W. **Materialised at step 0, not at phase 1 j==0, and regardless of
  `b_i`'s kind.** The old edition's "a classical `b_i` gives a classical `¬b_i` for 0
  gates and 0 qubits" is **withdrawn for qubits** (the gate saving partly survives — D9).
* `t[0..W-1]` — W.
* `c[1..W-1]` — W−1.
* `c[0]` — **1 qubit, was 0.** This is the entire `3W−1 → 3W` delta, and it is the same
  bit that costs the `+2 CCX` in §3. Under the old scheme `c[0]` was targeted only by
  phase 2's `X`, which flipped a `BIT_ZERO` constant in place (PRD §3 row 1), so it lived
  its whole life as a classical `BIT_ONE` used only as a control. Under I6(b) it is a
  qubit from step 0 and phase 2's `X` is a real gate. The claimed saving over Bennett is
  gone; we now match Bennett's `allocate!(wa, W)`, which reserves all W carry wires
  unconditionally (`src/wire_allocator.jl:9-28`).

**Cost of step 0: 3W qubits, 0 gates.** Scratch is born `BIT_ZERO` and `cq_materialise`
emits an `X` only for a constant 1, so pre-materialisation is *pure allocation*. Do not
add X gates for it (§3.2).

**Peak pool occupancy across the call is `4W`** — 3W scratch, live from step 0 until the
reverse half completes, plus the W qubits `copyout` materialises in `dst`. The 3W are
returned to the pool at the end; `dst`'s W are the result and stay.

**The all-classical case costs 0 qubits and 0 gates (L5), and it does NOT enter the
sandwich.** When every bit of both `a` and `b` is `BIT_ZERO`/`BIT_ONE`, `cqrt_sub_<W>`
short-circuits *before* `cq_sandwich` and folds `a − b` to a constant `dst` directly. This
is mandatory, not an optimisation: pre-materialisation would otherwise allocate 3W scratch
qubits for a fully classical subtraction and break L5's "zero gates and zero qubits" (plan
§0.2, consequence 2). **The all-classical case must never be reported as costing scratch
qubits.**

**Scratch returns to `|0⟩` by construction, and I6(b) is what makes that argument valid.**
The reverse half replays the compute half in exact reverse order; X/CX/CCX are
self-inverse; and — this is the part I6(b) supplies — every scratch bit has the same kind
on both passes, so each step emits the *same* gate in both directions and the replay
actually cancels. `c[0]` included: its phase-2 `X` is now a real `X` on a qubit, and it is
the last thing the reverse half replays before phase 1, returning that qubit to `|0⟩`.
Under the old scheme this argument had to be made bit by bit and failed for `t[i]` (§5 D2).
See K06 §5 D3: the *shadow* cannot prove any of this, so `cq_sandwich` establishes it
structurally.

## 5. Deltas from upstream

All of K06's deltas apply verbatim — **D1 (one gate per step, or the reverse half leaves
the carry chain dirty), D3 (scratch cleanliness is structural, not shadow-provable), D4
(lazy per-bit allocation + LIFO pool vs Bennett's `WireAllocator` and its lowest-index-
first free list, `src/wire_allocator.jl:2-3`), D5 (no global wrap, no entry predicate, no
constant wires), D6 (`t` is scratch, not `dst`), D7 (the identical-cost restructuring that
removes D2, flagged not taken — now **moot**, since I6(b) removes D2 outright)**. Read
K06.md §5 first. Sub-specific additions:

**D2 (sub instance) — HISTORICAL as of 2026-08-14; RESOLVED by I6(b). Kept because it is
the reason I6(b) exists.** The hazard was: step j=3 controls on `t[i]`, and step j=4 (later
forward, earlier in reverse) can materialise `t[i]`. The trigger is `a_i` and `b_i` both
classical while `c_i` is quantum — reachable exactly as in K06 (two narrow quantum values
in a wide register: `a = {Q, ZERO…}`, `b = {Q, ZERO…}` puts a quantum carry under classical
operand bits at every high index). Forward, `t[i]` is `BIT_ZERO` at j=3 and the `CCX` folds
to nothing; in reverse `t[i]` is already `CQ_BIT_Q`, so a real `CCX` is emitted and
`c[i+1]` is materialised. The passes are asymmetric in gate count *and* qubit count, the
"palindrome around the copyout" property fails, and **L1 stays green**. Root cause is
D6-non-demotion (a bit that was `BIT_ZERO` forward is a known-zero `CQ_BIT_Q` in reverse,
and the fold table dispatches on *kind*, not on shadow value). K06 §5 D2 carries the full
worked W=3 witness; **the same `bd remember` entry covers both.**

**This is now risk R8, and `cq_sandwich`'s pre-materialisation closes it** — `t[i]` is
`CQ_BIT_Q` from step 0, so the j=3 `CCX` is real on both passes and there is no asymmetry
to witness. The old edition's mitigation ("wants an explicit L2/L3 test at a mixed-kind
mask before M14 is called done") is still worth running, but it is now a regression test
for the pre-materialisation step rather than a hunt for a live bug.

**D2b — `c[0]`, HISTORICAL, and the bit that pays for the re-issue.** Under the old scheme
`c[0]` was the one scratch control that was *safe*: phase 2 set it to `BIT_ONE` for 0
gates, phase 3 i=0 read it twice as a control (j=3, j=4), it was never a target again so it
was **never materialised**, and its kind was classical on both passes — an exact mirror
image. The general rule the old edition drew from this was: *a scratch bit is
pass-symmetric iff it is never materialised, or is materialised on the first gate that
targets it.* The rule is sound; the trouble is that it is a **per-bit, per-kernel
obligation**, unenforceable by the `const`-qualification mechanism (which guards only
targets), and `t[i]` violates it. I6(b) replaces the obligation with a driver guarantee.

The bookkeeping consequence is that `c[0]` is exactly what the re-issue costs. Everything
that made it cheap — the free constant flip, the `CCX→CX` demotion at i=0, the `CX→X`
demotion at i=0 — is now withdrawn:

```
OLD (withdrawn)                             NEW (I6(b))
  step 0   c0 not materialised                c0 materialised   -> +1 QUBIT, 0 gates
  phase2   X(c0)          -> 0 gates          X(c0)             -> 1 X
  i=0 j=3  CCX(t0,c0=ONE) -> CX  [1 CX]       CCX(t0,c0)        -> 1 CCX   (+1 CCX, -1 CX)
  i=0 j=4  CX (c0=ONE)    -> X   [1 X ]       CX (c0 -> t0)     -> 1 CX    (+1 CX,  -1 X )
```

Net per compute half: X unchanged at `W+1`, CX unchanged at `4W`, **CCX `2W−3 → 2W−2`**.
Doubled by the sandwich, that is the `+2 CCX` / `15W−4 → 15W−2` of §3, and the `3W−1 → 3W`
of §4. Both deltas trace to this single bit.

**D11 — we pre-materialise the scratch region; Bennett does not, and cannot.** At step 0
`cq_sandwich` takes 3W qubits from the pool for `nb`, `t` and `c` before the first compute
step runs (I6(b), plan §0.2). Bennett has no equivalent step, and the difference is not a
disagreement about circuits — **it is a distinction Bennett cannot express.**

Upstream, a wire is an `Int` and nothing else: `src/gates.jl:1` is
`const WireIndex = Int`, and `NOTGate`, `CNOTGate` and `ToffoliGate` (`src/gates.jl:6-22`)
carry only `WireIndex` fields. There is **no classical operand kind anywhere in the gate
representation**, so "is this wire still a constant?" is not a question the lowering can
ask, and `allocate!(wa, n)` (`src/wire_allocator.jl:9-28`) hands out a real wire every
time, unconditionally. Bennett therefore gets I6(b) for free by having no alternative:
every wire is always "materialised". Constant folding upstream is a *separate, earlier*
pass over the IR (`fold_constants`, `src/Bennett.jl:146`, default `true`), not a property
of the gate stream.

libcqops has the tri-valued bit (I1) and folds *at emission time*, which is where the whole
`{BIT_ZERO, BIT_ONE, BIT_Q}` win comes from — and it is also what re-opens the question
Bennett never faces. Pre-materialisation is the price of keeping the fold table and the
sandwich in the same library: we give up folding on scratch (where it bought a handful of
gates and cost us reversal soundness) and keep folding on sources and on the classical
short-circuit (where it buys everything — L5's zero-gate zero-qubit path, and D9).

**D8 — the `nb` region is mandatory; there is no inverted-control shortcut.** The obvious
"optimisation" is to skip `nb` and control the adder directly off `b` with inverted
controls, or to bracket the whole thing in `X(b[i]) … X(b[i])`. Both are forbidden:
Rule 4 admits only `X`/`CX`/`CCX` (no negative-control gate exists to fold into), and
targeting `b` would mutate a source, violating both I6 and Rule 7's "leaving `a` and `b`
unchanged" — `cq_emit_*` takes controls as `const cq_bit *`, so it does not even compile.
The W CNOT + W NOT prologue and its W scratch bits are the price. Port it as written.

**D9 — a classical `b` still saves gates, but far fewer than the old edition claimed, and
now saves NO qubits. Corrected 2026-08-14.**

The old text said "the whole prologue vanishes … 0 gates, 0 qubits … the libcqops count is
*structurally* smaller than any Bennett count." **That is withdrawn.** It assumed `nb` was
free to stay classical. Under I6(b), `nb[i]` is a pre-materialised qubit, so:

* **j=1 `X(nb[i])` never folds** — the target is a qubit, so it is a real `X` at every `i`,
  whatever `b` is. W of them.
* **j=0 `CX(b[i] → nb[i])` still folds on the *control*** — `b[i] = BIT_ZERO` gives 0
  gates, `b[i] = BIT_ONE` gives `X(nb[i])`, 1 real gate. This is the surviving saving, and
  it is a source-side fold, which I6(b) does not touch.
* **`nb` costs W qubits regardless.** No qubit saving at all.

Worked for `x − 1` (so `b[0] = ONE`, `b[i>0] = ZERO`), with `a` quantum:

| | generic (all-Q) | `x − 1` | saving |
|---|---|---|---|
| compute X    | W + 1  | W + 2 | −1 |
| compute CX   | 4W     | 3W    | +W |
| compute CCX  | 2W − 2 | 2W − 2 | 0 |
| **compute total**    | 7W − 1  | **6W**  | **W − 1** |
| **sandwiched total** | 15W − 2 | **13W** | **2(W − 1)** |
| **scratch qubits**   | 3W      | **3W**  | **0** |

(compute X: `W` from j=1 plus `1` for `b[0]=ONE` folding j=0 to an `X`, plus `1` for
phase 2 = `W + 2`. Sandwiched: `2(6W) + W = 13W`; row check
`(2W+4) + 7W + (4W−4) = 13W` ✔. At W = 8: 20 X / 56 CX / 28 CCX = 104, against the generic
118 — a saving of 14 = 2·(8−1) ✔.)

The operative half of the old claim survives: **the L4 golden for a constant-operand sub
must be computed from the fold table, not scaled off the generic formula.** What does not
survive is the comparison to Bennett — we now pay the same `not_b` wires Bennett pays
(D11), so K07 is no longer structurally cheaper in qubits than upstream, only in gates and
only when an operand is constant.

**D10 — signedness is not our problem here.** `lower_sub!` is width-generic two's
complement mod 2^W; `sub` and the signed/unsigned distinction only diverge at comparison
and division. K07 is the same circuit for `sub nsw`, `sub nuw` and plain `sub`. (The
signed/unsigned split appears in K09 `slt` vs `ult` and in K12 `divrem_s` vs `divrem_u`.)
