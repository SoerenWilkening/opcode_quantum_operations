# K10 — mux (select), and the barrel shifter built over it

**Bennett source:** `third_party/bennett/src/lowering/arith.jl` lines 522-532 (`lower_mux!`),
with the barrel shifter at lines 333-400 (`_shift_stages`, `lower_var_lshr!`,
`lower_var_shl!`, `lower_var_ashr!`) (pinned commit 980805de85314b3da7ac25cf6454b56566f8e609)
**libcqops module:** M17 `kernels/mux.c` (IMPLEMENTATION_PLAN.md:205) — the barrel is
M12 `kernels/shift_var.c` (IMPLEMENTATION_PLAN.md:200)
**Clean or sandwich:** **sandwich** — both K10 and the barrel.
**Status:** §3.2, §4 and §5 delta 2 **re-issued 2026-08-16** under **I6(b)**
(pre-materialised scratch — IMPLEMENTATION_PLAN.md §0.2), which this document was
written before and `bd 84m` was filed about. The barrel's `shl`/`lshr` L4 golden moved
`10WL + 3W − 2^(L+2) + 4` → **`10WL + 3W − 2^(L+1) + 2`** (236 → **250** at W = 8), and
its scratch qubit count `3WL + W − 2^L + 1` → **`W(3L+1)`** (73 → **80** at W = 8).
**§3.1 (the mux itself) is arithmetically unchanged** — K10 never had a scratch-side
elision to lose. Every figure in §3 and §4 is now **measured** rather than derived; see
the box at the head of §6.

Why: `lower_mux!` allocates **two** W-wide vectors. `r` is the SSA result (Bennett returns
it); `diff` is pure scratch, and at return `diff[i] = tv[i] ⊻ fv[i]` — **dirty**. Nothing
in `src/lowering/` ever calls `free!` (verified: `grep -rn "free!(" src/lowering/` returns
nothing), so Bennett leaves `diff` dirty by design and relies on its one global
forward–copy–reverse wrap in `bennett_transform.jl` to clean it. libcqops has no global
wrap, so K10 gets Bennett-in-the-small (PRD §5): compute `r` and `diff` into scratch,
copy `r` out into `dst` with W CNOTs, replay the compute backwards, release the scratch.

The barrel shifter is a sandwich for the same reason, compounded: every stage leaves a
`shifted`, an `r` and a `diff` behind, and only the final stage's `r` is the answer.

function lower_mux!(g, wa, cond, tv, fv, W)
    r    = allocate!(wa, W)
    diff = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(fv[i], r[i]))
        push!(g, CNOTGate(tv[i], diff[i]))
        push!(g, CNOTGate(fv[i], diff[i]))
        push!(g, ToffoliGate(cond[1], diff[i], r[i]))
    end
    return r
end

```julia
# ---- variable-amount shifts (barrel shifter) ----
#
# Bennett-zmw3 / U111: variable-shift semantics. The `_shift_stages` helper
# bounds the number of MUX stages at `min(b_len, ceil(log2(W)))`, so the
# barrel shifter only consumes bits 0..ceil(log2(W))-1 of the shift amount.
# Effectively the shift amount is taken mod (next power of two ≥ W). For
# W = 8 this gives shift mod 8 (matches x86/ARM hardware shift semantics).
#
# Julia's `<<` / `>>` wrappers add a guarded select that zeroes the result
# when the shift amount is ≥ width — that select is part of the IR our
# compiler sees (Julia's lowering adds it), so Julia frontends always get
# Julia-saturate semantics. RAW LLVM input (e.g. from a future C/Rust
# frontend without that wrapper) gets the mod-W semantics described above
# instead of poison or zero. Future bead may add a `saturate=true` kwarg.

_shift_stages(W, b_len) = min(b_len, W <= 1 ? 0 : ceil(Int, log2(W)))
```

`arith.jl:350-400` — the three barrel bodies:

```julia
function lower_var_lshr!(g, wa, a, b, W)
    result = allocate!(wa, W)
    for i in 1:W; push!(g, CNOTGate(a[i], result[i])); end
    for k in 0:_shift_stages(W, length(b))-1
        s = 1 << k
        s >= W && break
        shifted = allocate!(wa, W)
        for i in 1:W
            src = i + s
            src <= W && push!(g, CNOTGate(result[src], shifted[i]))
        end
        result = lower_mux!(g, wa, [b[k+1]], shifted, result, W)
    end
    return result
end

function lower_var_shl!(g, wa, a, b, W)
    result = allocate!(wa, W)
    for i in 1:W; push!(g, CNOTGate(a[i], result[i])); end
    for k in 0:_shift_stages(W, length(b))-1
        s = 1 << k
        s >= W && break
        shifted = allocate!(wa, W)
        for i in 1:W
            src = i - s
            src >= 1 && push!(g, CNOTGate(result[src], shifted[i]))
        end
        result = lower_mux!(g, wa, [b[k+1]], shifted, result, W)
    end
    return result
end

function lower_var_ashr!(g, wa, a, b, W)
    result = allocate!(wa, W)
    for i in 1:W; push!(g, CNOTGate(a[i], result[i])); end
    for k in 0:_shift_stages(W, length(b))-1
        s = 1 << k
        s >= W && break
        shifted = allocate!(wa, W)
        for i in 1:W
            src = i + s
            if src <= W
                push!(g, CNOTGate(result[src], shifted[i]))
            else
                push!(g, CNOTGate(result[W], shifted[i]))
            end
        end
        result = lower_mux!(g, wa, [b[k+1]], shifted, result, W)
    end
    return result
end
```

## 2. Gate sequence as indexed pseudo-code

### 2.0 A driver constraint this kernel forces — ONE GATE PER STEP

**Read this before writing M09 or M17.** The `cq_sandwich` driver (plan §0.1) calls
`compute(env, s)` with the *same* argument on the forward and reverse passes and only
reverses the **step order**. That is the exact inverse of the compute half **only if each
step is itself self-inverse.** K10's natural 4-gate per-bit block is **not** self-inverse:

```
block(i) =  CX(f,r) ; CX(t,d) ; CX(f,d) ; CCX(c,d,r)
start r=0, d=0   →  after one block:  d = t⊻f,  r = f ⊻ c·(t⊻f)     (correct)
                 →  after a SECOND block: d = 0, r = c·(t⊻f)        (NOT zero — no cancel)
```

(K01's 2-gate block *is* self-inverse — two commuting CXs into the same target — which is
why this trap does not appear there.) Therefore, for K10 and for the barrel, **each step
emits exactly one gate**. `n_compute` is then the structural gate-slot count, and reversal
is exactly `Gn … G1` with every gate self-inverse. If M09 ever grows a multi-gate step
API, it must reverse gate order *within* the step too — otherwise this kernel silently
stops cancelling, which is the R1 failure mode.

`n_compute` must also be a pure function of `W` (and `L`), **never** of operand bit-kinds:
kinds change during the compute half (scratch gets materialised) but the step index space
must not. Steps whose gates fold away emit zero gates on both passes — symmetric, safe.

### 2.1 K10 — mux, faithful port (Form A, the one to pin)

```
kernel mux(ctx, dst[W], cond, t[W], f[W]):
    scratch r[W], d[W]                    # M08: born BIT_ZERO, 2W slots
    cq_sandwich(ctx, compute, n_compute = 4*W,
                     copyout, n_copyout = W, env = {dst, cond, t, f, r, d})

compute(s):                               # i = s / 4, phase = s % 4
    phase 0:  CX (  f[i]        -> r[i] )
    phase 1:  CX (  t[i]        -> d[i] )
    phase 2:  CX (  f[i]        -> d[i] )
    phase 3:  CCX(  cond, d[i]  -> r[i] )

copyout(s):                               # s = i
              CX (  r[i]        -> dst[i] )
```

Driver order: `compute 0..4W-1` → `copyout 0..W-1` → `compute 4W-1..0`.
After the reverse half, `d[i] = 0` and `r[i] = 0` for all `i`; scratch is released clean.

**I6 — every compute-half gate target is inside scratch: YES.**
Targets are `r[i]` (phases 0, 3) and `d[i]` (phases 1, 2) — both scratch. `f`, `t` and
`cond` appear **only as controls** and are never written; `d` appears as a *control* in
phase 3, which is allowed (I6 constrains targets, not controls). `dst` is touched only in
`copyout`, which is outside the reversed region. No I6 violation.

Distinctness (Rule 11): phase 3 is `CCX(cond, d[i], r[i])` — `cond` is a source bit,
`d[i]` and `r[i]` are distinct scratch bits, so `c1 ≠ c2 ≠ t` holds even under the D7
aliasing corner (`x ? x : y`), because scratch can never alias a source.

### 2.2 The barrel shifter (M12), faithful port

`L = _shift_stages(W, W)` = `0` for `W = 1`, `ceil(log2 W)` for `W ≥ 2` (our shift-amount
register is always W bits wide, so `b_len = W ≥ ceil(log2 W)` and the `min` always picks
the log term). The `s >= W && break` guard is defensive and never fires for `W ≥ 2`, since
`2^(L-1) < W` always.

```
kernel shift_var(ctx, dst[W], a[W], b[W], dir ∈ {shl, lshr, ashr}):
    scratch cur0[W], and per stage k∈[0,L):  sh_k[W], r_k[W], d_k[W]
    # W*(3L+1) scratch SLOTS (see §4 for how many become qubits)
    cq_sandwich(ctx, compute, n_compute (below), copyout, n_copyout = W, env = ...)

compute — flattened one-gate-per-step schedule:
    # phase INIT:  W steps
    for i in 0..W-1:            CX( a[i]  -> cur0[i] )

    # then, for k = 0 .. L-1, with s = 1<<k and cur = (k==0 ? cur0 : r_{k-1}):
    #   phase SHIFT: the index shuffle into sh_k
    lshr :  for i where i+s < W:      CX( cur[i+s] -> sh_k[i] )       # W-s steps
    shl  :  for i where i-s >= 0:     CX( cur[i-s] -> sh_k[i] )       # W-s steps
    ashr :  for i in 0..W-1:          CX( cur[min(i+s, W-1)] -> sh_k[i] )   # W steps
            # shl/lshr: the s sh_k bits that get no source are the shifted-in 0. They
            #   take no STEP and no gate here, which is structural — the source index
            #   does not exist — and is where the W-s comes from.
            #   RE-ISSUED 2026-08-16: this line used to continue "...stay BIT_ZERO, and
            #   it is why those stages elide s CX". THEY DO NOT STAY BIT_ZERO. I6(b)
            #   pre-materialises the whole region at sandwich step 1, so they are qubits
            #   holding |0> and the MUX phase's CX(sh_k[i] -> d_k[i]) EMITS for all W of
            #   them. The saving is in THIS phase only, once, not twice. See §3.
            # ashr: EVERY sh_k bit has a source (the else-branch at arith.jl:394 clamps
            #   to cur[W-1], replicating the sign bit), so ashr saves nothing here.

    #   phase MUX: K10 §2.1 with cond = b[k], t = sh_k, f = cur, r = r_k, d = d_k
    for i in 0..W-1:
        CX ( cur[i]        -> r_k[i] )
        CX ( sh_k[i]       -> d_k[i] )
        CX ( cur[i]        -> d_k[i] )
        CCX( b[k], d_k[i]  -> r_k[i] )

copyout(s):   CX( res[s] -> dst[s] )      where res = (L == 0 ? cur0 : r_{L-1})
```

`n_compute` (structural step slots, kind-independent):

| dir | `n_compute` | at `W = 8, L = 3` |
|---|---|---|
| `shl` / `lshr` | `W + Σ_{k<L}[(W − 2^k) + 4W] = 5WL + W − 2^L + 1` | 121 |
| `ashr` | `W + Σ_{k<L}[W + 4W] = 5WL + W` | 128 |

**RE-ISSUED 2026-08-16.** This paragraph used to read: *"Note `n_compute` ≠ emitted gate
count for `shl`/`lshr`: `2^L − 1` of the MUX phase-1 steps have a structurally-`BIT_ZERO`
control (`sh_k[i]` that received no CX) and the fold table emits nothing for them."*
Under **I6(b)** those controls are pre-materialised qubits, so **`n_compute` IS the
emitted compute-half gate count**, for all three directions, at the all-quantum operand
mask. The `n_compute` column above is unchanged — step counts were always structural —

The step counts themselves are confirmed by execution: they are the `n_compute` M12 hands

**I6 — every compute-half gate target is inside scratch: YES.**
Targets are `cur0`, `sh_k`, `r_k`, `d_k` — all scratch. `a` and `b` appear only as
controls; `b[k]` is a source used as a Toffoli control and is never materialised. `dst` is
written only in `copyout`. No I6 violation.

## 3. Gate-count formula in W

> ### ♻ RE-ISSUED 2026-08-16 UNDER I6(b) (`bd 84m`) — read before §3.2's tables
>
> This document was written before `ckd.9` decided **PRE-MATERIALISE**, and §3.2 rests
> on the pre-decision reasoning in one place. I6(b) has `cq_sandwich` materialise
> **every bit of the scratch region at step 1**, before any compute step runs, so a
> scratch bit is `CQ_BIT_Q` for the whole compute half whether or not a gate has written
> it yet — and the §3 fold table dispatches on **kind, never on shadow value** (D6, no
> demotion). Consequences, and there are exactly two:
>
> 1. **§3.2's `3W → 3W − s` MUX reduction is GONE for `shl`/`lshr`.** The `s` bits of
>    `sh_k` that receive no source are no longer `CQ_BIT_ZERO` controls that fold away;
>    they are qubits holding |0⟩ and `CX(sh_k[i] → d_k[i])` emits. The sandwiched total
>    is **higher by `2(2^L − 1)` CX** — 14 at W = 8, 254 at W = 128. `ashr` is
>    **unchanged**: its else-branch clamps to the sign bit (`arith.jl:394`) so every
>    `sh_k` bit is written, and it never had an elision.
> 2. **§4's two qubit columns collapse into one.** The whole region materialises for
>    every direction, so the count is the region size `W(3L+1)` and not
>    `3WL + W − 2^L + 1`.
>
> **The `shl`/`lshr` SHIFT phase still emits `W − s` CX and that is NOT a fold** — the
> source index does not exist, so the loop emits no gate and no step. Structural, not
> elided; unaffected by I6(b).
>
> A knock-on worth stating: the compute-half CX now **equals the raw Bennett figure**
> §3.2's last paragraph prints for comparison, so libcqops and a Julia `gate_count`
> agree on the barrel's compute half for all three directions. A golden copied from a
> pre-re-issue copy of this file **under-counts by `2(2^L − 1)` CX**.

Counting rule: gates are counted **as libcqops emits them**, i.e. Bennett's gate sequence
pushed through the PRD §3 fold table, for the **all-quantum operand case** (every bit of
`a`, `b`, `t`, `f`, `cond` is `CQ_BIT_Q`). That is what an L4 golden pins. **Operand-side
folds still fire** — a classical `ZERO` operand bit removes its gate, which is what L5
proves — so a count is a function of `(W, operand mask)` and all-quantum is the fixed
point. **Scratch-side folds no longer exist at all**, per the box above.

### 3.1 K10 — mux

Derivation: `lower_mux!` has exactly one loop, `for i in 1:W` (`arith.jl:525`), whose body
pushes 3 `CNOTGate` (`:526`, `:527`, `:528`) and 1 `ToffoliGate` (`:529`). No `NOTGate`
anywhere in the function. So the compute half is `3W` CX + `W` CCX. The sandwich adds a
`W`-CNOT copy-out and one replay of the compute half.

| | compute half | sandwiched total (`2 × compute + copyout`) |
|---|---|---|
| NOT (X) | `0` | `0` |
| CNOT (CX) | `3W` | `2·3W + W = 7W` |
| Toffoli (CCX) | `W` | `2·W = 2W` |
| **total** | **`4W`** | **`9W`** |

| W | compute X / CX / CCX / total | sandwiched X / CX / CCX / total |
|---|---|---|
| 1 | 0 / 3 / 1 / 4 | 0 / 7 / 2 / 9 |
| 8 | 0 / 24 / 8 / 32 | 0 / 56 / 16 / 72 |
| 16 | 0 / 48 / 16 / 64 | 0 / 112 / 32 / 144 |
| 32 | 0 / 96 / 32 / 128 | 0 / 224 / 64 / 288 |
| 64 | 0 / 192 / 64 / 256 | 0 / 448 / 128 / 576 |
| 128 | 0 / 384 / 128 / 512 | 0 / 896 / 256 / 1152 |

No fold-table elision occurs in K10 **at any operand mask**, because every bit of `r`
and `d` is written before it is read — so I6(b) changed which *qubits* K10 takes and not
which *gates* it emits, and this table is unchanged by the re-issue. These are also the
raw Bennett numbers for the compute half. **Measured** at
`W ∈ {1, 2, 4, 8, 16, 32, 64, 128}`, both passes, and pinned in
`tests/goldens/mux.counts`.

**A classical `cond` does not take this path at all** (§5 delta 4, decided at Step 14):
M17 dispatches at entry and copies the selected arm, `W` CX and no scratch. So the row
above is the cost when `cond` is a qubit, which is the case an L4 golden pins and the
only case where the sandwich runs.

## 4. Ancilla count

**K10:** `2W` scratch slots — `r[W]` and `d[W]`, both from M08, both born `BIT_ZERO`.
Under I6(b) all `2W` materialise into qubits **whatever the operand mask is** — the
driver does it at step 1, not the first gate that writes them, so the pre-re-issue
qualifier "in the all-quantum case" is now unconditional. They are returned to `|0⟩` by
the reverse half of `cq_sandwich` and released to the LIFO pool. (**Not by M08** — that
sentence was wrong when written: M08 ships no release a kernel can call;
`cq_scratch_dispose` asserts every bit is back to `CQ_BIT_ZERO`, a **kind** check, and
M09's epilogue is what returns the qubits, through
`cq_ctx_release_qubit(..., CQ_ZERO_BY_PALINDROME)`.) Zero ancillae survive the call, and
`cond`, `t`, `f` are unmodified.
Measured as a pool high-water mark: `peak = 3W` across the call, of which `W` is `dst`.

**With a classical `cond` there is no scratch at all** — the entry dispatch copies the
selected arm (§5 delta 4), so `peak = W`, all of it `dst`.

**Barrel (M12):** `W·(3L + 1)` scratch slots — `cur0[W]` plus `{sh_k, r_k, d_k}` for each
of the `L` stages — **and, re-issued 2026-08-16, every slot is a qubit for every
direction.** The pre-re-issue table had a separate, smaller `shl`/`lshr` column on the
premise that the `2^L − 1` never-written `sh_k` bits "stay `BIT_ZERO` and cost no qubit";
I6(b) materialises the whole region, so slots and qubits are the same number:

| W | L | scratch qubits `W(3L+1)` | WITHDRAWN `shl`/`lshr` `3WL + W − 2^L + 1` |
|---|---|---|---|
| 1 | 0 | — (delegates to M11; no region) | 1 |
| 8 | 3 | **80** | 73 |
| 16 | 4 | **208** | 193 |
| 32 | 5 | **512** | 481 |
| 64 | 6 | **1216** | 1153 |
| 80 | 7 | **1760** | — |
| 128 | 7 | **2816** | — |

All are returned to `|0⟩` by the structural reverse half and released together at the end
of the sandwich. **Flag for the orchestrator, and the re-issue made it worse:** a single
64-bit variable shift peaks at **1216** scratch qubits for *every* direction, not 1153
for two of them — plus `W` for `dst`. At the two widths this document did not previously
evaluate it is **1760** (i80) and **2816** (i128). Adjacent to `ckd.13`, which is the
same problem one kernel up. Nothing in Bennett reduces this (Bennett never frees inside
`lower_*`), and the sandwich driver cannot free mid-compute-half without breaking the
replay, so a reduction would be a genuine design change (staged/pebbled scratch), i.e. a
new bead — not something to improvise inside M12.

## 5. Deltas from upstream

1. **Bennett leaves `diff` dirty; we cannot.** `r` in Bennett is the *SSA result*, not
   scratch — it is returned and lives on. `diff` is never freed. libcqops turns the whole
   thing into a sandwich, uses Bennett's `r` as the **copy-out source** rather than as a
   returned value, and reverses. Cost 2×, per Rule 2.

2. **⚠ THE SIGN OF THIS DELTA INVERTED — RE-ISSUED 2026-08-16 (`bd 84m`).** It read:
   *"The fold table changes the barrel's gate count. `2^L − 1` CXs Bennett emits do not
   exist for us (`CX` from a structurally-`BIT_ZERO` `sh_k[i]`) … an L4 golden copied
   from a Julia gate count would be **wrong by `2(2^L − 1)` CX** in the sandwiched
   total."* **Under I6(b) there is no such delta at all.** Those `sh_k` bits are
   pre-materialised qubits, the fold does not fire, and the barrel's compute half now
   **equals** a raw Bennett count for all three directions. The correction that a reader
   must apply today is the opposite one: **a golden copied from a pre-2026-08-16 copy of
   this document under-counts `shl`/`lshr` by `2(2^L − 1)` CX** — 14 at W = 8, 254 at
   W = 128. A Julia gate count is now the *right* cross-check for the compute half, which
   it was not before. (§5 delta 9 is unaffected: constants still stay classical on the
   OPERAND side, and operand-side folds are the only ones left.)

3. **One gate per step (see §2.0).** Bennett has no step abstraction; the per-bit 4-gate
   mux block is not self-inverse, so a multi-gate step function would silently break
   cancellation. This is a constraint on M09/M17, not a construction change.

4. **A classical `cond` does not fold to nothing by itself.** With `cond = BIT_ZERO` the
   `W` CCXs vanish (PRD §3) but the `6W` CX of compute+reverse remain, so a constant-select
   would cost `7W` CX to compute `dst ^= f`. M17 should dispatch on operand kind at kernel
   entry — `cond` classical ⇒ plain `dst ^= (cond ? t : f)` copy, no scratch, no sandwich.
   Precedent for the pattern is explicit in the PRD (`cqrt_cswap` with a constant control
   is 0 gates, `PRD-v1.md:201`) and in Bennett itself, which dispatches constant vs.
   variable shifts at `arith.jl:185-198`. **This is a decision, not a port — record it
   before pinning the L5 goldens.**

   > **DECIDED AND SHIPPED 2026-08-16 at Step 14, as written above.** `cq_kernel_mux`
   > dispatches at entry: a classical `cond` copies the selected arm and costs `W` CX and
   > **no scratch**. It is not merely cheaper, it is **required** — pre-materialisation is
   > unconditional, so without it a fully classical select would take `2W` qubits for an
   > operation with no quantum input, and L5's "zero gates **and** zero qubits" is a
   > conjunction. The all-classical case is a strict subset, so dispatching on `cond`
   > alone discharges R9 and more. Executed in
   > `tests/test_kernel_mux_dispatch.inc:a_classical_cond_never_enters_the_sandwich`,
   > which pins `W` CX / 0 CCX and a pool high-water mark of exactly `W`.

5. **A classical shift amount must short-circuit to K4/M11.** Bennett gets this for free
   because LLVM hands it a `ConstOperand` (`arith.jl:186`); our shift amount arrives as a
   register of `cq_bit`, so M12 must test "all bits of `b` classical" itself and call the
   M11 constant-shift kernel. Otherwise `x << 3` on a tainted `x` costs `~10WL` gates
   instead of `≤ W` CX, and L5 (the classical short-circuit level) fails.

   > **SHIPPED 2026-08-16, with one refinement this text did not anticipate.** M12 tests
   > only the bits the construction READS — `b[0 .. L-1]` — and not "all bits of `b`". A
   > quantum bit at or above `L` is structurally invisible to the barrel (never a mux
   > control), so forcing the sandwich for one would cost `W(3L+1)` qubits to compute a
   > constant shift. The mirror of M11's own rule, which `cq_shift_amount` states and
   > `test_kernel_step11_death.a_quantum_bit_above_the_stages_is_fine` executes.
   > **A CONSEQUENCE WORTH KNOWING: at `W = 1`, `L = 0`, so the test is VACUOUSLY TRUE
   > and a variable shift never enters the sandwich at any operand mask.** That is why
   > the `W = 1` row of §3.2 is `1` CX and not the formula's `3`.

6. **`cqrt_copy_<W>_controlled` is NOT K10 — do not route it through the mux.** PRD §2.1
   (`PRD-v1.md:104`) specifies it as `dst ^= src` under `ctrl`, one `CCX(ctrl, src_i,
   dst_i)` per bit: `W` CCX, no scratch, clean, no sandwich. It is one *leg* of the mux
   identity `dst ^= f ⊕ c·(t⊕f)`, not the whole mux. Implementing it via K10 would turn
   `W` gates into `9W`. The tainted-`select` path reaches whichever symbol the CQ pass
   emits; K10 is for the case where both arms are live values merged into a fresh `dst`.

7. **Signature: K10 has three sources, not two.** Rule 7's contract shape is
   `kernel(ctx, dst, a, b, W)`; PRD §6 itself writes `mux(dst,c,t,f)` (`PRD-v1.md:274`).
   The semantics (`dst ^= f(sources)`, sources unchanged, ancilla-clean) are unaffected —
   but the literal 2-source signature does not fit, and the extra operand has to live in
   the sandwich `env`. Worth one line in the plan so it is not "discovered" in Step 14.

   > **RESOLVED 2026-08-16 as `bd ckd.15`, and the answer is that arity was never part of
   > the contract.** Rule 7 fixes the SEMANTICS — `dst ^= f(sources)`, sources unchanged,
   > ancilla-clean — and the block-quoted signature is the canonical two-source case and
   > the type `cq_kernel_fn`. A kernel whose arity or widths differ declares its own
   > signature and names every operand; K5 and K9 already departed from it, though
   > differently — K5 leaves the parameter list (unary, two widths) while K9 keeps it
   > exactly and breaks only the unwritten `|dst| == W`. K10 leaves it outright, which
   > is why it cannot be stored in a `cq_kernel_fn`. `cq_kernel_check_n` is
   > N-ary for exactly this, and `cq_kernel_fn` STAYS arity-2 — a mux cannot be stored in
   > one, which is why the test spec reaches it through a `call` adapter. Written into
   > CLAUDE.md Rule 7 and PRD §4.

8. **Variable-shift semantics are mod `2^ceil(log2 W)`**, not C's undefined behaviour and
   not Julia's saturate-to-zero (`arith.jl:333-346`). ~~For the power-of-two widths CQ has
   (`W ∈ {1,8,16,32,64}`)~~ this agrees with C on every *defined* input, and only differs
   in C's UB region (`shift ≥ W`). The M12 refmodel for L1 must implement mod-`2^L`, not
   C's `>>`, or the exhaustive `W ∈ {1,2,4,8}` sweep will report false failures. Note
   `W = 1` gives `L = 0`: zero stages, `dst ^= a` for any `b`.

   > **TWO CORRECTIONS, 2026-08-16.** (i) **The width list is wrong.** `shl` and `lshr`
   > ship at **i80** as well (`opcode_table.yaml:195-196`), and i80 is the ONLY shipped
   > width where `2^L > W`, so it is the only one where the interval `[W, 2^S)` is
   > non-empty and the mod-only reading could differ from the shipped one. `ashr` ships
   > i128 but not i80 (`:197`). (ii) **"mod `2^L`" is incomplete, and PRD §15 D8 is the
   > operative statement: MASK, THEN SATURATE**, `dst ^= sat_shift(a, k mod 2^S)`, one
   > formula for M11 and M12 both. The two readings agree on the barrel only because the
   > barrel saturates *as a side effect* — each stage zero-fills or sign-fills what it
   > shifts in, and saturating shifts compose — which is exactly the claim `ckd.16`
   > got backwards. A refmodel written to plain mod-`2^L` would disagree with the kernel
   > at `W = 80, k ∈ [80, 128)`. Executed at Step 14 in
   > `m11_and_m12_agree_at_every_width_amount_and_value`, which drives both modules over
   > every shipped width and every amount the construction can distinguish.

9. **Constants stay classical.** Bennett's `resolve!` materialises a `ConstOperand` onto
   fresh wires with one `NOTGate` per set bit (`src/lowering/operand.jl:22-43`); we never
   do (I4/I5). Any Bennett-side count involving a constant operand is therefore an upper
   bound for us, and `X` stays at 0 in every table above.

10. **Allocator order.** Bennett's `WireAllocator` reuses the *minimum* free wire
    (free list held descending-sorted so `pop!` yields the minimum — `wire_allocator.jl:3`
    and `:19-21`, with the descending insert at `:46-48`); D4 makes ours LIFO. Gate
    counts are unaffected; only qubit *indices* in a trace differ. Relevant at L6 only.

11. **No pointer path.** `lower_select!`'s `inst.width == 0` branch (`arith.jl:485-514`,
    `_not_wire!` / `_and_wire!` provenance merging, fan-out ≤ 8) is Bennett's
    pointer-metadata routing. libcqops has no pointer values — CQ_lang resolves those
    above us. Do not port it.

12. **`cond` is a vector upstream, a single bit for us.** `lower_mux!` takes `cond` as a
    vector and reads only `cond[1]` (`arith.jl:529`); the barrel passes the singleton
    `[b[k+1]]`. Our signature should take a single `const cq_bit *`.

13. **A cheaper equivalent form exists — recorded here so it is not "discovered" later.
    DO NOT implement it in v1.** Bennett's `r` rail exists only to be copied into `dst`.
    Identifying `r` with `dst` directly (compute half = the `2W` CX that build `d = t ⊕ f`;
    copy-out = `CX(f[i] → dst[i])` then `CCX(cond, d[i] → dst[i])`; reverse = `2W` CX)
    gives the *same* net map on `dst` — `dst ^= f ⊕ c·(t⊕f)` — for `5W` CX + `W` CCX
    (`6W` total) and `W` ancillae, against Form A's `9W` and `2W`. I6 still holds (the
    compute half targets only `d`). Two reasons it is **not** the v1 pin: (a) it makes the
    copy-out no longer "W CNOTs" (`PRD-v1.md:246`), which is the shape the shared driver
    and the "promote only the copy-out steps" controlled-axis optimisation are specified
    against; (b) under that promotion it is *worse* on Toffolis — Form A controlled is
    `3W` CCX, Form B controlled is `4W` CCX, because its copy-out CCX promotes to the
    3-Toffoli sandwich. v1 pins Form A (Rule 1: port, don't re-derive; and no gate-level
    fusion before a working baseline). File it as a v2 bead if `mux` shows up hot.

    > **STILL NOT IMPLEMENTED, AND THE BARREL HAS THE SAME TEMPTATION ONE LEVEL UP.**
    > Step 14 shipped Form A for both. The barrel's version is the `sh_k` region: since
    > `d_k[i] = sh_k[i] ⊕ cur[i]` and `sh_k[i]` is only ever read by that one CX, the
    > shuffle could write straight into `d_k` and `sh_k` would not exist — saving `W`
    > qubits and `W` CX **per stage**, i.e. `W·L` qubits and `2WL` CX sandwiched (384
    > qubits and 768 CX at i64). It is not implemented for delta 13's reasons applied
    > unchanged: it is a re-derivation rather than a port, upstream allocates `shifted`
    > as a distinct vector (`arith.jl:356`, `:372`, `:388`), and no gate-level fusion
    > lands before a working baseline. Recorded here so it is not "discovered" and
