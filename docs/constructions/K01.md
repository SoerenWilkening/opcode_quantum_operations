Why: `lower_xor!` allocates a result vector `r` and emits **only** `CNOTGate(a[i], r[i])`
and `CNOTGate(b[i], r[i])`. Every gate targets `r`; `a` and `b` appear **only as
controls** and are never written. There is no intermediate wire anywhere in the body, so
there is nothing that could be left dirty. Bennett's `allocate!` gives `r` because in
Bennett's model `r` *is* the new SSA value; the wire is not scratch and is never freed
inside the kernel. Substituting libcqops' caller-supplied `dst` for `r` yields exactly
`dst ^= a ^ b` for an **arbitrary** initial `dst` (the gates are XOR-accumulations whose
controls are independent of `dst`), which is precisely the Rule 7 kernel contract and
makes the kernel its own inverse — `_unc` is a second call to the same function.

## 1. Julia source excerpt

`third_party/bennett/src/lowering/arith.jl:284-291`:

```julia
function lower_xor!(g, wa, a, b, W)
    r = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(a[i], r[i]))
        push!(g, CNOTGate(b[i], r[i]))
    end
    return r
end
```

## 2. Gate sequence as indexed pseudo-code

libcqops vocabulary. There is **no** compute/copy-out/reverse split — the kernel is a
single straight-line pass.

```
kernel_xor(ctx, dst, a, b, W):        /* dst ^= a ^ b */
    for s in [0, W):
        step(s):
            CX(control = a[s], target = dst[s])
            CX(control = b[s], target = dst[s])
```

Written in the plan's indexed step-function shape (`n_compute = W`, 2 gates per step),
but driven by a plain loop rather than `cq_sandwich`, because no reverse half exists.

**I6 statement.** I6 constrains gate targets *inside a `cq_sandwich` compute half*. K01
never enters a `cq_sandwich`, so **I6 is vacuous here** — there is no scratch region to
be inside of. The stronger property that actually holds, and the one M10's test must
assert, is:

> Every gate target is a bit of `dst`. `a` and `b` occur only as controls and are never
> materialised (Rule 8's `const cq_bit *` control / `cq_bit *` target split enforces this
> by construction).

Corollary worth noting: because every target is `dst` and no source is written, K01 is
safe to call **as a callee inside another kernel's sandwich compute half** with
`dst = scratch` — it satisfies I6 for its caller automatically.

## 3. Gate-count formula in W

Derivation: one loop, `for i in 1:W` (`arith.jl:286`), body pushes exactly two
`CNOTGate`s (`arith.jl:287-288`) and nothing else. No `NOTGate`, no `ToffoliGate`
anywhere in the function. Hence `2 × W` CNOTs.

| Gate | Compute half | Sandwiched total (what libcqops emits) |
|---|---|---|
| NOT (X) | `0` | `0` |
| CNOT (CX) | `2W` | `2W` |
| Toffoli (CCX) | `0` | `0` |
| **Total** | **`2W`** | **`2W`** |

The two columns are identical **because K01 is clean**: libcqops applies no local
Bennett wrap, so no `2 × compute + W` copy-out is paid. (Counterfactually, had it needed
a sandwich, the total would have been `2·(2W) + W = 5W`. That figure is **not** what
libcqops emits and must **not** be pinned as the L4 golden.)

| W | X | CX | CCX | total |
|---|---|---|---|---|
| 1 | 0 | 2 | 0 | 2 |
| 8 | 0 | 16 | 0 | 16 |
| 16 | 0 | 32 | 0 | 32 |
| 32 | 0 | 64 | 0 | 64 |
| 64 | 0 | 128 | 0 | 128 |

All counts are at `ctx->ctrl_depth == 0`. Under one level of control the emitter mode
(Rule 9) promotes each CX to a Toffoli — Bennett's own
`promote_gate!(out, g::CNOTGate, ctrl, _anc) = push!(out, ToffoliGate(ctrl, g.control, g.target))`
(`third_party/bennett/src/controlled.jl:118-120`) — giving `2W` Toffoli and `0` CNOT.
L4 goldens must record the control depth they were pinned at.

## 4. Ancilla count

**0 ancillae, for every W.**

`lower_xor!` calls `allocate!` exactly once, for the *result* vector, which in libcqops
is the caller-supplied `dst` and is not an ancilla. No temporary wire is allocated or
freed in the body, so there is nothing to return to `|0⟩` — the ancilla-clean obligation
(Rule 2) is discharged trivially.

## 5. Deltas from upstream

1. **`dst` is a parameter, not an allocation.** Bennett allocates `r` inside the kernel
   (`arith.jl:285`); libcqops passes `dst` in (Rule 7). The gate loop is byte-for-byte the
   same; only the provenance of the target differs. This is exactly what lets one function
   serve forward (`dst` fresh all-`BIT_ZERO`, `0 ^ f = f`) and uncompute (`dst = out`,
   `f ^ f = 0`).
2. **Constant folding is per-bit here, per-operand upstream.** Bennett's
   `resolve!(::ConstOperand)` (`third_party/bennett/src/lowering/operand.jl:22-43`)
   materialises a constant operand into `width` fresh wires and emits one `NOTGate` per set
   bit, and its identity peephole `_try_identity_peephole!` / `_identity_emit_for_const`
   (`arith.jl:98-165`) only fires when an operand is a *whole-register* constant (`k == 0` or
   `k == mask` for xor, `arith.jl:121-138`). libcqops' §3 fold table decides classical/quantum
   **per bit**, so a mixed register costs strictly less than Bennett: a `CX` whose control is
   `BIT_ZERO` emits nothing, and one whose control is `BIT_ONE` folds to `X`. `x ^ 0x0f` at W=8
   is the sharp case — Bennett cannot peephole it (`0x0f` is neither `0` nor `0xff`) and pays 4
   NOT + 16 CNOT **at `fold_constants=false`, which is not Bennett's default** — dated
   correction below; libcqops pays 4 X on the constant-1 lanes plus 8 CX from `a`. **This is an
   L5 case, not an L4 golden**, and the L4 golden must be pinned on all-quantum operands so it
   measures the kernel and not the fold table.

   **Corrected 2026-09-10 by `bd o63`: the upstream half of that comparison was a
   `fold_constants=false` figure.** The retired claim was that Bennett "pays 4 NOT + 16 CNOT"
   for `x ^ 0x0f`, full stop, and the peephole sentence above is why it looked complete — but
   the peephole is not Bennett's only constant-aware machinery. `_fold_constants`
   (`driver.jl:407`) runs **by default** (`Bennett.jl:146` `fold_constants::Bool = true`,
   applied at `driver.jl:375-376`). `_try_identity_peephole!` returns `nothing` for a literal
   that is neither `0` nor the mask (`arith.jl:140`), so the instruction takes the heavy path
   (`arith.jl:182+`) — and the fold pass then runs over the whole lowering regardless
   (`driver.jl:375-376`). (`arith.jl:151-152` says the same for the neighbouring both-const
   case: `_fold_constants` handles it post-hoc.) Walked by hand on this doc's own example at
   default options — Julia is not installed here, so this is a *reading* of the pass, not a run
   of it: the constant's four `NOTGate`s are absorbed into the pass's `known` map and never
   emitted (`driver.jl:424-430`); all eight `CNOT(a[i], r[i])` survive, their control being an
   input wire the pass knows nothing about (`driver.jl:443-452`); each `CNOT(b[i], r[i])`
   becomes a `NOT` on the four set lanes (`driver.jl:436-442`) and vanishes on the four clear
   ones (`driver.jl:434-435`); and the four constant wires, which this kernel only ever reads
   as controls, are re-materialised as trailing `NOT`s at the end of the circuit
   (`driver.jl:496-501`). **Upstream at default options pays 8 CNOT + 8 NOT + 0 Toffoli** — in
   general `W` CNOT + `2p` NOT for a literal of popcount `p`. The libcqops figure is unchanged,
   and it is the one side of this comparison that is *executed* rather than derived:
   `tests/test_kernel_bitwise.c`'s `l5_xor_against_a_partial_constant` pins 8 CX + 4 X + 0 CCX
   and 8 owned qubits. **So the gate delta is `p` NOTs — upstream's end-of-circuit restore of
   the constant wires — not the eight-gate gap the retired figure implied.** What folding
   cannot touch is the *qubits*: `resolve!` allocates `W` wires for the constant
   unconditionally (`operand.jl:30`) and `_fold_constants` deletes gates without renumbering or
   releasing wires (`driver.jl:504-507`, the `lr.n_wires` threaded straight through), so
   upstream still holds eight wires for `0x0f` where libcqops allocates none. That is the delta
   the per-bit design actually claims, and it is the one that survives the default. **§3's
   headline `2W` CNOT is unaffected**: it is pinned at all-quantum operands, where every
   control is an input wire outside `known` and every target leaves `known` on its first write
   while holding false (`driver.jl:445-451`), so the pass provably adds and removes nothing
   there.
3. **Operand distinctness is asserted, not assumed (Rule 11 / D7).** Bennett has no
   distinctness check: `resolve!(::SSAOperand)` returns the *same* wire vector for the same
   SSA name (`operand.jl:3-20`), so `x ^ x` would emit `CX(w, r)` twice on the same control
   — harmless upstream, but a coincident-operand signature libcqops must hard-error on.
   Aliasing of `dst` with `a` or `b` is worse: it would break the "controls independent of
   target" property this kernel's correctness rests on. Assert `dst != a`, `dst != b` loud.
4. **Wire reuse order differs, harmlessly.** Bennett's `allocate!` pops the *minimum* free
   wire (`wire_allocator.jl:19-22`, free list sorted descending); libcqops uses LIFO (D4).
   K01 allocates no scratch, so this changes nothing for this kernel — noted only so nobody
   expects wire *indices* to match a Bennett trace.
5. **No global wrap to inherit.** Bennett's `bennett(lr)` applies one top-level
   forward/copy/reverse. K01 needs no share of it, so unlike the sandwich kernels there is
   nothing to localise here.
