# K04 — constant shifts (`shl` / `lshr` / `ashr`)

**Bennett source:** `third_party/bennett/src/lowering/arith.jl` lines 293–331 (pinned commit 980805de85314b3da7ac25cf6454b56566f8e609)
— bounds helper `_check_const_shift` at 301–303, `lower_shl!` at 305–312, `lower_lshr!` at 314–320, `lower_ashr!` at 322–331.
Dispatch site (constant-vs-variable selection) at `arith.jl` 185–198.

**libcqops module:** M11 `src/kernels/shift_const.c` (IMPLEMENTATION_PLAN.md line 199; Step 11, scheduled with M13 casts)

**Clean or sandwich:** **clean** — and not merely "clean after cleanup": there is *no
compute half at all*. `lower_shl!/lshr!/ashr!` allocate the result vector `r` and then
emit CNOTs whose **only** targets are `r`'s wires. No intermediate wire is ever written,
so nothing can be left dirty. Ancilla count is exactly **0** at every `W` and every `k`
(§4). Bennett's global forward–copy–reverse wrap is irrelevant to this kernel; there is
nothing for it to undo beyond the result itself.

> **Corollary — do NOT route K4 through `cq_sandwich`.** A clean kernel writes straight
> into `dst`. If someone wraps K4 in the sandwich driver "for uniformity", every emitted
> gate targets a `dst` bit, which lies **outside** the scratch extent — the Debug
> scratch-extent assert (Rule 8 / I6) fires on the very first gate. That is the
> enforcement mechanism working correctly, not a bug in it.

## 1. Julia source excerpt

Verbatim, `third_party/bennett/src/lowering/arith.jl` lines 293–331:

```julia
# ---- shifts (constant amount only) ----

# Bennett-zmw3 / U111: constant-shift bounds for `lower_shl!` / `lower_lshr!`
# / `lower_ashr!`. LLVM defines `shl/lshr/ashr` with `k >= W` as poison, but
# Julia's `<<`/`>>` wrappers always emit a guarded select so frontends never
# emit a bare shift with `k >= W`. We accept `k == W` (returns zero for
# shl/lshr; sign-extension for ashr) and `0 <= k < W` (the normal range).
# Negative `k` would silently iterate over invalid wire indices; reject loud.
@inline _check_const_shift(k::Int, W::Int) = (0 <= k <= W) || throw(ArgumentError(
    "lower_shl!/lshr!/ashr!: constant shift k=$k out of [0, W] for W=$W " *
    "(Bennett-zmw3 / U111)"))

function lower_shl!(g, wa, a, k, W)
    _check_const_shift(k, W)
    r = allocate!(wa, W)
    # k == W: empty loop → returns the freshly-allocated all-zero vector.
    # That matches Julia's `<< W` (saturates to zero).
    for i in (k + 1):W; push!(g, CNOTGate(a[i - k], r[i])); end
    return r
end

function lower_lshr!(g, wa, a, k, W)
    _check_const_shift(k, W)
    r = allocate!(wa, W)
    # k == W: empty loop → all-zero result (matches Julia `>>> W`).
    for i in 1:(W - k); push!(g, CNOTGate(a[i + k], r[i])); end
    return r
end

function lower_ashr!(g, wa, a, k, W)
    _check_const_shift(k, W)
    r = allocate!(wa, W)
    # k == W: first loop empty, second loop fills every bit with the sign
    # bit a[W] (sign-extension to all-ones for negative inputs, all-zero for
    # non-negative). Matches Julia `>> W` for arithmetic shift.
    for i in 1:(W - k); push!(g, CNOTGate(a[i + k], r[i])); end
    for i in (W - k + 1):W; push!(g, CNOTGate(a[W], r[i])); end
    return r
end
```

**Bit-index convention (verified, not assumed).** Bennett's wire vectors are
**little-endian, 1-based**: `a[1]` is the LSB, `a[W]` is the MSB. Two independent
confirmations in the pinned tree:

- `lower_ashr!` (line 329) broadcasts `a[W]` as the sign bit — the sign bit is the MSB,
  so index `W` is the MSB.
- `test/test_zmw3_shift_bounds.jl:112` pins `gates_shl[1] == CNOTGate(a[1], r[W])` for
  `shl` by `k = W-1` — the lone surviving bit moves from index 1 to index `W`, i.e.
  LSB → MSB. Index 1 is the LSB.
- Cross-check: `lower_add!` (`src/adder.jl:7–17`) starts its carry chain at index 1 and
  propagates to `carry[i+1]`, which is only a ripple-carry adder if index 1 is the LSB.

libcqops `cq_bit` arrays are 0-based; the translation is `bennett_index i` ↔
`cqops_index i-1`, MSB at `W-1`. Everything below is 0-based.

## 2. Gate sequence as indexed pseudo-code

Contract: `dst ^= f(a)`, `a` unchanged, no ancillae. `k` is the (classical) shift
amount; `b` in the generic kernel signature carries it (see §5 on how `k` is obtained).
There is **no scratch region and no copy-out**, because there is no sandwich.

### `shl` by `k`

```
n_compute = (k >= W) ? 0 : (W - k)

step(s)  for s in [0, n_compute):
    CX( control = a[s], target = dst[s + k] )
```

`dst[0 .. k-1]` are the shifted-in zeros: **no step touches them**, which is exactly
`dst[i] ^= 0`. Zero gates, zero qubits for those positions.

### `lshr` by `k`

```
n_compute = (k >= W) ? 0 : (W - k)

step(s)  for s in [0, n_compute):
    CX( control = a[s + k], target = dst[s] )
```

`dst[W-k .. W-1]` are the shifted-in zeros: untouched.

### `ashr` by `k`

Let `kk = min(k, W)`.

```
n_compute = W                       // always W, independent of k

step(s)  for s in [0, W - kk):      // the shifted-down body
    CX( control = a[s + kk], target = dst[s] )

step(s)  for s in [W - kk, W):      // the sign-bit broadcast
    CX( control = a[W - 1], target = dst[s] )
```

Note `a[W-1]` (the sign bit) is a control **`kk + 1` times** when `kk < W`
(once as `a[s+kk]` at `s = W-kk-1`, and `kk` more times in the broadcast), and `W` times
when `kk == W`. `ashr` is therefore a **fan-out**, not a permutation — see §5.

### Copy-out steps

**None.** Clean kernel; `n_copyout = 0`.

### I6 statement

**I6 does not apply to K4, because K4 has no `cq_sandwich` compute half.** Every gate
target above is a bit of `dst`, the caller-supplied result rail — *not* scratch. This is
correct and is precisely why the kernel is clean, but it means:

> **CRITICAL — K4 must never be passed to the `cq_sandwich` driver.** Under the sandwich
> the compute half must target scratch (I6); K4 targets `dst`. Wrapping it would (a) trip
> the Debug scratch-extent assert immediately, and (b) if that assert were ever disabled,
> emit `f` twice into `dst` and cancel to zero — a silent miscompile. K4 is emitted
> directly.

Controls are `a` bits and are read-only (`const cq_bit *`), so the `cq_emit_*` type
signature already forbids materialising a source here (Rule 8, first enforcement
mechanism).

## 3. Gate-count formula in W

### Derivation, by counting the loops in the Julia source

| Function | Loop | Trip count | Gate per trip |
|---|---|---|---|
| `lower_shl!` (310) | `for i in (k+1):W` | `W - k` (0 when `k == W`) | 1 CNOT |
| `lower_lshr!` (318) | `for i in 1:(W-k)` | `W - k` | 1 CNOT |
| `lower_ashr!` (328) | `for i in 1:(W-k)` | `W - k` | 1 CNOT |
| `lower_ashr!` (329) | `for i in (W-k+1):W` | `k` | 1 CNOT |

`lower_ashr!` total `= (W - k) + k = W`, **independent of `k`**. No `NOTGate` and no
`ToffoliGate` appears anywhere in lines 305–331 — verified by reading the whole range;
the only gate constructor used is `CNOTGate`.

Bennett's own test pins both endpoints of this derivation: `k == W` gives
`isempty(gates_shl)` / `isempty(gates_lshr)` and `length(gates_ashr) == W`
(`test/test_zmw3_shift_bounds.jl:74–83`), and `k == W-1` gives exactly 1 CNOT for `shl`
(`:110–113`).

### Compute half (= the whole kernel)

Valid for `0 <= k <= W`; see §5 for `k > W`, which Bennett rejects and libcqops must not.

| Gate | `shl` | `lshr` | `ashr` |
|---|---|---|---|
| NOT (`X`) | 0 | 0 | 0 |
| CNOT (`CX`) | `W − k` | `W − k` | `W` |
| Toffoli (`CCX`) | 0 | 0 | 0 |
| **total** | **`W − k`** | **`W − k`** | **`W`** |

### Sandwiched total

**Identical to the compute half** — `2 × compute + copy-out` does not apply, because K4 is
clean and never enters `cq_sandwich`. (For the record, had it been sandwiched it would
cost `2(W−k) + W` for `shl`/`lshr` and `3W` for `ashr`. It is not, and must not be.)

### Evaluation

`shl` / `lshr` (same formula, `W − k`):

| W | k=0 | k=1 | k=W/2 | k=W−1 | k=W |
|---|---|---|---|---|---|
| 1 | 1 | 0 | — | **1** (k=W−1=0) | 0 |
| 8 | 8 | 7 | 4 | 1 | 0 |
| 16 | 16 | 15 | 8 | 1 | 0 |
| 32 | 32 | 31 | 16 | 1 | 0 |
| 64 | 64 | 63 | 32 | 1 | 0 |

`ashr` (`W`, flat in `k`):

| W | k=0 | k=1 | k=W/2 | k=W−1 | k=W |
|---|---|---|---|---|---|
| 1 | 1 | 1 | — | 1 (k=W−1=0) | 1 |
| 8 | 8 | 8 | 8 | 8 | 8 |
| 16 | 16 | 16 | 16 | 16 | 16 |
| 32 | 32 | 32 | 32 | 32 | 32 |
| 64 | 64 | 64 | 64 | 64 | 64 |

The PRD's "≤ W CNOT" (PRD-v1.md line 268) holds at every row: `shl`/`lshr` peak at `W`
(the `k = 0` identity copy) and `ashr` is exactly `W` always.

### These are the ALL-QUANTUM figures — the actual libcqops count is data-dependent

The table above counts **`cq_emit_cx` calls**, not sink gates. Under the §3 fold table a
`CX` whose control is classical emits **0 or 1** gate, not 1. The pinnable numbers are:

| Case | Gates | Qubits allocated |
|---|---|---|
| every `a` bit is `CQ_BIT_Q` (L4 golden — pin this) | as the table above | `W−k` (`shl`/`lshr`), `W` (`ashr`) |
| every `a` bit is classical (L5 — pin this) | **0** | **0** |
| mixed | one `CX` per *quantum* source bit that lands in `dst` | one qubit per such bit |

For the forward direction `dst` is freshly allocated all-`BIT_ZERO`, so each
materialisation flips no constant and costs exactly 1 sink gate (the `CX` itself) — the
"1 or 2" row of the fold table collapses to 1. So forward and all-quantum agree.

**Rule 14 in the concrete.** Forward and `_unc` counts for K4 are *not* required to match,
and here is the exact mechanism: suppose `a[3]` is `BIT_ONE` at forward time and `dst` is
fresh. `CX(a[3], dst[3+k])` folds to `emit_x(dst[3+k])` on a *constant* target → **0
gates**, and `dst[3+k]` is left as the *constant* `BIT_ONE`. If CQ then applies an
in-place `cqrt_ry` to `a` before calling `_unc`, `a[3]` is now `CQ_BIT_Q` (we never
demote, D6) while `dst[3+k]` is still the constant `BIT_ONE`, so the *same* `CX` now
takes the `c = Q`, `t` constant row of the fold table (PRD-v1.md line 186): materialise
`dst[3+k]` — which emits an `X` because its constant was **1** — then `sink.cx` → **2
gates**. Forward 0, `_unc` 2, XOR still cancels. This is the "1 or 2" row *not*
collapsing, precisely because `dst` is no longer fresh at `_unc` time. Pin the two
counts separately; do not assert equality.

## 4. Ancilla count

| | formula in `W` |
|---|---|
| ancillae used by K4 | **0**, for `shl`, `lshr` and `ashr`, at every `W` and every `k` |

There is nowhere for one to come from: the only wires written are `r`'s (libcqops:
`dst`'s), and `r`/`dst` is the caller's result rail, not scratch. No `allocate!` other
than the result appears in lines 305–331. Nothing to return to `|0⟩` — the statement
"every internal ancilla returns to `|0⟩`" is vacuously true.

Bennett does allocate `W` wires for `r`; the `k` wires that receive no CNOT
(`r[1..k]` for `shl`, `r[W-k+1..W]` for `lshr`) stay at `0` and are simply never used.
libcqops spends **zero qubits** on those positions because they remain `BIT_ZERO`
constants — see §5.

## 5. Deltas from upstream

**(a) The shifted-in bits are free — this is the headline saving.** Bennett must allocate
`W` physical wires for `r` regardless of `k`, because a wire is the only representation
it has; the `k` zero positions are real qubits pinned at `|0⟩`. In libcqops those
positions stay `CQ_BIT_ZERO` constants: **0 qubits, 0 gates** (I4 — a register whose bits
are all constants owns zero qubits). Peak-qubit delta at `W=64, k=32`: Bennett 64 result
wires, libcqops 32.

**(b) Classical source bits are free.** Bennett's `resolve!(::ConstOperand)`
(`src/lowering/operand.jl:22–43`) allocates `width` wires and emits one `NOTGate` per set
bit, so `Int32(5) << 2` costs 32 wires + 2 NOTs upstream. In libcqops a fully-classical
`a` gives a fully-classical `dst`: **0 gates, 0 qubits** (L5). Partially-classical `a`
gives a proportional saving. This is the legitimate "port emits fewer gates than
upstream" case the task flagged, and it is not an optimisation — it falls out of Rule 3
plus the §3 fold table with no special-casing in M11.

**(c) It is still NOT a free relabelling. Do not alias.** The tempting move —
"`dst[i] = a[i-k]`, copy the `cq_bit` struct, zero gates even for quantum bits" — is
**forbidden by I2**: no qubit index may appear in two live registers, and that is exactly
what makes `cqrt_free` sound. `a` is still live after the shift (the kernel contract says
so), so the copy must be **physical**: materialise + `CX`, per Rule 5. The `W−k` CX
survive for quantum bits.

The only situation where a genuine zero-gate relabelling would be sound is when `a` is
dead at the shift — the shift would then *consume* `a`'s qubits and permute their indices
inside the register. libcqops has no liveness information (CQ_lang owns liveness and only
tells us via `cqrt_free`), and v1 forbids optimisation passes anyway. **Not in v1.**
Recorded here so a future reader does not think it was overlooked.

**(d) `ashr` is a fan-out, not an "index shuffle" — a PRD wording refinement.** PRD-v1.md
line 268 describes K4 as a "pure index shuffle". True for `shl`/`lshr`; for `ashr` the
sign bit `a[W-1]` is a control `k+1` times (`arith.jl:328–329`, and `W` times at `k ≥ W`).
Consequences that matter: the sign qubit is the control of up to `W` CX (no parallelism
in that layer, relevant only if a future depth metric is added), and in the shadow one
unknown source bit poisons `k+1` destination bits at once. The "≤ W CNOT" and "clean"
halves of the PRD claim hold exactly.

**(e) `k ≥ W` — Bennett throws; libcqops MUST NOT. This needs a recorded decision.**

Bennett's `_check_const_shift` (301–303) accepts `0 ≤ k ≤ W` and throws `ArgumentError`
otherwise. It can afford to: upstream, `k` is an LLVM `ConstOperand`
(`arith.jl:186`, `ConstOperand.value::Int`, `ir_types.jl:27–29`) and the comment at
296–299 records that Julia's `<<`/`>>` wrappers always emit a guarded select, so a bare
`k > W` never reaches the lowering.

libcqops has no such guarantee. M11 is selected when the shift-amount **register's bits
are all classical** — a runtime property of the tri-valued representation, not a
compile-time LLVM fact. Ordinary C (`x << n` where `n` folds to 40 at `i32`) reaches M11
with `k = 40`. `k` is decoded from `W` classical bits, so its domain is `[0, 2^W)`.
Aborting there would turn a legal-to-compile (if UB) C program into a hard backend
failure. The precedent is D3: `sdiv`/`srem` by zero is *deterministic-but-unspecified,
documented, and never traps*.

**Recommended (NOT settled — see the blocker below): saturate.**

| op | `k ≥ W` | gates |
|---|---|---|
| `shl` | `dst ^= 0` — emit nothing | 0 |
| `lshr` | `dst ^= 0` — emit nothing | 0 |
| `ashr` | `dst[i] ^= a[W-1]` for all `i` | `W` CX |

This is Bennett's accepted `k == W` row (308–309, 317, 325–327) extended monotonically,
matches Julia's saturating wrappers, is deterministic and never traps. The pseudo-code in
§2 already implements it (`n_compute = 0` / `kk = min(k,W)`).

> **BLOCKER — M11 and M12 must agree, and today they would not.** Bennett's *variable*
> shifter is **mod-2^⌈log₂W⌉**, not saturating: `_shift_stages(W, b_len) = min(b_len,
> W <= 1 ? 0 : ceil(Int, log2(W)))` (`arith.jl:348`, verbatim — the `W <= 1 ? 0 :`
> guard makes a `W = 1` barrel emit zero MUX stages) makes the barrel consume only bits
> `0 .. ⌈log₂W⌉−1` of the shift amount, which for `W ∈ {8,16,32,64}` is exactly `k mod W`
> — stated outright in the upstream comment at 333–346. Bennett never produces a wrong
> answer from this disagreement because its constant path *throws* rather than
> disagreeing. libcqops cannot throw, so if M11 saturates and M12 (ported verbatim)
> takes `k mod W`, then at `W=32` the expression `x << 40` yields **`0` when the shift
> amount is classical and `x << 8` when it is quantum**. That is an observable semantic
> difference driven purely by bit-kind — a guaranteed L1 differential-test failure
> against any single refmodel, and by the Prime Directive's standard a miscompile.
>
> **RESOLVED 2026-08-15 at Step 11 as PRD §15 D8: MASK, THEN SATURATE.** One formula for
> both paths — `dst ^= sat_shift(a, k mod 2^⌈log₂W⌉)`. The blocker below is preserved as
> written because it is what forced the decision, but **three of its factual claims are
> wrong and are corrected here**; read this box before the options.
>
> 1. **The barrel is not "mod, and therefore never saturates". It saturates too.** Each
>    stage zero-fills (`shl`/`lshr`) or sign-fills (`ashr`) the positions it shifts in —
>    `shifted` is a fresh all-zero register and the out-of-range copy is simply not
>    emitted (`arith.jl:355-400`) — and saturating shifts compose additively. So the
>    variable path is `sat_shift(a, k mod 2^S)`, and it saturates *unasked* on the whole
>    interval `[W, 2^S)`.
> 2. **i80 does not sharpen the conflict; it softens it.** The disagreement is a
>    power-of-two artefact: `2^S = W` makes `[W, 2^S)` empty, so at `W ∈ {8,16,32,64,128}`
>    the paths differ at every `k ≥ W`, while at `W = 80` they **agree** throughout
>    `[80,128)` and first differ at `k = 128`. The `W=32, k=32` example below reproduces
>    exactly and is the sharpest case there is — constant annihilates, variable returns
>    the value untouched. An i80 example at `k = 100` would **not** reproduce.
> 3. **Option 2 below is not the free one-liner it is billed as.** `k &= W-1` is exact only
>    for power-of-two `W`; at `W = 80` masking to 7 bits leaves amounts in `[80,128)` that
>    the barrel saturates, so a constant path that only masked would emit a shift by 100 on
>    an 80-bit register. The rule is mask **and then** saturate. Still zero gates and zero
>    ancillae — two operations rather than one.
>
> The decision went to option 2-corrected on cost and on Rule 1. Option 1 needs an
> OR-reduction over the `W − S` amount bits the barrel never reads plus a controlled force
> of the result: `+156` gates / `+26` qubits at `W=32` and `+432` / `+72` at `W=80`, about
> `+19%` on the barrel, paid on every variable shift — and it means deviating from the
> *ported* construction rather than from a classical index computation. Measured over the
> 239 goldens: 916 shift calls, 895 with a constant amount, **every one in `[0, W)` and
> none negative**, so this defines behaviour for a case CQ_lang has never emitted.
> The knowing delta — D8 disagrees with Bennett's own `k == W` row, which
> `test/test_zmw3_shift_bounds.jl` pins — is recorded in PRD §15.
>
> Options, all of which must be applied to M11, M12 **and** the L1 refmodel together:
> 1. **Both saturate** — M12 needs a guard: OR-reduce `b`'s bits above `⌈log₂W⌉−1` and
>    force the result to zero under it. Costs extra CCX + at least one ancilla in M12.
> 2. **Both take `k mod 2^⌈log₂W⌉`** — free in M11 (`k &= W-1` for power-of-two `W`),
>    zero change to M12, and it matches x86/ARM hardware shift masking. But it
>    contradicts Bennett's own `k == W` row (which returns `0`, not `x`).
> 3. **Both fail loud** — rejected: violates "never traps" for a runtime-classical `k`.
>
> **Do not silently pick one in M11.** Per CLAUDE.md's open-blockers rule, settle it in
> `PRD-v1.md`/`IMPLEMENTATION_PLAN.md` (it is a new D-decision, sibling to D3) and file it
> in `bd` before `test_shift_const.c` is written. My recommendation is option 2 for cost
> and hardware-agreement reasons, but that is a recommendation, not a finding.

**(f) `k = 0` is not peepholed upstream, and should not be here either.** Bennett's
identity peephole `_try_identity_peephole!` is gated on
`op in (:add, :sub, :mul, :and, :or, :xor)` (`arith.jl:146`) — shifts are excluded, so
`shl x, 0` falls through and emits a full `W`-CNOT copy. libcqops matches this
naturally: `k = 0` is the `n_compute = W` row and emits `W` CX for a quantum `a`. That is
*correct*, because the contract is `dst ^= a`, not `dst = a` — the copy is the semantics,
not overhead. Do not "optimise" it away (Rule: no gate-level optimisation in v1).

**(g) Aliasing (D7) is a silent-corruption hole here, and the distinctness assert does
not close it.** Bennett is structurally immune: `r = allocate!(wa, W)` is always fresh, so
`r` and `a` never overlap. libcqops takes `dst` from the caller. If CQ_lang ever emits
`cq_template_shl_i32(h, k)` with `dst` aliasing `a`, the ascending step order in §2 makes
`dst[i] ^= dst[i-k]` read positions it has already written — silent wrong value. The §3
operand-distinctness assert (`c != t`) does **not** catch it for `k ≥ 1`: the control is
`a[s]` and the target is `dst[s+k]` (`shl`) or `a[s+k]` → `dst[s]` (`lshr`), which are
different *bit indices* even when they are the same register. The assert only fires on
the sub-cases where an index coincides — `k = 0` for all three ops (control `a[s]`,
target `dst[s]`), and `ashr` with `k ≥ 1` at the `CX(a[W-1], dst[W-1])` step. Those are
incidental catches, not coverage. **M11 must assert `dst` and `a` are disjoint registers at
entry**, in Debug via the M07 owner map. Per risk R2 the eventual fix, if D7 ever fires,
is one defensive `cqrt_copy` — in one place, not twelve.

**(h) i128 ports for free; Bennett's plumbing does not.** Lines 305–331 are pure array
indexing and are width-agnostic. Bennett's `resolve!` caps at
`1 <= width <= 64` (`operand.jl:27–29`), so upstream cannot *reach* these functions at
`W = 128`. libcqops must, since `shl/lshr/ashr` are among the 16 i128 opcodes (PRD-v1.md
line 62). Nothing in the construction obstructs it — this is exactly the payoff of I5
(no packed scalar): the kernel is written over `reg->width` with no width switch and
`W = 128` is just another value.

**(i) Free-list / wire-allocation discipline.** Bennett's `WireAllocator.allocate!`
pops the *minimum* free wire (`src/wire_allocator.jl:8–28`, free list sorted descending);
libcqops is LIFO (D4). Irrelevant to correctness and to the gate counts above — K4 emits
no gate that depends on a wire *number* — but it means any Bennett-derived wire-index
trace will not match ours. Pin counts, not traces (project convention).
