# K06 — add (ripple-carry, out-of-place)

**Bennett source:** `third_party/bennett/src/adder.jl` lines 1–18 (`lower_add!`), pinned commit 980805de85314b3da7ac25cf6454b56566f8e609
**libcqops module:** M14 `kernels/add.c` (IMPLEMENTATION_PLAN.md §3 Layer 3; Step 12)
**Clean or sandwich:** **sandwich**.

The compute half writes two scratch regions: the sum region `t[0..W-1]` and the carry
chain `c[0..W-1]`. When it finishes, `c[1..W-1]` hold the intermediate carries — dirty
by construction. Bennett never cleans them locally; `bennett()` cleans them with its one
global forward–copy–reverse wrap (`src/bennett_transform.jl`). libcqops has no global
wrap, so Bennett-in-the-small applies: **pre-materialise the whole scratch region
(I6(b))** → compute → copy-out `t` into `dst` (W CNOTs) → replay the compute backwards →
free scratch. Note the sum region `t` is scratch too, not `dst`: the kernel contract is
`dst ^= f(a,b)`, and `dst` is not guaranteed zero on the `_unc` path, so the carry
recurrence cannot be run through `dst` (step j=3 below reads the sum-region bit as a
*control*, which would make the circuit depend on `dst`'s incoming value).

> **Re-issued 2026-08-14 under I6(b).** `cq_sandwich` now pre-materialises the entire
> scratch region at step 0 (IMPLEMENTATION_PLAN.md §0.2, GAP 1). Every gate count and
> qubit count below changed. §3 carries the old figures alongside the new ones.

**Strategy selection.** `src/lowering/arith.jl:206-214` dispatches `:add` through
`_pick_add_strategy` to one of `lower_add_cuccaro!` / `lower_add_qcla!` / `lower_add!`.
`_pick_add_strategy` (`src/lowering/arith.jl:20-26`) returns `:ripple` for `:auto` since
Bennett-spa8 / U27. libcqops v1 ports the **`:ripple`** path — `lower_add!` — per
PRD-v1 §4: Cuccaro is in-place (`(a,b) → (a, a+b)`), so its uncompute is the reverse
circuit rather than a re-run, which does not match CQ_lang's `_unc(out, srcs…)`
"recompute from the still-live sources" contract. Cuccaro is ported separately as K08
(the in-place accumulator inside the multiplier). QCLA is out of v1 scope.

## 1. Julia source excerpt

`third_party/bennett/src/adder.jl` lines 1–18, verbatim:

```julia
"""Ripple-carry full adder: result = a + b  (mod 2^W)."""
function lower_add!(gates::Vector{ReversibleGate}, wa::WireAllocator,
                    a::Vector{Int}, b::Vector{Int}, W::Int)
    result = allocate!(wa, W)
    carry  = allocate!(wa, W)
    # Bennett-5kio / U109: 3 CNOTs per i + 2 Toffolis for i<W = 5W - 2 gates.
    sizehint!(gates, length(gates) + 5 * W)
    for i in 1:W
        push!(gates, CNOTGate(a[i], result[i]))
        push!(gates, CNOTGate(b[i], result[i]))
        if i < W
            push!(gates, ToffoliGate(a[i], b[i], carry[i + 1]))
            push!(gates, ToffoliGate(result[i], carry[i], carry[i + 1]))
        end
        push!(gates, CNOTGate(carry[i], result[i]))
    end
    return result
end
```

Recurrence realised (Julia is 1-based; everything below is 0-based):

- `t[i] ^= a[i]; t[i] ^= b[i]`  → `t[i] = a_i ⊕ b_i`
- `c[i+1] ^= a[i]·b[i]`, then `c[i+1] ^= t[i]·c[i]` → `c[i+1] = a_i b_i ⊕ (a_i⊕b_i) c_i = MAJ(a_i,b_i,c_i)`
- `t[i] ^= c[i]` → `t[i] = a_i ⊕ b_i ⊕ c_i` = sum bit

The order is load-bearing: the `MAJ` Toffoli at j=3 consumes `t[i]` while it still holds
`a_i ⊕ b_i`, **before** the j=4 CNOT turns it into the sum bit. `c[0]` is never written
(the loop writes `carry[i+1]` for `i < W`, i.e. `c[1..W-1]` 0-based) and is read at i=0
as a control — it is the permanently-zero carry-in.

> `c[0]`'s **value** is permanently zero. Its **kind** is not: under I6(b) it is a
> pre-materialised `CQ_BIT_Q` holding `|0⟩`, and libcqops's fold table dispatches on kind,
> never on shadow value (PRD §3, "Kind, never shadow"). That single fact is the whole
> difference between the old `11W − 8` golden and the new `11W − 4` — see §3.

## 2. Gate sequence as indexed pseudo-code

One gate per step. See §5 Delta D1 — **this granularity is mandatory, not a stylistic
choice.**

```
env: { cq_bit *dst; const cq_bit *a, *b; cq_bit *t, *c; int W; }
     t[0..W-1]  scratch sum region      (born BIT_ZERO)
     c[0..W-1]  scratch carry chain     (born BIT_ZERO; c[0] is the carry-in, never a target)

step 0 (the DRIVER's, not the kernel's) — I6(b):
     for every bit s of {t[0..W-1], c[0..W-1]}:  cq_materialise(s)
        /* 2W pool qubits; ZERO gates — scratch is born BIT_ZERO and
           cq_materialise emits an X only when the constant was 1.       */

n_compute = 5*(W-1) + 3            /* = 5W - 2 gate slots, ALL of which emit */
n_copyout = W

compute(s):
    if s < 5*(W-1):
        i = s / 5 ;  j = s % 5
        j==0 :  CX (a[i]        -> t[i]   )
        j==1 :  CX (b[i]        -> t[i]   )
        j==2 :  CCX(a[i], b[i]  -> c[i+1] )
        j==3 :  CCX(t[i], c[i]  -> c[i+1] )
        j==4 :  CX (c[i]        -> t[i]   )
    else:
        i = W-1 ;  j = s - 5*(W-1)      /* top bit: no carry-out is produced */
        j==0 :  CX (a[W-1]      -> t[W-1])
        j==1 :  CX (b[W-1]      -> t[W-1])
        j==2 :  CX (c[W-1]      -> t[W-1])

copyout(k):
        CX (t[k] -> dst[k])             /* k in [0, W) — this is the "^=" */

cq_sandwich(ctx, compute, n_compute, copyout, n_copyout, env);
/* driver: pre-materialise scratch ; compute 0..n-1 ; copyout 0..W-1 ; compute n-1..0 */
```

W=1 degenerates correctly: `5*(W-1) = 0`, so only the `j==0,1,2` tail runs —
`CX(a[0]→t[0]); CX(b[0]→t[0]); CX(c[0]→t[0])`. Under I6(b) **all three emit**: `c[0]` is
`CQ_BIT_Q`, so the third is a real `CX` from a known-`|0⟩` qubit. (Pre-decision this
folded to nothing and W=1 needed a closed-form exception; it no longer does — see §3.)

**All-classical short-circuit.** If every bit of `a` *and* every bit of `b` is `BIT_ZERO`
or `BIT_ONE`, K6 **never enters `cq_sandwich`**. It folds `a + b` to a constant `dst`
directly: **0 gates, 0 qubits, no scratch**. This is mandatory, not an optimisation —
pre-materialisation would otherwise allocate `2W` scratch qubits for a fully classical
add and break L5 (plan §0.2, consequence 2).

### I6(a) — is every compute-half gate target inside scratch?

**Yes.** Every target in `compute(s)` is `t[i]` or `c[i+1]`, both scratch. `a` and `b`
appear **only as controls**, never as targets, so the `const cq_bit *` control /
`cq_bit *` target signature split enforces I6(a) at compile time here with nothing left
to check. `dst` is touched exclusively in `copyout`, which sits outside the reversed
region. No I6(a) violation.

### I6(b) — is every scratch bit `CQ_BIT_Q` for the whole compute half?

**Yes, by the driver — and this kernel is exactly why the clause exists.** I6(a) alone is
*not* sufficient here. It guarantees no asymmetric materialisation `X` on the first touch
of a scratch **target**; it says nothing about a scratch bit read as a **control** whose
*kind* differs between passes. K6 has two such bits:

* `c[0]` — never a target, so pre-decision it stayed `BIT_ZERO` for the kernel's whole
  life and folded slots j=3 and j=4 at `i=0` away on both passes (symmetric, but 2 gates
  and 1 qubit cheaper — see §5 D8);
* `t[i]` — read as a control at j=3 and written as a target at j=4. Pre-decision, at a
  mask like `a = {Q,ZERO,ZERO}`, `b = {Q,ZERO,ZERO}`, `t[1]` was `BIT_ZERO` when j=3 read
  it forwards and `CQ_BIT_Q` when j=3 read it in reverse. **The reverse half emitted a
  `CCX` the forward half never emitted, and allocated a qubit for `c[2]`.** That is risk
  **R8**, and it is the reason for the 2026-08-14 decision.

Under I6(b) both bits are `CQ_BIT_Q` from step 0, no fold on a scratch bit can fire on
either pass, and the two halves are gate-for-gate mirrors. Re-running the witness: at
`i=1`, forward emits `CCX(t1,c1→c2)` then `CX(c1→t1)`; reverse emits `CX(c1→t1)` then
`CCX(t1,c1→c2)`. Identical multiset, exact reversal. **D2 is closed** (§5).

### 3.1 The construction count (re-derived from source)

Counting the loop in `adder.jl:8-16` directly: `for i in 1:W` (`:8`); the body
unconditionally pushes 3 `CNOTGate`s (`:9`, `:10`, `:15`) and, guarded by `if i < W`
(`:11`), 2 `ToffoliGate`s (`:12`, `:13`). No `NOTGate` anywhere in the function.

```
CNOT    = 3 · W              (three unguarded pushes, W iterations)
Toffoli = 2 · (W − 1)        (two pushes, guarded i < W ⇒ W−1 iterations)
NOT     = 0
total   = 3W + 2W − 2 = 5W − 2
```

Corroborated upstream by the comment on `adder.jl:6` — "3 CNOTs per i + 2 Toffolis for
i<W = 5W - 2 gates" — and by `sizehint!(gates, length(gates) + 5*W)` on `:7`. That is an
independent check on my reading of the loop, not a source for it.

### 3.2 What I6(b) does to that count

1. **Pre-materialisation costs qubits, never gates.** Scratch is born `BIT_ZERO`;
   `cq_materialise` emits an `X` only when the constant was 1 (PRD §3, Rule 5). Step 0
   therefore takes `2W` qubits from the pool and emits **zero** gates.
2. **No fold on a scratch bit can fire.** Every `t[i]` and every `c[i]` — including
   `c[0]` — is `CQ_BIT_Q` for the whole compute half, and the fold table dispatches on
   kind, never on shadow value (PRD §3, "Kind, never shadow"). A `CQ_BIT_Q` control whose
   shadow is known-`0` is *not* folded away; that would be D6 demotion, excluded from v1.
3. **Therefore, at the all-quantum operand mask, every one of the `5W − 2` slots emits
   exactly one gate**, and the libcqops emitted count *equals* Bennett's unfolded
   construction count. The `(S)` and `(E)` columns collapse into one.

### 3.3 Sandwiched total

Sandwiched = 2 × compute half + copyout. Copyout is `W` `CX`s (`t[k] → dst[k]`); `t[k]`
is `Q` by I6(b) and `dst[k]` is either a fresh `BIT_ZERO` (forward — materialises at 0
gates, since the constant is 0) or already `Q` (`_unc`), so it is `W` `CX` on both paths.
Copyout sits **outside** the reversed region and is not doubled.

```
CX      = 2·(3W)     + W = 7W
CCX     = 2·(2W − 2)     = 4W − 4
X       = 0
total   = 2·(5W − 2) + W = 11W − 4        check: 7W + 4W − 4 = 11W − 4  ✓
```

**W = 1 needs no exception now.** `5·1 − 2 = 3`: the three tail `CX`s all emit, because
`c[0]` is a pre-materialised qubit. `2W − 2 = 0` Toffolis, correctly. Sandwiched
`11·1 − 4 = 7 = 2·3 + 1` ✓. The pre-decision closed forms needed a `W ≥ 2` dagger; these
do not.

| | compute half | sandwiched (**the L4 golden**) |
|---|---|---|
| NOT (X)      | 0       | 0 |
| CNOT (CX)    | 3W      | 7W |
| Toffoli (CCX)| 2W − 2  | 4W − 4 |
| **total**    | 5W − 2  | **11W − 4** |

### 3.6 Cross-check against a number printed in Bennett's own source ✔

`src/lowering/arith.jl:15-16` (inside the `_pick_add_strategy` docstring) states, for
`(x,y)->x+y` at W=32:
`ripple : 346 total / T-depth 62` and `cuccaro: 408 total / T-depth 122`.

Reconstructing 346 from source (this reconstruction is *verified line by line*, not
recalled):

* Bennett's forward pass is the entry-block predicate `NOTGate` (`driver.jl:236-241` —
  `pw = allocate!(wa, 1); push!(gates, NOTGate(pw[1]))`) plus `lower_add!`.
* `_fold_constants` runs by default (`driver.jl:105` `fold_constants::Bool=true`, called
  at `:376`). Critically, it is **not** an IR-level constant-propagation pass: it is a
  *gate-level, value-driven* fold over wires (`driver.jl:407-510`), seeded with
  `known[w] = false` for **every non-input wire** (`:415-420`). It is structurally the
  same table as PRD §3 — but dispatching on **known value**, where libcqops dispatches on
  **kind**. That difference is the whole of the delta below.
* `carry[1]` (0-based `c[0]`) is a non-input wire and is never a target, so it stays
  `known == false` throughout. The CNOT arm (`:434-435`, "XOR with 0 = noop") drops
  `CNOTGate(carry[1], result[1])`; the Toffoli arm (`:462-463`, `(c1_val === false) ||
  (c2_val === false)` → noop) drops `ToffoliGate(result[1], carry[1], carry[2])`. Two gates
  gone — **the same two slots that libcqops folded pre-decision and now emits.**
* Forward `= 1 NOT + (3W − 1) CNOT + (2W − 3) Toffoli = 5W − 3`. At W=32:
  `1 + 95 + 61 = 157`.
* The wrap is `2·L + |outputs|` (`_allocate_copy_wires` / `_emit_copy_gates!`,
  `bennett_transform.jl:44-69`): `2·157 + 32 = 346` ✔ — i.e. Bennett's own end-to-end
  formula for a general two-register ripple add is `11W − 6`.
* Same model on Cuccaro (`6W − 5`, docstring `adder.jl:33-38`; nothing folds, since
  `X[1]` becomes unknown at its first use): `2·(1 + 6·32 − 5) + 32 = 2·188 + 32 = 408` ✔.

**libcqops 348 vs Bennett 346 at W=32 — the +2, fully accounted:**

```
  −2   the entry-block predicate NOT, doubled by the wrap.
       libcqops has no CFG and no path predicates (§5 D5).
  +2   the c[0]-controlled CX at i=0, doubled.   ) I6(b): kind is Q, so the
  +2   the c[0]-controlled CCX at i=0, doubled.  ) value-based fold has no analogue.
  ───
  +2   = 348 − 346                                                            ✔

This is the price of I6(b) stated exactly: **libcqops emits 4 more gates per sandwiched
general add than Bennett-with-folding, and exactly matches Bennett's unfolded
construction.** It is bought with structural, per-kernel-unforgeable reverse-half
correctness (plan §0.2). Do not "optimise" it back.

### 3.7 Precision note — "a function of `W` alone" is true for qubits, not for gates

Plan §0.2 consequence 1 says pre-materialisation makes a kernel's gate count "a function
of `W` alone". For K6, checked against the fold table rather than assumed:

* **Qubits: yes, unconditionally.** Scratch is `2W` for *any* operand mask that reaches
  the sandwich at all, because pre-materialisation is unconditional. (The all-classical
  mask never reaches it — §2.)
* **Gates: a function of `(W, operand mask)`, not of `W` alone.** Operand bits are still
  free to be classical, and an operand control still folds. Counter-example, hand-folded
  against PRD §3 at W=3, `a = {Q,ZERO,ZERO}`, `b = {Q,ZERO,ZERO}`: i=0 emits 3 CX + 2 CCX;
  i=1 emits 1 CX + 1 CCX (both `a1` and `b1` are `ZERO`, so j=0/j=1/j=2 fold away, but
  j=3/j=4 fire on the pre-materialised `t1`,`c1`); the i=2 tail emits 1 CX. Compute half
  **8**, not `5W−2 = 13`; sandwiched `2·8 + 3 = 19`, not `29`.

**What I6(b) actually buys is not mask-independence — it is pass-symmetry at every mask.**
Forward and reverse now emit the identical sequence for *any* mask (that same witness
emitted 4 forward / 5 reverse pre-decision — §5 D2), which is what makes a golden
well-defined at all. **L4 pins the all-quantum mask** (`11W − 4`); that single number per
`(kernel, W)` is sound because the all-quantum mask is one specific, reproducible mask,
not because every mask agrees with it. If L4 also pins a mixed mask, it must pin that
mask's own number.

**Why the all-quantum mask specifically — the forward/`_unc` argument (added by review,
2026-08-14).** Mask-dependence has a second consequence this section did not state, and it
bears directly on Rule 14 / PRD §10: the operand mask at the `_unc` call site need not
equal the mask at the forward call site. Because we never demote (**D6**), an in-place
`cqrt_ry`/`cqrt_rz` on a *source* between the two materialises bits that were constants at
forward time, so the mask can only ever move *towards* `Q`. A mixed-mask K6 golden is
therefore **not** safe to assert equal across the two call sites — asserting that is
exactly the R6 mistake Rule 14 forbids. **The all-quantum mask is the fixed point of that
monotone motion:** every operand bit is already `Q`, scratch is pre-materialised
identically on both calls, and `dst` costs `W` CX either way (fresh `BIT_ZERO`
materialises at 0 gates on the forward path; already `Q` on `_unc`). So at the all-quantum
mask — and, of the masks K6 can be handed, only there in general — forward and `_unc` both
emit `11W − 4`. That is an additional reason to make it *the* primary golden, and it is not
licence to pin `unc == forward` at any other mask.

### 3.8 `x + 1` at i8 — Step 12's mandated upstream validation

> **This is a CONSTANT INCREMENT and it is NOT the same circuit as K6's general
> two-register add.** `58/6/40/12` is `x + Int8(1)` at `fold_constants=true`; the literal
> collapses most of the carry chain. K6 is `add(dst, a, b)` over two live registers and
> its carry chain does not collapse. Pinning K6 against 58 would under-count by 26 gates
> and 16 Toffolis at i8 alone. BASELINES.md §4 exists to say exactly this; the correct
> K6 golden is **84**, in §3.4 above. The two are listed side by side, never substituted.

The `x+1` shape is still worth deriving, because it is the one place an upstream number
pins a circuit libcqops can reach: it is K6 invoked with `b = {BIT_ONE, BIT_ZERO×7}`.
Bennett reaches it via `_fold_constants`; libcqops reaches it natively via the PRD §3
fold table, with no pass and no wires for the constant (I4: an all-constant register owns
zero qubits). Note `b` is all-classical but `a` is not, so the §2 all-classical
short-circuit does **not** fire — the sandwich runs and scratch is pre-materialised.

Hand-folding K6 at `a` all-`Q`, `b = 1`, **under I6(b)** (`t`, `c` all `CQ_BIT_Q`):

* i=0: `CX(a0→t0)` = 1 CX; `CX(b0=ONE→t0)` → `X(t0)` = 1 X; `CCX(a0,b0=ONE→c1)` →
  `CX(a0→c1)` = 1 CX; `CCX(t0,c0→c1)` = **1 CCX** (was 0 pre-decision); `CX(c0→t0)` =
  **1 CX** (was 0). ⇒ 3 CX + 1 X + 1 CCX.
* i=1..W−2: `CX(a_i→t_i)` = 1 CX; `CX(ZERO→t_i)` = 0; `CCX(a_i,ZERO→c_{i+1})` = 0;
  `CCX(t_i,c_i→c_{i+1})` = 1 CCX; `CX(c_i→t_i)` = 1 CX. ⇒ 2 CX + 1 CCX each.
* i=W−1 (tail): `CX(a→t)` = 1 CX; `CX(ZERO→t)` = 0; `CX(c_{W−1}→t)` = 1 CX. ⇒ 2 CX.

```
compute half : X = 1,  CX = 3 + 2(W−2) + 2 = 2W + 1,  CCX = 1 + (W−2) = W − 1
               total = 3W + 1                    (W=8: 1 / 17 / 7  = 25)
sandwiched   : X = 2,  CX = 2(2W+1) + W = 5W + 2,     CCX = 2W − 2
               total = 2(3W+1) + W = 7W + 2       (W=8: 2 / 42 / 14 = 58)
```

## 4. Ancilla count

> **Re-issued 2026-08-14 under I6(b): `2W − 1` → `2W`.** The pre-decision figure excluded
> `c[0]`, which is never a gate *target* anywhere in the construction (the loop writes
> `carry[i+1]` only) and so stayed `BIT_ZERO` for the kernel's whole life under Rule 5's
> lazy per-bit allocation. I6(b) pre-materialises the **entire** scratch region, `c[0]`
> included. At W=8: 15 → **16**.

**Scratch bits: `2W`** — sum region `t[0..W-1]` (W) + carry chain `c[0..W-1]` (W).

**Qubits taken from the pool: `2W`, all at step 0, for any operand mask that reaches the
sandwich.** This is now a function of `W` alone — pre-materialisation is unconditional
and does not consult the operand kinds, so a mixed mask costs the same scratch as an
all-quantum one. (Gate counts still vary with the mask; qubits do not — §3.7.)

**Cost of step 0: `2W` qubits, ZERO gates.** Scratch is born `BIT_ZERO` and
`cq_materialise` emits an `X` only if the constant was 1 (PRD §3, Rule 5). Nothing in the
pre-materialisation loop reaches a sink. Do not add `X` gates for it — a golden that
carries `2W` extra `X`s is wrong.

**The all-classical case costs nothing at all: 0 qubits, 0 gates.** When every bit of `a`
and every bit of `b` is `BIT_ZERO`/`BIT_ONE`, K6 short-circuits **before** `cq_sandwich`
and folds `a + b` to a constant `dst` (§2). It never allocates scratch, so L5's "zero
gates and zero qubits fully-classical" is preserved. This short-circuit is load-bearing
under I6(b) in a way it was not before: without it, pre-materialisation would take `2W`
qubits for a fully classical add (plan §0.2, consequence 2).

**Peak live qubits across the kernel: `2W` scratch + `W` for `dst`**, on top of whatever
the operands already own (up to `2W`, owned by the caller's registers, not by K6). The
`W` `dst` qubits materialise during copyout on the forward path and already exist on the
`_unc` path.

Scratch returns to `|0⟩` by construction: the reverse half replays the compute half's
gates in exact reverse order, X/CX/CCX are each self-inverse, and under I6(b) the two
halves are now gate-for-gate identical at every operand mask (§2), so every scratch bit's
logical value is restored to its birth value of 0. See §5 D3 — the *shadow* cannot prove
this (poison is sticky), so the driver must establish it structurally. I6(b) makes that
obligation **larger, not smaller**: all `2W` scratch bits are now qubits that must be
released to the pool as known-zero (I3), where pre-decision `c[0]` was a constant and
needed no release at all.

## 5. Deltas from upstream

**D0 — NEW (2026-08-14): we PRE-MATERIALISE the scratch region; Bennett does not, and
upstream the question cannot even be asked.** Before the first compute step,
`cq_sandwich` takes `2W` pool qubits for `t[0..W-1]` and `c[0..W-1]` and sets every one
to `CQ_BIT_Q` (I6(b), plan §0.2). Bennett has no such step because **Bennett has no
classical operand kind at all**: `src/gates.jl:1` is `const WireIndex = Int`, and
`NOTGate`/`CNOTGate`/`ToffoliGate` (`:6-22`) carry nothing but `WireIndex` fields. Every
gate operand upstream is a wire; a wire is always "materialised"; there is no `BIT_ZERO`
kind for a scratch bit to sit in and therefore no way for the forward and reverse halves
to disagree about it. The hazard is *created* by libcqops's tri-valued bit (I1), so the
fix has to live here too.

Bennett's nearest analogue is `_fold_constants` (`src/lowering/driver.jl:407-510`,
default-on at `:105`, called at `:376`), and the comparison is the useful one:

| | Bennett `_fold_constants` | libcqops PRD §3 fold table |
|---|---|---|
| Dispatches on | the wire's **known value** (`known::Dict{Int,Bool}`, `:416-420`) | the bit's **kind** (`ZERO`/`ONE`/`Q`) — "Kind, never shadow" |
| Runs | once, as a pass over a finished gate list | inline, at every emission |
| On `c[0]` | known-`false` throughout ⇒ drops both `i=0` slots (`:434`, `:462`) | `CQ_BIT_Q` under I6(b) ⇒ emits both |

Value-driven folding is exactly D6 (shadow-driven demotion), which v1 excludes. So for the
identical construction libcqops emits **2 more gates per compute half / 4 more sandwiched**
than Bennett-with-folding, and exactly matches Bennett's *unfolded* construction. In §3.6
that `+4` is netted against D5's `−2` (the wrap-doubled entry predicate NOT, which
libcqops has no analogue for) to give the observed `348 − 346 = +2` at W=32. It is the
price of making reverse-half correctness structural instead of per-kernel. **It is not a
regression and must not be optimised away.**

**D1 — CRITICAL: the sandwich step function must be ONE GATE PER STEP.** The plan's
driver (IMPLEMENTATION_PLAN.md §0.1) is `for s in (n_compute, 0]: compute(env, s)` — it
*re-calls step `s`*. That undoes step `s` only if step `s` is an involution. **A
per-bit-index step is not an involution for ripple-carry.** Taking step `i` as the whole
5-gate loop body `g1..g5` and re-running it from the post-state:

```
forward  (t_i, c_{i+1}) : (0, 0) -> (a⊕b⊕c, MAJ(a,b,c))
re-run   g1: t=b⊕c ; g2: t=c ; g3: c_{i+1}=MAJ⊕ab=(a⊕b)c ; g4: c_{i+1}^=c·c=c ; g5: t=0
result   (t_i, c_{i+1}) = (0, (a⊕b)c ⊕ c) = (0, c·(a⊕b⊕1))   -- NOT clean
```

`c_{i+1}` is left dirty whenever `c_i = 1` and `a_i = b_i`. The correct reverse is
`g5,g4,g3,g2,g1`, which does clean it (`g5: t=a⊕b ; g4: c_{i+1}=MAJ⊕(a⊕b)c=ab ; g3:
c_{i+1}=0 ; g2,g1: t=0`). One gate per step makes the driver's index reversal *be* the
gate reversal, and is the only formulation that needs no per-kernel reverse code
(Rule 8). The alternative — a direction flag threaded into the step function so a
multi-gate step emits its gates in reverse on the backward pass — is also structural, but
it changes M09's API and must be decided before M14 is written. **This is exactly risk R1
and it is not hypothetical: it is the default reading of "step" and it silently leaks a
dirty carry qubit.**

> **I6(b) does not rescue D1.** Pre-materialisation fixes *which gates* a step emits; it
> says nothing about *what order* a multi-gate step emits them in. The algebra above is
> about gate order and is unchanged. D1 remains fully live and remains the single most
> important line in this document.

**D2 — CLOSED by I6(b) (2026-08-14). Recorded because it is the witness that motivated
the decision, and because a reader of an older copy of this file will find it presented
as live.** Pre-decision, I6 (now I6(a)) was necessary but **not** sufficient here, and
the reverse half could emit MORE gates than the forward half and allocate qubits. The old
argument for symmetry was "scratch is born `BIT_ZERO`, so materialisation there emits no
`X`" — which covers scratch bits used as *targets* but not a scratch bit used as a
**control** whose *kind* differs between passes. Step j=3 controls on `t[i]`; step j=4
(later, so *earlier* in reverse) materialises `t[i]`. The witness, hand-simulated against
the PRD §3 fold table — W=3, `a = {Q, ZERO, ZERO}`, `b = {Q, ZERO, ZERO}` (two narrow
quantum values in a wide register — the *typical* CQ_lang shape, not a corner case):

```
--- PRE-DECISION BEHAVIOUR (no longer what the code does) ---
i=1 forward :  j0,j1  -> 0 gates (a1=b1=ZERO)        t1 stays BIT_ZERO
               j2     -> 0 gates (control ZERO)
               j3  CCX(t1=ZERO, c1=Q -> c2)  -> 0 gates   [control is ZERO]
               j4  CX (c1=Q -> t1=ZERO)      -> 1 CX      [materialises t1 -> Q]
i=1 reverse :  j4  CX (c1 -> t1=Q)           -> 1 CX
               j3  CCX(t1=Q, c1=Q -> c2=ZERO)-> 1 CCX + materialise c2   [!!]
               j2,j1,j0 -> 0 gates
```

Forward emitted 1 gate at that index; the reverse emitted 2 **and allocated a qubit for
`c2`**. Full pre-decision W=3 tally: forward compute 3 CX + 1 CCX = 4; reverse compute
3 CX + 2 CCX = 5; qubits 3 forward vs 4 after the reverse. This is risk **R8**, and it is
the K6-specific instance of the hazard the plan §0.2 decision was taken to kill.

**Under I6(b) the same witness is symmetric.** `t1` and `c1` are `CQ_BIT_Q` from step 0,
so j=3 emits its `CCX` on **both** passes and j=4 its `CX` on both:

```
--- CURRENT BEHAVIOUR ---
i=1 forward :  j0,j1,j2 -> 0 gates (a1=b1=ZERO)
               j3  CCX(t1=Q, c1=Q -> c2=Q)   -> 1 CCX
               j4  CX (c1=Q -> t1=Q)         -> 1 CX
i=1 reverse :  j4  CX (c1 -> t1)             -> 1 CX
               j3  CCX(t1, c1 -> c2)         -> 1 CCX
               j2,j1,j0 -> 0 gates
```

Full W=3 tally at that mask: forward compute 5 CX + 3 CCX = 8, reverse identical, scratch
`2W = 6` qubits allocated once at step 0 and never again. Consequences of the closure:

* PRD §5's "the gate sequence is a deterministic function of `(W, operand bit-kinds)`" is
  **restored** — it no longer depends on the *evolving* kinds of scratch bits, because
  they no longer evolve.
* Plan §0.2's "step `s` emits an identical gate sequence forwards and backwards" is now
  **true for K6 at every operand mask**, which is what makes the driver's index reversal a
  genuine gate reversal.
* The Step-8 palindrome gate ("the recorded stream is a palindrome around the copyout")
  **may now be extended to K6/K7 with mixed-kind operands** — and it should be. It is the
  cheapest available regression test for a pre-materialisation bug. Pre-decision it was
  restricted to a synthetic step function.
* Peak-qubit accounting is now flat: the reverse half allocates nothing, so forward peak
  == reverse peak == `2W` scratch (§4).
* L4 may pin one golden per `(kernel, W)` at the all-quantum mask (§3.4) — but see §3.7,
  the count is still mask-dependent, so a mixed-mask golden must pin its own number.

The root cause was D6: we never demote a known-zero qubit back to a constant, so a bit
that was `BIT_ZERO` forward became a known-zero `CQ_BIT_Q` in reverse and the kind-driven
fold table emitted a real gate. I6(b) sidesteps D6 entirely by making the bit `CQ_BIT_Q`
*from the start* on both passes, rather than by adding demotion. **This whole entry — the
witness, the closure, and the fact that the closure costs `+4` gates and `+1` qubit — is
what belongs in `bd remember` before M14 is written.**

**D3 — scratch cleanliness must be established structurally, not by the shadow.** After
`CX(a_i → t_i)` with `a_i` unknown, the shadow rule `t.unknown |= c.unknown` makes `t_i`
unknown, and poison is sticky, so at scratch-free time `t_i` is an unknown-shadow qubit
even though it is physically `|0⟩`. A literal Rule 6 check would hard-error on every
sandwich kernel. `cq_sandwich` therefore has to assert-and-reset the scratch shadow on
the strength of "compute ∘ copyout ∘ compute⁻¹", which is precisely why D1 must be right.

> I6(b) makes this obligation **larger**. Pre-decision `c[0]` was a `BIT_ZERO` constant
> that needed no shadow reasoning and no release; it is now one of `2W` qubits the driver
> must hand back to the pool as known-`|0⟩` (I3). Every scratch bit is now in scope for
> D3, none is exempt.

**D4 — no `result`/`carry` wire allocation, no `WireAllocator`.** Bennett's
`allocate!(wa, W)` reserves W wire *indices* unconditionally (`wire_allocator.jl:8-28`),
and its free list is **lowest-index-first** (`free_list` sorted descending, `pop!` takes
the minimum — lines 3, 19-21). libcqops allocates lazily *per bit* at materialisation
(Rule 5) and its pool free list is **LIFO** (D4), so identical circuits will differ in
qubit *indices*. This is why kernel goldens pin counts, never traces (risk R5).

> **Amended 2026-08-14.** This entry used to add "consequence: `c[0]` costs a wire in
> Bennett and costs nothing here". That is now **false** — under I6(b) `c[0]` costs a
> qubit here too (§4), and the scratch total matches Bennett's wire total at `2W`. What
> survives is the *timing*: Bennett reserves both regions at the top of `lower_add!`
> (`allocate!(wa, W)` twice, `adder.jl:4-5`); libcqops reserves the same `2W` at the
> driver's step 0. Lazy per-bit allocation (Rule 5) still governs `dst` and the operands —
> it just no longer governs scratch.

**D5 — no global wrap, no entry predicate, no constant wires.** Bennett's totals include
the entry-block predicate NOT (`driver.jl:236-241`) and one NOT per set bit of every
constant operand (`operand.jl:22-43`). libcqops has neither. This accounts for the
`−2·(1 + popcount(K))` half of the `x+K` delta in §3.8; the other half is D0's `+4`, so
the identity to write into the golden's header comment (alongside the Bennett commit SHA,
risk R3) is `Bennett_total = libcqops_total + 2·(1 + popcount(K)) − 4`. It happens to
evaluate to **zero at K = 1**, which is a trap, not a validation — see the §3.8 box.

**D6 — `t` is scratch, not `dst`.** Bennett returns `result` as the SSA value; the caller
owns it. libcqops must copy `t` into `dst` (the `^=`) and then uncompute `t`, because
`dst` is non-zero on the `_unc` path and `t[i]` is read as a *control* at step j=3.
Writing the sum straight into `dst` would make the circuit depend on `dst`'s incoming
value and would break the "same kernel, `dst = out`" uncompute contract of PRD §4.

**D7 — a restructuring at identical gate cost; flagged, NOT taken, and now unmotivated.**
Move the sum XOR out of the compute half: keep `x[i] = a_i ⊕ b_i` in scratch, run the same
carry chain, and make the copy-out `dst[k] ^= a[k]; ^= b[k]; ^= c[k]` (3W CNOTs instead of
W). Re-derived under I6(b), the totals are still *identical* to §3.3: compute half `2W`
CX + `2(W−1)` CCX = `4W − 2`, sandwiched `2(4W−2) + 3W = 11W − 4`, with CX `2(2W) + 3W =
7W` and CCX `4W − 4`. Scratch is still `2W`. Its original motivation was that no scratch
bit is ever both a fold-eliminated control and a later materialisation target, so D2
disappeared — **but I6(b) already removes D2 structurally and for every kernel, so that
motivation is gone.** The cost that remains is real: Rule 9 / plan §0.1 promote **only the
copyout steps**, so a controlled add would emit `3W` Toffolis instead of `W`. It is also a
**deviation from `lower_add!` verbatim** (Rule 1). Recorded for completeness only. **Do
not adopt.**

**D8 — NEW (2026-08-14): `c[0]` could legitimately be exempted from pre-materialisation,
saving 1 qubit and 4 sandwiched gates. FLAGGED, NOT TAKEN. This is not a recommendation.**
Honesty demands it be written down, because a reader will notice it. `c[0]` is the one
scratch bit that is **never a gate target on either pass** (the loop writes `carry[i+1]`
only, `adder.jl:12-13`), so its kind cannot change during the compute half. Leaving it
`BIT_ZERO` would fold slots j=3 and j=4 at `i=0` away **symmetrically on both passes** —
it is sound, and it would restore `5W − 4` / `11W − 8` / `2W − 1` (80 at W=8). Rejected
anyway, on three grounds:

1. It reintroduces exactly the per-kernel reasoning obligation that I6(b) exists to
   abolish — "this scratch bit is safe to leave classical *because* it is never a target"
   is a proof each kernel author would have to redo, and get right, twelve times. Plan
   §0.2 rejects the general form of this trade ("unenforceable by the `const`-qualification
   mechanism, which only guards targets") for the same reason.
2. It would trip the plan's own debug check — "on entry to a compute half, assert every
   scratch bit is already `CQ_BIT_Q`" — so taking it means weakening the enforcement
   mechanism at the same time.
3. It is a **deviation from `lower_add!` verbatim**, which allocates `carry` as a full
   `W`-wire region unconditionally (`adder.jl:5`). Rule 1: port, never re-derive.

If anyone ever wants the qubit back, the decision belongs in `IMPLEMENTATION_PLAN.md`
§0.2 as an amendment to I6(b), not in `kernels/add.c`. **Do not take it silently.**
