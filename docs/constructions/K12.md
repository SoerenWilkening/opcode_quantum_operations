The compute half leaves, per division iteration, the whole comparator chain (`nb`,
`carry`, `axnb`, the `ult` bit, the `fits` bit), the whole subtractor chain (`nsb`,
`diff`, `scarry`), and the mux's `diff` register sitting at arbitrary values. None of

`aggregate.jl:150-172` says so in as many words for `_cond_negate_inplace!`: *"The wires
ARE returned to zero by Bennett's outer reverse pass at simulate time … they just stay
allocated"*, and `aggregate.jl:119-127` says the same for the 64-bit division result.
libcqops has no global wrap, so K12 gets the local wrap (Bennett-in-the-small, PRD §5).

> **Do not `cqrt_free` anything inside K12's compute half.** The remainder's dropped top
> bit is provably `0` mathematically (see §2, shift-in) but the two-bit shadow cannot
> prove it — it is a qubit of unknown value. A mid-kernel free is exactly the Rule 6
> hard error, and it would be firing correctly. The sandwich reverse is the only thing
> that returns K12's scratch to `|0⟩`.

```julia
function _soft_udiv_compile(a::UInt64, b::UInt64)::UInt64
    q = UInt64(0)
    r = UInt64(0)
    for i in 63:-1:0
        # Shift remainder left, bring in bit i of a
        r = (r << 1) | ((a >> i) & UInt64(1))
        # Trial: can we subtract b?
        fits = r >= b
        r = ifelse(fits, r - b, r)
        q = ifelse(fits, q | (UInt64(1) << i), q)
    end
    return q
end
```

```julia
    r = UInt64(0)
    for i in 63:-1:0
        r = (r << 1) | ((a >> i) & UInt64(1))
        fits = r >= b
        r = ifelse(fits, r - b, r)
```

```julia
function _cond_negate_inplace!(gates::Vector{ReversibleGate}, wa::WireAllocator,
                               val::Vector{Int}, cond::Vector{Int}, W::Int)
    # Two's complement negate = flip all bits + add 1
    # Conditional flip: CNOT(cond, val[i]) for each bit
    for i in 1:W
        push!(gates, CNOTGate(cond[1], val[i]))
    end
    # Conditional add 1: ripple carry adding cond[1] to val
    carry = allocate!(wa, 1)
    push!(gates, CNOTGate(cond[1], carry[1]))  # carry starts as cond
    for i in 1:W
        # val[i] += carry; new_carry = val[i] AND carry (before add)
        next_carry = allocate!(wa, 1)
        push!(gates, ToffoliGate(val[i], carry[1], next_carry[1]))
        push!(gates, CNOTGate(carry[1], val[i]))
        carry = next_carry
    end
end
```

```julia
function lower_sub!(gates::Vector{ReversibleGate}, wa::WireAllocator,
                    a::Vector{Int}, b::Vector{Int}, W::Int)

    # Bennett-5kio / U109: 2W gates for ~b; carry_in = 1 NOTGate; then
    # adder body 5W - 2 gates ⇒ ~7W total.
    sizehint!(gates, length(gates) + 7 * W + 1)
    for i in 1:W
        push!(gates, CNOTGate(b[i], not_b[i]))
        push!(gates, NOTGate(not_b[i]))

    carry  = allocate!(wa, W)
    push!(gates, NOTGate(carry[1]))        # carry_in = 1

function lower_ult!(g, wa, a, b, W)
    nb = allocate!(wa, W)
    for i in 1:W; push!(g, CNOTGate(b[i], nb[i])); push!(g, NOTGate(nb[i])); end
    carry = allocate!(wa, W + 1)
    push!(g, NOTGate(carry[1]))
    axnb = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(a[i], axnb[i])); push!(g, CNOTGate(nb[i], axnb[i]))
        push!(g, ToffoliGate(a[i], nb[i], carry[i + 1]))
        push!(g, ToffoliGate(axnb[i], carry[i], carry[i + 1]))
    end
    r = allocate!(wa, 1)
    push!(g, CNOTGate(carry[W + 1], r[1])); push!(g, NOTGate(r[1]))
    return r
end

function lower_not1!(g, wa, w::Vector{Int})
```

## 2. Gate sequence as indexed pseudo-code

### 2.0 The width claim that makes a W-bit remainder legal

Bennett runs the loop 64 iterations on 64-bit registers regardless of the source width
(`aggregate.jl:52-66` widens, `aggregate.jl:128-131` truncates). libcqops runs **W
iterations on W-bit registers**. That is only sound if the W-bit remainder never
overflows, so here is the derivation, from the source loop:

Let `P_k = ⌊a / 2^(W−k)⌋` be the value of the top `k` bits of `a`. The loop invariant
after `k` iterations is `r_k = P_k mod b` (and for `b = 0`, `r_k = P_k`, since
`fits = r >= 0` is always true and `r − 0 = r`). Either way `r_k ≤ P_k < 2^k`.

* **The dropped bit is zero.** Iteration `k+1` (with `k ∈ [0, W−1]`) shifts `r_k` left,
  discarding bit `W−1`. From `r_k < 2^k ≤ 2^(W−1)`, bit `W−1` of `r_k` is `0`. Always.
* **The shifted value fits.** `r' = 2·r_k + a[W−1−k] ≤ 2(2^k − 1) + 1 = 2^(k+1) − 1 < 2^W`
  because `k+1 ≤ W`.

So a W-bit remainder register is exactly sufficient — no `W+1`-bit window is needed, and
the comparator/subtractor run at width W. **This derivation is load-bearing; if a future
reader doubts it, widen `r` to W+1 bits rather than guessing.** The conservative variant
costs `C_ult(W+1) + C_sub(W+1) + C_mux(W+1)` per iteration instead of the width-W ones.
*(§2.0's derivation is no longer only a derivation: an exhaustive L1 sweep over every `(a,b)`
including `b = 0` at `W ∈ {1,2,3,4}`, for **both** `udiv` and `urem`, reproduces plain C —
see §6.0a. `urem` is the stronger half of that test, since it reads the remainder chain out
directly.)*

### 2.1 Vocabulary and scratch layout

`W` = register width. Iteration counter `t ∈ [0, W)`; the dividend bit consumed at
iteration `t` is `i = W − 1 − t` (the source counts `i` down from 63).

Scratch allocated **fresh per iteration `t`** (the flat scheme — settled 2026-08-16 as
PRD §15 **D9**; see §4 for the alternative that was measured and rejected):

| name | bits | role |
|---|---|---|
| `z[t]` | 1 | the incoming dividend bit slot; `r_in[t][0]` |
| `nb[t]` | W | `~b`, inside the comparator |
| `ucar[t]` | W+1 | comparator carry chain — **`ucar[t][W]` IS `fits[t]`** |
| `axnb[t]` | W | `a ⊕ ~b`, inside the comparator |
| `nsb[t]` | W | `~b`, inside the subtractor |
| `diff[t]` | W | `r' − b` |
| `scar[t]` | W | subtractor carry chain |
| `rnext[t]` | W | mux output — the next remainder |
| `mdiff[t]` | W | mux's internal `tv ⊕ fv` |

`8W + 2` bits per iteration. Allocated **once** for the whole kernel:

| name | bits | role |
|---|---|---|
| `q[0..W−1]` | W | unsigned quotient (`udiv`/`sdiv` only) |
| `r0_hi[0..W−2]` | W−1 | **the upper bits of the initial remainder `r_0 = 0`** — see the I6(b) note below and §3.6 |

> **THERE IS NO `ult[t]` AND NO `fits[t]` WIRE, AND THAT IS D9(b), NOT A PEEPHOLE
> [DECIDED 2026-08-16].** `lower_ult!` builds a full ripple-carry chain whose carry-out
> `carry[W+1]` is `1` exactly when `a >=u b` — that *is* `fits`. Bennett allocates a separate
> `r` wire and negates twice only because `uge` reaches it through the generic `lower_icmp!`
> dispatcher (`arith.jl:414`), which must return a wire. **libcqops's own `uge` already
> declines that**: `src/kernels/cmp.c`'s `PRIM_ULT` sets `raw = &carry[W]` and
> `cq_kernel_uge` copies it out unchanged, which is `K09.md` §5 delta 2 — Bennett's double
> negation folding into the copy-out. K12 composes *libcqops kernels*, not Bennett's IR
> shape (PRD §6), so using a second, more expensive realisation of `uge` inside K12 than the
> one M16 ships would be the anomaly. Worth `4W` gates and `2W` qubits (§5 delta 11).

**Every one of these bits is scratch, and under I6(b) `cq_sandwich` pre-materialises the
whole lot at step 0** (plan §0.2). Pre-materialisation emits **no gates** — scratch is born
`CQ_BIT_ZERO` and `cq_materialise` emits an `X` only for a constant `1` — so step 0 costs
**qubits, never gates**.

`r_in[t]` is a **view, not a register**: `r_in[t][0] = z[t]`, and
`r_in[t][j] = rnext[t−1][j−1]` for `j ∈ [1, W)`. The left shift is therefore a
relabelling of `cq_bit` array entries and costs **zero gates and zero qubits** (Rule 3 —
a `cq_bit` is a value, not a wire). `r_in[0]` is `z[0]` plus the `W−1` bits of `r0_hi`.
**`r0_hi` is a real scratch register, not a run of literal `CQ_BIT_ZERO` entries
[CHANGED 2026-08-14 under I6(b), CONFIRMED 2026-08-16 as D9(d)]** — as literals they would
fold, iteration `t = 0` would stop costing what every other iteration costs, and the slot
decode would need a `t = 0` branch. §3.6 has both self-consistent options in full. The
dropped top bit `rnext[t−1][W−1]` is simply left in scratch; the sandwich reverse cleans it.

### 2.1a The remainder tape — what makes `r_in[t]` CONTIGUOUS, and why that is required

**A reused step function takes `const cq_bit *a` and indexes it, so `r_in[t]` has to be one
contiguous run of `cq_bit`.** It is, at no cost in gates or qubits, if `z[t]` is laid
immediately *below* `rnext[t−1]`:

```
block 0 :  z[0]  r0_hi[0..W-2]                          W   slots
block b :  z[b]  rnext[b-1][0..W-1]     b in [1, W)     W+1 slots
block W :        rnext[W-1][0..W-1]                     W   slots

r_in[t] = the first W slots of block t
        = z[t] ++ rnext[t-1][0..W-2]        <- the left shift, 0 gates, 0 qubits
```

so `rnext[t−1][W−1]` — the dropped top bit, provably `0` by §2.0 — is the *last* slot of
block `t` and nothing reads it again. Offsets are a pure function of `t`:
`off(0) = 0`, `off(b) = W + (b−1)(W+1)` for `b ∈ [1, W]`, and
`rnext[t] = &tape[off(t+1) + (t+1 < W ? 1 : 0)]`. The whole tape is
`W² + 2W − 1` bits, which is exactly `z` (`W`) + `rnext` (`W²`) + `r0_hi` (`W−1`) — the
contiguity is free, not paid for.

**`r_in[t]` deliberately ALIASES `rnext[t−1]`.** That is legal and is the point: `r_in[t]`
is read *only as controls* (by the comparator, by the subtractor, and as the mux's `f` arm),
while the iteration's targets are `z[t]`, the inner block and `rnext[t]` — all disjoint from
it. `cq_scratch_span` hands out sub-arrays of one region for exactly this
(`kernels/kernel.h`), and the I6(a) extent check is a pointer *range* test, so a sub-array
view is what it is built to accept.

At `W = 1` the tape degenerates cleanly: `r0_hi` is empty, block 0 is `z[0]` alone, block 1
is `rnext[0]`, and the tape is `1 + 2 − 1 = 2` bits. No special case is needed anywhere.

**The shift offset must be recomputed from `t`, never carried in mutable state** — the
sandwich driver replays step indices in reverse, so every index the step function uses
has to be a pure function of `s`.

### 2.2 The step function

Per plan §0.1 the compute half is an indexed step function. Let

```
K(W) = 17W + 2          /* compute-half STEP SLOTS per division iteration, udiv/sdiv */
     = 17W + 1          /*                                                urem/srem  */
n_compute = W * K(W)    /* = 17W^2 + 2W slots, for udiv */
```

**`K(W)` is a slot count. [REVISED 2026-08-14 under I6(b); RE-REVISED 2026-08-16 under D9(b),
which removed the four-slot `not1(ult(…))` tail.]** It used to differ from the gate count:
three separate fold-table elisions fired inside the compute half and the emitted
total came out `17W² − 2W + 7`. **Under I6(b) none of them can fire** — every scratch bit is
`CQ_BIT_Q` from step 0, so no gate whose only classical operand was a scratch bit folds any
more (§3.1a). For the all-operands-quantum mask that L4 pins, **one slot emits exactly one
gate** and `n_compute = 17W² + 2W` is both the slot count and the gate count.

**THE THREE INNER PHASES ARE SHIPPED STEP FUNCTIONS, NOT TRANSCRIPTIONS [D9(e), bd `4tt`].**
P1 is M16's `lower_ult!` compute half, P2 is M14's `k7_compute`, P3 is M17's `cq_mux_step`.
K12 re-transcribes **nothing**; it maps a contiguous run of its own slot indices onto each
block's own index, exactly as M12's barrel does with `cq_mux_step` and M18's multiplier does
with `cq_addacc_step`. The pseudo-code below is therefore a *specification of the operand
bindings and the slot arithmetic*, not a second copy of the gate lists — the gate lists are
in `src/kernels/cmp.c`, `src/kernels/add.c` and `src/kernels/mux.c`, and they are already
tested there. Reading it as something to re-type is the mistake this note exists to prevent.

The distinction is still worth keeping in the driver's vocabulary, because folds on
**source** bits survive: a classical `b` still elides `CX(b[k] → nb[t][k])`. Those are
mask-dependent, they are *symmetric* across the two halves (a source is never materialised
inside a compute half, I6(a)), and they can only ever make the count **smaller than or equal
to** the golden — never larger. (Equal is reachable, not just a theoretical bound: a
`CQ_BIT_ONE` source turns `CX(c,t)` into `X(t)`, one gate for one gate, so an all-`ONE` `b`
emits exactly the all-quantum count. It is an all-`ZERO` `b` that shrinks it.)
The driver must index *slots*, not gates, so that a slot emitting nothing forward is still
visited backward.

and decode `s ∈ [0, n_compute)` as `t = s / K(W)`, `j = s % K(W)`, `i = W − 1 − t`.
Phase boundaries inside an iteration (all closed-form in `W`):

| `j` range | phase | owner | gates in phase |
|---|---|---|---|
| `0` | P0 shift-in | M19 | 1 |
| `[1, 6W+1]` | P1 `fits = uge(r_in, b)` | **M16** `lower_ult!` compute half | `6W+1` |
| `[6W+2, 13W]` | P2 `diff = sub(r_in, b)` | **M14** `k7_compute` | `7W−1` |
| `[13W+1, 17W]` | P3 `rnext = mux(fits, diff, r_in)` | **M17** `cq_mux_step` | `4W` |
| `17W+1` | P4 quotient bit (`udiv`/`sdiv` only) | M19 | 1 |

```
step(s):
  K = 17W + (is_div ? 2 : 1)
  t = s / K;  j = s % K;  i = W-1-t
  r = r_in[t]                       /* the relabelled contiguous view, 0 gates */

  /* ---- P0 : r_in[t][0] ^= a[i]  (the "| ((a >> i) & 1)") ---- */
  j == 0                ->  CX( a[i] -> r[0] )                      /* r[0] IS z[t] */

  /* ---- P1 : fits[t] = (r >=u b), M16's ult step, index j-1 in [0, 6W+1) ----
     bindings: ua = r,  ub = b,  nb = nb[t],  carry = ucar[t],  axnb = axnb[t]
     fits[t] IS ucar[t][W] -- the carry-out of r + ~b + 1.  No ult/fits wires. */
  j in [1, 6W+1]        ->  cq_ult_step(ua=r, ub=b, nb[t], ucar[t], axnb[t], W, j-1)

  /* ---- P2 : diff[t] = r - b, M14's k7_compute, index j-(6W+2) in [0, 7W-1) ----
     bindings: a = r,  b = b,  nb = nsb[t],  t = diff[t],  c = scar[t]          */
  j in [6W+2, 13W]      ->  cq_sub_step(a=r, b=b, nsb[t], diff[t], scar[t], W, j-(6W+2))

  /* ---- P3 : rnext[t] = fits ? diff : r, M17's cq_mux_step, index j-(13W+1) ----
     bindings: cond = &ucar[t][W],  t = diff[t],  f = r,  r = rnext[t],  d = mdiff[t] */
  j in [13W+1, 17W]     ->  cq_mux_step(block, j-(13W+1))

  /* ---- P4 : q[i] ^= fits.  udiv/sdiv only. ---- */
  j == 17W+1            ->  CX( ucar[t][W] -> q[i] )
```

**Two orderings inside that decode are load-bearing.** P3's mux reads `diff[t]`, so it must
follow P2; and P3's `f` arm is `r_in[t]`, which P0 completes — so P0 must precede P1, P2 and
P3, and it does. Everything else about the *phase* order is free, because each phase writes
only its own sub-arrays. (The order *within* each phase is Bennett's and is already enforced
where it is transcribed — that is the whole point of not re-typing it here.)

Copy-out steps (the `^=` of the kernel contract), run once between the forward and
reverse halves:

```
copyout(c) for c in [0, W):
    udiv / sdiv :  CX( q[c]          -> dst[c] )
    urem / srem :  CX( rnext[W-1][c] -> dst[c] )
```

### 2.3 Signed wrapper (M20)

Prefix (before the core) and suffix (after it), all targets scratch:

```
/* prefix — 2W CX, then two conditional negates */
for c in [0,W):  CX( a[c] -> sa[c] )          /* |a| starts as a  */
for c in [0,W):  CX( b[c] -> sb[c] )          /* |b| starts as b  */
condneg(sa, ctrl = a[W-1])                    /* a[W-1] is a CONTROL, never a target */
condneg(sb, ctrl = b[W-1])

/* core: run §2.2 on (sa, sb) instead of (a, b) */

/* suffix */
sdiv :  CX( a[W-1] -> rs );  CX( b[W-1] -> rs );  condneg(q,          ctrl = rs )
srem :                                            condneg(rnext[W-1], ctrl = a[W-1])

/* condneg(val[0..W-1], ctrl) — aggregate.jl:174-191, transcribed */
for c in [0,W):  CX( ctrl -> val[c] )         /* conditional bit flip */
                 CX( ctrl -> ncar[0] )        /* carry starts as ctrl */
for c in [0,W):  CCX( val[c], ncar[c] -> ncar[c+1] )
                 CX ( ncar[c]         -> val[c] )
```

Bennett copies the sign bit into a fresh wire first (`aggregate.jl:76-77`) because its
`_cond_negate_inplace!` mutates `a64`/`b64` in place and would otherwise clobber its own
control. libcqops does not need that copy for `sa`/`sb`: `a[W−1]` and `b[W−1]` are
**sources**, used only as controls, and `sa`/`sb` are separate scratch registers. The
`rs` wire for `sdiv` is still needed — it holds `sign(a) ⊕ sign(b)`.

### 2.4 I6(a) targets, I6(b) controls

#### 2.4a I6(a) — every compute-half gate target is scratch

Walk the target column of every emission above:

| phase | targets | in scratch? |
|---|---|---|
| P0 | `z[t]` (= `r_in[t][0]`) | ✔ |
| P1 | `nb[t]`, `ucar[t]`, `axnb[t]` | ✔ |
| P2 | `nsb[t]`, `scar[t]`, `diff[t]` | ✔ |
| P3 | `mdiff[t]`, `rnext[t]` | ✔ |
| P4 | `q[i]` | ✔ |
| signed prefix/suffix | `sa`, `sb`, `ncar`, `rs`, and `condneg`'s in-place `val` ∈ {`sa`, `sb`, `q`, `rnext[W−1]`} | ✔ |

`a`, `b` and `dst` never appear as a target in the compute half. `a[i]`, `b[k]`,
`a[W−1]`, `b[W−1]` appear **only as controls**. `dst` is touched only by the copy-out,
which is outside the compute half by construction. **I6 holds for K12 in both the
unsigned and the signed form.**

**The tape's aliasing does not weaken this, and it is worth walking once.** `r_in[t]` is a
view over `z[t] ++ rnext[t−1]` (§2.1a), so it *aliases a register a previous iteration
wrote*. Every use of `r_in[t]` after P0 is a **control** — the comparator's `ua`, the
subtractor's `a`, the mux's `f` — and the only target inside it is `z[t]`, at P0, which no
earlier iteration touches. The iteration's own targets (`nb`/`ucar`/`axnb`/`nsb`/`diff`/
`scar`/`mdiff`, all in block `t` of the inner region, plus `rnext[t]`, which is block `t+1`
of the tape) are disjoint from `r_in[t]` at every `t`, including `t = 0` and `t = W−1`.
**Measured 2026-08-16** by running the whole construction under `CQOPS_DEBUG_INVARIANTS`,
where `src/emit.c`'s I6(a) extent check is live: green at `W ∈ {1,2,3,4,8,16,32,64,128}`.

**The one way to break it, loudly flagged.** Bennett's `_cond_negate_inplace!` takes its
`val` argument **in place** and its sole caller passes `a64`/`b64` — Bennett's *own
widened copies*, not the user's operands. A port that "saves the copy" by passing the
caller's `a`/`b` straight in would (i) violate I6, (ii) violate the kernel contract's
"leaving `a` and `b` unchanged", and (iii) be a silent miscompile whose reverse half
still cancels, so L1/L3 would stay green. The `cq_emit_*` signature (`const cq_bit *`
controls, `cq_bit *` targets) makes it a compile error — do not cast it away.

#### 2.4b I6(b) — every scratch bit is `CQ_BIT_Q` for the whole compute half

Guaranteed by the driver, not by this kernel: `cq_sandwich` pre-materialises the entire
scratch region (§2.1) at step 0. Nothing in K12's step function has to arrange it, and
nothing in K12's step function may rely on a scratch bit still being classical.

**K12 *is* where risk R8 bites. [CORRECTED 2026-08-14 — this section previously asserted the
exact opposite; see the correction log.]** Walk every scratch bit K12 reads as a control and
ask the R8 question — *is it read as a control while still classical, and materialised by a
**later** gate?* The trap the previous revision fell into is that **"written" and
"materialised" are not the same thing**: a write whose sources are all classical *folds*, and
leaves its target classical.

| scratch control | materialised by | first read as control | R8? |
|---|---|---|---|
| `z[t]`, `nb[t][k]`, `nsb[t][k]`, `axnb[t][k]` | P0 / P1 / P2 loop 1 | after | no |
| `mdiff[t][k]` | P3 sub-slots 1–2 | sub-slot 3, then never a target again | no |
| **`diff[t][k]`** | **`CX(scar[t][k] → diff[t][k])` — the *last* gate of the `k` group** | **the `CCX(diff[t][k], scar[t][k] → scar[t][k+1])` immediately *before* it** | **YES** |
| `ucar[t][k]`, `scar[t][k]` (`k ≥ 1`) | group `k−1` | group `k`, then never a target again | no |
| `ucar[t][0]`, `scar[t][0]` | the carry-seed `X` | slot after | no — written first |
| `ucar[t][W]` (= `fits[t]`) | P1's last `k` group | P3, P4 — then never a target again | no |
| `rs`, `ncar[c]`, `val[c]` | preceding slot | after | no |
| `r0_hi[j]` | **never a target** | P1/P2/P3 at `t = 0` | no — never materialised mid-half |

**The `diff[t][k]` witness, read out of the pinned source.** `lower_sub!`'s body
(`adder.jl:147-155`) emits, per `i`:

```
CNOT(a[i],     result[i])                 /* r[k]   -> diff[t][k]           */
CNOT(not_b[i], result[i])                 /* nsb[k] -> diff[t][k]           */
Toffoli(a[i], not_b[i], carry[i+1])
Toffoli(result[i], carry[i], carry[i+1])  /* diff[t][k] read as a CONTROL   */
CNOT(carry[i], result[i])                 /* diff[t][k] targeted AGAIN, after */
```

If `r[k]` and `nsb[t][k]` are *both* classical when the first two `CX`s run, both fold and
`diff[t][k]` is **still classical** at the `Toffoli` — which therefore folds as well. The very
next gate, `CX(scar[t][k] → diff[t][k])`, has a quantum control and **materialises it**. On
the reverse pass `diff[t][k]` is already `CQ_BIT_Q` when that `Toffoli` is replayed, so the
reverse emits a `CCX` the forward never emitted. The halves stop mirroring, scratch is left
dirty, and **L1 stays green**. That is R8 verbatim.

The precondition is easy to hit: `nsb[t][k]` is classical for the whole compute half whenever
`b` is classical. Smallest witness found by replaying §2.2's gate list under the PRD §3 fold
table: **`W = 3`, `a` all `CQ_BIT_Q`, `b` all `CQ_BIT_ZERO`** (all `CQ_BIT_ONE` also
witnesses), diverging at `t = 0`, `k = 1` on `CCX(diff[0][1], scar[0][1] → scar[0][2])`.
`W ∈ {1,2}` do **not** witness it. Put that mask in the fixed L1/L2/L3 mask set — a regression
must not depend on random masks to be caught.

**Which test layer would have caught it, under the old rules.** Replaying forward-vs-reverse
over the operand masks separates into three regimes, and the middle one is the alarming one:

| mask | gate order | gate multiset | **total count** | caught by |
|---|---|---|---|---|
| `a` all `ONE`, `b` `Q` | broken | **same** | same | nothing — a benign reorder of a materialisation `X` past disjoint gates; the net permutation is still the inverse |
| **`a` `Q`, `b` all `ZERO`** | broken | **different** | **same** (116/204/318/458/816 at `W`=3/4/5/6/8) | **L2/L3 only** — L1 green *and* **L4 green**, because the count is unchanged while the gates are not |
| `a` `Q`, `b` all `ONE` | broken | different | **different** (322 vs 328 at `W = 8`) | L4, and L2/L3 |

The middle row is why a gate-count golden is not a defence against R8 and why L2/L3 are not
optional (CLAUDE.md's Prime Directive, in one table). Under I6(b) all three regimes collapse:
every scratch bit is `CQ_BIT_Q` from step 0, so nothing folds on scratch, and the two halves
are identical gate-for-gate by construction.

**So I6(b) fixes a real K12 bug; it is not only a cost change.** This is the same hazard
`K07.md` §5 D2 records against `lower_add!`'s sum register `t[i]`, and K12 inherits it through
`lower_sub!`, whose `result[i]` has the identical shape. K07's rule — *a scratch bit is
pass-symmetric iff it is never materialised, or is materialised on the first gate that targets
it* — is exactly what `diff[t][k]` breaks. **Do not exempt K12 from pre-materialisation**, and
do not restore the "K12 was already safe" reading this section used to carry.

None of this moves §3's arithmetic: under I6(b) every bit in the table above is `CQ_BIT_Q`
from step 0, so the folded variants cannot arise at all and the pinned counts are unchanged.

not fire, and anyone working from a pre-2026-08-14 note will now **under**-count by 1 X and
1 CCX per `ult`. That is a genuine cross-check of §3.1's `C_ult`, arrived at by a different
reader from the same pinned source — and it is now settled by execution besides: M16's
shipped `ult` golden is `12W + 4`, whose compute half is `(12W+4−2)/2 = 6W+1`.)*

**Fold 2 — the `sub` carry seed, was worth `−1 CCX` per iteration.** `lower_sub!`'s
`NOT(carry[1])` (`adder.jl:161`) is the same shape: it used to emit nothing and set
`scar[t][0] := ONE`, after which `ToffoliGate(result[1], carry[1], carry[2])` degraded to
`CX(diff[t][0] → scar[t][1])` and `CNOTGate(carry[1], result[1])` degraded to
`X(diff[t][0])` (those two deltas cancelled in X and CX, leaving `−1 CCX`).
Pre-materialised, none of it happens. ⇒ `C_sub(W) = 7W − 1`, tuple `(W+1, 4W, 2W−2)`.
*(Counterfactual: `7W − 2`, `(W+1, 4W, 2W−3)`.)*

**Fold 3 — the `t = 0` remainder, was worth `6W − 7` gates, once.** `r_in[0]`'s upper `W−1`
entries hold the constant `r_0 = 0`. As literal `CQ_BIT_ZERO` values they made every gate
that reads `r[k]`, `k ≥ 1`, as a control vanish at `t = 0`, and every `CX` copying one emit
nothing — a `−(2W−2)` CX, `−(2W−3)` CCX, `−(2W−2)` CX saving across P1/P2/P3. As the
pre-materialised scratch register `r0_hi` (§2.1) they are qubits and nothing folds, so
**`t = 0` costs exactly what every other iteration costs**. This is the one fold whose death
is a *layout* consequence rather than a direct consequence of I6(b), and it is the difference
between `34W² + 5W` and `34W² − 7W + 14`. It is set out in full, with the counterfactual
arithmetic, in **§3.6** — read that before pinning.

`lower_mux!` and `_cond_negate_inplace!` folded **nothing** before the decision and fold
nothing after it — neither seeds a scratch bit with a constant, and every control they use
was already a qubit. `C_mux(W) = 4W` and `C_condneg(W) = 3W + 1` are unchanged. (For `mux`
this is checked against `K10.md` in §3.0 rather than assumed.)

**One further simplification falls out: there is no `W = 1` special case any more.** The old
`(E)` figures needed a hand-counted `W = 1` row, because at `W = 1` `lower_sub!`'s `i < W`
guard kills both Toffolis and fold 2's `CCX → CX` half had nothing to fire on. With no folds,
the closed forms below are exact at `W = 1` — verified by hand-executing all four loop bodies
at `W = 1` in §6.

### 3.2 The composition — `udiv`

Substituting §3.1's primitive costs into §3.0's symbolic form, per division iteration:

```
C_iter(W) = 1 + C_ult(W) + C_sub(W) + C_mux(W) + 1
          = 1 + (6W + 1)  + (7W − 1) + (4W)     + 1
          = 17W + 2
```

which is the symbolic `W · (C_K7(W) + C_K9(W) + C_K10(W))` the PRD's K12 row calls for
(PRD §6, "| K12 | `divrem(dst,a,b)`" — `PRD-v1.md:631 @ 961905f`; re-anchored 2026-08-14
from a stale `:276`, and converted to the pinned form 2026-09-10, `bd 0a7`, because that
re-anchor was stale again by then), with the two additive
per-iteration terms being the dividend-bit shift-in
(1 CX) and the quotient-bit accumulation (1 CX). There are **no additive terms outside the
loop** for `udiv`/`urem`; the signed wrapper adds a fixed prefix/suffix (§3.4).

Per-iteration column sums, from the §3.1 tuples:

| | X | CX | CCX | total |
|---|---|---|---|---|
| P0 shift-in | `0` | `1` | `0` | `1` |
| P1 `ult` (M16) | `W+1` | `3W` | `2W` | `6W+1` |
| P2 `sub` (M14) | `W+1` | `4W` | `2W−2` | `7W−1` |
| P3 `mux` (M17) | `0` | `3W` | `W` | `4W` |
| P4 quotient bit | `0` | `1` | `0` | `1` |
| **per iteration** | **`2W+2`** | **`10W+2`** | **`5W−2`** | **`17W+2`** |

Multiply by `W` for the compute half; double and add the `W` copy-out CNOTs for the
sandwiched total:

| gate | compute half | **sandwiched total** `= 2× + W` CX |
|---|---|---|
| X (NOT) | `2W² + 2W` | `4W² + 4W` |
| CX (CNOT) | `10W² + 2W` | `20W² + 5W` |
| CCX (Toffoli) | `5W² − 2W` | `10W² − 4W` |
| **total** | **`17W² + 2W`** | **`34W² + 5W`** |

*(Counterfactuals, do not pin: with the retired `not1(ult(…))` flag, compute `17W² + 6W` and
sandwiched `34W² + 13W`; pre-I6(b), compute `17W² − 2W + 7` and sandwiched `34W² − 3W + 14`.)*

**Slots and gates now coincide.** §2.2's step-index decode has `17W + 2` slots per iteration
and `n_compute = W · (17W + 2) = 17W² + 2W`. For the all-operands-quantum mask that L4 pins,
every slot emits exactly one gate, so that number is simultaneously the driver's slot count
and the sink's gate count. Keeping the two *concepts* separate still matters — a classical
`b` elides source-controlled `CX`s, and those slots must still be visited on the reverse
pass — but the two *numbers* no longer diverge at the golden mask.

`urem` drops the `q` register and the P4 quotient CX entirely (`divider.jl:50-58` has no

| gate | compute half | **sandwiched total** |
|---|---|---|
| X | `2W² + 2W` | `4W² + 4W` |
| CX | `10W² + W` | `20W² + 3W` |
| CCX | `5W² − 2W` | `10W² − 4W` |

### 3.4 `sdiv` / `srem`

Fixed prefix `2W` CX (copy `a`,`b` into `sa`,`sb`) `+ 2 · C_condneg(W)`; fixed suffix

folds nothing after it** (§3.1a), so the prefix/suffix cost is unchanged; the whole delta is
inherited from the core. `sdiv` builds on the `udiv` core, `srem` on the `urem` core.

### 3.6 `r_0` — RESOLVED 2026-08-16 as D9(d): a pre-materialised scratch register

**This section used to say "read this before pinning, and do not resolve it in code". It is
resolved now, in the PRD, and this section records why and what the alternative cost.**

I6(b) pre-materialises *the scratch region*. Whether the upper `W−1` bits of the initial
remainder `r_0 = 0` are **inside** that region is a **layout** choice, and it was the only
input to §3's arithmetic that I6(b) did not fix on its own. The two options are not close
together:

| `r_0` upper bits | fold 3 | `udiv` compute | **`udiv` sandwiched** | `W=8` | `udiv` qubits |
|---|---|---|---|---|---|
| **`r0_hi`, a pre-materialised scratch register — D9(d), PINNED** | dead | `17W² + 2W` | **`34W² + 5W`** | **2216** | **`8W² + 4W − 1`** |
| literal `CQ_BIT_ZERO` values synthesised in the step function | alive | `17W² − 4W + 7` | `34W² − 7W + 14` | 2134 | `8W² + 3W` |

Delta: `6W − 7` gates per compute half, `12W − 14` sandwiched (**82** at `W = 8`), and
`W − 1` qubits (**7** at `W = 8`).

The counterfactual row's closed form holds for **`W ≥ 2`** only. At `W = 1` there are no
upper bits (`W − 1 = 0`), the two layouts coincide, and both give 19 / **39** — the
counterfactual forms would wrongly say 20 / 41. The *pinned* row has no such exception:
`34W² + 5W` is exact at every `W ≥ 1`, and is measured there.

Why the pinned row, in three points:

1. **Both options are I6-sound.** Literal zeros are never targets and are never materialised
   mid-half, so the forward and reverse halves still mirror exactly and the sandwich still
   cancels (§2.4b). This is *not* an R8 hazard in either direction — soundness does not
   decide it.
2. **Both options give a mask-independent golden.** `r_0 = 0` is a constant whatever `a` and
   `b` are, so fold 3 never depended on the operand bit-kind mask. Fold 3 is *not* what the
   decision's "L4 goldens become independent of operand bit-kinds" argument is about — folds
   1 and 2 are.
3. **Uniformity decides it, and uniformity is worth more here than `W − 1` qubits.** With
   `r0_hi` in scratch, iteration `t = 0` emits exactly the same gate sequence as every other
   iteration: the step decode stays a pure function of `s` with no `t = 0` branch (which
   Rule 8 requires for the reverse replay to be index reversal), the tape layout of §2.1a
   has no special first block, and — decisively — **the composition identity
   `compute = W · (2 + C_ult + C_sub + C_mux)` of §3.0 holds exactly.** The literal-zero
   layout breaks that identity, and the identity is the one L4 assertion that survives
   `CQOPS_UPDATE_GOLDENS`.

*(The plan's GAP 1 used to record the gate count of the first row with the qubit count of the
second — an inconsistent pair, flagged here and unresolved until 2026-08-16. GAP 1 has been
corrected to `34W² + 5W` / `8W² + 4W − 1`, which are a consistent pair and are both measured.)*

**There is no upstream number to cross-check any of this against.** `BENCHMARKS.md`
contains no division entry (grep: zero hits for `udiv`/`sdiv`/`urem`/`srem`),
`test/test_gate_count_regression.jl` pins no division count (zero hits for `div`/`rem`),

upstream magnitude that exists is a *wire* count in prose, `aggregate.jl:170`: **"279,416

comparable to our width-native figure. See §5 delta 1 and §6.

## 4. Ancilla count

**FLAT — decided 2026-08-16, PRD §15 D9(a).** Fresh scratch every iteration, one sandwich for
the whole kernel. Counting per §2.1: `z` 1 + `nb` W + `ucar` (W+1) + `axnb` W + `nsb` W +
`diff` W + `scar` W + `rnext` W + `mdiff` W = **`8W + 2` per iteration**.

**Scratch bits and qubits are now the same number — [RE-ISSUED 2026-08-14 under I6(b)].**
The previous revision of this section carefully separated the two, because two scratch bits
per iteration (`ucar[t][0]`, `scar[t][0]`) were seeded to a classical `ONE` by folds 1 and 2
and were never materialised, so each iteration held `8W + 4` bits but drew only `8W + 2`
qubits. **That gap is closed.** *(Do not read those two numbers as today's: they are the
pre-I6(b) pair under the retired `not1(ult(…))` flag shape. Under D9(b) an iteration holds
`8W + 2` bits and draws all `8W + 2`.)* `cq_sandwich` pre-materialises the whole scratch region at

`cq_materialise` emits an `X` only for a constant `1`, so step 0 emits nothing. Do not add

* **`r0_hi`, `W − 1` bits** (§2.1) — the upper bits of `r_0 = 0`, a real scratch register
  rather than literal constants. This is what kills fold 3 and buys the pinned `34W² + 5W`

* `condneg`'s `W+1` carry wires per call, which materialised before the decision too (its

the only thing standing between K12 and an L5 failure. The figures in the table above are
the all-operands-quantum case, which is what L4 pins.

### 4.1 `bd ckd.13` — RESOLVED 2026-08-16 as FLAT, and its premise was false in BOTH directions

`bd ckd.13` asked: flat (quadratic) or nested (`O(W)`)? **The answer is FLAT.** But the bead's
framing was wrong twice over, and both errors were settled by *building the schemes and
measuring them* rather than by argument. Three schemes were built and run at
`W ∈ {1,2,3,4,8,16,32,64,128}` in both configurations (§6.0a); all three are L1-exhaustive
green at `W ≤ 4` over every `(a,b)` including `b = 0`, leave the pool restored, and are
I6-clean under `CQOPS_DEBUG_INVARIANTS`:

| scheme | scratch qubits | sandwiched gates | `W=8` | `W=64` | `W=128` |
|---|---|---|---|---|---|
| **FLAT — PINNED** | **`8W² + 4W − 1`** | **`34W² + 5W`** | 543 q / 2 216 g | 33 023 q / 139 584 g | 131 583 q / 557 696 g |
| nested (per-iteration uncompute of the inner scratch) | `W² + 10W` | `64W² + 5W` | 144 / 4 136 | 4 736 / 262 464 | 17 664 / 1 049 216 |
| **linear** (nested **plus** remainder reclaim) | **`13W + 3`** | **`90W² − 3W`** | 107 / 5 736 | 835 / 368 448 | 1 667 / 1 474 176 |

**Error 1 — "nested is `O(W)`". It is not; it is `W² + 10W`.** Per-iteration uncompute
reclaims the comparator chain, the subtractor chain and the mux's `mdiff` — `7W + 1` bits,
reused `W` times — but *not* the running remainder. `rnext[t]` is `W` bits and there are `W`
of them, so the remainder tape stays quadratic. Nesting alone buys 7.0× fewer qubits for
1.88× more gates, with the quadratic term untouched.

claimed it could not.** *(That claim was written here, then refuted by an adversarial verifier
and by execution, inside the same day. It is recorded rather than quietly deleted, because
"the remainder chain cannot be uncomputed without a controlled adder, which is M06 and lands
after Step 17" is a plausible and wrong argument that the next reader may well re-derive.)*
The remainder **can** be reclaimed, because

```
r_in[t]  =  rnext[t] + fits_t · b          exact over the integers, no wrap (§2.0)
```

and a *controlled add of `b` by one qubit* is **already a ported libcqops construction** — it
is `mul.c`'s own shape (`multiplier.jl:22-29`): mask the addend into scratch with Toffolis,
then run an **uncontrolled** adder over it. No M06, no control stack, nothing above `CCX`:

```
M[k]       ^= q[i] & b[k]                  W CCX      mask,   M = fits_t · b
r_in[t][k] ^= (rnext[t] + M)[k]            K6 inlined reclaim, r_in[t] -> 0
M[k]       ^= q[i] & b[k]                  W CCX      unmask
```

`q[i]` is already live (it *is* the saved flag), and K6's emitted circuit is independent of
`dst`'s incoming value — its sum lives in scratch and `dst` is touched only by the copy-out —
so XORing into a non-zero `dst` is exactly what `dst ^= a + b` is for. With that, two
alternating `(W+1)`-slot blocks replace the whole tape and the peak is `13W + 3`. **Measured,
both configurations, L1-exhaustive at `W ≤ 4`: it works.**

**Why FLAT is still the v1 answer.** In decreasing weight:

1. **It is the ported shape, and LINEAR is a scheduling invention.** Bennett's divider
   allocates fresh wires every iteration and frees none, relying on one global
   forward–copy–reverse wrap (`aggregate.jl:119-127`, `:150-172`). Flat is that, with
   Bennett-in-the-small applied once at the kernel boundary — PRD §5, verbatim. LINEAR's
   *pieces* are all ported (`lower_ult!`, `lower_sub!`, `lower_mux!`, `lower_add!`, and
   multiplier.jl's Toffoli mask), but the *schedule that reclaims a division iteration* is in
   no upstream source and covered by no upstream test.
2. **This repo already has a settled posture for exactly this shape, twice.** "Quadratic →
   linear by per-iteration uncompute and wire reuse" is recorded as a known, measured,
   **deliberately-not-taken-in-v1** option in `src/kernels/mul.c` (recycling `pp`:
   `W² + 2W → 2W + 1` qubits for `W(W+1)/2` more Toffolis per half) and in `bd b8g` (the
   barrel's `sh_k` region: `W·L` qubits and `2WL` CX). K12 is the third instance of the same
   call, and consistency across the catalogue is worth more than a local win.
3. **Gate count is what L4 pins, what a QEC cost model multiplies, and what the suite pays.**
   LINEAR is 2.64× flat. `bd mmv` already records the barrel becoming the longest pole in the
   project at a tenth of K12's size.
4. **It is a much smaller kernel.** Flat's step decode is `t = s/K`, `j = s%K` and four
   contiguous phases. LINEAR has eleven ranges, three of which run a sub-step function
   *backwards*, inside a 220-LOC budget that R4 already names as the likeliest breach.

**What FLAT costs, stated without softening: `131,583` scratch qubits for one i128 `udiv`,
against LINEAR's `1,667`.** That is a 79× difference in the resource D2's ceiling meters, and
LINEAR's spacetime volume (qubits × gates) is ~30× smaller at i128. If the QEC target ever
makes divrem's ancilla count binding, **LINEAR is the answer and it is already designed and
measured** — filed as a v2 issue with the schedule above, its numbers, and the reclaim
identity. The switch changes `n_compute`, the step decode and the L4 goldens **inside M19**,
and touches no API, no other module and no invariant.

**None of the three needs a depth-aware `cq_sandwich` — `bd 4tt` item (b) is answered NO.**
The refusal at `src/sandwich.c` (`ctx->sandwich_depth != 0`, both configurations) is not in
the way of any of them, because per-iteration uncompute is **scheduled as extra step indices
inside the one flat step space**, not nested as an inner sandwich. Measured: the nested and
linear variants both run through the **unmodified** driver. M09 needs no change under any
option considered here.

### 4.2 The D2 pool ceiling — where K12 fails, and how loudly

`8W² + 4W − 1` is **33,023** qubits at `W = 64` and **131,583** at `W = 128`, and `divrem`
does ship at i128 (§3.5). That is the largest scratch region in the v1 catalogue by 8×, and
it is where D2's ceiling bites first once Step 26 wires it to `qec_n_logical`. **The
behaviour is already correct and already loud**: `cq_qubits_acquire` fails hard on exceeding
the ceiling (D2), so an i128 `divrem` on a device that cannot hold it aborts naming the pool
rather than silently emitting a circuit nobody can run. Nothing extra is owed in M19 beyond
not swallowing that abort. Filed alongside `bd fxz`, which records the same obligation for
K11's `W² + 2W` at i128.

## 5. Deltas from upstream

1. **Width-native `W` iterations vs Bennett's unconditional 64.** `lower_divrem!`
   zero/sign-extends **both** operands to 64 (`aggregate.jl:52-66`), runs the 64-iteration
   kernel, and truncates (`aggregate.jl:128-131`) — for every source width, including
   `Int8`. libcqops runs `W` iterations at width `W`. The derivation in §2.0 shows the
   value is identical. This is the single biggest delta and the reason **no libcqops K12
   gate count can be validated against any Bennett figure** (risk R3's golden-provenance
   header should say so in words, not just carry the SHA).
2. **Direct emission vs callee inlining.** Bennett routes the kernel through
   `lower_call!` and LLVM IR extraction (`aggregate.jl:90-101`, registered at
   `callees.jl:12-14`), which is why its gate count depends on LLVM's `optimize=false` IR
   shape. libcqops emits the loop directly, so our count is a closed form and theirs is
   not.
3. **Constant shifts and bit extraction are free.** `r << 1` is `lower_shl!`
   (`arith.jl:305-312`, `W−1` CNOTs into a fresh register) and `(a >> i) & 1` is
   `lower_lshr!` + `lower_and!` in Bennett. In libcqops both are `cq_bit` array
   relabelling — 0 gates, 0 qubits — because a bit is a value, not a wire (Rule 3 / I5).
   The only survivor is the single `CX(a[i] → z[t])`.
4. **The quotient bit is 1 CX, not `or` + `mux`.** Bennett's IR computes
   `q | (UInt64(1) << i)` then `ifelse`s the whole 64-bit `q` — that is
   `C_or(W) + C_mux(W) = 5W` CX `+ 2W` CCX per iteration. libcqops emits
   `CX(fits[t] → q[i])`, valid because `q[i]` is provably `CQ_BIT_ZERO` at that point (each
   iteration writes a distinct bit, exactly once). **This is an intentional deviation from
   the shape of Bennett's IR** — it is not a new reversible construction (it is the literal
   `dst ^= f` of the kernel contract), and PRD §6's K12 note already sanctions composing
   rather than porting a circuit. Record it in `bd remember` so nobody "restores fidelity"
   and multiplies the gate count by ~1.4×.
   **TAKEN — this is PRD §15 D9(c), decided 2026-08-16.** `q[i]` is provably `CQ_BIT_ZERO`
   before P4 and is written exactly once, by iteration `t = W−1−i` and no other, so
   `q[i] ^= fits` *is* `q[i] := fits`. The alternative costs `C_or(W) + C_mux(W) = 5W` CX and
   `2W` CCX **per iteration** — `7W²` extra gates — for the identical permutation.
5. **`_cond_negate_inplace!` leaks `W+1` wires per call, by design.** `aggregate.jl:150-172`
   documents it: three calls per signed div, "~195 wires at W=64", never `free!`d, cleaned
   only by the outer reverse. libcqops inherits the leak and cleans it with the sandwich
   reverse. Do **not** try to free them mid-kernel — Bennett tried exactly that
   (`aggregate.jl:159-167`) and it broke correctness.
6. **In-place `val` must be a scratch copy.** See §2.4. Bennett passes its own widened
   `a64`/`b64`; the port must pass `sa`/`sb`. This is the most dangerous line in the
   whole extraction.
7. **A dead Toffoli at the top of every `condneg`.** At `i == W` the loop allocates
   `next_carry` and writes `ToffoliGate(val[W], carry, next_carry)` which is never read
   (`aggregate.jl:186-188`). Dropping it saves 1 CCX and 1 ancilla per call (3 per signed
   op). The §3 formulas keep it, faithfully. If the plan decides to drop it, `sdiv`/`srem`
   CCX becomes `5W² + W − 3` compute / `10W² + 2W − 6` sandwiched and ancillae drop by 3.
   *(Restated 2026-08-14 against the I6(b) figures; the old text quoted the retired (E)
   base `5W² − 3W` / `10W² − 6W`.)*
8. **`fits` and the subtractor's borrow are the same bit, computed twice.** `lower_ult!`
   (`arith.jl:449`) builds a full ripple-carry chain purely to read its carry-out, and
   `lower_sub!` (`adder.jl:149`) then builds the same chain again. Sharing would remove
   `C_ult(W) = 6W+1` gates and `3W+1` ancillae per iteration — roughly a third of the
   kernel. **Not for v1**: it is gate-level optimisation (explicitly out of scope) and it
   would decouple our counts from the primitives K7/K9 pin — specifically it would break the
   §3.0 composition identity, which is K12's only golden-independent L4 assertion. Worth a
   `bd` issue against a post-baseline pass. *(Note this is a different question from D9(b):
   D9(b) chose which of two `uge` realisations libcqops already ships; this would fuse the
   comparator into the subtractor, which is a construction neither Bennett nor libcqops has.)*
9. **One Bennett function becomes two libcqops modules.** `lower_divrem!` handles all four
   opcodes in one body (`aggregate.jl:49`, dispatched by `arith.jl:257-258`); the plan
   splits M19 `divrem_u` / M20 `divrem_s` (plan §3 Layer 3, "| M19 | `kernels/divrem_u.[ch]`"
   and "| M20 | `kernels/divrem_s.[ch]`" — `IMPLEMENTATION_PLAN.md:1172-1173 @ 961905f`;
   this cited "rows 207-208" until 2026-09-10, and R4 names this split as
   the pre-planned mitigation for the 300-line limit).
10. **No `throw`, ever, on either path.** Bennett has a *pair* of entry points: public
    `soft_udiv`/`soft_urem` throw `DivideError` (`divider.jl:73-76`, `85-88`) and are
    deliberately **not** registered as callees, precisely so a `@ijl_throw` never reaches
    the gate stream (`callees.jl:8-14`, `divider.jl:8-21`). libcqops has no Julia-caller
    surface, so it has no throwing twin — only the branchless behaviour below.
11. **`fits` is a double negation of a bit we already have — and the double negation is now
    GONE. [ADDED 2026-08-14; TAKEN 2026-08-16 as PRD §15 D9(b).]** The old P1 ended with four
    gates — `CX(ucar[W] → ult); X(ult); CX(ult → fits); X(fits)` — which is
    `not1(ult(r,b))`, i.e. `¬¬carry_out`. `K09.md` §2's `lower_ult!` walkthrough records the
    fact out of the source:
    *"`carry[W+1]` is the carry-out of `a − b`, which is 1 iff `a ≥u b`"* — so
    `fits[t]` **is** `ucar[t][W]`, verbatim, and that tail cost 4 gates and 2 scratch bits
    per iteration (`4W` gates, `2W` qubits over the kernel) to reproduce a wire it already
    held. Bennett pays it only because `uge` goes through the generic `lower_icmp!`
    dispatcher (`arith.jl:414`), which must return a wire.
    **What settled it is not the saving; it is that M16 ALREADY DOES THIS.**
    `src/kernels/cmp.c` sets `PRIM_ULT`'s `raw = &carry[W]` and `cq_kernel_uge` copies it out
    unchanged — Bennett's double negation folded into the copy-out, `K09.md` §5 delta 2, on
    disk and tested since Step 13. Keeping `not1(ult(…))` inside K12 would have put **two
    different realisations of `uge` in one library**, with the more expensive one in the only
    kernel that invokes it `W` times per call. Worth `4W` gates (`8W` sandwiched) and `2W`
    qubits: `34W² + 13W` → `34W² + 5W`, `8W² + 6W − 1` → `8W² + 4W − 1`.
12. **We pre-materialise scratch; Bennett does not, and upstream cannot even ask the
    question. [ADDED 2026-08-14]** `cq_sandwich` turns every bit of K12's scratch region into
    a qubit at step 0, before the first compute step runs (I6(b), plan §0.2). Bennett emits
    no such step, and there is no upstream construct to compare it against, because
    **Bennett has no classical operand kind at all**: `third_party/bennett/src/gates.jl:1`
    declares `const WireIndex = Int`, and `NOTGate` (`:7`), `CNOTGate` (`:12`) and
    `ToffoliGate` (`:18`) each hold nothing but `WireIndex` fields. Every operand of every
    Bennett gate is a wire. There is no tri-valued bit, no fold table, and therefore no
    notion of a scratch bit "still being classical" — so the hazard I6(b) closes (risk
    **R8**) cannot arise upstream and Bennett had no reason to pay for it.

    This is the delta that moved K12's numbers most: **`34W² − 3W + 14` → `34W² + 13W`**
    (2166 → 2280 at `W = 8`), because three fold-table elisions died at once (§3.1a), and
    **`8W² + 3W` → `8W² + 6W − 1`** qubits (§4). *(Both of those figures were then superseded
    again by D9(b), for an unrelated reason — see the three-generation table at the head of
    §3. The I6(b) delta itself is unchanged: `+4W` gates and `+3W − 1` qubits.)* It also
    *simplified* the doc — the count is
    now a function of `W` alone at the golden mask, the `W = 1` special case is gone, and
    slots and gates coincide. **The price is paid in K12 more than anywhere else in the
    catalogue** precisely because K12 was the only kernel with three independent elisions:
    `W` `uge` carry seeds, `W` `sub` carry seeds, and the one-off `t = 0` remainder.

    Do not "restore fidelity to Bennett" by removing pre-materialisation. Bennett's
    construction is unchanged; what changed is our emitter, and Bennett's gate list is still
    what §3.1 counts.

Read out of `divider.jl:15-18` and `divider.jl:44-46`, and pinned by

| | Bennett's value | source |
|---|---|---|

| `_soft_urem_compile(a, 0)` | `a` — every trial subtract is a no-op, so `r` accumulates `a` | `divider.jl:44-46`; `test_salb_div_by_zero.jl:34` |

**libcqops pins, at width `W`:**

* `cqrt_udiv_<W>(a, 0)` → `2^W − 1` (all ones). The §2.0 invariant makes this exact at
  width `W`: `fits` is true at every one of the `W` iterations, so every `q[i]` is set.
* `cqrt_urem_<W>(a, 0)` → `a`. Every mux selects the un-subtracted branch, so
  `r_W = P_W = a`.
* **Never traps, never allocates an error path, never branches.** The circuit is a fixed
  permutation; `b = 0` is just another input. There is no `H`/`T`, no runtime check, and
  nothing to fail loud about — D3 is *deterministic-but-unspecified*, which is a value
  contract, not an error contract. (This is the one place in libcqops where "fail loud" is
  wrong; Rule 6's refusal is about *dirty rails*, not about *poison values*.)
* `sdiv`/`srem` at `b = 0`, **derived, not executed** (see §6): the sign-magnitude wrapper
  runs on top of the unsigned contract. `|0| = 0`, `b_sign = 0`, so
  `sdiv(a, 0) = condneg(2^W − 1, sign(a))` = `-1` for `a ≥ 0` and `+1` for `a < 0`; and
  `srem(a, 0) = condneg(|a|, sign(a)) = a`. The `typemin ÷ -1 → typemin` case reproduces
  at width `W` without the 64-bit widening: `|typemin|` is `typemin` again in two's
  complement, `÷ 1` leaves it, and the sign fix is a no-op because
  `sign(a) ⊕ sign(b) = 1 ⊕ 1 = 0`.
* Whatever the L1 refmodel and the L4 goldens record, **document the b=0 row in the test
  file with a pointer to `divider.jl:15-18`** so the next reader knows these values are
  inherited, not chosen.
