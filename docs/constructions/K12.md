**libcqops module:** M19 `src/kernels/divrem_u.c` (unsigned core, plan §3 budget 220 LOC,
split seam "loop body ↔ driver") · M20 `src/kernels/divrem_s.c` (signed wrappers + D3,
budget 110 LOC). Plan step 17.

**Clean or sandwich:** **sandwich** — and it is the most dirty kernel in the catalogue.
The compute half leaves, per division iteration, the whole comparator chain (`nb`,
`carry`, `axnb`, the `ult` bit, the `fits` bit), the whole subtractor chain (`nsb`,
`diff`, `scarry`), and the mux's `diff` register sitting at arbitrary values. None of
those are self-cleaning: `lower_ult!` and `lower_sub!` both build a full ripple carry
chain and never unwind it, and `lower_mux!` never unwinds its `diff`. Bennett gets away
with this because it applies **one global** forward-copy-reverse wrap at the top level —
`aggregate.jl:150-172` says so in as many words for `_cond_negate_inplace!`: *"The wires
ARE returned to zero by Bennett's outer reverse pass at simulate time … they just stay
allocated"*, and `aggregate.jl:119-127` says the same for the 64-bit division result.
libcqops has no global wrap, so K12 gets the local wrap (Bennett-in-the-small, PRD §5).

> **Do not `cqrt_free` anything inside K12's compute half.** The remainder's dropped top
> bit is provably `0` mathematically (see §2, shift-in) but the two-bit shadow cannot
> prove it — it is a qubit of unknown value. A mid-kernel free is exactly the Rule 6
> hard error, and it would be firing correctly. The sandwich reverse is the only thing
> that returns K12's scratch to `|0⟩`.

```julia
function _soft_udiv_compile(a::UInt64, b::UInt64)::UInt64
    q = UInt64(0)
    r = UInt64(0)
    for i in 63:-1:0
        # Shift remainder left, bring in bit i of a
        r = (r << 1) | ((a >> i) & UInt64(1))
        # Trial: can we subtract b?
        fits = r >= b
        r = ifelse(fits, r - b, r)
        q = ifelse(fits, q | (UInt64(1) << i), q)
    end
    return q
end
```

```julia
        fits = r >= b
        r = ifelse(fits, r - b, r)
```

```julia
function _cond_negate_inplace!(gates::Vector{ReversibleGate}, wa::WireAllocator,
                               val::Vector{Int}, cond::Vector{Int}, W::Int)
    # Two's complement negate = flip all bits + add 1
    # Conditional flip: CNOT(cond, val[i]) for each bit
    for i in 1:W
        push!(gates, CNOTGate(cond[1], val[i]))
    end
    # Conditional add 1: ripple carry adding cond[1] to val
    carry = allocate!(wa, 1)
    push!(gates, CNOTGate(cond[1], carry[1]))  # carry starts as cond
    for i in 1:W
        # val[i] += carry; new_carry = val[i] AND carry (before add)
        next_carry = allocate!(wa, 1)
        push!(gates, ToffoliGate(val[i], carry[1], next_carry[1]))
        push!(gates, CNOTGate(carry[1], val[i]))
        carry = next_carry
    end
end
```

```julia
function lower_ult!(g, wa, a, b, W)
    nb = allocate!(wa, W)
    for i in 1:W; push!(g, CNOTGate(b[i], nb[i])); push!(g, NOTGate(nb[i])); end
    carry = allocate!(wa, W + 1)
    push!(g, NOTGate(carry[1]))
    axnb = allocate!(wa, W)
    for i in 1:W
        push!(g, CNOTGate(a[i], axnb[i])); push!(g, CNOTGate(nb[i], axnb[i]))
        push!(g, ToffoliGate(a[i], nb[i], carry[i + 1]))
        push!(g, ToffoliGate(axnb[i], carry[i], carry[i + 1]))

    push!(g, CNOTGate(carry[W + 1], r[1])); push!(g, NOTGate(r[1]))

end
```

## 2. Gate sequence as indexed pseudo-code

### 2.0 The width claim that makes a W-bit remainder legal

Bennett runs the loop 64 iterations on 64-bit registers regardless of the source width
(`aggregate.jl:52-66` widens, `aggregate.jl:128-131` truncates). libcqops runs **W
iterations on W-bit registers**. That is only sound if the W-bit remainder never
overflows, so here is the derivation, from the source loop:

Let `P_k = ⌊a / 2^(W−k)⌋` be the value of the top `k` bits of `a`. The loop invariant
after `k` iterations is `r_k = P_k mod b` (and for `b = 0`, `r_k = P_k`, since
`fits = r >= 0` is always true and `r − 0 = r`). Either way `r_k ≤ P_k < 2^k`.

* **The dropped bit is zero.** Iteration `k+1` (with `k ∈ [0, W−1]`) shifts `r_k` left,
  discarding bit `W−1`. From `r_k < 2^k ≤ 2^(W−1)`, bit `W−1` of `r_k` is `0`. Always.
* **The shifted value fits.** `r' = 2·r_k + a[W−1−k] ≤ 2(2^k − 1) + 1 = 2^(k+1) − 1 < 2^W`
  because `k+1 ≤ W`.

So a W-bit remainder register is exactly sufficient — no `W+1`-bit window is needed, and
the comparator/subtractor run at width W. **This derivation is load-bearing; if a future
reader doubts it, widen `r` to W+1 bits rather than guessing.** The conservative variant
costs `C_uge(W+1) + C_sub(W+1) + C_mux(W+1)` per iteration instead of the width-W ones.

### 2.1 Vocabulary and scratch layout

`W` = register width. Iteration counter `t ∈ [0, W)`; the dividend bit consumed at
iteration `t` is `i = W − 1 − t` (the source counts `i` down from 63).

Scratch allocated **fresh per iteration `t`** (the flat scheme — see §4 for the
qubit-frugal alternative):

| name | bits | role |
|---|---|---|
| `z[t]` | 1 | the incoming dividend bit slot; `r_in[0]` |
| `nb[t]` | W | `~b`, inside the comparator |
| `ucar[t]` | W+1 | comparator carry chain |
| `axnb[t]` | W | `a ⊕ ~b`, inside the comparator |
| `ult[t]` | 1 | `r' < b` |
| `fits[t]` | 1 | `r' >= b` — the `not1` of `ult[t]` |
| `nsb[t]` | W | `~b`, inside the subtractor |
| `diff[t]` | W | `r' − b` |
| `scar[t]` | W | subtractor carry chain |
| `rnext[t]` | W | mux output — the next remainder |
| `mdiff[t]` | W | mux's internal `tv ⊕ fv` |

Allocated **once** for the whole kernel:

| name | bits | role |
|---|---|---|
| `q[0..W−1]` | W | unsigned quotient (`udiv`/`sdiv` only) |
| `r0_hi[0..W−2]` | W−1 | **the upper bits of the initial remainder `r_0 = 0`** — see the I6(b) note below and §3.6 |

**Every one of these bits is scratch, and under I6(b) `cq_sandwich` pre-materialises the
whole lot at step 0** (plan §0.2). Pre-materialisation emits **no gates** — scratch is born
`CQ_BIT_ZERO` and `cq_materialise` emits an `X` only for a constant `1` — so step 0 costs
**qubits, never gates**.

`r_in[t]` is a **view, not a register**: `r_in[t][0] = z[t]`, and
`r_in[t][j] = rnext[t−1][j−1]` for `j ∈ [1, W)`. The left shift is therefore a
relabelling of `cq_bit` array entries and costs **zero gates and zero qubits** (Rule 3 —
a `cq_bit` is a value, not a wire). `r_in[0]` is `z[0]` plus the `W−1` bits of `r0_hi`.
**`r0_hi` is a real scratch register, not a run of literal `CQ_BIT_ZERO` entries
[CHANGED 2026-08-14 under I6(b)]** — as literals they would fold, and the folded count is
not what the plan pins. This is the single layout choice that decides `34W² + 13W` versus
`34W² + W + 14`; it is spelled out and flagged in §3.6. The dropped top bit
`rnext[t−1][W−1]` is simply left in scratch; the sandwich reverse cleans it.

**The shift offset must be recomputed from `t`, never carried in mutable state** — the
sandwich driver replays step indices in reverse, so every index the step function uses
has to be a pure function of `s`.

### 2.2 The step function

Per plan §0.1 the compute half is an indexed step function. Let

```
K(W) = 17W + 6          /* compute-half STEP SLOTS per division iteration */
n_compute = W * K(W)    /* = 17W^2 + 6W slots, for udiv */
```

**`K(W)` is a slot count. [REVISED 2026-08-14 under I6(b).]** It used to differ from the
gate count: three separate fold-table elisions fired inside the compute half and the emitted
total came out `17W² − 2W + 7`. **Under I6(b) none of them can fire** — every scratch bit is
`CQ_BIT_Q` from step 0, so no gate whose only classical operand was a scratch bit folds any
more (§3.1a). For the all-operands-quantum mask that L4 pins, **one slot emits exactly one
gate** and `n_compute = 17W² + 6W` is both the slot count and the gate count.

The distinction is still worth keeping in the driver's vocabulary, because folds on
**source** bits survive: a classical `b` still elides `CX(b[k] → nb[t][k])`. Those are
mask-dependent, they are *symmetric* across the two halves (a source is never materialised
inside a compute half, I6(a)), and they can only ever make the count **smaller than or equal
to** the golden — never larger. (Equal is reachable, not just a theoretical bound: a
`CQ_BIT_ONE` source turns `CX(c,t)` into `X(t)`, one gate for one gate, so an all-`ONE` `b`
emits exactly the all-quantum count. It is an all-`ZERO` `b` that shrinks it.)
The driver must index *slots*, not gates, so that a slot emitting nothing forward is still
visited backward.

and decode `s ∈ [0, n_compute)` as `t = s / K(W)`, `j = s % K(W)`, `i = W − 1 − t`.
Phase boundaries inside an iteration (all closed-form in `W`):

| `j` range | phase | gates in phase |
|---|---|---|
| `0` | P0 shift-in | 1 |
| `[1, 6W+5]` | P1 `fits = uge(r_in, b)` | `6W+5` |
| `[6W+6, 13W+4]` | P2 `diff = sub(r_in, b)` | `7W−1` |
| `[13W+5, 17W+4]` | P3 `rnext = mux(fits, diff, r_in)` | `4W` |
| `17W+5` | P4 quotient bit | 1 |

```
step(s):
  t = s / (17W+6);  j = s % (17W+6);  i = W-1-t
  r = r_in[t]                       /* the relabelled view, 0 gates */

  /* ---- P0 : r_in[t][0] ^= a[i]  (the "| ((a >> i) & 1)") ---- */
  j == 0                     ->  CX( a[i]        -> z[t] )

  /* ---- P1 : fits[t] = (r >= b) = NOT( r < b ) ----
     lower_ult!(a=r, b=b, W) followed by lower_not1!            */
  j in [1, 2W]               ->  m = j-1;  k = m/2
                                 m even  ->  CX( b[k]   -> nb[t][k] )
                                 m odd   ->  X ( nb[t][k] )
  j == 2W+1                  ->  X ( ucar[t][0] )               /* carry_in = 1 */
  j in [2W+2, 6W+1]          ->  m = j-(2W+2);  k = m/4
                                 m%4==0  ->  CX ( r[k]                     -> axnb[t][k] )
                                 m%4==1  ->  CX ( nb[t][k]                 -> axnb[t][k] )
                                 m%4==2  ->  CCX( r[k],       nb[t][k]     -> ucar[t][k+1] )
                                 m%4==3  ->  CCX( axnb[t][k], ucar[t][k]   -> ucar[t][k+1] )
  j == 6W+2                  ->  CX ( ucar[t][W] -> ult[t] )
  j == 6W+3                  ->  X  ( ult[t] )                  /* ult[t] = (r < b) */
  j == 6W+4                  ->  CX ( ult[t]     -> fits[t] )
  j == 6W+5                  ->  X  ( fits[t] )                 /* fits[t] = (r >= b) */

  /* ---- P2 : diff[t] = r - b   (lower_sub!, two's complement) ---- */
  j in [6W+6, 8W+5]          ->  m = j-(6W+6);  k = m/2
                                 m even  ->  CX( b[k] -> nsb[t][k] )
                                 m odd   ->  X ( nsb[t][k] )
  j == 8W+6                  ->  X ( scar[t][0] )               /* carry_in = 1 */
  j in [8W+7, 13W+4]         ->  m = j-(8W+7)     /* 5W-2 slots, ONE gate each */
                                 m <  5(W-1) : k = m/5;  p = m%5
                                   p==0 -> CX ( r[k]                   -> diff[t][k] )
                                   p==1 -> CX ( nsb[t][k]              -> diff[t][k] )
                                   p==2 -> CCX( r[k],      nsb[t][k]   -> scar[t][k+1] )
                                   p==3 -> CCX( diff[t][k], scar[t][k] -> scar[t][k+1] )
                                   p==4 -> CX ( scar[t][k]             -> diff[t][k] )
                                 m >= 5(W-1) : k = W-1;  p = m-5(W-1)  /* no carry-out */
                                   p==0 -> CX ( r[W-1]                 -> diff[t][W-1] )
                                   p==1 -> CX ( nsb[t][W-1]            -> diff[t][W-1] )
                                   p==2 -> CX ( scar[t][W-1]           -> diff[t][W-1] )

  /* ---- P3 : rnext[t] = fits ? diff : r   (lower_mux!) ---- */
  j in [13W+5, 17W+4]        ->  m = j-(13W+5);  k = m/4
                                 m%4==0  ->  CX ( r[k]                     -> rnext[t][k] )
                                 m%4==1  ->  CX ( diff[t][k]               -> mdiff[t][k] )
                                 m%4==2  ->  CX ( r[k]                     -> mdiff[t][k] )
                                 m%4==3  ->  CCX( fits[t],   mdiff[t][k]   -> rnext[t][k] )

  /* ---- P4 : q[i] ^= fits ---- */
  j == 17W+5                 ->  CX( fits[t] -> q[i] )
```

Copy-out steps (the `^=` of the kernel contract), run once between the forward and
reverse halves:

```
copyout(c) for c in [0, W):
    udiv / sdiv :  CX( q[c]        -> dst[c] )
    urem / srem :  CX( rnext[W-1][c] -> dst[c] )
```

### 2.3 Signed wrapper (M20)

Prefix (before the core) and suffix (after it), all targets scratch:

```
/* prefix — 2W CX, then two conditional negates */
for c in [0,W):  CX( a[c] -> sa[c] )          /* |a| starts as a  */
for c in [0,W):  CX( b[c] -> sb[c] )          /* |b| starts as b  */
condneg(sa, ctrl = a[W-1])                    /* a[W-1] is a CONTROL, never a target */
condneg(sb, ctrl = b[W-1])

/* core: run §2.2 on (sa, sb) instead of (a, b) */

/* suffix */
sdiv :  CX( a[W-1] -> rs );  CX( b[W-1] -> rs );  condneg(q,          ctrl = rs )
srem :                                            condneg(rnext[W-1], ctrl = a[W-1])

/* condneg(val[0..W-1], ctrl) — aggregate.jl:174-191, transcribed */
for c in [0,W):  CX( ctrl -> val[c] )         /* conditional bit flip */
                 CX( ctrl -> ncar[0] )        /* carry starts as ctrl */
for c in [0,W):  CCX( val[c], ncar[c] -> ncar[c+1] )
                 CX ( ncar[c]         -> val[c] )
```

Bennett copies the sign bit into a fresh wire first (`aggregate.jl:76-77`) because its
`_cond_negate_inplace!` mutates `a64`/`b64` in place and would otherwise clobber its own
control. libcqops does not need that copy for `sa`/`sb`: `a[W−1]` and `b[W−1]` are
**sources**, used only as controls, and `sa`/`sb` are separate scratch registers. The
`rs` wire for `sdiv` is still needed — it holds `sign(a) ⊕ sign(b)`.

### 2.4 I6(a) targets, I6(b) controls

#### 2.4a I6(a) — every compute-half gate target is scratch

Walk the target column of every emission above:

| phase | targets | in scratch? |
|---|---|---|
| P0 | `z[t]` | ✔ |
| P1 | `nb[t]`, `ucar[t]`, `axnb[t]`, `ult[t]`, `fits[t]` | ✔ |
| P2 | `nsb[t]`, `scar[t]`, `diff[t]` | ✔ |
| P3 | `mdiff[t]`, `rnext[t]` | ✔ |
| P4 | `q[i]` | ✔ |
| signed prefix/suffix | `sa`, `sb`, `ncar`, `rs`, and `condneg`'s in-place `val` ∈ {`sa`, `sb`, `q`, `rnext[W−1]`} | ✔ |

`a`, `b` and `dst` never appear as a target in the compute half. `a[i]`, `b[k]`,
`a[W−1]`, `b[W−1]` appear **only as controls**. `dst` is touched only by the copy-out,
which is outside the compute half by construction. **I6 holds for K12 in both the
unsigned and the signed form.**

**The one way to break it, loudly flagged.** Bennett's `_cond_negate_inplace!` takes its
`val` argument **in place** and its sole caller passes `a64`/`b64` — Bennett's *own
widened copies*, not the user's operands. A port that "saves the copy" by passing the
caller's `a`/`b` straight in would (i) violate I6, (ii) violate the kernel contract's
"leaving `a` and `b` unchanged", and (iii) be a silent miscompile whose reverse half
still cancels, so L1/L3 would stay green. The `cq_emit_*` signature (`const cq_bit *`
controls, `cq_bit *` targets) makes it a compile error — do not cast it away.

#### 2.4b I6(b) — every scratch bit is `CQ_BIT_Q` for the whole compute half

Guaranteed by the driver, not by this kernel: `cq_sandwich` pre-materialises the entire
scratch region (§2.1) at step 0. Nothing in K12's step function has to arrange it, and
nothing in K12's step function may rely on a scratch bit still being classical.

**K12 *is* where risk R8 bites. [CORRECTED 2026-08-14 — this section previously asserted the
exact opposite; see the correction log.]** Walk every scratch bit K12 reads as a control and
ask the R8 question — *is it read as a control while still classical, and materialised by a
**later** gate?* The trap the previous revision fell into is that **"written" and
"materialised" are not the same thing**: a write whose sources are all classical *folds*, and
leaves its target classical.

| scratch control | materialised by | first read as control | R8? |
|---|---|---|---|
| `z[t]`, `nb[t][k]`, `nsb[t][k]`, `axnb[t][k]` | P0 / P1 / P2 loop 1 | after | no |
| `mdiff[t][k]` | P3 sub-slots 1–2 | sub-slot 3, then never a target again | no |
| **`diff[t][k]`** | **`CX(scar[t][k] → diff[t][k])` — the *last* gate of the `k` group** | **the `CCX(diff[t][k], scar[t][k] → scar[t][k+1])` immediately *before* it** | **YES** |
| `ucar[t][k]`, `scar[t][k]` (`k ≥ 1`) | group `k−1` | group `k`, then never a target again | no |
| `ucar[t][0]`, `scar[t][0]` | the carry-seed `X`, slot `2W+1` / `8W+6` | slot after | no — written first |
| `ult[t]`, `fits[t]`, `rs`, `ncar[c]`, `val[c]` | preceding slot | after | no |
| `r0_hi[j]` | **never a target** | P1/P2/P3 at `t = 0` | no — never materialised mid-half |

**The `diff[t][k]` witness, read out of the pinned source.** `lower_sub!`'s body
(`adder.jl:147-155`) emits, per `i`:

```
CNOT(a[i],     result[i])                 /* r[k]   -> diff[t][k]           */
CNOT(not_b[i], result[i])                 /* nsb[k] -> diff[t][k]           */
Toffoli(a[i], not_b[i], carry[i+1])
Toffoli(result[i], carry[i], carry[i+1])  /* diff[t][k] read as a CONTROL   */
CNOT(carry[i], result[i])                 /* diff[t][k] targeted AGAIN, after */
```

If `r[k]` and `nsb[t][k]` are *both* classical when the first two `CX`s run, both fold and
`diff[t][k]` is **still classical** at the `Toffoli` — which therefore folds as well. The very
next gate, `CX(scar[t][k] → diff[t][k])`, has a quantum control and **materialises it**. On
the reverse pass `diff[t][k]` is already `CQ_BIT_Q` when that `Toffoli` is replayed, so the
reverse emits a `CCX` the forward never emitted. The halves stop mirroring, scratch is left
dirty, and **L1 stays green**. That is R8 verbatim.

The precondition is easy to hit: `nsb[t][k]` is classical for the whole compute half whenever
`b` is classical. Smallest witness found by replaying §2.2's gate list under the PRD §3 fold
table: **`W = 3`, `a` all `CQ_BIT_Q`, `b` all `CQ_BIT_ZERO`** (all `CQ_BIT_ONE` also
witnesses), diverging at `t = 0`, `k = 1` on `CCX(diff[0][1], scar[0][1] → scar[0][2])`.
`W ∈ {1,2}` do **not** witness it. Put that mask in the fixed L1/L2/L3 mask set — a regression
must not depend on random masks to be caught.

**Which test layer would have caught it, under the old rules.** Replaying forward-vs-reverse
over the operand masks separates into three regimes, and the middle one is the alarming one:

| mask | gate order | gate multiset | **total count** | caught by |
|---|---|---|---|---|
| `a` all `ONE`, `b` `Q` | broken | **same** | same | nothing — a benign reorder of a materialisation `X` past disjoint gates; the net permutation is still the inverse |
| **`a` `Q`, `b` all `ZERO`** | broken | **different** | **same** (116/204/318/458/816 at `W`=3/4/5/6/8) | **L2/L3 only** — L1 green *and* **L4 green**, because the count is unchanged while the gates are not |
| `a` `Q`, `b` all `ONE` | broken | different | **different** (322 vs 328 at `W = 8`) | L4, and L2/L3 |

The middle row is why a gate-count golden is not a defence against R8 and why L2/L3 are not
optional (CLAUDE.md's Prime Directive, in one table). Under I6(b) all three regimes collapse:
every scratch bit is `CQ_BIT_Q` from step 0, so nothing folds on scratch, and the two halves
are identical gate-for-gate by construction.

**So I6(b) fixes a real K12 bug; it is not only a cost change.** This is the same hazard
`K07.md` §5 D2 records against `lower_add!`'s sum register `t[i]`, and K12 inherits it through
`lower_sub!`, whose `result[i]` has the identical shape. K07's rule — *a scratch bit is
pass-symmetric iff it is never materialised, or is materialised on the first gate that targets
it* — is exactly what `diff[t][k]` breaks. **Do not exempt K12 from pre-materialisation**, and
do not restore the "K12 was already safe" reading this section used to carry.

None of this moves §3's arithmetic: under I6(b) every bit in the table above is `CQ_BIT_Q`
from step 0, so the folded variants cannot arise at all and the pinned counts are unchanged.

### 3.1a The three folds that used to fire, and why none of them can now

Fold rows quoted from `PRD-v1.md:286-296` *(re-anchored 2026-08-14; the `:180-191` this file
carried had gone stale — line 180 is now PRD §1's "Non-negotiable constraints")*:
*`X(t)`, `t` constant → flip the constant → **0**
gates*; *`CX(c,t)`, `c = ONE` → `emit_x(t)`*; *`CX(c,t)`, `c = ZERO` → nothing*;
*`CCX(c1,c2,t)`, `c1 = ONE` → `emit_cx(c2,t)`*; *`CCX`, either control `ZERO` → nothing*.

Every one of these rows dispatches on a bit being **classical**. Under I6(b) every scratch
bit is `CQ_BIT_Q` from step 0, so a row can only fire on a bit of `a` or `b`. K12's three
elisions were all scratch-only. **All three are dead.**

| # | what it was | fired on | dead because |
|---|---|---|---|
| 1 | `uge` carry seed | `ucar[t][0]` | scratch, pre-materialised |
| 2 | `sub` carry seed | `scar[t][0]` | scratch, pre-materialised |
| 3 | `t = 0` remainder | `r_in[0][k]`, `k ≥ 1` | scratch (`r0_hi`), pre-materialised — **layout-dependent, see §3.6** |

**Fold 1 — the `uge` carry seed, was worth `−1 X, +1 CX, −1 CCX` per iteration.**
`lower_ult!`'s `NOT(carry[1])` (`arith.jl:453`) targets `ucar[t][0]`. That bit used to be a
freshly acquired `CQ_BIT_ZERO`, so row 1 emitted **0 gates** and left it a classical `ONE`,
which then degraded `CCX(axnb[t][0], ucar[t][0], ucar[t][1])` to a `CX`. Pre-materialised,
`ucar[t][0]` is a qubit: the `X` is emitted and the `CCX` stays a `CCX`.
⇒ `C_uge(W) = 6W + 5`, tuple `(W+3, 3W+2, 2W)`. *(Counterfactual: `6W + 4`,
`(W+2, 3W+3, 2W−1)` — the "GOLDEN TRAP" of `K09.md` §5. **That warning is now itself the

### 3.6 The one thing §3 assumes that I6(b) does not settle by itself — `r_0`

**Read this before pinning `2280`, and do not resolve it in code.**

I6(b) pre-materialises *the scratch region*. Whether the upper `W−1` bits of the initial
remainder `r_0 = 0` are **inside** that region is a **layout** choice, and it is the only
input to §3's arithmetic that the decision does not fix on its own. The two options are not
close together:

| `r_0` upper bits | fold 3 | `udiv` compute | **`udiv` sandwiched** | `W=8` | `udiv` qubits |
|---|---|---|---|---|---|
| **`r0_hi`, a pre-materialised scratch register** (what §2.1 and §3 pin) | dead | `17W² + 6W` | **`34W² + 13W`** | **2280** | `8W² + 6W − 1` |
| literal `CQ_BIT_ZERO` values synthesised in the step function | alive | `17W² + 7` | `34W² + W + 14` | 2198 | `8W² + 5W` |

Delta: `6W − 7` gates per compute half, `12W − 14` sandwiched (**82** at `W = 8`), and
`W − 1` qubits (**7** at `W = 8`).

The counterfactual row's closed form holds for **`W ≥ 2`** only. At `W = 1` there are no
upper bits (`W − 1 = 0`), the two layouts coincide, and both give 23 / **47** — the
`17W² + 7` / `34W² + W + 14` forms would wrongly say 24 / 49. The *pinned* row has no such
exception: `34W² + 13W` is exact at every `W ≥ 1`.

Three things to be clear about:

1. **Both options are I6-sound.** Literal zeros are never targets and are never materialised
   mid-half, so the forward and reverse halves still mirror exactly and the sandwich still
   cancels (§2.4b). This is *not* an R8 hazard in either direction.
2. **Both options give a mask-independent golden.** `r_0 = 0` is a constant whatever `a` and
   `b` are, so fold 3 never depended on the operand bit-kind mask. Fold 3 is *not* what the
   decision's "L4 goldens become independent of operand bit-kinds" argument is about — folds
   1 and 2 are.
3. **Plan §0.2 GAP 1 records `34W² + 13W` (2280), which is the first row.** §2.1 and §3 are
   written to match it. The reason to prefer it is uniformity, not soundness: with `r0_hi` in
   scratch, iteration `t = 0` emits exactly the same gate sequence as every other iteration,
   so the step function has no `t = 0` branch and the driver's slot decode stays a pure
   function of `s`.

**⚠ The plan's two recorded K12 numbers are inconsistent with each other by `W − 1` qubits.**
GAP 1 records the gate count of the first row (`34W² + 13W`) together with the qubit count of
the second (`8W² + 5W`). They cannot both hold: killing fold 3 is exactly what costs those
`W − 1` qubits. §4 reports `8W² + 6W − 1`, the figure that goes with the pinned gate count,
and flags the discrepancy rather than silently picking a side (CLAUDE.md, "Open blockers").
**Settle it in the plan before M19 is written.**

**There is no upstream number to cross-check any of this against.** `BENCHMARKS.md`
contains no division entry (grep: zero hits for `udiv`/`sdiv`/`urem`/`srem`),
`test/test_gate_count_regression.jl` pins no division count (zero hits for `div`/`rem`),
and `test/test_y56a_division_paths.jl` asserts values only, never `gate_count`. The one
upstream magnitude that exists is a *wire* count in prose, `aggregate.jl:170`: **"279,416
wires for Int8 sdiv"** — which is Bennett's 64-bit-widened path and therefore not
comparable to our width-native figure. See §5 delta 1 and §6.

## 4. Ancilla count

Flat scheme (fresh scratch every iteration, one sandwich for the whole kernel), counting
per §2.1: `z` 1 + `nb` W + `ucar` (W+1) + `axnb` W + `ult` 1 + `fits` 1 + `nsb` W + `diff`
W + `scar` W + `rnext` W + `mdiff` W = **`8W + 4` per iteration**.

**Scratch bits and qubits are now the same number — [RE-ISSUED 2026-08-14 under I6(b)].**
The previous revision of this section carefully separated the two, because two scratch bits
per iteration (`ucar[t][0]`, `scar[t][0]`) were seeded to a classical `ONE` by folds 1 and 2
and were never materialised, so each iteration held `8W + 4` bits but drew only `8W + 2`
qubits. **That gap is closed.** `cq_sandwich` pre-materialises the whole scratch region at
step 0, so *every* scratch bit draws a qubit. The distinction survives only as history.

Pre-materialisation costs **qubits, never gates**: scratch is born `CQ_BIT_ZERO` and
`cq_materialise` emits an `X` only for a constant `1`, so step 0 emits nothing. Do not add
`X` gates for it anywhere in §3.

Two additions to the tally beyond simply promoting every bit:

* **`r0_hi`, `W − 1` bits** (§2.1) — the upper bits of `r_0 = 0`, now a real scratch register
  rather than literal constants. This is what kills fold 3 and buys the pinned `34W² + 13W`.
  **It is also the whole of the disagreement with the plan's recorded qubit figure — see the
  flag below and §3.6.**
* `condneg`'s `W+1` carry wires per call, which materialised before the decision too (its
  control is a source qubit, so nothing ever folded there).

| opcode | composition | **qubits drawn from the pool** | counterfactual (pre-decision) |
|---|---|---|---|
| `udiv` | `W(8W+4) + W` (q) `+ (W−1)` (`r0_hi`) | **`8W² + 6W − 1`** | `8W² + 3W` |
| `urem` | `W(8W+4) + (W−1)` | **`8W² + 5W − 1`** | `8W² + 2W` |
| `sdiv` | `udiv + 2W` (sa,sb) `+ 3(W+1)` (condneg) `+ 1` (rs) | **`8W² + 11W + 3`** | `8W² + 8W + 4` |
| `srem` | `urem + 2W + 3(W+1)` | **`8W² + 10W + 2`** | `8W² + 7W + 3` |

`udiv` qubits evaluated: W=1 → 13; W=8 → **559**; W=16 → 2143; W=32 → 8383;
W=64 → **33151**.

> **⚠ FLAGGED, NOT RESOLVED — this figure disagrees with plan §0.2 GAP 1 by `W − 1`.**
> GAP 1 records K12's qubits as `8W² + 5W` (552 at `W = 8`). That is this table's `udiv` row
> **minus `r0_hi`** — i.e. it is the figure that goes with the *unpinned* gate count
> `34W² + W + 14`, not with the pinned `34W² + 13W`. The gate count and the qubit count as
> recorded cannot both be right. §3.6 lays out both self-consistent options in full.
> **Settle it in the plan before M19 is written; do not settle it in code.**

They come from the comparator chain, the subtractor chain and the mux `diff` of each of
the `W` iterations, plus the persistent quotient register, plus (signed only) the two
magnitude registers, the three `condneg` carry chains and the result-sign wire. **Every
one of them is returned to `|0⟩` by the sandwich reverse half, and by nothing else** —
none of these primitives self-cleans (`lower_ult!`, `lower_sub!`, `lower_mux!` and
`_cond_negate_inplace!` all leave their carry/diff chains loaded; `aggregate.jl:143-148`
states this explicitly for `_cond_negate_inplace!`).

**The remainder's `r_0` bits and the dropped top bit now cost qubits like everything else
[CHANGED 2026-08-14].** The old text here said they cost *zero* qubits "while they are still
`CQ_BIT_ZERO` (Rule 5)". Under I6(b) they are not still `CQ_BIT_ZERO` — they are
pre-materialised at step 0 along with the rest of the scratch region, and they are counted in
the table above.

**L5 is preserved, and it is preserved by short-circuiting, not by folding.** A fully
classical `a` and `b` still costs **zero gates and zero qubits** — but the reason has
changed, and it matters. It is *no longer* because the fold table empties the sandwich out;
if the all-classical case entered `cq_sandwich`, pre-materialisation would allocate the full
`8W² + 6W − 1` qubits for an operation that needs none. **The all-classical path must
short-circuit before `cq_sandwich` is entered** and fold to a constant result directly
(plan §0.2 consequence 2, risk **R9**). That is a kernel-entry check in M19/M20, and it is
the only thing standing between K12 and an L5 failure. The figures in the table above are
the all-operands-quantum case, which is what L4 pins.

**`8W² + 6W − 1` is `33,151` qubits at `W = 64` and this is a real scaling problem — it is
the only quadratic-ancilla kernel in the catalogue,** and I6(b) made it worse rather than
better (`+2W + W − 1` qubits, ~0.6% at `W = 64`, but the quadratic term is untouched and it
was always the problem). The fix is a *nested* sandwich: uncompute each iteration's
comparator/subtractor/mux scratch at the end of that iteration, keeping only `fits[t]`,
`rnext[t]` and `q`, which drops the peak to `O(W)` (`≈ 8W + 4` plus the two carried
registers) at the cost of roughly `2×` the gate count. **That is a plan decision, not a
kernel author's choice — it is tracked as `bd ckd.13` and is still open, and this document
does not resolve it.** The flat scheme is what the formulas above pin, and switching schemes
changes every L4 golden. Settle it before writing M19 if the pool ceiling (D2) matters for
the target QEC device.

## 5. Deltas from upstream

1. **Width-native `W` iterations vs Bennett's unconditional 64.** `lower_divrem!`
   zero/sign-extends **both** operands to 64 (`aggregate.jl:52-66`), runs the 64-iteration
   kernel, and truncates (`aggregate.jl:128-131`) — for every source width, including
   `Int8`. libcqops runs `W` iterations at width `W`. The derivation in §2.0 shows the
   value is identical. This is the single biggest delta and the reason **no libcqops K12
   gate count can be validated against any Bennett figure** (risk R3's golden-provenance
   header should say so in words, not just carry the SHA).
2. **Direct emission vs callee inlining.** Bennett routes the kernel through
   `lower_call!` and LLVM IR extraction (`aggregate.jl:90-101`, registered at
   `callees.jl:12-14`), which is why its gate count depends on LLVM's `optimize=false` IR
   shape. libcqops emits the loop directly, so our count is a closed form and theirs is
   not.
3. **Constant shifts and bit extraction are free.** `r << 1` is `lower_shl!`
   (`arith.jl:305-312`, `W−1` CNOTs into a fresh register) and `(a >> i) & 1` is
   `lower_lshr!` + `lower_and!` in Bennett. In libcqops both are `cq_bit` array
   relabelling — 0 gates, 0 qubits — because a bit is a value, not a wire (Rule 3 / I5).
   The only survivor is the single `CX(a[i] → z[t])`.
4. **The quotient bit is 1 CX, not `or` + `mux`.** Bennett's IR computes
   `q | (UInt64(1) << i)` then `ifelse`s the whole 64-bit `q` — that is
   `C_or(W) + C_mux(W) = 5W` CX `+ 2W` CCX per iteration. libcqops emits
   `CX(fits[t] → q[i])`, valid because `q[i]` is provably `CQ_BIT_ZERO` at that point (each
   iteration writes a distinct bit, exactly once). **This is an intentional deviation from
   the shape of Bennett's IR** — it is not a new reversible construction (it is the literal
   `dst ^= f` of the kernel contract), and PRD §6's K12 note already sanctions composing
   rather than porting a circuit. Record it in `bd remember` so nobody "restores fidelity"
   and multiplies the gate count by ~1.4×.
5. **`_cond_negate_inplace!` leaks `W+1` wires per call, by design.** `aggregate.jl:150-172`
   documents it: three calls per signed div, "~195 wires at W=64", never `free!`d, cleaned
   only by the outer reverse. libcqops inherits the leak and cleans it with the sandwich
   reverse. Do **not** try to free them mid-kernel — Bennett tried exactly that
   (`aggregate.jl:159-167`) and it broke correctness.
6. **In-place `val` must be a scratch copy.** See §2.4. Bennett passes its own widened
   `a64`/`b64`; the port must pass `sa`/`sb`. This is the most dangerous line in the
   whole extraction.
7. **A dead Toffoli at the top of every `condneg`.** At `i == W` the loop allocates
   `next_carry` and writes `ToffoliGate(val[W], carry, next_carry)` which is never read
   (`aggregate.jl:186-188`). Dropping it saves 1 CCX and 1 ancilla per call (3 per signed
   op). The §3 formulas keep it, faithfully. If the plan decides to drop it, `sdiv`/`srem`
   CCX becomes `5W² + W − 3` compute / `10W² + 2W − 6` sandwiched and ancillae drop by 3.
   *(Restated 2026-08-14 against the I6(b) figures; the old text quoted the retired (E)
   base `5W² − 3W` / `10W² − 6W`.)*
8. **`fits` and the subtractor's borrow are the same bit, computed twice.** `lower_ult!`
   (`arith.jl:449`) builds a full ripple-carry chain purely to read its carry-out, and
   `lower_sub!` (`adder.jl:149`) then builds the same chain again. Sharing would remove
   `C_uge(W) = 6W+5` gates and `3W+3` ancillae per iteration — roughly a third of the
   kernel. **Not for v1**: it is gate-level optimisation (explicitly out of scope) and it
   would decouple our counts from the primitives K7/K9 pin. Worth a `bd` issue against a
   post-baseline pass.
9. **One Bennett function becomes two libcqops modules.** `lower_divrem!` handles all four
   opcodes in one body (`aggregate.jl:49`, dispatched by `arith.jl:257-258`); the plan
   splits M19 `divrem_u` / M20 `divrem_s` (plan §3 rows 207-208, and R4 names this split as
   the pre-planned mitigation for the 300-line limit).
10. **No `throw`, ever, on either path.** Bennett has a *pair* of entry points: public
    `soft_udiv`/`soft_urem` throw `DivideError` (`divider.jl:73-76`, `85-88`) and are
    deliberately **not** registered as callees, precisely so a `@ijl_throw` never reaches
    the gate stream (`callees.jl:8-14`, `divider.jl:8-21`). libcqops has no Julia-caller
    surface, so it has no throwing twin — only the branchless behaviour below.
11. **`fits` is a double negation of a bit we already have. [ADDED 2026-08-14]** §2.2's P1
    ends with four gates — `CX(ucar[W] → ult); X(ult); CX(ult → fits); X(fits)` — which is
    `not1(ult(r,b))`, i.e. `¬¬carry_out`. `K09.md` §2's `lower_ult!` walkthrough records the
    fact out of the source:
    *"`carry[W+1]` is the carry-out of `a − b`, which is 1 iff `a ≥u b`"* — so
    `fits[t]` **is** `ucar[t][W]`, verbatim, and P1's tail costs 4 gates and 2 scratch bits
    per iteration (`4W` gates, `2W` qubits over the kernel) to reproduce a wire it already
    holds. Bennett pays it only because `uge` goes through the generic `lower_icmp!`
    dispatcher (`arith.jl:414`). The §3 formulas **keep** it, faithfully — dropping it is a
    kernel-shape decision like delta 4, not a gate-level peephole, but it is *not* taken
    here. If the plan takes it, every `fits[t]` reference becomes `ucar[t][W]` and the
    compute half drops by `4W` gates (`8W` sandwiched) and `2W` qubits. *(Unchanged by the
    2026-08-14 re-issue — none of those four gates ever folded.)*
12. **We pre-materialise scratch; Bennett does not, and upstream cannot even ask the
    question. [ADDED 2026-08-14]** `cq_sandwich` turns every bit of K12's scratch region into
    a qubit at step 0, before the first compute step runs (I6(b), plan §0.2). Bennett emits
    no such step, and there is no upstream construct to compare it against, because
    **Bennett has no classical operand kind at all**: `third_party/bennett/src/gates.jl:1`
    declares `const WireIndex = Int`, and `NOTGate` (`:7`), `CNOTGate` (`:12`) and
    `ToffoliGate` (`:18`) each hold nothing but `WireIndex` fields. Every operand of every
    Bennett gate is a wire. There is no tri-valued bit, no fold table, and therefore no
    notion of a scratch bit "still being classical" — so the hazard I6(b) closes (risk
    **R8**) cannot arise upstream and Bennett had no reason to pay for it.

    This is the delta that moved K12's numbers most: **`34W² − 3W + 14` → `34W² + 13W`**
    (2166 → 2280 at `W = 8`), because three fold-table elisions died at once (§3.1a), and
    **`8W² + 3W` → `8W² + 6W − 1`** qubits (§4). It also *simplified* the doc — the count is
    now a function of `W` alone at the golden mask, the `W = 1` special case is gone, and
    slots and gates coincide. **The price is paid in K12 more than anywhere else in the
    catalogue** precisely because K12 was the only kernel with three independent elisions:
    `W` `uge` carry seeds, `W` `sub` carry seeds, and the one-off `t = 0` remainder.

    Do not "restore fidelity to Bennett" by removing pre-materialisation. Bennett's
    construction is unchanged; what changed is our emitter, and Bennett's gate list is still
    what §3.1 counts.

### D3 — division by zero: what to pin

Read out of `divider.jl:15-18` and `divider.jl:44-46`, and pinned by
`test/test_salb_div_by_zero.jl`:

| | Bennett's value | source |
|---|---|---|
| `_soft_udiv_compile(a, 0)` | `typemax(UInt64)` — every quotient bit set, because the trial `r >= 0` always succeeds | `divider.jl:17-18`; `test_salb_div_by_zero.jl:33` |
| `_soft_urem_compile(a, 0)` | `a` — every trial subtract is a no-op, so `r` accumulates `a` | `divider.jl:44-46`; `test_salb_div_by_zero.jl:34` |
| compiled `UInt8 ÷ 0` | `typemax(UInt8)` | `test_salb_div_by_zero.jl:52-58` |
| compiled `UInt8 % 0` | the dividend `a` | `test_salb_div_by_zero.jl:60-66` |
| compiled `Int8` `typemin ÷ -1` | `typemin(Int8)` (wrap, not poison) | `test_salb_div_by_zero.jl:69-76` |

**libcqops pins, at width `W`:**

* `cqrt_udiv_<W>(a, 0)` → `2^W − 1` (all ones). The §2.0 invariant makes this exact at
  width `W`: `fits` is true at every one of the `W` iterations, so every `q[i]` is set.
* `cqrt_urem_<W>(a, 0)` → `a`. Every mux selects the un-subtracted branch, so
  `r_W = P_W = a`.
* **Never traps, never allocates an error path, never branches.** The circuit is a fixed
  permutation; `b = 0` is just another input. There is no `H`/`T`, no runtime check, and
  nothing to fail loud about — D3 is *deterministic-but-unspecified*, which is a value
  contract, not an error contract. (This is the one place in libcqops where "fail loud" is
  wrong; Rule 6's hard error is about *dirty rails*, not about *poison values*.)
* `sdiv`/`srem` at `b = 0`, **derived, not executed** (see §6): the sign-magnitude wrapper
  runs on top of the unsigned contract. `|0| = 0`, `b_sign = 0`, so
  `sdiv(a, 0) = condneg(2^W − 1, sign(a))` = `-1` for `a ≥ 0` and `+1` for `a < 0`; and
  `srem(a, 0) = condneg(|a|, sign(a)) = a`. The `typemin ÷ -1 → typemin` case reproduces
  at width `W` without the 64-bit widening: `|typemin|` is `typemin` again in two's
  complement, `÷ 1` leaves it, and the sign fix is a no-op because
  `sign(a) ⊕ sign(b) = 1 ⊕ 1 = 0`.
* Whatever the L1 refmodel and the L4 goldens record, **document the b=0 row in the test
  file with a pointer to `divider.jl:15-18`** so the next reader knows these values are
  inherited, not chosen.
