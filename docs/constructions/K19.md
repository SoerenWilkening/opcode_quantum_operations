`fptoui` has ~69,000 slots over 74 rows and runs the program twice per call.

### 1.2 `soft_fptosi` — `fptosi.jl:1-70`, verbatim

```julia
"""
    soft_fptosi(a::UInt64)::UInt64

Convert IEEE 754 double-precision float (as UInt64 bit pattern) to signed Int64
(as UInt64 bit pattern). Branchless implementation for reversible circuit compilation.
Bit-exact with LLVM `fptosi double to i64` lowered for x86 SSE
(`cvttsd2si`): any NaN, ±Inf, or out-of-range operand saturates to
INT_MIN = 0x8000000000000000 per Intel SDM Vol 1 §4.8.3.7.

Algorithm:
1. Extract sign, exponent, mantissa from IEEE 754 encoding
2. Compute shift amount: how many bits to shift the 53-bit mantissa
3. If exponent >= 1023+52: shift left (large values)
4. If exponent < 1023+52: shift right (truncate fractional part)
5. Apply sign (two's complement negation if negative)
6. Saturate NaN / ±Inf / |x| ≥ 2^63 to INT_MIN (Bennett-r84x / U08).
   The single in-range value with biased exp = 1086 is x = -2^63 exactly
   (sign=1, fraction=0), and its natural `(~mag) + 1` computation also
   yields INT_MIN, so the unconditional saturation at exp ≥ 1086 is
   idempotent on that value.
"""
@inline function soft_fptosi(a::UInt64)::UInt64
    sign = (a >> 63) & UInt64(1)
    exp  = (a >> 52) & UInt64(0x7ff)
    mant = a & UInt64(0x000fffffffffffff)

    # Add implicit 1-bit for normal numbers (exp != 0)
    is_normal = ifelse(exp != UInt64(0), UInt64(1), UInt64(0))
    full_mant = mant | (is_normal << 52)  # 53-bit significand: 1.mant

    # Unbiased exponent: exp - 1023
    # Shift amount: unbiased_exp - 52 (positive = shift left, negative = shift right)
    # For the integer part, we want: full_mant >> (52 - unbiased_exp)
    #   = full_mant >> (52 - (exp - 1023))
    #   = full_mant >> (1075 - exp)
    #
    # If exp >= 1075: shift LEFT by (exp - 1075)
    # If exp < 1075: shift RIGHT by (1075 - exp)
    # If exp < 1023: result is 0 (value < 1.0)

    right_shift = UInt64(1075) - exp
    left_shift = exp - UInt64(1075)

    # Clamp shifts to valid range [0, 63]
    right_shift_clamped = ifelse(right_shift > UInt64(63), UInt64(63), right_shift)
    left_shift_clamped = ifelse(left_shift > UInt64(63), UInt64(63), left_shift)

    # Compute both paths
    result_right = full_mant >> right_shift_clamped
    result_left = full_mant << left_shift_clamped

    # Select: if exp >= 1075, use left shift; otherwise right shift
    go_left = ifelse(exp >= UInt64(1075), UInt64(1), UInt64(0))
    magnitude = ifelse(go_left == UInt64(1), result_left, result_right)

    # Zero for subnormals and zero (exp == 0 gives right_shift = 1075, so result = 0 anyway)
    # This is handled naturally by the shift.

    # Apply sign: if sign == 1, negate (two's complement: -x = ~x + 1)
    negated = (~magnitude) + UInt64(1)
    signed_result = ifelse(sign == UInt64(1), negated, magnitude)

    # Saturate to INT_MIN for NaN / ±Inf (biased exp = 2047) and |x| ≥ 2^63
    # (biased exp ≥ 1086). x86 `cvttsd2si` returns 0x8000000000000000 on the
    # invalid-operation flag.
    is_invalid = exp >= UInt64(1086)
    result = ifelse(is_invalid, UInt64(0x8000000000000000), signed_result)

    return result
end
```

### 1.3 `soft_fptoui` — `fptoui.jl:1-49`, verbatim

```julia
"""
    soft_fptoui(a::UInt64)::UInt64

Convert IEEE 754 double-precision float (as UInt64 bit pattern) to unsigned
UInt64. Branchless implementation for reversible circuit compilation.
Bit-exact with Julia's native `unsafe_trunc(UInt64, ::Float64)` on x86-64,
which lowers `fptoui double to i64` via `cvttsd2si` with a 2^63 bias
correction for the [2^63, 2^64) half.

Bennett-b1vp / U31: prior to this function, the `LLVMFPToUI` opcode was
silently routed through `soft_fptosi`, corrupting any in-range value that
requires the high bit of an unsigned 64-bit integer (e.g. 1e19).

Semantics:
- x ∈ [0, 2^63): identical to `soft_fptosi` (cvttsd2si path).
- x ∈ [2^63, 2^64): subtract 2^63, convert the remainder in [0, 2^63),
  then OR bit 63.
- NaN / ±Inf / |x| ≥ 2^64 / x ≤ -2^63: saturate to 0x8000000000000000
  (the x86 `cvttsd2si` indefinite value).
- x ∈ (-2^63, 0): two's-complement reinterpretation of the signed
  convert. Strictly LLVM poison, but matches x86-64 native behaviour —
  honesty over a stricter LLVM-spec saturation.

Biased-exponent 1086 is the [2^63, 2^64) half: 2^63 has biased exp=1086,
mant=0; prevfloat(2^64) has biased exp=1086, mant=all-ones. 2^64 itself
has biased exp=1087 and is therefore routed down the invalid path.
"""
@inline function soft_fptoui(a::UInt64)::UInt64
    sign = (a >> 63) & UInt64(1)
    exp  = (a >> 52) & UInt64(0x7ff)

    # Select between the "cvttsd2si" path (sign=0, exp < 1086 OR sign=1)
    # and the "subtract 2^63" path (sign=0, exp == 1086).
    in_high_range = (sign == UInt64(0)) & (exp == UInt64(1086))

    # Path A: direct signed convert. For x < 2^63 (positives or any
    # negative in [-2^63, 0)), the reinterpreted bits are what we want.
    # For NaN / ±Inf / x ≤ -2^63, soft_fptosi already saturates to
    # 0x8000000000000000, giving the invalid sentinel unchanged.
    path_a = soft_fptosi(a)

    # Path B: x ∈ [2^63, 2^64). Subtract 2^63 exactly — representable
    # in Float64 as 0x43E0000000000000 — leaving a remainder in [0, 2^63)
    # that soft_fptosi can convert without saturation. OR bit 63 back in.
    adjusted = soft_fsub(a, UInt64(0x43E0000000000000))
    path_b = UInt64(0x8000000000000000) | soft_fptosi(adjusted)

    return ifelse(in_high_range, path_b, path_a)
end
```

### 1.4 `soft_sitofp` — `sitofp.jl:1-86`, verbatim

```julia
"""
    soft_sitofp(a::UInt64)::UInt64

Convert signed Int64 (as UInt64 bit pattern) to IEEE 754 double-precision float
(as UInt64 bit pattern). Branchless implementation for reversible circuit compilation.

Algorithm:
1. Extract sign (bit 63), compute absolute value
2. Find position of MSB (count leading zeros)
3. Compute exponent = 1023 + 62 - clz
4. Shift mantissa: align MSB to bit 52 (the implicit 1-bit)
5. Round-to-nearest-even on the lost bits
6. Pack sign + exponent + mantissa
"""
@inline function soft_sitofp(a::UInt64)::UInt64
    # Handle zero
    is_zero = a == UInt64(0)

    # Extract sign and absolute value
    sign = (a >> 63) & UInt64(1)
    # Two's complement absolute value: if negative, negate
    neg = (~a) + UInt64(1)
    magnitude = ifelse(sign == UInt64(1), neg, a)

    # Count leading zeros (branchless binary search, 6 stages for 64-bit)
    clz = UInt64(0)
    tmp = magnitude
    # Stage 1: check top 32 bits
    top32_zero = (tmp >> 32) == UInt64(0)
    clz = ifelse(top32_zero, clz + UInt64(32), clz)
    tmp = ifelse(top32_zero, tmp << 32, tmp)
    # Stage 2: check top 16
    top16_zero = (tmp >> 48) == UInt64(0)
    clz = ifelse(top16_zero, clz + UInt64(16), clz)
    tmp = ifelse(top16_zero, tmp << 16, tmp)
    # Stage 3: check top 8
    top8_zero = (tmp >> 56) == UInt64(0)
    clz = ifelse(top8_zero, clz + UInt64(8), clz)
    tmp = ifelse(top8_zero, tmp << 8, tmp)
    # Stage 4: check top 4
    top4_zero = (tmp >> 60) == UInt64(0)
    clz = ifelse(top4_zero, clz + UInt64(4), clz)
    tmp = ifelse(top4_zero, tmp << 4, tmp)
    # Stage 5: check top 2
    top2_zero = (tmp >> 62) == UInt64(0)
    clz = ifelse(top2_zero, clz + UInt64(2), clz)
    tmp = ifelse(top2_zero, tmp << 2, tmp)
    # Stage 6: check top 1
    top1_zero = (tmp >> 63) == UInt64(0)
    clz = ifelse(top1_zero, clz + UInt64(1), clz)

    # Exponent: biased (1023 + bit_position_of_MSB)
    # MSB position = 63 - clz (for non-zero). Exponent = 1023 + 63 - clz = 1086 - clz
    exponent = UInt64(1086) - clz

    # Shift magnitude so MSB is at bit 63.
    # Left-shift by clz puts MSB at bit 63. Then bits [62:11] are the mantissa
    # (bit 63 is the implicit 1-bit, not stored in IEEE 754).
    shift_clamped = ifelse(clz > UInt64(63), UInt64(63), clz)
    shifted = magnitude << shift_clamped

    # Mantissa = bits [62:11] of shifted (52 bits after the implicit 1)
    mantissa = (shifted >> 11) & UInt64(0x000FFFFFFFFFFFFF)

    # Round-to-nearest-even: check bit 10 (round bit), bits 9:0 (sticky)
    # After shifting MSB to bit 63: mantissa bits are [62:11], round bit is [10],
    # sticky bits are [9:0]
    round_bit = (shifted >> 10) & UInt64(1)
    sticky = shifted & UInt64(0x3FF)  # bits 9:0
    # Round up if round_bit=1 AND (sticky!=0 OR mantissa bit 0 = 1)
    round_up = round_bit & (ifelse(sticky != UInt64(0), UInt64(1), UInt64(0)) | (mantissa & UInt64(1)))
    mantissa = mantissa + round_up

    # Handle mantissa overflow from rounding (mantissa becomes 2^52 → increment exponent)
    mant_overflow = (mantissa >> 52) & UInt64(1)
    exponent = exponent + mant_overflow
    mantissa = mantissa & UInt64(0x000FFFFFFFFFFFFF)  # mask back to 52 bits

    # Pack result
    result = (sign << 63) | (exponent << 52) | mantissa

    # Zero → +0.0
    result = ifelse(is_zero, UInt64(0), result)

    return result
end
```

## 2. Gate sequence as an indexed block table

### 2.0 Grain, spans, and the three representation rules

**Grain is LITERAL, per PRD-v2 §7.2** — *"One block per operator occurrence as the source
spells it; every intermediate a 64-bit span (the Julia type's width); no common-subexpression
sharing; no narrowing towards the field width."* The three readings K15.md §2.0 and K18.md's
D-K18-1 fixed apply verbatim and are not re-derived here:

- **"the Julia type's width" is the DECLARED type**, so a `Bool` is **one** bit and a
  `UInt64`/`Int64` is **sixty-four**. In K19 the `Bool`s are exactly the `ifelse` conditions
  and the two lines that assign a comparison directly: `is_zero` (`sitofp.jl:17`),
  `top32_zero … top1_zero` (`:29 :33 :37 :41 :45 :49`), `is_invalid` (`fptosi.jl:66`),
  `in_high_range` (`fptoui.jl:34`) and the two conjuncts feeding it. **Everything else is a
  64-bit span, including `sign`, `exp`, `is_normal`, `go_left`, `round_bit`,
  `mant_overflow`** — all of which are `UInt64` in the source and all of which hold 0 or 1.
  Narrowing any of them is refused on PRD-v2 §7.2 and on K11's recorded finding.
- **No CSE means no CSE.** §5.1 lists what this costs in K19, and it is bigger than in K15
  because `soft_fptoui` re-extracts `sign` and `exp` that both of its nested `soft_fptosi`
  calls extract again — **three** copies of each.
- **Constants are SOURCES, never scratch** — PRD-v2 §7.3, verbatim. §2.1 lists K19's
  constant tables.

**The three representation rules** (K15.md §2.0, applied unchanged):

1. **A block** — anything that computes a new value: every `+ − & | ⊻ ~ == != < <= > >=`, every
   `ifelse`, and every variable-amount shift. It targets a fresh scratch span.
2. **A view — zero gates, zero qubits** — a **constant-amount** shift and a reinterpret. The
   step function assembles a 64-entry local `cq_bit` array holding the source span's entries
   at the shifted positions and `CQ_BIT_ZERO` at the vacated ones, **rebuilt from the step
   index on every call** and never carried in mutable state (K12.md §2.1's rule, because the
   driver replays indices in reverse).
3. **A constant is a source.** `K0`, `K1`, `K2`, `K4`, `K8`, `K16`, `K32`, `K63`, `K7FF`,
   `K3FF`, `K1075`, `K1086`, `KFRAC`, `KONES`, `KHIBIT`, `KBIAS` are file-static
   `const cq_bit[64]` tables costing zero qubits.

> **`~x` IS `lower_xor!` WITH AN ALL-ONES CONSTANT, AND THAT IS A PORT RATHER THAN A CHOICE.**
> There is **no full-width `lower_not!`** in `arith.jl` — only `lower_not1!` at `:474-478`,
> which allocates **one** bit. LLVM spells `~a` as `xor i64 %a, -1`, so the operator reaches
> `lower_xor!` (`:284-291`, two CNOTs per bit into a fresh `W`-wide vector) with a constant
> all-ones operand. Both of K19's `~` occurrences (`fptosi.jl:60`, `sitofp.jl:22`) transcribe
> that way. Under the §3 fold table the second CNOT of each bit becomes an `X`, so the row
> emits `2W` gates in `2W` slots and nothing folds to nothing — see §2.9.

> **A VIEW OVER A *SCRATCH* SPAN CARRIES THAT SPAN'S HIGH LANES AS QUBITS, NOT AS CONSTANTS,
> AND K19 IS THE FIRST K-DOC WHERE THAT BITES.** `fptosi.jl:29`'s `is_normal << 52` is a view
> over `is_normal`, which is a **mux output** — 64 pre-materialised scratch bits under I6(b),
> of which lanes 1..63 provably hold `|0⟩` and are nonetheless `CQ_BIT_Q`. So the `or` at
> `:29` emits on lanes 53..63 exactly as it does on lane 52, and none of it folds. Contrast
> K18's four shift views, every one of which is over a **rail** with a `K_ZERO` fill and whose
> vacated lanes therefore *do* fold. **The distinction is which thing the vacated lanes come
> from**, and a scan that assumes "a shift view folds" is wrong here in the direction that
> under-predicts gates. Same for `sitofp.jl:80`'s two pack views.

### 2.1 Scratch layout — flat, one region per kernel, offsets in spans

**FLAT, as K12's and K15's are** (PRD §15 D9). One `cq_scratch` region per kernel, laid out

offset of row `n` is the prefix sum of the preceding rows' scratch sizes — a compile-time
constant table, because every one of K19's four compute halves is **straight-line**: there is
no iteration anywhere, not even in the CLZ ladder, which is six *written-out* stages and not
a loop. The per-block sizes are their modules':

### 2.2 `fptosi` — 27 rows in SOURCE ORDER, of which 3 are views

**Reading instructions**, as K15.md §2.2 sets them. One row per **operator occurrence**.
`V` = view (rule 2: zero slots, zero gates, zero qubits). `C_x(w)` is the cost of block `x`
at width `w`, **asked of its module and never written down** (§3.0). `Kn` is a constant
source. Every `ifelse` row names its `cond` first.

**`==` is `C_eq(W) + 1` and `!=` is `C_eq(W)`**; **`>=`/`<=` are `C_ult(W)` and `<`/`>` are

### 2.6 Copy-out — and the `trunc` is FOLDED INTO IT

```
fp → int (fptosi, fptoui), T in {1, 8, 16, 32, 64}:
    copyout(c) for c in [0, T):    CX( result[c] -> dst[c] )      /* T CX */

int → fp (sitofp, uitofp):

```

**Upstream emits the narrowing `trunc` as a second IR instruction** (`instructions.jl:7657`);
we fold it into the copy-out by writing only `T` lanes. That is the sanctioned fold and it has
a named precedent: K09's `eq` folds its trailing `NOT` into the copy-out on exactly this
ground (K09 §5 delta 2, ratified as PRD §15 D9(b)). It is sound because `cq_kernel_trunc`'s
own contract is *"The high bits `a[T..F-1]` are never read and never written"* (`cast.h`) —
and here those lanes are K19's scratch, uncomputed by the sandwich reverse like everything
else in the region.

**The widening cast cannot be folded the same way** and is a real row (S0 / W1): it runs
*before* the kernel body and feeds it, so there is no copy-out to hide it in.

### 2.7 I6(a) and I6(b)

**I6(a) — every compute-half gate target a kernel names is scratch. YES, by construction.**
Every row of §2.2–§2.5 is a view (emits nothing), a block whose targets are the block's own
vectors inside K19's region, or an inline CX loop targeting a scratch span. The rail `a`
appears in rows P1/P3/P5, U1/U3/U8/U9, S0/S1/S4/S7, W1 — **only ever as a `const cq_bit *`
control**, which `cq_emit_*`'s signature makes structural (Rule 8's first enforcement
mechanism). The sixteen constant tables are `const` for the same reason. The one row that is
not M37's own gates — U9, M33's — inherits the obligation and must be discharged in `9ve.21`.

**I6(b) — every scratch bit is `CQ_BIT_Q` for the whole compute half. YES, the driver's
doing.** Three K19-specific consequences:

- **No fold ever fires on a scratch bit**, so §3's slot arithmetic is a function of `W` alone.
- **The folds that DO fire are exactly the constant-source ones** (§2.0 rule 3) and they are
  identical at every operand mask, forward and backward. A constant-elided slot is still a
  slot: the driver visits it in both directions and it emits nothing in both, so the
  palindrome is unaffected.
- **A view over a scratch span folds NOTHING** (§2.0's second box). K19's view rows split
  into two classes and only the first folds: views over the **rail** (`P1 P3 U1 U3 S2`, whose
  vacated lanes are literal `CQ_BIT_ZERO`), and views over a **scratch span** (`P8 S8 S13 S15
  S24 S28 S29` and the eleven ladder views, whose vacated lanes are the span's own `|0⟩`
  qubits).

**The I6(a) extent must cover a view's *underlying* span**, and a view is not a separate
allocation. Reading `shifted >> 11` as a control reads `shifted`, which is inside the extent.
Nothing targets a view.

### 2.8 The step dispatch — a static prefix sum, and for `fptoui` a NESTED one

K12's decode is `t = s / K(W)`, `j = s % K(W)`, because its compute half is `W` identical
iterations. **K19's four compute halves are straight-line, so there is no modulus** — not even
in the CLZ ladder, which the source writes out six times.

```
/* built once, at kernel entry, from §2.2's / §2.4's row table */
static int off[N+1];        /* off[0] = 0; off[n+1] = off[n] + slots(row n) */

step(s):
    n = upper_bound(off, s) - 1      /* which row owns slot s */
    u = s - off[n]                   /* the row's own index    */
    dispatch on row n's block type:
        and/or/xor       -> emit directly, one gate at index u
        zext/sext        -> emit directly, one CX at index u   [K5 inline]
        eq | ne          -> cq_eq_step     (block_n, u)
        ult family       -> cq_ult_step    (block_n, u)  [ + the trailing X for `<`/`>` ]
        add              -> cq_add_step    (block_n, u)  [ M14, DOES NOT EXIST — §5.7 ]
        sub              -> cq_sub_step    (block_n, u)
        mux              -> cq_mux_step    (block_n, u)
        barrel           -> cq_barrel_step (block_n, u)
        fptosi           -> cq_fptosi_step (block_n, u)  [ M37's own, recursive ]
        fsub             -> cq_fsub_step   (block_n, u)  [ M33, DOES NOT EXIST — §5.7 ]
```

**`off[]` must be a pure function of `W` (and of `F`, for the two conditional widen rows) and
of nothing else** — the driver replays indices in reverse and a table rebuilt from mutable
state would desynchronise the halves. Building it at entry from `cq_ult_steps(64)`,
`cq_eq_steps(64)`, `cq_barrel_steps(64, dir)`, … — the *measurements*, never the literals — is
what makes §3.0's composition identity hold by construction rather than by coincidence.

> **`fptoui`'s DISPATCH IS TWO LEVELS DEEP AND THAT IS NEW.** Rows U8 and U10 own
> `C_fptosi(64)` slots each, and *their* internal decode is §2.2's own prefix sum. So
> `cq_fptoui_step` resolves a slot to row U8, subtracts `off[U8]`, and hands the remainder to
> `cq_fptosi_step` with instance 1's block — which then runs its own `upper_bound`. No kernel
> in v1 has a two-level decode; K12's is one level over `W` iterations. **The hazard is that
> the two levels have separate off-by-ones and the outer one is invisible**: shifting U8's
> base by `n` slots shifts U10's base by the same `n`, so the *shape* of the stream is intact
> and only the operand bindings move. §2.9's scan cannot see it — the kind schedule is
> identical — and only L1's anchors 20–24 can.

### 2.9 The slot-scan derivation — FOUR-VALUED, `{NONE, X, CX, CCX}`

**What a K12-shaped kernel gets wrong is the slot arithmetic, not the gates** (CLAUDE.md's
callout; PRD-v2 §7.1 repeats it and requires the scan be written **before** the kernel, with
the composition check). The instrument is K12's
`the_phase_boundaries_match_an_independent_slot_scan`: re-derive the **op KIND** of every
compute-half slot from the blocks' own structure and compare against the recorded stream at
the all-quantum operand mask. It records only which of `X` / `CX` / `CCX` each slot emits —
what a boundary error moves and what a gate-list error does not — so it is not a second
transcription of anything.

**THE KIND IS FOUR-VALUED, exactly as K15.md §2.6 and K18.md's D-K18-6 establish.** §2.0
rule 3's constants make some slots emit nothing and demote others, so `slot index ≠ stream
index` permanently. The scan predicts `{NONE, X, CX, CCX}` per slot and walks the stream with
a separate cursor that advances only on non-`NONE`. **A scan that keeps K12's 1:1 assumption
goes red on row P2 and stays red, and the reflex fix — deleting the constant rows from the
prediction — is what turns the instrument off.**

**The per-block op-kind sub-schedules**, each read out of its module's own K-doc and none of
them re-derived here (K15.md §2.6 prints the same list; it is reproduced rather than cited so
the scan is writable from one document):

```
/* K02 §2 — and: one CCX per bit. With a CONSTANT operand mask m: */
sched_and (W, m, v) = m[v] ? CX : NONE                  /* v in [0, W)          */
sched_and (W, ·, v) = CCX                               /* two quantum operands */

/* K03 §2 — or: three gates per bit, CX, CX, CCX. With a constant operand m: */
sched_or  (W, m, v) : i = v/3, j = v%3
    j==0 -> CX
    j==1 -> m[i] ? X   : NONE
    j==2 -> m[i] ? CX  : NONE

/* K01 §2 — xor: two CX per bit. With a constant operand m: */
sched_xor (W, m, v) : i = v/2, j = v%2
    j==0 -> CX
    j==1 -> m[i] ? X : NONE

/* K09 §2.1 — eq/ne compute half, 5W-3 slots */
sched_eq  (W, v) = v < 2W ? CX : ((v-2W)%3 == 2 ? CCX : CX)

/* K09 §2.2 — ult compute half, 6W+1 slots */
sched_ult (W, v) : v <  2W -> (v%2==0 ? CX : X)
                   v == 2W -> X
                   else    -> ((v-(2W+1))%4 < 2 ? CX : CCX)

/* K06 §2 — add compute half, 5W-2 slots */
sched_add (W, v) : v < 5(W-1) -> [CX,CX,CCX,CCX,CX][v%5]
                   else       -> CX

/* K07 / add.h — sub compute half, 7W-1 slots */
sched_sub (W, v) : v <  2W -> (v%2==0 ? CX : X)
                   v == 2W -> X
                   else    -> u = v-(2W+1);
                              u >= 5(W-1) ? CX : ((u%5==2||u%5==3) ? CCX : CX)

/* K10 §2.1 — mux, 4 slots per bit */
sched_mux (v) = (v%4 == 3) ? CCX : CX

/* K10 §2.2 / K04 §7.4 — barrel, S = cq_shift_stages(W) stages */
sched_barrel(W, S, v) : v < W -> CX                       /* INIT               */
                        else, per stage k: (W - 2^k) CX   /* SHIFT, shl & lshr  */
                                           then 4W slots sched_mux

/* K05 §2 — the widen rows, emitted inline */
sched_zext(F, v) = CX        /* v in [0, F)  */
sched_sext(F, v) = CX        /* v in [0, 64) */
```

**The K19-specific fold facts the scan needs**, all statically determined by §2.1's constant
tables and §2.0's two view classes:

| row shape | what folds | net |
|---|---|---|
| `and(x, K)` with `K` a constant mask | `sched_and(64, K, v)` — a `CCX` becomes `CX` on a `ONE` lane and **`NONE`** on a `ZERO` lane | `popcount(K)` gates in 64 slots |
| `and(x, K1)` (P2, S3, S16, S20, S25) | 63 of 64 lanes are `ZERO` | **1 gate in 64 slots** |
| `and(x, K7FF)` (P4, U4) | 11 `ONE` lanes | 11 gates in 64 slots |
| `and(x, KFRAC)` (P5, S14, S27) | 52 `ONE` lanes | 52 gates in 64 slots |
| `and(x, K3FF)` (S17) | 10 `ONE` lanes | 10 gates in 64 slots |
| `and` at 1 with two scratch operands (U7) | nothing | 1 CCX in 1 slot |
| `xor(x, KONES)` (P22, S4) | every lane `ONE`, so `j==1` is `X` | **2W gates in 2W slots**, none elided |
| `or(x, view-over-scratch)` (P9, S30, S31) | nothing — both operands are `CQ_BIT_Q` | `3W` gates in `3W` slots |
| `or(KHIBIT, x)` (U11) | 63 `ZERO` lanes on the constant side | `2W + 1` gates in `3W` slots |
| `mux(cond; K1, K0)` (P7, P19, S19) | `t=K1` gives one `X` on lane 0, `f=K0` elides both its CX | **1 X + 64 CCX in 256 slots** |
| `mux(cond; K63, x)` (P13, P15, S11) | `t=K63` gives `X` on six lanes | `6 + 64 + 64` gates in 256 slots |
| `eq(x, K0)` / `ne(x, K0)` | `lower_eq!`'s first `2W` CX are `diff = a ^ b`; the `K0` half elides | `W` CX then `3(W−1)` — see below |
| any block whose both operands are scratch | nothing | every slot emits |

> **THE `eq(x, K0)` ROW IS THE ONE WHERE THE FOLD REACHES INSIDE A BLOCK'S OWN SCHEDULE, AND
> THE SCAN MUST MODEL IT THERE.** `lower_eq!` (`arith.jl:424-447`) writes `diff = a ⊻ b` with
> `2W` CNOTs — `W` from `a`, `W` from `b` — and then OR-reduces. With `b = K0` the second `W`
> vanish entirely and with `b = KFRAC` 52 of them survive. So `sched_eq`'s first `2W` slots
> are **not** uniformly `CX` here, and a scan that applies the fold only at the *row*
> granularity (constant row ⇒ whole row `NONE`) is wrong in both directions. K19 has **eleven**
> `eq`/`ne` rows against a constant (P6 P20 P24 P26-adjacent, U5 U6, S1 S6, the six ladder
> rows, S18) and the scan is worthless if it gets them wrong.

**Four boundaries worth a named case**, because an off-by-one there produces a plausible gate
rather than a crash:

1. **The stage-5 ↔ stage-6 seam in the CLZ ladder** (§2.4's box) — the one place K19's
   repeating structure changes length.
2. **P16 ↔ P17**, the two barrels back to back: same `S`, same slot count at `W = 64`
   (`shl` and `lshr` share the `W − 2^k` shuffle count by construction — `arith.jl:359`,
   `:375` — so only `ashr` differs, `:394`), so a swapped pair is invisible to the scan and
   visible only to L1.
3. **U8 ↔ U9 ↔ U10**, `fptoui`'s three sub-kernel spans (§2.8's box).
4. **S0 / W1's presence**, which is a function of `F` and not of `W`: the scan must be run at
   at least one `F < 64` and one `F == 64`, or the conditional row is never exercised.

### 2.10 The seam, CONFIRMED: zero named spans cross it

PRD-v2 §5 records **INT→FP ↔ FP→INT** in advance and says the two halves *"share nothing but
the field views"*. That holds, and more strongly than the sentence claims:

| | FP→INT (`fptosi`, `fptoui`) | INT→FP (`sitofp`, `uitofp`) |
|---|---|---|
| named spans | 24 + 10 | 48 (+1 for S0) |
| spans crossing the seam | **0** | **0** |
| barrels | 2 (`lshr` + `shl`) | 1 (`shl`) |
| the saturation / D3 story | **entirely here** (`fptosi.jl:66-67`, `fptoui.jl:18-22`) | none — every `i64` maps to a finite double |
| the CLZ ladder and RTNE | none | **entirely here** (`sitofp.jl:29-50`, `:63-77`) |
| shared | the IEEE field idiom `(a>>63)&1`, `(a>>52)&0x7ff`, `a & FRAC_MASK` — which is **M31 `fpfield`'s**, not a K19 intermediate | same |

**Suggested file split when M37 crosses 300 lines:** `src/kernels/fconv_to_int.c` (§2.2 +
§2.3) and `src/kernels/fconv_to_fp.c` (§2.4 + §2.5). Unlike K15, there is **no shared
prefix-sum table to keep in one place** — each of the four kernels owns its own `off[]`,
because none of them is a phase of another. That is what makes this seam cleaner than K15's,
where eleven named spans cross and the one `off[]` must not be duplicated.

## 3. Gate-count formula

### 3.0 Symbolic form — substitute, do not re-derive

K19 is a **composition**, not a construction. State it symbolically and substitute; if a
sibling's number moves, re-substitute here rather than re-deriving anything. Every `C` is
**asked of its module at width `W`** and never written down.

```
compute_fptosi(W) =  3·C_and(W) + C_or(W) + C_xor(W)
                  +  2·C_eq(W) + 2            /* P20, P24 — the `==` inversions   */
                  +  1·C_eq(W)                /* P6 — `!=`, raw wire              */
                  +  4·C_ult(W) + 2           /* P12 P14 strict, P18 P26 raw      */
                  +  1·C_add(W) + 2·C_sub(W) + 7·C_mux(W)
                  +  C_barrel(W, lshr) + C_barrel(W, shl)

compute_fptoui(W) =  2·C_and(W) + C_and(1) + C_or(W)
                  +  2·C_eq(W) + 2            /* U5, U6                           */
                  +  C_mux(W)
                  +  2·compute_fptosi(W)      /* U8, U10                          */
                  +  C_fsub(W)                /* U9 — M33's                       */

compute_sitofp(W) =  8·C_and(W) + 3·C_or(W) + C_xor(W)
                  +  8·C_eq(W) + 8            /* S1 S6 + the six ladder rows      */
                  +  1·C_eq(W)                /* S18 — `!=`                       */
                  +  1·C_ult(W) + 1           /* S10, strict                      */
                  +  9·C_add(W) + 1·C_sub(W) + 15·C_mux(W)
                  +  C_barrel(W, shl)
                  + [F < 64] · C_sext(F, W)

compute_uitofp(W) =  compute_sitofp(W)
                  -  [F < 64] · C_sext(F, W)
                  + [F < 64] · C_zext(F, W)

sandwiched_fp_to_int(W, T) = 2 · compute(W) + T      /* T copy-out CX, the trunc folded in */
sandwiched_int_to_fp(W)    = 2 · compute(W) + W      /* 64 copy-out CX                     */
```

|---|---|---|---|
| `C_and`, `C_or`, `C_xor` | **M10** | one / three / two gates per bit | K02 §2, K03 §2, K01 §2; emitted directly in the fp step function (PRD-v2 §7.10) |
| `C_zext`, `C_sext` | **M13** | `F` CX / `T` CX, zero ancillae | K05 §2; emitted directly |
| `C_eq(W)` | **M16** | the eq/ne compute half; raw flag is `a != b` | `cq_eq_steps(W)` — **SHIPPED** (bead `9ve.1`; K09 §7) |
| `C_ult(W)` | **M16** | `lower_ult!` minus its `r`/`not1` tail; raw flag is `a >=u b` | `cq_ult_steps(W)` — shipped |
| `C_add(W)` | **M14** | `k6_compute`, the out-of-place ripple | `cq_add_steps(W)` — **DOES NOT EXIST**, §5.7 |
| `C_sub(W)` | **M14** | `k7_compute` | `cq_sub_steps(W)` — shipped |
| `C_mux(W)` | **M17** | `lower_mux!` | `CQ_MUX_STEPS_PER_BIT · W`; `cq_mux_steps(W)` would be cleaner |
| `C_barrel(W, dir)` | **M12** | the `S`-stage barrel | `cq_barrel_steps(W, dir)` — **SHIPPED** (bead `9ve.2`; K04 §7). **The direction is a parameter and that is forced**, K04 §7.4 |
| `C_fsub(W)` | **M33** | `soft_fsub`'s compute half | `cq_fsub_steps(W)` — **DOES NOT EXIST**, §5.7; bead `9ve.21` |
| `C_fptosi(W)` | **M37** | §2.2's own compute half | `cq_fptosi_steps(W)`, recursive into `compute_fptoui` |

> ### THE COMPOSITION IDENTITY IS THE ASSERTION THAT SURVIVES `CQOPS_UPDATE_GOLDENS`
>
> `compute(64) = Σ (row's block cost, asked of its module)` over §2's tables, with §3.1's
> occurrence counts. It reads **no golden**, so `CQOPS_UPDATE_GOLDENS=1` cannot bless a
> reduction. CLAUDE.md's K11 callout is the reason and K19 offers the trade in **four**
> specific, tempting shapes:
>
> - `exp` is provably 11 bits and appears as an operand in nine rows — P4 P6 P10 P11 P18 P26,
>   U4 U6 — every one of which "could" be 11 or 12 bits wide.
> - `sign`, `is_normal`, `go_left`, `round_bit`, `mant_overflow`, `sticky_flag`, `mant_lsb`
>   and `round_up` are provably one bit in a 64-bit span. **Eight rows.**
> - `clz` is provably in `[0, 63]`, so the six `add` rows and the `sub` at S9 "could" be 6 or 7
>   bits.
> - `full_mant` is provably 53 bits, so P16 and P17 "could" be 53-bit barrels — a **`5WS`**
>   saving, the largest single one available.
>
> **Every one of those leaves L1, L2, L3 and L5 green**, because the values are right. PRD-v2
> §7.2 refuses all four on the ground D9 refused K12's `~17W²` → `~8.5W²`: it is a

### 3.2 Why there is no substituted magnitude in this document

K15.md §3.1 prints an *illustrative* substitution of the published closed forms and labels it
*"Order of magnitude only. Do not pin it, do not quote it, and do not use it to size
anything."* **K19 prints none at all**, for a reason specific to it: `C_barrel(64, dir)` is a
**measured** figure in K04 §7.4, not a closed form this document may evaluate, and
`C_fsub(64)` does not exist. Substituting the rest would produce a number that looks like the
answer and is missing the two largest terms. The composition identity of §3.0 is the whole
claim; anything smaller than it is a number that needs a run.

**SLOTS ARE NOT GATES HERE, AND THAT IS PERMANENT.** Every figure above is a **slot** count:
structural, a pure function of `W` (and `F`), identical at every operand mask, and what the
driver replays. The **emitted** count is strictly smaller because §2.0 rule 3's constant
sources fold — §2.9's fold table is the accounting. The emitted count is still deterministic
— a constant is constant at every mask — but it is not derivable from `W` alone, it is what
L4 pins, and **the composition check must pin slots, never gates.**

### 3.3 There is NO upstream magnitude for ANY of these four, and that is measured

`third_party/bennett/BENCHMARKS.md` has **no row for `fptosi`, `fptoui`, `sitofp` or
`uitofp`**. Its `## Gate Counts` table carries `soft_fadd`, `soft_fma`, `soft_fmul` and the
eighteen `soft_mux_load_*`/`soft_mux_store_*` memory primitives, and nothing else from the
softfloat surface; `grep -niE "fptosi|fptoui|sitofp|uitofp|conv|cast"` over the whole 297-line
file returns **zero** hits. Nor is there a `.jsonl` benchmark result naming one.

**So the number a reader will reach for does not exist**, and the temptation here is different
from K15's: rather than mis-using a published figure, someone will *derive* one from
`soft_fadd`'s 63,058 / 12,488 / 29,949 by ratio. Do not. Two of the four kernels contain a
barrel, which `soft_fadd` also has, and two contain none; `soft_fptoui` contains two whole
`soft_fptosi`s **and** a whole `soft_fsub`, so it is strictly larger than `soft_fadd`; and
PRD-v2 §7.3 means our constants cost zero wires where upstream's cost 64 each, so even a
correct upstream figure would not be ours. **The K-doc convention applies verbatim: do not
repeat upstream's comparison numbers as a claimed win**, and CLAUDE.md records that the
K-docs' §5 comparison figures were `fold_constants=false` figures while Bennett folds by
default.

### 3.4 What the composition check is, concretely — THREE cases, not two

K11 and K12 have two; K19 needs three, because `fptoui` composes `fptosi` and a sibling's
kernel rather than a sibling's *block*. Neither reads a golden.

1. **`the_block_costs_are_what_the_modules_report`** — runs **no kernel**. Calls the per-bit
   `and`/`or`/`xor` costs, `cq_eq_steps(64)`, `cq_ult_steps(64)`, `cq_add_steps(64)`,
   `cq_sub_steps(64)`, `cq_mux_steps(64)`, `cq_barrel_steps(64, shl)`,
   `cq_barrel_steps(64, lshr)`, `cq_fsub_steps(64)` and pins each. A sibling moving reddens
   **this** case and names the block.
2. **`the_two_leaf_compute_halves_are_the_sum_of_their_rows`** — pins `cq_fptosi_steps(64)`
   and `cq_sitofp_steps(64)` against §3.1's occurrence counts multiplied by what case 1 just
   measured. The occurrence counts are the only literals, and they are what §2 *is*.
3. **`fptoui_is_twice_fptosi_plus_fsub_plus_its_own_eight_rows`** — pins
   `cq_fptoui_steps(64)` against `2·cq_fptosi_steps(64) + cq_fsub_steps(64)` plus its own
   eight emitting rows. **This is the case that would go red if U8 and U10 were collapsed
   into one instance**, which is the reduction a reader will propose (§5.2).

Plus **`the_phase_boundaries_match_an_independent_slot_scan`** (§2.9) and
**`the_clz_ladder_is_five_uniform_stages_and_a_short_sixth`**, which is the only instrument
that can see §2.4's box.

### 5.6 The classical short-circuit — a C transcription, and here it is FORCED

Risk R9's short-circuit applies: all-classical operands never enter the sandwich and `dst` is
written as constants. **PRD-v2 §7.4 forbids computing those constants with the host `double`
operator**, and for K19 the ground is stronger than the host-dependence §7.4 measures for
`fadd`: for rows 1–9, 18–27 of §5.4 the host operator is not merely a different *choice*, it
is **undefined behaviour in C**. A compiler is entitled to fold `(int64_t)(0.0/0.0)` to
anything.

So `cq_fptosi_classical(uint64_t)`, `cq_fptoui_classical(uint64_t)` and
`cq_sitofp_classical(uint64_t)` are C transcriptions of §1's Julia over `uint64_t` — the same
source, evaluated on constants — and `cq_uitofp_classical` is `cq_sitofp_classical` after the
`zext`, matching §1.1's routing. Four riders:

- **`-ffp-contract=off`'s reason does not reach here**: the transcription is integer-only and
  touches no `double`. The library's only contact with a C `double` on the fp surface is the
  `memcpy` at `cqrt_alloc_f64` / `cqrt_measure_f64` (PRD-v2 §3.1).
- **L1's oracle stays INDEPENDENT**: rows 29–36 against the host `(double)(int64_t)x`
  operator (fully specified), rows 1–28 against §5.4's table **as literals**. An oracle
  sharing code with the implementation is blind to what that code gets wrong (the Step 18
  trap), so the reference does **not** reuse the transcription.
- **The transcription must use `uint64_t` arithmetic throughout**, including for the
  wraparound at `fptosi.jl:41-42`. Writing `right_shift` as an `int64_t` reproduces §5.3's
  signed-comparator mutant in C, where it is equally unobservable and equally wrong.
- **Cost: roughly 40 lines for `fptosi`, 15 for `fptoui`, 55 for `sitofp`**, and L1 checks
  each against the circuit on every mixed-mask case.

Under a **quantum** control L5's *"zero gates, zero qubits"* becomes false and that is the
correct answer, not a regression (CLAUDE.md's callout): the short-circuit still writes `dst`
through `cq_emit_x`, whose constant row cannot fire inside a promoted region, so each `dst`
lane becomes a wire driven by a real `CX`. K19's claim to assert at `CQ_KD_CTRL_Q0` is
`live` grew by exactly `T` (fp→int) or exactly 64 (int→fp).

```c
    uint32_t      off;     /* where this fsub's region starts inside it          */
    int           W;
} cq_fsub_block;

int           cq_fsub_region(int W);
int           cq_fsub_steps (int W);
void          cq_fsub_step  (cq_ctx *ctx, const cq_fsub_block *k, int u);
const cq_bit *cq_fsub_result(const cq_fsub_block *k);
```

Four obligations, the first two from plan §0.4 and the last two specific to this call site:

1. **The block allocates nothing** and `off` indexes the caller's one contiguous region, as
   `cq_divrem_block` and `cq_barrel_block` both have it.
2. **`a` and `b` are controls only**, so I6(a) holds for the block by construction and an
   operand that aliases a span an earlier step wrote is legal.
3. **It must be `fsub`, NOT `fadd ∘ fneg`.** PRD-v2 §5's M33 row: *"Do not spell `fsub` as
   `fadd(a, fneg(b))` — upstream fixed a NaN-RHS sign bug in exactly that composition
   (`Bennett-m63k`)."* **And this is the one call site where the wrong spelling is
   invisible**: `b` is the constant `KBIAS = 0x43E0000000000000`, which is not a NaN, so
   `fsub.jl:23`'s `b_is_nan` is provably false and the two spellings agree on every input to
   `fptoui`. A shortcut taken here is right here and wrong for every other consumer. §6.5
   risk 4.
4. **`cq_fsub_result` must be the accessor**, never a spelled offset — K04 §7.3's rule for
   `cq_barrel_result`, for the same reason: every other span in the region is an intermediate
   the reverse half has to unwind.

### 5.8 Six smaller deltas

1. **The narrowing `trunc` is folded into the copy-out** (§2.6), where upstream emits a
   second IR instruction (`instructions.jl:7657`). Precedent: K09 §5 delta 2 / PRD §15 D9(b).
2. **The widening cast is a real row and is emitted inline** (S0/W1), one CX per slot, rather
   than by calling `cq_kernel_zext`/`cq_kernel_sext`. PRD-v2 §7.10's rule for bitwise ops,
   applied to K5.
3. **`cast.h`'s zero-qubit claim does not survive the move into a compute half** (§2.5's
   box): I6(b) pre-materialises all 64 lanes whatever `F` is. The *gate* claim survives.
4. **Constants are sources, not wires** (§2.0 rule 3). Sixteen tables, zero qubits, against
   upstream's fresh 64 wires per constant per use (`arith.jl:202`).
5. **`>=` reads the raw carry** and `==`/`>` pay one `X`. Four rows here read a raw wire
   directly (P18, P26, and the eq/ne blocks' `!=` at P6 and S18). PRD §15 D9(b) / K09 §5
   delta 2 is the precedent, and the ground is that two realisations of `eq` in one library
   is the anomaly, not the saving.
6. **Constant-amount shifts are wiring** (§2.0 rule 2), where `lower_lshr!`
   (`arith.jl:314-320`) allocates a fresh `W`-wide vector and emits `W − k` CNOTs. K19 has
   **23** such occurrences across the three files and they emit nothing and allocate nothing
   — but §2.0's second box is the rider: a view over a *scratch* span does not make its
   consumer's gates fold.

### 5.9 L1's anchor list for K19 — PRD-v2 §7.12, refined against the sources' predicates

**§7.12's instruction:** the budget stays `cq_kd_samples()` = 32 and the anchors are **forced
into every draw** rather than pooled, *"because each is a branch of the `ifelse` tree that a
random draw of 32 reaches with no guarantee"*, and *"per kernel the list is refined against
the source's own special-case predicates."*

> REFINEMENT.** There is **no `is_nan` and no `is_inf`** anywhere in `fptosi.jl`,

> `fptosi`-side `is_nan` row is naming a row that can never go red on its own. What each of

The **named** predicates, enumerated: `is_normal` (`fptosi.jl:28`), `go_left` (`:53`),

`in_high_range` (`fptoui.jl:34`) and its two conjuncts; `is_zero` (`sitofp.jl:17`),

clamp (`:59`), `round_up` (`:71`), `mant_overflow` (`:75`).

**§5.4's 36 rows ARE the anchor list for the value-class predicates.** Five more are needed
for the predicates that §5.4 does not force:

> ### `soft_fptosi` CONTAINS THREE STRUCTURALLY EQUIVALENT MUTANTS, AND THAT IS A PROPERTY OF
> ### THE TWO-ARM DESIGN RATHER THAN A GAP IN THE ANCHOR LIST
>
> A first draft of the three rows above claimed each discriminated something. **Checked** —
> against a Python transcription of §1.2's body, over 300,000 random `uint64_t` operands plus
> a sweep of all 2,048 exponents × five mantissa corners × both signs — **none of the three
> does**, and the reason is the same in each case: `fptosi` computes **both** shift arms
> unconditionally and they coincide at exactly the point each predicate switches.
>
> | mutation of `fptosi.jl` | differences found | why |
> |---|---:|---|
> | `:28` `is_normal` forced to 1 | **0** | at `exp == 0`, `right_shift = 1075` clamps to 63 and `full_mant >> 63 = 0` whether or not the implicit bit was added — `full_mant < 2^53` either way |
> | `:53` `exp >= 1075` written as `exp > 1075` | **0** | the two spellings differ only at `exp == 1075`, where `right_shift = left_shift = 0` and **both arms equal `full_mant`** |
> | `:45`/`:46` clamp comparator made **signed** | **0** | §5.3's box — each wrapped amount occurs only on the arm `:53` discards |
>

> against a port that **drops** the `:45`/`:46` clamps — the D8 shortcut §5.5's box warns
> about — reports **132,203 differences** in the same 320k cases, with `fptosi(2^-12)`
> returning `0010000000000000` instead of `0000000000000000`. So the instrument works; the
> three mutants above really are equivalent.
>
> **Disposition, per CLAUDE.md's *equivalent-mutant-record-at-the-site*:** all three are
> transcribed exactly as the source spells them and the equivalence is recorded here, at the
> site. **Do not "simplify" any of them to match its mutant**, and do not write an anchor that
> claims to catch one — an assertion that cannot fail is the thing §6.5 risk 7 exists to stop
> someone adding. Every one of the three goes live the moment the redundant arm is narrowed,
> which is precisely the reduction §3.0's box refuses.
>
> **This was checked against a transcription of the SOURCE, not against libcqops** (§6.3).

### 6.5 Ranked risks

1. **`uitofp i64 → f64` HAS NO BIAS CORRECTION UPSTREAM, AND THAT IS A PRD-v2 DECISION, NOT
   `9ve.23`'s.** §1.1 fact 3: `instructions.jl:7666-7670` routes `UIToFP` to `soft_sitofp`,
   `:7672-7673` returns the bare call at `src_w == 64`, and `sitofp.jl:20` reads bit 63 as a
   sign. So every `uitofp i64` operand with the high bit set converts as a negative number —
   the exact mirror of the `U31` bug upstream fixed on the fp→int side (`fptoui.jl:10-12`).
   **Rule 1 says port, never re-derive**, so M37 must transcribe the routing and **record**
   this; "fixing" it by writing a `soft_uitofp` would be original construction work in this
   repo. But the ABI ships `{ from: i64, to: f64 }` under `uitofp`, so the divergence is
   reachable. **CLAUDE.md's *Open blockers* rule applies: resolve it in PRD-v2 §5 or §7.7
   before `9ve.23` starts, never implicitly in code.** Anchor 44 is the witness, and its
   oracle must be §5.4 row 30 (what the port does) and **not** the host
   `(double)(uint64_t)x` (what a correct conversion does) — pointing it at the host makes the
   anchor red for a reason that is upstream's, and someone will then "fix" the port.
   *Not measured here: whether CQ_lang's e2e corpus reaches a `uitofp i64` with bit 63 set.
   This repo does not pin CQ_lang and cannot build it.*
2. **THE SLOT ARITHMETIC — and `fptoui`'s decode is TWO LEVELS DEEP.** §2.8's box: shifting
   U8's base shifts U10's by the same amount, so the *shape* of the stream is intact and only
   the operand bindings move — which §2.9's scan cannot see, because the kind schedule is
   identical either way. Inside that, the CLZ ladder's stage-6 asymmetry (§2.4's box) is the
   single likeliest off-by-one in the document, and it lands in `:54`'s `sub`. The scan is
   the first thing `9ve.23` writes, before the kernel, and it must be **four-valued**
   (§2.9) — a scan that keeps K12's one-gate-per-slot assumption goes red on row P2 and the
   reflex fix turns the instrument off.
3. **THE D8 CLAMPS ARE THREE ROWS THAT LOOK LIKE COMMENTS.** §5.5's box: dropping `:45`'s
   clamp is a live miscompile on **every operand below `2^−12`, every subnormal and every
   zero** — the most common inputs there are — and the audit's own CLAMPED verdict is what
   stops anyone looking. `sitofp.jl:59`'s is *inert* and will look even more droppable. The
   detectors are anchors 40 and 12–14, and nothing structural.
4. **`fsub` VS `fadd ∘ fneg` IS INVISIBLE AT THIS ONE CALL SITE.** §5.7 obligation 3: `b` is
   the constant `KBIAS`, not a NaN, so `fsub.jl:23`'s guard is provably false and both
   spellings agree on every `fptoui` input. An implementer who takes the shortcut here has a
   green K19 and a defect waiting for M33's next consumer. It crosses a bead boundary
   (`9ve.21` ↔ `9ve.23`), which is where contracts go to be assumed.
5. **THE MISSING `add` EXPORT, AND THE K8 SUBSTITUTION THE CLZ LADDER INVITES.** §5.7's box:
   ten occurrences, nine of them in a shape that reads exactly like an in-place accumulate,
   and CLAUDE.md's verdict on that substitution is *"the forward value would be right and only
   the `_unc` wrong, which is a silent miscompile rather than a test failure."* The second,
   independent reason is that C*j*4's false arm reads the pre-add value.
6. **THE MUX ARM ORDERS AT P25 AND P27.** §2.2's box. P25 transposed is right on every
   non-negative input and P27 transposed is right on every input that is not NaN / Inf /
   out-of-range, so a 32-sample draw of ordinary doubles reaches neither. Only §5.4's rows
   1–9 and 16–17 see them, and they emit the identical `(X, CX, CCX)` tuple, keep the
   palindrome and leave scratch clean.
7. **THREE OF `fptosi`'s PREDICATES ARE STRUCTURALLY EQUIVALENT MUTANTS (§5.3's and §5.9's
   boxes)** — the clamp comparators' signedness, `:28`'s `is_normal`, and `:53`'s `>=` vs
   `>`. Listed here rather than higher because **nothing can see any of them**, which is
   precisely why each must be transcribed as written and recorded at the site rather than
   left to an implementer's judgement. Two failure modes to avoid in opposite directions:
   **do not "simplify" one to match its mutant** (each goes live the moment the redundant arm
   is narrowed, which §3.0's box already refuses), and **do not write an anchor claiming to
   catch one** — an assertion that cannot fail makes a suite vacuously greener than it is.
8. **THE `eq(x, K0)` FOLD REACHES INSIDE A BLOCK'S OWN SCHEDULE (§2.9's box).** Eleven rows,
   and a scan that applies the fold at row granularity is wrong in both directions.
9. **R11's POOL CEILING.** `S_fptoui(64)` is over 11k qubits before M33's `fsub`, and D2/D20's
   ceiling is hard. The behaviour is already decided (PRD-v2 §4's R11, D25) and the live
   prohibition is that **neither the shim nor M37 may grow its own "that will not fit"
   check**. Listed last because it is a known disposition, not an open question — but §4.3's
   box notes the new shape: `fptoui` is the first kernel whose peak is dominated by a nested
   copy of another kernel, and the tempting share is a silent miscompile.
