\field{The ask}
Make \texttt{libcqops.a} an install-once CQ production backend at CQ\_lang
\texttt{0707dfd6}: export the canonical CMake target, install CQ's generated
provider manifest, supply a batch-safe installer, prove an installed consumer
does not pull CQ's trace archives into the link, and document the contracts for
another CQ backend or QEC engine.

\field{What landed}
The existing \texttt{cqops} static target now installs its archive and public
header with a relocatable \texttt{CQBackend} CMake package whose imported spelling
is \texttt{CQBackend::backend}; the build-tree \texttt{cqops::cqops} alias remains.
The export carries \texttt{libm}, and a QEC-enabled export carries the QEC include
directory and \texttt{libqec.a}, \texttt{libtommath.a}, and \texttt{libcjson.a} in
that order.  The generated manifest and the three CMake package files install
beside it.  \texttt{tools/install\_cqops.py} pins the CQ contract commit, checks a
requested QEC tree before configuration, regenerates and compares the manifest,
builds, tests, installs, and validates the installed archive.  A separate installed
consumer finds both packages, calls a real \texttt{cqrt\_*} symbol, runs, and checks
its link map for backend provenance.

\texttt{docs/BACKEND\_CONTRACT.md} now separates and specifies the complete CQ
static ABI, libcqops' six-callback logical-gate sink, and the concrete
\texttt{qec.h} adapter.  It includes provider CMake and manifest recipes,
semantic and clean-ancilla obligations, installed-consumer tests, and the current
QEC deployment constraint: link metadata is complete, while its external build
tree and runtime configuration remain required.

\field{Not taken}
The backend was not weakened to accept CQ's one emitted i64 QRAM index.  CQ's
frozen runtime contract says that rail is always i32, and libcqops' refusal protects
the reversible QROM operand model; the cross-repository mismatch is isolated in
\bead{b6a}.  The exhaustive L6 audit remains outside the installation gate, matching
the repository manual, while L7 and the package/contract checks run in the installer.
The QEC archives were not copied into the libcqops prefix: the installed target
records their build-tree paths, and the provider manual names the resulting
deployment constraint instead of calling that prefix a self-contained QEC bundle.

\field{Verified}
\texttt{make lint}, \texttt{make shim-check}, the full local CTest suite in Debug
with ASan/UBSan and Release, the installed-package consumer in both configurations,
the Release QEC installer end to end, CQ's L7 Grover integration, direct CQ backend
contract validation, and the opt-in L6 audit all ran.  Every packaging and local
gate passed.  L6's sole abort is the i64-index mismatch above; all other 412 L6
fixtures either ran or were classified deferred by the existing audit.  The manual's
contract counts were re-read from CQ's descriptor, and all four documented QEC
artifacts were checked at their configured paths.
