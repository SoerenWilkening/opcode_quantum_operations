# cq_templates_abi.txt -- the cq_template_* ABI, 2479 declarations VERBATIM.
#
# WHAT THIS IS AND WHY IT IS NOT A REGENERABLE GOLDEN. tests/goldens/*.counts are
# L4 gate counts that CQOPS_UPDATE_GOLDENS=1 re-pins from our own library; this
# file is the opposite. It is an INDEPENDENT ORACLE: the 2479 declarations
# CQ_lang's own tools/gen_templates.py produced from the SAME pinned yaml, by a
# different program that cannot share our reading of the naming rules.
#
# THAT INDEPENDENCE IS THE WHOLE POINT (CLAUDE.md's "an oracle that shares a
# constant with the code is blind to exactly what that constant gets wrong").
# shim/gen_shim.py expands opcode_table.yaml:35-59 into names and signatures; a
# test that re-expanded them itself would share every transcription slip the
# generator made -- the `_controlled`-before-`_inv` suffix order, the bare-QQ
# base symbol, `_lh`'s operand order, the classical operand's c_type. Diffing
# against THIS catches all of them. Nothing in libcqops may write this file.
#
# PROVENANCE, and the R3-shaped drift check that rides on it:
#   source        : CQ_lang runtime/cq_templates.h (generated, not hand-written)
#   CQ_lang HEAD  : b978796b7b3cc110571c4d920adbaef6f645556f
#   yaml-sha256   : 6245117dcffb4b1c34935ac9ba3f9d42d754c2dc5a881c9510ad594ba3e82426
#
# The sha above is the banner of that generated header AND the sha256 of our
# pinned third_party/cq_lang/opcode_table.yaml -- they are equal, which is what
# proves this manifest is the expansion of the yaml we actually ship rather than
# of whatever CQ_lang happens to have today (CQ_lang is UNPINNED: its HEAD has
# already moved past third_party/cq_lang/COMMIT's a6a92fe while the yaml has
# not). tests/test_gen_shim.py asserts that equality before reading a line of
# it, so re-pinning the yaml turns this red LOUDLY instead of silently
# comparing the new grid against the old ABI.
#
# To refresh: re-pin opcode_table.yaml first, then re-extract from CQ_lang's
# regenerated header. Never hand-edit a declaration.
